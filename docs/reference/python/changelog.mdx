### 1.45.17 (2026-11-22) {#v1-45-17}

**Added**

- **RPCInvokeOptions.request_id** sets the request ID of one **invoke_rpc** call. Pass the same ID on every attempt, such as the ID of an event delivered at least once, and Dex Server applies the RPC's Flow changes at most once. [Reference](/reference/server/runtime-data#rpc-request-ids).
- A repeat of a transactional or locking RPC returns the recorded reply without running its handler again. **None**, the default, keeps the generated request ID. Dex Server 0.1.36 and earlier reject a different request under one ID with **DexServiceError** INVALID_ARGUMENT.

### 1.45.16 (2026-11-20) {#v1-45-16}

**Added**

- Client-side payload encryption. Set **payload_encryption** on **ClientOptions** and **WorkerOptions** to a **PayloadEncryptionOptions**, and the SDK encrypts every Value before it reaches the Server and decrypts it after it returns. The Server stores only ciphertext and never holds keys.
- **AesGcmPayloadCodec** uses AES-256-GCM with a random nonce per Value and optional gzip. Install with **pip install 'dex-python-sdk[encryption]'** and use **FilePayloadEncryptionKeyProvider** for shared key files and rotation. [Reference](/reference/server/payload-encryption#interfaces).
- Plug in your own encryption, such as a KMS, with **PayloadCodec**, or with **AsyncPayloadCodec** for **AsyncClient** and **AsyncWorker**. **PayloadContext** tells the codec which Flow stores the Values, so a key provider can use one key per tenant.
- With a codec, strings, objects, ints, doubles, and bools encrypt by default, except indexed Attributes. The SDK requires **plaintext=True** for **wait_for_attribute_match** or Action conditions on Attributes it would encrypt. [Reference](/reference/server/payload-encryption#plaintext-attributes).
- Worker error text and the reasons of **force_fail**, **stop_flow**, **time_travel**, and **clone_fork_flow** are encrypted too, and the SDK decrypts them where it exposes them.
- Encrypted and plaintext Flows can share one Worker. A Client or Worker without a codec that reads an encrypted Value fails with "value is encrypted; configure a PayloadCodec". The Java and Rust SDKs cannot read encrypted Flows yet.

### 1.45.9 (2026-11-19) {#v1-45-9}

**Fixed**

- Keep AsyncWorker stopped when stop or close occurs during startup. Release its channels if the start task is canceled.

### 1.45.8 (2026-11-18) {#v1-45-8}

**Fixed**

- Workers now accept omitted input for inputless RPCs, including calls from TypeScript Clients before 1.45.8. RPCs that declare input still reject an omission with **ValueMappingError**. (#2034)

### 1.45.7 (2026-11-18) {#v1-45-7}

**Added**

- **PullWorkerOptions.min_open_slots** lets a pull Worker vary open streams with load when set below **max_concurrent_tasks**. The default equals **max_concurrent_tasks**, keeping the stream count fixed. [Reference](/reference/python/workers#capacity-and-shutdown).
- Adaptive Workers warn and clamp **max_concurrent_tasks** when it exceeds **matching.maxConcurrentTasksCap**. Growth and post-readiness reconnects retry after **RESOURCE_EXHAUSTED** without a **PullRegistrationError**. [Reference](/reference/server/workers#adaptive-slot-streams).
- **Worker.pull_slot_stream_state** and **AsyncWorker.pull_slot_stream_state** return a **PullSlotStreamState** snapshot of streams, handlers, capacities, and scaling counters. [Reference](/reference/python/workers#capacity-and-shutdown).

**Changed**

- Fixed pull Workers with unset **max_concurrent_tasks** now warn and clamp the CPU-count default to **matching.maxConcurrentTasksCap**. An explicit limit above the cap still prevents startup. [Reference](/reference/server/workers#adaptive-slot-streams).
- When **reserved_rpc_tasks** is None, it now reserves an RPC-only slot only when both **max_concurrent_tasks** and **min_open_slots** are at least two. With the default **min_open_slots** the reserve is unchanged.

### 1.45.4 (2026-11-16) {#v1-45-4}

**Added**

- **graceful_completion_requested** lets Steps wait for a graceful completion request and **is_graceful_completion_condition_completed** reads the result. Requires Dex Server 0.1.34 or later and protocol 7. [Reference](/reference/python/waits#graceful-completion-requests).
- **StopType.GRACEFUL_COMPLETE**, **StopType.FORCE_COMPLETE**, and **StopFlowOptions.output** let **Client.stop_flow** and **AsyncClient.stop_flow** complete a Flow with a result, like the **graceful_complete** and **force_complete** Step decisions. They need Dex Server 0.1.34 or newer.
- Use **graceful_completion_requested** in **wait_for** only when **supports_graceful_completion_condition** returns True. It checks the negotiated protocol for version 7+ and returns False for Contexts created outside Dex. [Reference](/reference/python/waits#graceful-completion-requests).

### 1.45.3 (2026-11-15) {#v1-45-3}

**Added**

- **Client.clone_fork_flow** and **AsyncClient.clone_fork_flow** copy run state into a new Flow. **CloneForkFlowOptions** defaults to the current point and **CloneForkFlowResult** identifies it. Requires server-zd 0.1.33+. [Reference](/reference/server/runtime-client#clone-fork).
- **TimeTravelType.EVENT_ID** with **TimeTravelOptions.event_id** time travels to the point right after one history event, and **TimeTravelOptions.sub_flow_reset_policy** takes a **SubFlowResetPolicy** that decides what happens to the SubFlow conditions of restored Steps.
- The SDK supports Dex Server protocol version 6.
- **FlowErrorType.SUB_FLOW_ABANDONED** marks a failed SubFlow result whose parent Flow stopped waiting for the child, because a Time Travel's SubFlow reset policy failed the restored SubFlow condition. **execute** reads it from **SubFlow.get_condition_results** like any other failed child.

**Fixed**

- Reading a SubFlow result with an error type this SDK version does not recognize no longer raises **ValueError**. **FlowResult.error_type** is then **None**.

### 1.45.2 (2026-11-14) {#v1-45-2}

**Added**

- **Client.get_flow_state** and **AsyncClient.get_flow_state** return open Step executions and **FlowState.task_queue** without a Worker. An empty queue name means the default. [Reference](/reference/python/client#api-names).

### 1.45.1 (2026-11-14) {#v1-45-1}

**Added**

- Set named queues with **PullWorkerOptions.task_queue**, **StartFlowOptions.task_queue**, and **SubFlowOptions.task_queue**. Empty uses the default queue for Workers and Flows or the parent's queue for SubFlows. [Named task queues](/reference/python/workers#named-task-queues).
- Named queues require Server protocol 5. **start** and **start_flow** raise **RuntimeError** on older Servers. Queue mismatches are permanent rejections. **PullRegistrationError** and **pull_registration_state** entries carry **task_queue**. [Reference](/reference/python/workers#named-task-queues).

### 1.45.0 (2026-11-11) {#v1-45-0}

**Breaking**

- A custom Step type containing "-" can no longer start SubFlows. For a Wait containing **SubFlow.run**, the Worker logs a warning and Dex Server fails the attempt without retry. Change **get_step_type** to return a name without "-". [Reference](/reference/python/subflow#step-types-that-start-subflows).

**Added**

- **WorkerOptions.flow_definition_paths** and **WorkerOptions.flow_definitions** upload registered graphs at startup. Use **FlowDefinitionDocument** in memory. Uploads require server-zd 0.1.26+ and share **source.path** only as relative. [Reference](/reference/python/workers#flow-definitions).
- **Client.upload_flow_definitions** uploads Flow definitions from a deploy script and returns a **FlowDefinitionUploadResult** with a **FlowDefinitionUploadOutcome** for each document. **AsyncClient** has the same coroutine. [Reference](/reference/python/workers#flow-definitions).

**Fixed**

- The **Join** documentation no longer recommends reporting a result for a cancelled branch from the cancelling RPC, which could count that branch twice. A cancelled branch never reports, and no other code can safely report for it. [Reference](/reference/python/waits).

### 1.38.0 (2026-11-07) {#v1-38-0}

**Added**

- **FlowConfig.history_window_events** controls recent history for reads and Time Travel at start or via **update_flow_config**. None uses **history.windowEvents**, and the option requires server-zd 0.1.21 or later. [Reference](/reference/server/configuration#history-window).

**Changed**

- The gRPC receive limit rises from 4 MiB to **DEFAULT_GRPC_MAX_MESSAGE_BYTES** (32 MiB) on every FlowService and pull stream channel. Set **grpc_max_message_bytes** on **ClientOptions** or **WorkerOptions** to change it.

**Fixed**

- A LoadBlobs request splits in half when its response exceeds a gRPC size limit, so a Worker with an empty blob cache no longer fails on a long Flow. A single blob that does not fit raises the new **BlobMessageTooLargeError**.

### 1.35.0 (2026-11-06) {#v1-35-0}

**Breaking**

- Workers and the Client’s first call now require server-zd 0.1.17 or later (protocol version 4). Upgrade all server processes before upgrading the SDK. [Reference](/reference/server/upgrades).
- Worker startup fails when **max_concurrent_tasks** exceeds **matching.maxConcurrentTasksCap** (256 by default). Lower the Worker setting or raise the server cap and **matching.maxStreams** first. [Reference](/reference/python/workers#capacity-and-shutdown).
- **RetryPolicy.total_duration** now starts at the first hand-out and only gates scheduling another retry. Set method timeouts to bound running attempts. [API reference](pathname:///api/python/latest/dex.html#RetryPolicy.total_duration).
- A Step with no available or supporting Worker waits durably without consuming a retry. Set a Flow timeout to bound that wait. [Reference](/reference/server/workers#step-task-queue).
- A Step attempt interrupted after its hand-out was committed fails with **NOT_COMPLETED** and consumes a retry. Review retry policies and side effects before upgrading. [Reference](/reference/python/failure-and-retries#same-attempt-redelivery).

**Added**

- **RecoveryErrorInfo.attempt_progress** distinguishes a failed Step method that never started from one that may have run. [API reference](pathname:///api/python/latest/dex.html#RecoveryErrorInfo.attempt_progress).

**Changed**

- Workers open one execution stream per slot; **reserved_rpc_tasks** selects RPC-only slots. By default, a Worker with at least two slots reserves one for RPCs. [Reference](/reference/python/workers#capacity-and-shutdown).
- **stop** drains running handlers and returns tasks that did not start without consuming a retry. [Reference](/reference/python/workers#capacity-and-shutdown).

**Deprecated**

- **idle_streams_per_queue** is accepted but ignored, and **pull_reserved_rpc_declines** always reports zero. Use execution-slot capacity and queue metrics instead. [Reference](/reference/python/workers#reserved-rpc-capacity).
