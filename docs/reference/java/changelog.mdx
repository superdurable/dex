### 1.45.16 (2026-11-20) {#v1-45-16}

No user-visible changes.

### 1.45.8 (2026-11-18) {#v1-45-8}

**Fixed**

- A Worker serves an RPC declared without input when the request leaves the input unset, as TypeScript Clients before 1.45.8 send it. Before, the Worker failed the call with **Value has no concrete kind**. An RPC declared with an input still needs one; an unset input fails the call with **ValueMappingException**. (#2034)

### 1.45.7 (2026-11-18) {#v1-45-7}

**Added**

- **PullWorkerOptions.Builder.minOpenSlots** makes a pull Worker adaptive when it is below **maxConcurrentTasks**. The Worker keeps between the two counts of slot streams open, both including the reserved RPC slots: it doubles its Step-and-RPC streams when a task takes the last idle one, and every 30 seconds it half-closes half of the idle surplus. An idle adaptive Worker holds only its floor of Server streams. The default equals **maxConcurrentTasks**, which keeps the Worker fixed with unchanged behavior.
- An adaptive Worker clamps **maxConcurrentTasks** above the Server's **matching.maxConcurrentTasksCap** to the cap with a warning. It treats a **RESOURCE_EXHAUSTED** registration of a growth stream, or of a reconnect after readiness, as a soft limit, without a **PullRegistrationError**. After a soft rejection the Worker waits for another of its registered streams to end, or for the next 30-second shrink window, before it opens a stream again. While rejections continue, it grows by at most one batch per window.
- **Worker.getPullSlotStreamState** returns a **PullSlotStreamState** snapshot of the slot streams: open, registering, busy, and idle streams, orphaned handlers, the floor and capacities, and grow and shrink counters.

**Changed**

- A fixed pull Worker with **maxConcurrentTasks** unset now opens one stream first, learns the Server's **matching.maxConcurrentTasksCap** from its registration, and clamps its CPU-count default to the cap with a warning instead of failing to start. Its other streams open after that first registration. An explicit **maxConcurrentTasks** above the cap still fails to start, and a fixed Worker with an explicit value still opens all its streams at once.

### 1.45.3 (2026-11-16) {#v1-45-3}

**Added**

- **GracefulCompletion.requested()** creates a wait condition that completes once the Flow has a graceful completion request, from **Client.stopFlow** with **StopType.GRACEFUL_COMPLETE** or from a Step's **gracefulComplete** decision. **Context.isGracefulCompletionConditionCompleted()** reports its result in execute. A Step can wait for its next message or the request with **Wait.anyOf**, handle a consumed message first, and return **deadEnd** otherwise. The condition needs Dex Server 0.1.34 or newer; with an older Server, the Step's waitFor fails with **GracefulCompletionConditionUnsupportedException**. The SDK now supports Server protocol 7.
- **StopType.GRACEFUL_COMPLETE**, **StopType.FORCE_COMPLETE**, and the **StopFlowOptions(StopType, String, Object)** constructor let **Client.stopFlow** complete a Flow with a result, like the **gracefulComplete** and **forceComplete** Step decisions. They need Dex Server 0.1.34 or newer.
- **Context.supportsGracefulCompletionCondition** reports whether the connected Server supports **GracefulCompletion.requested**, from the protocol version the Worker negotiated, without a request. **waitFor** can add the condition only when it returns true and keep working with Servers older than protocol 7. The default method returns false. [Reference](/reference/java/waits#graceful-completion-requests).

### 1.45.2 (2026-11-15) {#v1-45-2}

**Added**

- **Client.cloneForkFlow** creates a new Flow whose first run starts from a copy of another Flow run's state, at the current point or at a time travel point, while the source run keeps running. **CloneForkFlowOptions** selects the point, the source run, the new Flow's ID reuse policy, request ID, configuration, task queue, Attributes, Flow timeout, reason, and SubFlow reset policy; **CloneForkFlowResult** returns the new run ID and the copied source point. The call requires Dex server-zd 0.1.33 or later; against an older Server it throws **IllegalStateException** before sending the request.
- **TimeTravelType.EVENT_ID** with **TimeTravelOptions.Builder.eventId** returns a Flow to the point right after a history event, and **TimeTravelOptions.Builder.subFlowResetPolicy** takes a **SubFlowResetPolicy** that decides what happens to SubFlow conditions that restored Steps wait on. **TimeTravelType.CURRENT** selects the current point for **cloneForkFlow** only.
- **FlowErrorType.SUB_FLOW_ABANDONED** marks a failed SubFlow result whose parent Flow stopped waiting for the child, because a Time Travel's SubFlow reset policy failed the restored SubFlow condition. Earlier versions report such a result with a **null** error type. Code that matches every **FlowErrorType** value exhaustively, such as a switch expression, must handle the new value.

**Fixed**

- Maven POM metadata links the Apache 2.0 license text shipped with the Java SDK.

### 1.45.1 (2026-11-14) {#v1-45-1}

**Added**

- **PullWorkerOptions.Builder.taskQueue** makes a Worker pull one named task queue, and **StartFlowOptions.Builder.taskQueue** starts a Flow on one. Only Workers of that task queue run the Flow's Steps and RPCs, even when Workers of other task queues register the same Flow type. **SubFlowOptions.Builder.taskQueue** sends a SubFlow to another task queue; a SubFlow without it inherits its parent's task queue, and **dex.default** selects the default task queue. To serve several task queues, run one Worker per task queue. **PullQueueRegistrationState.getTaskQueue** and **PullRegistrationError.getTaskQueue** report the Worker's task queue. A named task queue requires Server protocol 5: the Worker and Client refuse it on an older Server, and a stream that the Server registers on a different task queue becomes a permanent rejection. [Reference](/reference/java/workers#task-queues).

### 1.45.0 (2026-11-11) {#v1-45-0}

**Breaking**

- A Step whose Step type contains **-** can no longer start SubFlows. The child Flow ID joins the parent Flow ID, Step execution ID, and SubFlow index with **-**, so a dash made two parents share one child. When such a Step's **waitFor** returns a **SubFlow.run** condition, the server rejects the result as an invalid Worker response and fails the attempt without retry; with the default failure policy, the Flow fails. Steps that start no SubFlows are unaffected. To migrate, rename the Step type, for example by overriding **getStepType**; the rename changes the child Flow IDs of new SubFlow starts. [Reference](/reference/java/subflow#step-types-that-start-subflows).

**Added**

- **WorkerOptions.Builder.flowDefinitionPaths** and **WorkerOptions.Builder.flowDefinitions** make a **Worker** upload Flow Definition Graph documents when it starts, so Dex Web can draw the Flow types it registers. **FlowDefinitionDocument** holds an in-memory document. Upload failures, including a Server without Flow definition storage, are logged as warnings and never stop the Worker. [Reference](/reference/java/workers#upload-flow-definitions).
- **Client.uploadFlowDefinitions** uploads documents from a deploy or CI script and returns a **FlowDefinitionUploadResult** with a **FlowDefinitionUploadOutcome** for each document. [Reference](/reference/java/client#api-names).

**Fixed**

- The **Join** documentation no longer recommends reporting a result for a cancelled branch from the cancelling RPC, which could count that branch twice. A cancelled branch never reports, and no other code can safely report for it. [Reference](/reference/java/waits).

### 1.44.0 (2026-11-10) {#v1-44-0}

**Added**

- **Join** and **JoinRound** synchronize parallel branches of one Flow. **Join.fork** starts a round from a split Step and derives the round key and branch count; **Join.forkWithRoundKey** takes an application key, for example in an RPC. Branches report with **endBranch** or **reportBranchResult**. The join Step waits with **forAllBranches**, **forFirstBranch**, or **forBranches**, and the next round resets with **forRemainingBranches**. A Join is stored as a ChannelMap with the same name; **Join.getChannelMap** returns it for reading a round's pending results, never for publishing. [Reference](/reference/java/waits).
- **StepDecision.goToMany(List)** and **RPCResult.of(output, List)** accept a list of movements, such as the result of **Join.fork**, and behave like the varargs forms. A call with a literal **null** argument is now ambiguous and no longer compiles; it always threw at run time. [Reference](/reference/java/step-decisions#gotomulti).

### 1.40.0 (2026-11-09) {#v1-40-0}

**Added**

- **FlowConfig.Builder.offloadHistory(boolean)** chooses whether a run offloads its history to object storage. Omitting it means true. Pass false for many short runs that close soon. Set it at start through **StartFlowOptions.Builder.configOverride** or in **SubFlowOptions**. A SubFlow otherwise inherits its parent's value, and **Client.updateFlowConfig** rejects it with INVALID_ARGUMENT. It requires server-zd 0.1.23 or later. [Reference](/reference/server/configuration#history-offload).

**Changed**

- **FlowConfig.Builder.deleteExpiredHistoryObjects(boolean)** is deprecated. It has no effect, and the SDK no longer sends it. Existing code that sets it still compiles.

### 1.35.0 (2026-11-06) {#v1-35-0}

**Breaking**

- Workers and the Client’s first call now require server-zd 0.1.17 or later (protocol version 4). Upgrade all server processes before upgrading the SDK. [Reference](/reference/server/upgrades).
- Worker startup fails when **maxConcurrentTasks** exceeds **matching.maxConcurrentTasksCap** (256 by default). Lower the Worker setting or raise the server cap and **matching.maxStreams** first. [Reference](/reference/java/workers#capacity-and-shutdown).
- **RetryPolicy.Builder.totalDuration** now starts at the first hand-out and only gates scheduling another retry. Set method timeouts to bound running attempts. [API reference](pathname:///api/java/latest/io/superdurable/dex/RetryPolicy.Builder.html).
- A Step with no available or supporting Worker waits durably without consuming a retry. Set a Flow timeout to bound that wait. [Reference](/reference/server/workers#step-task-queue).
- A Step attempt interrupted after its hand-out was committed fails with **NOT_COMPLETED** and consumes a retry. Review retry policies and side effects before upgrading. [Reference](/reference/java/failure-and-retries#same-attempt-redelivery).

**Added**

- **RecoveryErrorInfo.getAttemptProgress()** distinguishes a failed Step method that never started from one that may have run. [API reference](pathname:///api/java/latest/io/superdurable/dex/RecoveryErrorInfo.html).

**Changed**

- Workers open one execution stream per slot; **reservedRpcTasks** selects RPC-only slots. By default, a Worker with at least two slots reserves one for RPCs. [Reference](/reference/java/workers#capacity-and-shutdown).
- **stop** drains running handlers and returns tasks that did not start without consuming a retry. [Reference](/reference/java/workers#capacity-and-shutdown).

**Deprecated**

- **idleStreamsPerQueue** is accepted but ignored, and **getPullReservedRpcDeclines()** always reports zero. Use execution-slot capacity and queue metrics instead. [Reference](/reference/java/workers#reserved-rpc-capacity).
