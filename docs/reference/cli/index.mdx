# Dex CLI reference

**dexcli** operates and inspects Flows. Its output is JSON by default, so shell
scripts and AI agents can use it as well as human operators.

## Start a local development server {#start-locally}

**dexcli dev** starts server-zd and the embedded Dex Web. server-zd is the only
engine. Existing scripts can keep **--engine zd**; it has no effect.
The release package includes **dex-server-zd** next to **dexcli**. To find the
server binary, dexcli checks **--zd-binary**, then **DEX_SERVER_ZD_BINARY**, then
the directory of the dexcli executable (and the directory a symlink to it
resolves to), then PATH.

```bash
dexcli dev --open=false --zd-data-dir ./dex-state
```

| Flag | Default and behavior |
|---|---|
| **--engine** | **zd**; accepted for compatibility. |
| **--zd-binary** | Override the bundled server-zd executable. |
| **--zd-data-dir** | **$HOME/.dex/zd/&lt;dex-port&gt;**; persistent local state. |
| **--zd-config** | Optional server-zd YAML overrides. |
| **--attribute-store-config** | Optional YAML file; server-zd reads its **attributeStore** section. Supports PostgreSQL. Since dexcli 1.19.0. |
| **--bind-address** | **127.0.0.1**; bind IP for local services. |
| **--dex-port** | **8801**; Dex gRPC port. |
| **--web-port** | **8802**; embedded Dex Web port. |
| **--open** | **true**; use **--open=false** to keep the browser closed. |
| **--server-log-folder** | Empty; logs go to stderr. When set, also writes **dex-server-zd.log** in that directory. |
| **--flow-rendering-dir** | Empty; optional Flow Definition Graph JSON directory. Leave it empty when Workers or **dexcli flow-definition upload** store the definitions on the server. |
| **--connector-config-dir** | **$HOME/.dex/connectors**; local Connector credentials. |
| **--connector-release-override** | Repeatable **connector-id=artifact-directory** for a local Connector release. |
| **--allowed-hosts** | Empty; comma-separated host names that Dex Web **/api** requests may name besides loopback names and IP addresses. Since 1.42. See [Allowed hosts](/reference/web/dex-web#allowed-hosts). |
| **--connectors-mcp** | **true**; finds or starts the Dex Connectors MCP server and serves it at **/mcp** on the Dex Web port. Only a loopback **--bind-address** serves **/mcp**. Since 1.43. See [Connectors MCP server](#connectors-mcp). |
| **--connectors-mcp-version** | Empty; the newest compatible release. Set **X.Y.Z** to pin a release. Since 1.43. |
| **--connectors-mcp-binary** | **DEX_CONNECTORS_MCP_BINARY**; a local **dex-connectors-mcp** executable to run instead of a downloaded release. Since 1.43. |
| **--connectors-mcp-connection** | Repeatable **connectorId/connectionName[=tool,...]**; the connections the server offers, optionally narrowed to tools. Empty offers every authorized connection. Since 1.43. |

If a default port is in use, Dex picks the next free port and prints its
addresses. If a port you pass explicitly is in use, the command fails. The
default state directory uses the Dex port that was picked. Ctrl+C stops Dex Web
and the server-zd child process.
server-zd supports pull Workers. See [Server reference](/reference/server/)
for storage, durability, and Attribute Store configuration.

A new state directory has 32 partitions. A state directory that dexcli before
1.37.0 created has 1024 partitions, and server-zd refuses to start on it with
the default. To keep using it, pass a **--zd-config** file that sets
**cluster.partitionCount** to 1024. Otherwise delete the state directory. See
[Partition count](/reference/server/configuration#single-node-partition-count).

The Temporal engine was removed. **--engine temporal**, all
**--external-temporal-*** and **--temporal-*** flags, **--sqlite-db-filename**,
**--verbose-engine-log**, and **--blob-store-dir** now fail with an error that
names server-zd as the only engine. Remove those flags and use **--zd-data-dir**
and **--zd-config** instead. Start with a new server-zd data directory;
Temporal SQLite files cannot be used as server-zd state.

## Connectors MCP server {#connectors-mcp}

Since 1.43. **dexcli dev** serves the agent tools of authorized Connector
connections at **http://127.0.0.1:8802/mcp**, the **/mcp** path of the Dex Web
port. An agent that connects to Connectors through MCP uses this URL. The URL
stays the same while the server behind it restarts or updates.

The tools come from the Dex Connectors MCP server, **dex-connectors-mcp**, which
the Connectors library releases. No Connector is compiled into dexcli.
**dexcli dev** prepares the server in this order:

1. It reuses a compatible server that already runs for the same state
   directory and **connections.json**. dexcli does not trust **server.json**
   alone: the server must hold the state directory's instance lock, and its
   **/healthz**, on the same address as its **/mcp**, must confirm the
   instance, launch contract, and version. dexcli must support that launch
   contract. The server must offer the same **--connectors-mcp-connection**
   selection; the order does not matter.
2. Otherwise it runs **--connectors-mcp-binary** when set. Without it, dexcli
   reads the release index at
   **https://connectors.superdurable.io/connectors-mcp/index.json** at most once
   a day. It picks the newest release whose launch contract it supports, and
   downloads the archive for this platform. Every request and redirect must use
   https. It checks the archive's SHA-256 against the index before it extracts
   the binary. Releases are cached in
   **$HOME/.dex/tools/dex-connectors-mcp/&lt;version&gt;**, with the SHA-256 of the
   extracted binary. Before each start, dexcli checks the cached binary against
   that SHA-256 and refuses symlinks in the cache. It deletes a cache entry that
   fails, and downloads the release again. When the index cannot be fetched,
   dexcli uses the newest cached release that passes the check.
3. It starts the server on a free loopback port. The server reads the
   **connections.json** in **--connector-config-dir**, the file the Dex Web
   Connectors page writes. Its state directory is
   **$HOME/.dex/connectors-mcp**. With another **--connector-config-dir**, it is
   **$HOME/.dex/connectors-mcp-&lt;digest&gt;**, so each **connections.json** has its
   own server. When the server stops, dexcli restarts it after a delay that
   grows from 1 second to 30 seconds. The server exits when **dexcli dev**
   exits.

In its ready output, **dexcli dev** prints the **/mcp** URL. It reports Dex
Server and Dex Web ready without waiting for the Connectors MCP server. Until it is ready, and while it
restarts, **/mcp** answers HTTP 503. When no server can run, for example
offline with an empty cache, on a platform without a release, or after 5
failed starts in a row, **dexcli dev** keeps running and prints a hint to
stderr. Pass **--connectors-mcp=false** to turn the server off.

The cache check detects a corrupt or replaced cache entry. It does not protect
against a program that runs as the same user: a program that can write
**$HOME/.dex** can also replace **dexcli** itself.

Tool calls carry no credentials, so **/mcp** accepts only loopback **Host**
names: **localhost**, ***.localhost**, and loopback IP addresses. Other names
get HTTP 403. This stops DNS rebinding. **--allowed-hosts** does not
apply to **/mcp**, so a tunnel name added for Dex Web does not expose tool
calls. A request whose **Origin** is not an **http** loopback origin, or that a
browser marks as cross-site, also gets HTTP 403.

### Serve only the Connectors MCP server {#connectors-mcp-command}

Since 1.47.7. **dexcli connectors mcp** serves the Connectors MCP server
without Dex Server or Dex Web. Use it when an agent works against a remote Dex
server, such as Dex Cloud, and still needs the Connector tools authorized on
this machine. Dex Agents CLI commands 0.6.9 and later run it for
**connectors.mcp: auto**.

It prepares the server in the same order as **dexcli dev**, with the same
state directory and instance lock. So it reuses the server of a running
**dexcli dev** for the same **connections.json**, and a later **dexcli dev**
reuses the server it started. Only one server runs for each
**connections.json**, so credential refreshes never run twice. Paths that
reach the same file through a symlink count as the same **connections.json**.

It serves its own **/mcp** proxy on a free loopback port. The proxy URL stays
the same while the server behind it restarts, and it has the same **Host** and
**Origin** checks as **/mcp** on the Dex Web port.

| Flag | Default and meaning |
| --- | --- |
| **--connector-config-dir** | **$HOME/.dex/connectors**; the directory whose **connections.json** the server reads. |
| **--connectors-mcp-version** | As for **dexcli dev**. |
| **--connectors-mcp-binary** | As for **dexcli dev**. |
| **--connectors-mcp-connection** | As for **dexcli dev**. |
| **--exit-on-stdin-close** | **false**; also stop when standard input closes. A caller that starts the command sets it, so the command stops even when the caller is killed. |

The command waits until a server answers, then prints exactly one JSON line on
stdout and serves until SIGINT or SIGTERM:

```text
{"type":"ready","url":"http://127.0.0.1:53124/mcp","pid":4242,"connectionsFile":"/home/me/.dex/connectors/connections.json"}
```

**url** is the proxy URL. **pid** is the dexcli process; stop it to stop the
proxy. When it cannot start, such as for an invalid flag, offline with an
empty cache, or after 5 failed starts in a row, it prints one line with
**type** **error** and a **message** that says why, and exits with code 1.
Logs go to stderr.

On exit it stops a server it started. It never stops a server it reused. A
**dexcli dev** that reused its server starts its own server after a short
delay.

## Connect to Dex

Commands connect to **127.0.0.1:8801** by default. Set
**DEX_FLOW_SERVICE_ADDRESS** to change the target for every command, or pass
**--server** for one command. The server address is a gRPC **host:port**, not an HTTP URL. The
connection is plaintext unless you enable TLS.

```bash
DEX_FLOW_SERVICE_ADDRESS=dex.example.internal:8801 dexcli health
dexcli --server 127.0.0.1:9901 flow search
```

### Connect over TLS

When Dex, or a load balancer in front of it, terminates TLS, pass **--tls** or
set **DEX_TLS=true**. The CLI then uses TLS 1.2 or later and verifies the server
certificate against the system root CAs. The certificate must match the
**--server** host, which is also sent as the TLS server name. TLS never falls
back to plaintext.

```bash
dexcli --server dex.example.com:443 --tls health
DEX_TLS=true dexcli --server dex.example.com:443 flow search
```

Two optional settings require TLS:

- **--tls-ca-file** or **DEX_TLS_CA_FILE** names a PEM file of root CAs that are
  trusted in addition to the system roots. Use it when a private or self-signed
  CA issued the server certificate.
- **--tls-server-name** or **DEX_TLS_SERVER_NAME** sets the name that the server
  certificate must match, for example when **--server** is an IP address.

```bash
dexcli --server 10.0.0.12:443 --tls \
  --tls-ca-file /etc/dex/ca.pem --tls-server-name dex.example.internal health
```

The CLI negotiates HTTP/2 with the **h2** ALPN protocol. A load balancer that
terminates TLS must accept **h2** and forward gRPC to Dex over HTTP/2.

## Authentication

When Dex requires a bearer credential, provide the token in one of three ways.
In order of precedence: set **--credential-file** to a token file, set
**DEX_CREDENTIAL_FILE** to a token file path, or set **DEX_CREDENTIAL** to the
token value. dexcli reads the file before the first call. During long-running
commands such as **flow watch**, it checks the file for changes at most once per
second. An empty or unreadable file stops the call before it contacts Dex.
dexcli trims surrounding whitespace from the token.

```bash
dexcli flow search --credential-file /run/secrets/dex/token
DEX_CREDENTIAL_FILE=/run/secrets/dex/token dexcli flow watch order-123
```

There is no flag for the token value, because command arguments can appear in
shell history and process listings. Without **--tls**, the FlowService connection is
plaintext gRPC and the token crosses the network unencrypted. Enable TLS or
protect the network path.

## View a remote server in Dex Web {#web}

**web** serves Dex Web against the existing server given by **--server**. It
does not start a server. To reach a server whose FlowService port is bound only
to the remote host's loopback address, open an SSH tunnel in one terminal and
leave it running:

```bash
ssh -N -L 8801:127.0.0.1:8801 operator@dex-host
```

In another terminal, start Dex Web:

```bash
dexcli --server 127.0.0.1:8801 web
```

Then open [http://127.0.0.1:8802](http://127.0.0.1:8802). Startup fails when the **HealthCheck** call
cannot reach the server. **--timeout** bounds only the startup checks. **--open=false** skips
the browser. A running **dexcli dev** also uses ports 8801 and 8802, so pick
another tunnel port and **--web-port** to run both. Dex Web has no
authentication, so keep **--bind-address** on loopback. See
[View a remote server with dexcli web](/reference/web/dex-web#dexcli-web) for every
flag.

## Upload Flow definitions {#flow-definition}

**flow-definition upload** stores Flow Definition Graph 2.0 JSON on the server.
Pass files or directories. Since 1.45.

```bash
dexcli flow-definition upload ./flow-definitions --server dex.example.com:8801
```

It reads files with the Go SDK rules:

- A missing path, or a named file that is not a valid FDG 2.x document, fails
  the command with a usage error. **flow.name** is the Flow type.
- A directory is read recursively. Files whose extension is **.json**, in any
  letter case, are considered. Other JSON files, such as **package.json** or FDG
  1.x files, are skipped and logged on stderr.
- The generated time is the top-level **generatedAt**, which must be a valid
  RFC 3339 time such as **2026-11-01T00:00:00Z**. Without it, the file modification time is used. It
  is truncated to whole milliseconds.
- Two files with the same Flow type fail the command before anything is sent.
- An absolute **source.path** is sent relative to the working directory, or as
  its base name. A relative one is sent unchanged.

The output lists each Flow type with its **outcome**, **storedDigest**, and
**storedGeneratedAt**. The outcome is **CREATED**, **REPLACED**, **UNCHANGED**,
or **KEPT_EXISTING**. **KEPT_EXISTING** means the server already has a different
definition with the same or a later generated time; its entry also has
**uploadedDigest** and **uploadedGeneratedAt**. An outcome this dexcli does not
know prints a warning on stderr. Add **--force** to replace it
anyway, for example to roll back. The command sends at most 256 definitions per
request. A request fails as a whole, and the command stops at the first failed
request.

**flow-definition list** prints every Flow type that has a stored definition. It
reads all pages.

```bash
dexcli flow-definition list --server dex.example.com:8801
```

Workers can upload the same files when they start. See
[Go Workers](/reference/go/workers#flow-definitions).

## Friendly Flow operations

**flow search**, **summary**, **state**, **history**, and **inspect** return JSON
of bounded size. **inspect** combines the summary, the current state, and the
history. Start with it when an agent investigates a Flow.

```bash
dexcli flow inspect order-123 --all-history
```

By default, dexcli loads stored strings and objects and prints their values.
Use **--no-hydrate** when you need only the structure and blob identities. The
output then contains stable **__dexBlobReference** objects instead of the
stored payload.

**flow watch** first prints the semantic history events that exist, then
long-polls for new ones. Each line is one JSON object. It stops when the run
reaches a terminal status.

Stop and time travel always require an exact **--run-id** and **--yes**. This
keeps an agent that looked up an older run from changing a newer one.

## Complete public API access

The **api** commands call any public **FlowService** RPC that the installed CLI
version knows:

```bash
dexcli api list
dexcli api describe InvokeRPC
dexcli api call InvokeRPC --data @invoke.json --yes
```

**api describe** reports request and response fields, oneofs, enums, maps, and
reachable message definitions. **api call** accepts canonical protobuf JSON from
an inline string, **@file**, or stdin with **--data -**. It returns canonical
protobuf JSON and, unlike the friendly commands, does not load stored values.

The **api** commands do not cover **WorkerService** or **InternalService**.
Workers and the server use them internally; they are not operator APIs.

## Check protocol compatibility

**dexcli version** prints the CLI build version. **dexcli version check** asks
the server for its supported protocol range (inclusive) and checks that it
overlaps the range built into this CLI:

```bash
dexcli version check --server dex.example.internal:8801
dexcli version check --output table
```

On success, the output includes the client and server versions, both ranges,
the highest common protocol as **negotiatedProtocol**, and **compatible: true**.
The command then exits with status 0. It prints a structured compatibility
error and exits with status 1 when the server does not implement the
information RPC, returns an invalid response, cannot be reached, or shares no
protocol with the CLI. The command supports the normal **--server**,
**--timeout**, and **--output** flags.

## Describe or step down the active server process {#admin-step-down}

**dexcli admin describe** prints the **nodeId**, **nodeEpoch**, and
**holderProcessId** of the active server process, and changes nothing. It fails
with **FAILED_PRECONDITION** while a step down or its hold-off is in progress,
and with **UNAVAILABLE** when no server process is reachable. Then wait until
the hold-off ends and describe again.

**dexcli admin step-down --yes** asks the active server process of a node ID to
give up its lease, so that another process of the same node ID can take over.
Both commands call **AdminService**, not **FlowService**. Step down needs
**--yes**, because the server stops serving until a process takes over.

```bash
dexcli --server dex.example.internal:8801 admin describe \
  --credential-file /run/secrets/dex/admin-token
dexcli --server dex.example.internal:8801 admin step-down --yes \
  --credential-file /run/secrets/dex/admin-token
```

Every step down request names the node ID and node epoch it expects. A process
that does not match answers **FAILED_PRECONDITION** and changes nothing. Without
**--expected-node-id** and **--expected-node-epoch**, the command first describes
the active process and expects the node ID and node epoch that describe returns.
With **--expected-node-id** alone, it describes first, refuses if the server
reports another node ID, and otherwise expects the described node epoch. This
protects a first run against a wrong **--server**. With both flags, it does not
describe. **--expected-node-epoch** alone is a usage error. If the first describe
fails, the command steps nothing down. A step down that is already in progress
may be one that you or someone else started.

The commands support the normal connection, TLS, credential, **--timeout**, and
**--output** flags. **dexcli admin step-down** waits up to 2 minutes by default.
That is longer than the default attempt drain plus the hold-off before the
stepped-down process competes for the lease again. If the server sets a longer
**lifecycle.attemptDrainTimeout**, raise **--timeout** by at least the same
amount. When the server requires authentication, the credential must be an admin
JWT. The API key exchange cannot ask for an admin audience. See
[admin credentials](/reference/server/authentication#admin-credentials).

The step down output reports **expectedNodeId**, **expectedNodeEpoch**,
**nodeId**, **releasedNodeEpoch**, **leaseReacquisitionHoldOff**, and
**leaseHolderAfterStepDown**. That last field is **takenOverByAnotherProcess**,
**takenBackByThisProcess**, or **unknown**. **activeNodeEpoch** and
**activeHolderProcessId** identify the process that holds the lease when it is
known. Node epochs are decimal strings.

A step down that fails with **DEADLINE_EXCEEDED**, **CANCELLED**, or
**UNAVAILABLE** has an unknown outcome. Its error output carries
**stepDownOutcome** set to **unknown**, the **expectedNodeId** and
**expectedNodeEpoch** that the call used, and a **hint**. Retry only with those
values: the node ID and epoch of the process you originally meant to step down.
Never use an epoch that describe printed after the failed call, because it
identifies whichever process is active by then. If describe now shows another
node epoch or holder process ID, the step down already happened, so do not
retry. Do not run the command again without these flags; it would describe and
step down whichever process is active now. A server without **AdminService** answers **UNIMPLEMENTED**. See
[retry a step down safely](/reference/server/high-availability#retry-step-down)
for details.

## Output and errors

JSON is the default output, and its format is stable. **--output table** is
for people to read; scripts must not depend on its format. A bounded command
has a 30-second client deadline by default; use **--timeout 0** to turn it off.
The deadline does not apply to **flow watch**.

Errors are JSON on stderr. They include **kind**, **operation**, **message**, and,
when they apply, **grpcCode**, **grpcCodeName**, and structured status details.
Exit status 2 means invalid usage or a missing confirmation. Status 1 means the
request failed.
