# Flow source visualization

`dexcli visualize` turns one Flow source file into a static Flow Definition Graph. The graph shows the paths the analyzer can determine from the source. It supports Go, Python, and TypeScript. **Since 1.47.23.** It also supports Java and Rust.

```bash
dexcli visualize ./order_flow.go
```

**Changed in 1.47.23.** The command generates only Flow Definition Graph 2.0 for the Dex Web **Designs** page. The deprecated `--schema-version` flag accepts only `2.0`.

**Since 1.47.23.** If the source defines multiple Flows, pass the registered Flow type with `--flow`. This is the name the application registers, including any custom name. If you omit the flag for a file with multiple Flows or supply an unknown name, the diagnostic lists the available Flow types.

```bash
dexcli visualize ./refund_flow.go --flow RefundFlow
```

The command opens the local **Designs** page and keeps it available until you press Ctrl+C. Use **--json** to get the Flow Definition Graph as JSON. Without **--out**, it writes the JSON to stdout:

```bash
dexcli visualize ./order_flow.py --json
```

Use **--out** to write files with a chosen prefix instead:

```bash
dexcli visualize ./order_flow.py --json --out ./build/order-flow
```

## Render definitions in Dex Web

Give Dex Web the generated JSON files through one of the [definition sources](#definition-sources). For example, start Dex with a directory containing them:

```bash
dexcli dev --flow-rendering-dir ./build
```

Open **Designs** from the **Experimental** menu, at **/v1/rendering**. Changed in 1.41.0: the page was called **Flow Rendering**. The menu links to it only while at least one Flow type has a definition. The header checks again on every page change. Without definitions, the page explains how to load them. Since 1.45.0, each definition in the list shows its source, and an uploaded one also shows when it was generated and uploaded. A definition that Dex Web rejected shows why instead of a graph. The page does not use Flow search or run details. It renders the selected definition interactively. Its legend can show or hide control flow, WaitFor, RPCs, Attributes, Channels, Streams, SubFlows, and diagnostics. Flow timeout handlers are always shown as part of the Flow. Streams are hidden by default. The other layers start visible. Changed in 1.41.0: one Flow design graph draws Version 1.0 and Version 2.0 files. For a Version 2.0 file, its diagnostics follow the graph. See [Dex Web](/reference/web/dex-web#flow-canvas).

**Designs** renders the definition of each Flow type, and **Work Queue** uses the definitions to list runs. See [Dex Web](/reference/web/dex-web).

### Definition sources {#definition-sources}

Since 1.45.0, Dex Web reads Flow Definition Graphs from two sources:

- **Uploaded definitions.** A Worker uploads the definitions it is given when it starts, and a deployment script can upload them too. The Dex Server stores one document for each Flow type. See [Flow definitions](/reference/server/runtime-client#flow-definitions) for **UploadFlowDefinitions** and its replacement rule. Dex Web reads them through the FlowService connection it already has, so it needs no directory for them. A Dex Server without these RPCs reports none, and Dex Web then shows only the directory.
- **The directory.** **--flow-rendering-dir** for **dex-web**, **dexcli dev**, and **dexcli web**, or **FlowRenderingDirectory** for [embedded Dex Web](/reference/web/embed-dex-web#targets). Dex Web reads the JSON files in the directory and its subdirectories on every definition request, so a changed file shows on the next page load without a restart. A path that is not a directory makes definition requests fail with **FLOW_DEFINITION_SOURCE_UNAVAILABLE**.

When both sources have a definition for one Flow type, the directory wins, even when its file is invalid, except for a file over the document size limit, which claims no Flow type. The two never conflict. Uploaded definitions must use schema version 2.0. A directory may hold Version 1.0 and Version 2.0 files.

Dex Web validates each definition on its own. An invalid or oversized definition is marked invalid, with the reason, and the other definitions keep working. Two valid Version 2.0 directory files for one Flow type mark both invalid. A directory file larger than the document size limit is not read. It is listed as invalid with an error that says it is too large, and it claims no Flow type, so an uploaded definition of the same Flow type is shown.

Every node, edge, and diagnostic must be a JSON object. Each node needs string **id**, **kind**, and **name**, each edge string **id**, **kind**, **from**, and **to**, and each diagnostic string **severity**, **code**, and **message**. The other fields that Dex Web reads, such as **metadata**, **resource**, **wait**, **decision**, and **span**, must have their documented JSON types when present; **null** is not accepted for them. A **wait** needs a string **type** and **conditions**, and each condition needs string **kind** and **label**. **conditions** may be **null**, which **dexcli visualize** 1.44 and older writes for a WaitFor that only fails; it reads as no conditions. In **metadata**, a node's **connectorFactory** must be a boolean, its **connector** must match the Connector identity that the analyzer writes, its **flowType** and **explanation** must be strings, and an edge's **rpcName** and **phase** must be strings. A group Step ID that names no Step node is ignored. When the Dex Server cannot be read, the definition list still shows the directory and reports the failure, while a page that needs one uploaded Flow type gets **FLOW_DEFINITION_SOURCE_UNAVAILABLE**.

Dex Web loads definitions only where they are used:

| Page or route | What it reads |
| --- | --- |
| The header and **/readyz** | The Flow types that have a definition, without their content. |
| A run page, its **Actions** and **Conversation**, and the v2 routes for one Flow type | The definitions of that one Flow type, through **GET /api/flow-definitions/by-type?flowType=FLOW_TYPE**. The Flow type is a query parameter, so Flow types such as **.** work. The browser keeps the answer and asks again with its revision, so an unchanged definition is not sent again. The route answers 304 to an **If-None-Match** that names the revision, weak or strong, or **\***. |
| **Designs** | Every definition without its graph, through **GET /api/flow-definitions**, then the graph of the selected one. |
| **Work Queue** | Every Version 2.0 contract, through **GET /api/v2/catalog**, and the graphs of the Flow types being searched. |
| **Connectors** | Every definition, to find the connections that Flows use. The app asks for the Connectors listing once when it loads, not on every page. |

Dex Web rejects a definition that exceeds one of these limits. The canvas also refuses to draw a larger graph and says that it is too large.

| Limit | Value |
| --- | --- |
| Document size | 8 MiB |
| Nodes | 2,000 |
| Edges | 10,000 |
| Characters in one JSON string or field name | 16,384 |
| JSON nesting depth | 128 |
| Connector Steps | 200 |
| Diagnostics | 1,000 |
| Step groups | 1,000 |
| Step IDs in all groups | 2,000 |
| Items in each of these Version 2.0 lists: Indexed Attributes, Summary fields, Display fields, Actions, one Action's input fields, one Action's condition values, Connector Trigger bindings, one binding's UI units, and one UI unit's bindings | 256 |
| Fields and enum values of the start input, counted at every depth | 1,024 |

Since 1.45.0, Dex Web ignores top-level fields that it does not know, such as **generatedAt**, so a newer **dexcli visualize** does not break an older Dex Web. Every field that Dex Web knows is still validated strictly, including unknown fields inside it. Dex Web 1.44 and older reject a Version 2.0 file with an unknown top-level field.

## What the graph contains

The main Flow appears as a lavender frame. Each Step is a blue frame inside it. WaitFor paths appear above Execute decisions. A conditional WaitFor or Execute return first passes through a diamond, then branches into separate cards labeled with the source condition.

The definition graph includes:

- the Flow and start Step
- registered Steps and statically known transitions grouped by Execute decision
- condition labels and fixed or runtime-sized fan-out
- ordered WaitFor conditions, including Channel counts, Timer durations, and external SubFlows
- RPC and timeout decisions and their next Steps
- Attribute names, source-language value types, and map status
- Channel, Attribute, and optional Stream access
- completion, failure, Channel-empty checks, and cancellation inside Execute cards
- Execute failure recovery paths

Terminal decisions do not create separate terminal nodes. Cancellation is shown inside the Execute card instead of adding duplicate arrows. The start Step carries a START marker instead of an incoming start edge. Timers appear as rows in WaitFor rather than separate nodes.

An error return or raised exception does not name a next Step, so it creates no transition. An explicit **ProceedToOnExecuteFailure** or **on_execute_failure_proceed_to** policy creates a solid magenta recovery edge to the recovery Step. The label records when the recovery skips WaitFor.

Resource arrows always point the same way:

- publisher → Channel → consuming WaitFor
- Attribute writer → Attribute box → Attribute reader
- WaitFor → folded SubFlow

Resource and SubFlow relations are dashed, so they look weaker than the solid Step transitions. Channels are grouped at the upper left of the Flow. Attributes share one box. RPC hexagons cross the left Flow boundary. A SubFlow is a small dashed frame containing only its Flow type; its internal Steps are not expanded.

The renderer fits the complete Flow into the viewport by default. Channel and Attribute arrows stay hidden until you select that resource or a related Step, WaitFor, Execute decision, RPC, or timeout handler.

Attribute relations include reads, writes, and locks. The Python analyzer follows static resource aliases on the Flow class, and records Attribute locks declared by RPC or Step options. Since 1.39.0, the TypeScript analyzer adds a node for each RPC, from **rpc** decorators and **declareRPCMethod** calls, and records the locks in its **lockAttributes**. Python and TypeScript RPC lock edges also carry **metadata.rpcName**. The Go analyzer counts a read or write in a same-package helper as made by the handler that calls it. The edge records the helper in its metadata. Since 1.39.0, the Go analyzer also records the Attribute locks in **RPCOptions.LockAttributes**. Each lock edge carries **metadata.rpcName**, the RPC name Dex Web invokes. In a Version 2.0 graph, an Action, Summary, or Display RPC whose locks the analyzer cannot read produces the blocking **rpc_lock_unresolved** diagnostic. Build the lock list from **dex.LockAttribute** or **dex.LockAttributeMap** calls in the options or in a variable of the Flow's package.

Stream relations describe observable application output, not control flow. They are hidden by default in Designs and can be enabled from the legend. The JSON marks Step Stream writes as repeatable and best effort. The graph leaves out heartbeat calls and checkpoint reads.

Go reports **step_progress_outside_step** when an RPC or Flow timeout handler calls **Stream.Write** or creates a writer with **NewBufferedTextStream**. The check also follows same-package helpers and buffered writer aliases. The error names the handler, Stream, and helper location. Move the output to a Step. An RPC can publish a Channel message or return **NextSteps** to schedule that Step. Since dexcli 1.47.3, TypeScript reports the same diagnostic for **write** or **bufferedText** on a Stream in an RPC or **handleTimeout**, including through a same-file helper.

## Supported source profile

For the selected Flow, the file must directly contain:

- static Step registration
- each registered Step handler
- Dex transitions and WaitFor definitions
- RPC next Steps
- execute-failure recovery targets
- persistence resource definitions
- Step Stream progress operations

Ordinary business helpers and imported models are allowed. A helper must not hide a Dex transition, WaitFor definition, resource definition, or recovery target. Resource names must be statically known. Flow types and Step types follow the rules in [Flow and Step names](#flow-and-step-names).

Go resource access may also be in functions and methods of the same package that a handler calls. The analyzer follows those calls up to six levels deep, including calls inside loops and function literals. A resource passed as an argument is bound to the matching parameter, so access through that parameter counts for the resource.

In Go, `WaitFor` can return `dex.AllOf` or `dex.AnyOf` with a spread slice of `dex.SubFlow` conditions. The graph draws one SubFlow condition and one `start` edge for the group. In the same block as the return, declare a local condition slice immediately before a `range` loop over a slice or array. Use a zero-value declaration, an empty slice literal, or `make` with a constant length of zero. The loop body must consist of one assignment that appends a direct `dex.SubFlow` call back to that slice. The slice appears in the loop only as the assignment target and first argument to `append`. The child Flow must have a concrete Go type and a statically known Flow type name. Return the Wait immediately after the loop. Spreads with only statically known non-SubFlow conditions still draw an unknown condition and report a warning. Changed in dexcli 1.48.1: this shape was an unknown condition; other Go condition spreads that can hold SubFlow conditions now report `dynamic_wait_condition`.

For ordinary resource operations, the Python analyzer scans the handler's own syntax and does not follow calls into separate helpers. See [Python Waits, movements, and resource access](#python-waits-movements-and-resource-access).

Go analysis requires a local Go toolchain. The input must belong to a module and package that can be type checked. Python analysis requires Python 3.11 or newer. The Python analyzer uses the standard-library AST. It runs the interpreter in isolated mode with automatic **site** initialization disabled, so **.pth** import lines and **sitecustomize** never run. It never imports or executes the application module.

For Python, the analyzer recognizes Stream outputs yielded by synchronous Step generators and synchronously enqueued Stream writes in asynchronous Step handlers. Step Stream progress in an RPC or Flow timeout handler is invalid and produces a blocking diagnostic.

TypeScript analysis requires Node.js and a **typescript** package. By default, the analyzer loads the **typescript** package that the source project resolves, through **node_modules** or **NODE_PATH**, and never one from the **dexcli** working directory. That package runs as code. Visualize untrusted TypeScript source only with a [trusted TypeScript compiler](#typescript-compiler). The analyzer reads the compiler AST without importing application modules.

A source project without **node_modules**, such as one in a build environment without network access, can use a separately installed compiler. Install a **typescript** package once in its own directory, and pass its package directory with **--typescript-compiler**. The **dexcli** tests use Node.js 22 and TypeScript 5.9.3. A Flow that calls a Connector factory still needs that Connector package installed under **node_modules** next to the source. See [Connector package manifests](#connector-package-manifests).

```bash
# Once, from a local npm cache or registry mirror.
npm install --prefix /opt/dex-typescript --no-save typescript@5.9.3
dexcli visualize src/review-flow.ts \
  --typescript-compiler /opt/dex-typescript/node_modules/typescript \
  --schema-version 2.0 --json --out build/review-flow
```

Listing **/opt/dex-typescript/node_modules** in **NODE_PATH** also finds that compiler. A **typescript** package that the source project resolves comes first, though, and runs instead of it.

The TypeScript analyzer recognizes these source shapes:

- Local Step classes and static Flow fields registered with **StepList.startStep**, **StepList.withoutStartStep**, **otherSteps**, or **StepList.empty**.
- Execute decisions returned directly: **goTo**, **goToMany** with **StepMovement.of**, **gracefulComplete**, **forceComplete**, **forceFail**, **deadEnd**, and **forceCompleteIfChannelsEmpty**. **withCancelingSteps** and **withCancelingSiblingSteps** add cancellations. Named, aliased, and namespace imports of **@superdurable/dex** all work.
- Conditions from **if**, **switch**, conditional expressions, loops, and **try** blocks.
- **ExecuteFailure.proceedTo** in **getStepOptions**, directly or through a helper method or function in the same file.
- Attribute, Channel, and Stream definitions, and manifest-declared Connector factories.
- Since dexcli 1.47.3, **waitFor**, RPC handlers, **handleTimeout**, and resource access in the shapes listed in [TypeScript Waits, RPCs, and resource access](#typescript-waits-rpcs-and-resource-access).

Pass `--flow` to select one Flow type from a file with multiple Flows. Without it, the analyzer reports `multiple_flows` and produces one unknown node for each Flow class, as it does for Go and Python.

The TypeScript analyzer reads one file, so a SubFlow node names the expression passed to **SubFlow.run**, such as the imported child Flow instance, instead of the child's Flow type. Step option locks and state loads stay out of the graph, as in Go.

In Go, an Execute method whose decision is hidden in a helper produces **hidden_dex_decision**. In Python, an Execute method annotated with `StepDecision` gets **hidden_dex_decision** when it directly returns a helper call and none of its returns is a recognized decision. When a Python Execute method hides its decision in another way, such as without the annotation or by returning a variable, the graph leaves that decision out without a diagnostic. In TypeScript, every Execute return that is not a recognized decision, such as a helper call or a variable, produces its own **hidden_dex_decision**, even when another return is recognized.

The Python, TypeScript, Java, and Rust analyzers each read the supplied Flow source file. Keep the registered Steps, Dex declarations, and custom Start input types in that file. Go uses package type information and can resolve types defined in other files or packages.

The analyzer requires static control flow. It reports reflection, dynamic classes, wildcard imports, getattr-based targets, monkeypatching, and movement collections that escape the handler as unsupported.

Named directive parameters can appear in any order within a line. Directive lines keep their source order, and Dex Web shows them in that order. Unknown, repeated, missing, or invalid parameters are blocking diagnostics.

**Changed in 1.47.23.** All five analyzers read Indexed Attributes, Summary, Display, and Start input schemas. Actions come from Go, Python, and TypeScript sources only. The Java and Rust SDKs have no Action API.

Use one `dex:group` and one `dex:explanation` on each local Step. Add `dex:indexed-attribute` to each indexed Attribute you want to expose in the graph. Add one `dex:field` per Summary or Display field. The view RPC protocol names are `GetDexSummary` and `GetDexDisplay`. See [Dex Web](/reference/web/dex-web) for directive arguments.

| Source | Comment prefix | Group and explanation | Indexed Attribute | Summary and Display fields |
| --- | --- | --- | --- | --- |
| Go | `//` | Above the Step type | Above the indexed variable declaration | Above the RPC method |
| Python | `#` | Above the Step class or its decorators | Above the indexed Attribute assignment | Above the `@rpc` decorator |
| TypeScript | `//` | Above the Step class | Above the indexed Attribute declaration | Above the `@rpc` decorator on the RPC method |
| Java | `//` | Above the Step class, including any Javadoc and annotations | Above the indexed Attribute field | Above the `@RPC` annotation |
| Rust | `//` | Above the Step struct, or above its `impl Step` if neither directive is on the struct | Above the indexed Attribute declaration | Above the function bound to the RPC |

Version 2.0 builds an optional start-input schema from the Start Step's input type. In Go, this is the Step registered with **DefineStartStep**. The Go analyzer follows JSON field names, ignored fields, pointers, and **omitempty**. It supports nested and imported structs, named string and integer constants, **time.Time**, ordinary numeric widths, slices, fixed arrays, and string-key maps. Integer bounds and integer enum values remain decimal strings in the schema. Recursive types, nesting beyond 32 levels, non-string map keys, interfaces, functions, channels, byte slices, conflicting anonymous fields, JSON string encoding tags, and custom JSON codecs produce a warning and omit the start schema. They do not invalidate the remaining graph.

In Python and TypeScript, annotate the Start Step's **execute** input using types defined in the same file. Python supports dataclasses, **TypedDict**, **Enum**, **Literal**, optional values, lists, string-key dictionaries, and **datetime**. TypeScript supports interfaces, type aliases, string-literal unions, optional properties, arrays, string-key **Record** types, and **Date**. An unresolved or unsupported input type produces a **start_input_unresolved** warning and leaves the rest of the graph valid.

Version 2.0 recognizes operation-specific Connector factories such as **openai.NewCreateResponseStep** through the config's canonical Connector SDK marker and generated field metadata, rather than a list of connector or function names. Dex Web shows these Steps with their app's initials. Steps of the **llm** Connector, which reaches any model provider, read as AI model work. The generic SDK factories **MustNewQueryStep** and **MustNewMutationStep** are still supported. Put the factory call directly in **DefineStep** or **DefineStartStep** and use an inline config literal. Step type, annotations, named **GoTo** branch targets (or generic **GoToBranch** targets), **StepRef** names, Result Attributes, Streams, and **ProceedToOnExecuteFailure** targets must be statically visible. Factory annotations supply the Step group and explanation, so the generated Step does not need local directives. Each Connector Step passes only its current operation result to its branch target. Persist business context in an application Attribute before entering the Connector Step. The graph emits one labeled transition per Connector branch, a write relation for the Result Attribute, and best-effort progress relations for structured and text Streams. A dynamic config, branch slice, target, annotation, or resource reference produces a blocking diagnostic. See the [Connector factory example](https://github.com/superdurable/dex/blob/main/examples/go/products/connector-factory/workflow.go).

### Python Waits, movements, and resource access {#python-waits-movements-and-resource-access}

Write the Wait, the Step movements, and the resource operations directly in the Step method that uses them. The Python analyzer reads Waits from `wait_for`. It reads Step movements from `execute`, RPC methods, and `handle_timeout`. It scans those handlers for resource operations, including nested syntax such as a lambda in the handler. It does not follow a call into a separate helper body.

The supported forms are:

- In `wait_for`, return `Wait.until`, `Wait.all_of`, `Wait.any_of`, `Wait.any_combination_of`, or `Wait.skip_immediately` directly, such as `return Wait.until(APPROVALS.for_one())`. Write the Channel, Join, Timer, and SubFlow conditions inside that returned call. The analyzer labels branches from `if` tests, `match` case patterns, and conditional expressions. A `wait_for` that raises and has no `return` is a failure Wait.
- A single `SubFlow.run` with a fixed child Flow can also be assigned once at the top level of `wait_for` and passed by name to a Wait.
- `Wait.all_of` and `Wait.any_of` can unpack a list comprehension or generator expression of `SubFlow.run` calls. Use synchronous `for` clauses, with optional `if` filters. Write `SubFlow.run` as the element and pass the same child Flow for every item as the first positional argument or as `flow=`. The graph shows one SubFlow condition and one **start** edge for the collection.
  - Use an imported child Flow, including one accessed through an imported module, an instance of a Flow class defined in the file, or a name or field that the analyzer can trace to one of these. A field can also receive the child from a constructor parameter of the parent Flow annotated with a concrete Flow type.
  - A list comprehension can be assigned once at the top level of `wait_for`, before the Wait, and read only to unpack it in that Wait. Keep assignment expressions out of SubFlow comprehensions. Inline comprehensions and generator expressions of `Timer.by_duration` calls also draw a Timer condition.

  Changed in dexcli 1.48.1: The analyzer draws bound SubFlow conditions and unpacked SubFlow comprehensions.

  Unsupported arguments include other unpacked lists, keyword unpacking, lists passed without unpacking, and bound conditions the analyzer cannot draw. When every condition is known to be a non-SubFlow condition, the graph may omit those conditions and the analyzer adds a `dynamic_wait_condition` warning.
- Pass `StepMovement.of` calls to `go_to_many`, or unpack a list comprehension or generator expression of them. To unpack a local list, build it in the same method from `StepMovement.of` calls. You can also unpack the result of a Join `fork` or `fork_with_round_key` call. Each of its builders is a lambda, or a module-level function of the same file, that returns a `StepMovement.of` call.
- Call `get`, `set`, `delete`, `publish`, and the other resource methods on an `Attribute`, `AttributeMap`, `Channel`, `ChannelMap`, `Join`, or `Stream` that the analyzer can resolve.
- Define each resource with a Dex constructor call in the Flow source file. Assign it at module scope, in the Flow class body, or at the top level of the Flow's `__init__`, as a local name or a `self` field. The Flow can pass a resource to a Step constructor when the Step's `__init__` assigns that parameter to a Step field.

Ordinary helpers can still compute values, such as the text that a `set` call writes. Attribute locks in RPC decorators and Step options are read as described in [What the graph contains](#what-the-graph-contains).

Unsupported shapes can omit parts of the graph. Some also produce diagnostics:

| Source shape | What the graph shows | What to change |
| --- | --- | --- |
| `wait_for` returns a helper result or a variable in every path | A `Dynamic WaitFor` node and a blocking `hidden_dex_wait` error, "wait_for hides its Dex Wait in a helper". The Step has no resource edges from `wait_for`. | Return a supported `Wait` factory call directly. |
| `go_to_many` takes a helper call directly or through unpacking, such as `*build_movements(step_input)` | A `Dynamic Step` node and a blocking `dynamic_step_target` error, "fan-out movements must be built directly in the handler". | Write the `StepMovement.of` calls in the method. |
| `go_to_many(*movements)` unpacks a local list that a helper returned | The decision has no edges for those movements. If the graph has a Start Step, each target that is unreachable from the Start Step, every RPC, and the timeout handler gets the `unreachable_step` warning, such as "Step Ship is not reachable from the start Step or an RPC". | Build the list from `StepMovement.of` calls in the same method. |
| A separate helper performs the resource operation | The helper call adds no resource edge for that operation. A resource node with no resource or Wait condition edge gets the `unused_resource` warning, such as "attribute Summary has no direct access in the source file". | Write the resource operation in the handler. |
| An ordinary handler operation or a Wait condition uses a resource imported from another module | The imported resource has no node or edges. A Wait on an imported Channel keeps its Wait node and omits that Channel condition. These uses produce no diagnostic for the missing resource. | Define the resource in the Flow source file. |

Some of these omissions have no diagnostic of their own:

- If at least one `wait_for` return is a recognized Wait, the graph shows the recognized Waits and omits the other returns without a `hidden_dex_wait` error.
- If an unpacked comprehension or generator uses a helper call as its element, the analyzer omits that movement without a `dynamic_step_target` error.
- An ordinary resource call in a separate helper adds no edge and gets no call-specific warning. A resource edge from any handler suppresses `unused_resource` for that resource.

Blocking diagnostics make the graph invalid. Warnings do not. See [Unknown nodes and diagnostics](#unknown-nodes-and-diagnostics).

TypeScript follows same-file helpers in the shapes listed in [TypeScript Waits, RPCs, and resource access](#typescript-waits-rpcs-and-resource-access).

### Java source and directives

**Since 1.47.23.** Java analysis requires JDK 17 or newer. The command infers Java from **.java** or accepts **--language java**. It uses **java** from **PATH** by default. Set **DEX_JAVA** to a different executable or pass **--java** to override it.

```bash
dexcli visualize ./OrderFlow.java --java /path/to/jdk/bin/java --json
```

The analyzer parses the supplied file with javac. It finds classes that implement **Flow** and **Step**, including nested classes. Targets such as **StepDecision.goTo(Ship.class, input)** use the Step type returned by **getStepType()** when the method returns a string literal or a constant declared in the same file. The class's simple name is the default. A target from another file keeps its simple name and produces a **step_type_unresolved** warning.

Put **dex:group** and **dex:explanation** on consecutive comment lines above the Step class. The directives can precede Javadoc and annotations. For an Attribute defined with **AttributeIndex**, put **dex:indexed-attribute** above the field. Put **dex:field** above the **@RPC** annotation on the method with protocol name **GetDexSummary** or **GetDexDisplay**. Set the protocol name with **@RPC(name = "GetDexSummary")** or use that exact Java method name.

```text
// dex:group group-id:shipping group-label:"Shipping"
// dex:explanation text:"Ship the order."

// dex:indexed-attribute attribute-key:status index-key:status index-type:keyword value-type:string description:"Order status."

// dex:field attribute-key:statusText value-type:string editable:false description:"Order status."
```

For the **Start** form, the analyzer looks for a class literal returned by `getInputType()` on the starting Step, or on the Flow if the Step has no override. It falls back to the input type argument of `Flow`, then to the starting Step's `Step` type argument. Declare input classes, records, nested types, and enums in the same file. The analyzer supports primitive types, strings, lists, string-keyed maps, `Optional`, and date-time types. If a type cannot be represented, the graph reports `start_input_unresolved` and omits the **Start** form.

### Rust source {#rust-source}

**Since 1.47.23.** Pass a `.rs` file or specify `--language rust`. The Rust analyzer requires Cargo and Rust 1.97 or newer. Use `--cargo /path/to/cargo` or set `DEX_CARGO` to select Cargo. The flag takes precedence. The default is `cargo` on `PATH`.

Dexcli builds the embedded analyzer on its first run using `cargo build --release --locked`. Cargo needs access to its registry or a local cache with the dependencies. Later runs reuse the binary under `dexcli/flowviz-rust` in the operating system's user cache directory. The cache entry depends on the OS, architecture, Cargo version, and embedded analyzer sources. Dexcli removes stale analyzer versions from that directory.

The analyzer reads `impl Flow` and `impl Step` in the given file. A string literal returned directly or through a file-local `const` or `static` in `flow_type()` or `step_type()` overrides the Rust type name. The analyzer warns when it cannot resolve the name. Pass the registered name to `--flow` for a file with multiple Flows.

Use `//` for Rust directives. Put `dex:group` and `dex:explanation` directly above the Step struct, or above its `impl Step` block if the struct has neither directive. Put `dex:indexed-attribute` above the indexed Attribute declaration and `dex:field` above the function bound to the `GetDexSummary` or `GetDexDisplay` RPC. Use the same arguments as in Go.

```text
// dex:group group-id:intake group-label:"Intake"
// dex:explanation text:"Receives a case."
// dex:indexed-attribute attribute-key:status index-key:keyword1 index-type:keyword value-type:string description:"Case status"
// dex:field attribute-key:title value-type:string editable:false description:"Case title"
```

The Start input comes from the starting Step's `type Input` or the Flow's `type StartInput`. The analyzer supports primitive types, named-field structs, unit-variant enums, `Option`, `Vec`, string-keyed maps, and serde `rename` and `rename_all`. Declare custom input types and any nested types in the same file. An unreadable type produces a warning and leaves the Start form empty.

### TypeScript Waits, RPCs, and resource access {#typescript-waits-rpcs-and-resource-access}

Since dexcli 1.47.3, the TypeScript analyzer reads these handler parts. It accepts only the shapes listed here. Any other shape that it detects is a blocking diagnostic that names it.

The graph describes source written in these shapes in good faith. It does not hold against source written to mislead the analyzer. For untrusted source, the guarantee is that the analyzer never runs it when you pass a [trusted TypeScript compiler](#typescript-compiler).

Every **return** ends its path. Statements after a statement that always returns or throws are unreachable: they add no decision, Wait, or edge.

**waitFor**:

- The return value is a **Wait.until**, **Wait.allOf**, **Wait.anyOf**, **Wait.anyCombinationOf**, or **Wait.skipImmediately** call. The call is written in the **return**, or bound to a **const** declared directly in the **waitFor** body that is used only as a returned value. Each return is its own Wait node. Conditions come from **if**, **switch**, and conditional expressions, as for Execute decisions.
- Each Wait argument is a condition call written in place with a dot: **Timer.byDuration**, **SubFlow.run**, **ConditionCombination.of**, or a **forOne**, **forN**, **atLeast**, **atMost**, **range**, or Join branch condition on a resource reference described below. Each **ConditionCombination.of** numbers its own conditions from 0, as Go numbers a **Combo**. A static millisecond duration gets a unit label, such as **2 seconds timer**.
- A **Wait.allOf** or **Wait.anyOf** argument may also spread one **map** call over a list of SubFlow runs, such as `...requests.map((request) => SubFlow.run(this.childFlow, request))`. The graph shows one SubFlow condition for the whole group, as the Python analyzer does for a starred generator. The analyzer has no type checker, so it accepts only this exact shape. Any other spread is a **dynamic_wait_condition**. Changed in dexcli 1.48.1: this shape was a **dynamic_wait_condition**.
  - The list is a parameter of the enclosing function whose type annotation is an array, readonly array, or tuple type, and the function never assigns it.
  - The **map** call has one argument: an inline arrow or function written in place, neither async nor a generator. Its parameters are plain names without default values, rest, or destructuring.
  - The callback body is `SubFlow.run(childFlow, ...)`, or a block with only `return SubFlow.run(childFlow, ...);`.
  - The child Flow argument is an import, a module-level `const` bound to an import or to `new` of a Flow class, or `this.<field>` in an arrow callback. The field is a `readonly` constructor parameter typed as a Flow class of the file, or a `readonly` field initialized the same way as the module-level `const`. The class never assigns the field.
  - The **map**, **SubFlow.run**, and child Flow expressions are plain calls and property accesses. None of them uses optional chaining, even inside parentheses.
- A **waitFor** that only throws is a failure Wait, as for Go and Python.
- The graph uses the Go names for two Wait types: **skipWaitImmediately** and **anyComboOf**.

RPC handlers and **handleTimeout**:

- An RPC returns an **RPCResult** object literal written in the **return**, nothing, or a call to a method of the Flow class or a function of the file. Each object literal is an **rpcResult** decision. A called method contributes its own results once for each call, and a method that returns nothing ends the caller's path. Nothing means an empty **return**, **void** expression, or the global **undefined**.
- **nextSteps** is an array literal of **StepMovement.of** calls written in the object literal. It may also be a block **const** array literal that nothing else reads. **cancelingSteps** follows the same rule and lists Step targets.
- **handleTimeout** decisions follow the Execute rules.

Resource access in Execute, **waitFor**, RPC, and **handleTimeout**:

- A resource is an **Attribute**, **AttributeMap**, **Channel**, **ChannelMap**, **Join**, or **Stream** created with **new**, optionally configured with **syncToAttributeStore** or **hardDeleteOnNull**. It is declared as a module-level variable or a Flow field that the file assigns once. The file never writes the resource's members or prototype.
- A resource reference is a module-level name bound to a resource, including a module-level **const** alias of another resource name. It may also be a **this** field chain that the analyzer can follow to a resource, such as **this.status** in a Flow method, **this.flow.status** in a Step that holds its Flow, or a Step field that holds the resource.
- An access calls a method by name or with a string literal key on a resource reference, such as **approvals.publish(context, value)** or **progress["write"](context, value)**. The call is written in the handler or helper body, not in a nested function. A read points from the resource to the handler. Writes and publishes point from the handler to the resource.
- A **bufferedText** writer is bound to a **const** and used only by calling its methods. Its **write** calls are Stream writes.
- A helper is a method declaration of the handler's class or a function declaration of the file, called directly by name. The analyzer follows a helper up to six calls deep when the helper never reassigns or destructures its parameters and does not call itself. A resource reference passed to a helper binds the matching parameter. An edge reached through a helper records the helper in its metadata.
- Unused resources produce the same **unused_resource** warning as in Go and Python.

These shapes are blocking diagnostics:

- A **waitFor** return that is not a supported Wait, such as a helper call or a module-level Wait constant, produces **hidden_dex_wait**.
- A Wait argument that is not a supported condition, such as any other spread, a spread of a bound list, a helper call, a bound name, a computed method key, or a condition on a local alias, produces **dynamic_wait_condition**. The graph shows that condition as unknown. The Go analyzer follows condition helpers.
- An RPC result stored in a variable, any other returned value, or a recursive result helper produces **hidden_dex_decision**.
- A **nextSteps** or **cancelingSteps** value that is not a supported list, such as an alias, a spread, a list that is changed or passed on, or a movement built in a helper, produces **dynamic_step_target**.
- These produce **dynamic_resource_access**:
  - a resource call through a computed key, or a resource access inside a nested function, such as a callback;
  - any method call on a local alias of a resource;
  - a helper used as a value, such as a callback, **call**, **apply**, or **bind**; **call**, **apply**, or **bind** on any method or function; an arrow function or function expression field called as a helper; a recursive helper; and a helper that reassigns or destructures a parameter;
  - a resource passed to a function that the analyzer does not follow, and a Stream writer used in another way;
  - a write to a member of a resource, an **Object.defineProperty**, **Object.assign**, **Reflect.set**, or similar reflective write on a resource or its prototype, and a class that extends a Dex resource class.
- A call to a resource method name, such as **get** or **publish**, with a Dex **Context** argument on any other receiver also produces **dynamic_resource_access**. Such receivers include destructured or reassigned names, computed fields, values returned by functions, **new Proxy(...)**, and instances of your own classes. The analyzer recognizes the Dex **Context** and **AsyncContext** types through renamed imports, type aliases, and **const** aliases. A receiver that is provably no resource is not checked: a literal, a function, a Dex import other than a resource class, or a new **Map**, **WeakMap**, **Set**, **WeakSet**, **Array**, **Date**, **RegExp**, **Error**, **Promise**, or **URL**.

### Trusted TypeScript compiler {#typescript-compiler}

Since dexcli 1.47.2, **--typescript-compiler** names a trusted **typescript** package directory. The **DEX_TYPESCRIPT_COMPILER** environment variable names the same directory. The flag wins when both are set. An empty flag value, or an empty **DEX_TYPESCRIPT_COMPILER** that is set, is a usage error, and the command exits with status 2. It never falls back to the source project's compiler. Only an unset flag and an unset variable keep that default. Go and Python sources do not use the directory.

Set a trusted compiler whenever you visualize TypeScript source that you do not trust, such as a branch from someone else. Without one, the analyzer loads and runs the **typescript** package that the source project resolves. That package can come from the source tree: a **node_modules/typescript** directory in the source directory or any parent directory, or a **package.json** named **typescript** that points at its own file. Node.js resolves all of them before **NODE_PATH**. Such a package runs with your permissions and can forge the Flow Definition Graph.

Pass the package directory itself, the one that holds the package's **package.json**, such as **/opt/dex-typescript/node_modules/typescript**. Keep it outside every source tree that you analyze. dexcli checks the directory before analysis:

- Its **package.json** names the **typescript** package.
- Its **main** entry is a file inside the directory, after symbolic links are resolved.

Any other directory stops the command before analysis with an error that names it. A **node_modules** directory gets an error that names the **typescript** directory to pass instead.

With a trusted compiler, the analyzer loads only that entry file. It never resolves **typescript** from the source project, its parent directories, a **package.json** named **typescript**, or **NODE_PATH**. dexcli starts Node.js in the compiler directory and removes every environment variable that starts with **NODE_**, such as **NODE_OPTIONS** and **NODE_PATH**. So a **--require** or **--import** option in **NODE_OPTIONS** loads nothing. The analyzer still reads the **dex-connector.json** manifest of each imported Connector package as JSON data. It never runs code from the source tree.

dexcli finds the **node** executable through your **PATH**, so that executable must be trusted too. Keep every directory of the analyzed tree out of **PATH**, such as its **bin** or **node_modules/.bin** directory. A **node** wrapper found there runs before the trusted compiler, even when the compiler directory is valid.

### Actions in Python and TypeScript

Since 1.39.0, a Version 2.0 graph of a Python or TypeScript Flow includes its Actions, in the same shape as a Go graph. The analyzer reads each RPC's **action** option without running the module. Write it in this form:

- The value is a direct **Action(...)** call in Python or **new Action(options)** in TypeScript, or a module-level constant bound to one.
- The label and the required permission are string literals or module-level string constants.
- The condition, when present, is a direct **when_attribute_matches** or **whenAttributeMatches** call. Its first argument names an Attribute declared in the file. Each other argument is an **AttributeMatch** equality match on a literal or a module-level constant. A TypeScript **bigint** literal is an integer value.
- The input, when present, is a Python dataclass or a TypeScript interface or object type alias in the same file. Each of its fields has one **dex:input** directive on the RPC. See [Dex Web](/reference/web/dex-web#actions).

Anything else is a blocking **v2_action** or **v2_action_input** diagnostic that names the construct and its line, and the graph has no Action for that RPC. A condition value must match the Attribute's type: **str**, **int**, **float**, **bool**, or **datetime** in Python, and **string**, **bigint**, **number**, **boolean**, or **Date** in TypeScript. An Action RPC whose lock list is not a literal list of Attribute **lock()** calls produces the blocking **rpc_lock_unresolved** diagnostic, as in Go.

### Python and TypeScript Step annotations

Put exactly one group directive and one explanation directive directly above each local Step class. Python uses **#** comment lines; decorators may appear between those comments and the class. TypeScript uses **//** comment lines directly above the class. Do not separate the comments from the declaration with a blank line. The grammar matches Go:

```text
# dex:group group-id:lookup group-label:"Lookup"
# dex:explanation text:"Look up a catalog record."
```

```text
// dex:group group-id:lookup group-label:"Lookup"
// dex:explanation text:"Look up a catalog record."
```

The group ID must be kebab-case. Steps sharing an ID must use the same non-empty label. The explanation is one non-empty sentence describing the Step. FDG 2.0 stores it as **metadata.explanation**. Missing, duplicate, or malformed directives are blocking errors, including with **--lint app**.

### Connector package manifests

A Python or npm Connector package ships **dex-connector.json**. A Python package places it inside the import package directory, and an npm package places it next to **package.json**. The Python analyzer resolves imports through the selected interpreter's installed packages and the Flow source directory; **--python /path/to/venv/bin/python** selects a virtual environment. It reads site-packages directories and the plain directory lines of their **.pth** files, which covers path-based editable installs. It never runs **.pth** import lines, so an editable install that relies on an import hook is not found. TypeScript resolves the imported package through **node_modules**, starting at the Flow source directory and walking toward the filesystem root. Named import aliases and package namespace aliases are supported. Analysis does not execute the imported Connector.

The [manifest JSON schema](https://github.com/superdurable/dex/blob/main/cli/internal/flowviz/dex-connector.schema.json) defines the manifest structure. A manifest has **connectorId**, an exact **releaseTag** such as **connectors/catalog/v1.2.3**, a **package** object with **ecosystem**, **name**, and **version**, and a non-empty **factories** array. Package ecosystems are **pypi**, **npm**, or **go**; the Python and TypeScript analyzers require **pypi** and **npm**, respectively. Package versions are exact installed versions, independent of the Connector release tag. The CLI also enforces rules that JSON Schema cannot express. Factory names, branch IDs, and ConfigurationUI unit IDs must be unique. Mapped config field names must be distinct. Binding ports must be unique within a unit.

Each exported factory declares **name**, **kind** (**query**, **mutation**, or **trigger**), and **fields** mapping semantic names to source config field names. Query and mutation factories require **operationId**, **stepType** and **annotations** field mappings, and named **branches**. Every branch has an **id**, a config **field**, and an optional **optional** flag. An unwired optional branch appears as a failure decision. Trigger factories require **triggerName** and a **bindingName** field mapping. All factories require a **connectionName** mapping.

Query and mutation factories may also carry agent tool metadata. **inputType** names the public input model in the package's language. **inputSchema** is a JSON Schema draft 2020-12 object for that input, written with its JSON field names. Set both or neither. **description** is a model-facing description. **agent** records a review for agent use: **exposed** is required, and **approval** may be **recommended** when **exposed** is true. On a mutation, **retry** may be **safe** when **exposed** is true: repeating the call with the same Call ID, inside the operation's own Execute retry policy, cannot make a second effect. Without it, a repeat may not be safe. A query never carries **retry**. **branches** may map optional branch IDs to **rejected**, which means the call changed nothing, or **unknown**, which means its effect may have happened. A host treats an unlisted optional mutation branch as **unknown** and an unlisted optional query branch as a failure, and a query uses only **rejected**. The analyzers ignore an unknown field inside **agent**, so a package with a newer field still analyzes, though the JSON schema rejects it. An unknown field anywhere else fails. An **agent** block requires **inputType** and **inputSchema**, and a missing block means the operation is not offered to agents. Trigger factories carry none of these fields. All four are optional, so a manifest without them stays valid. The analyzers check their shape, and they do not change the Flow definition.

The optional mappings **resultAttribute**, **resultStream**, **progressStream**, and **textStream** identify declared resources. **configurationUI** maps a static override; the manifest may also provide a default **configurationUI** object containing **units**, their **bindings**, and JSON pointers. The graph preserves this information for Dex Web. An optional **executeFailure** mapping names a static recovery Step and adds an Execute failure edge.

Python factory calls use keyword arguments, one inline dictionary, or one inline config constructor with keyword arguments. TypeScript calls use one inline object. Factory **annotations** is a static object with **groupId**, **groupLabel**, and **explanation**; generated Steps use those values instead of local class comments. Branch fields reference registered local Steps, static Step references, or a direct **go_to** / **goTo** wrapper. Trigger bindings must be returned as one static list or array from **get_connector_trigger_bindings** / **getConnectorTriggerBindings**.

A Step registration or Trigger binding that calls a name from a package without **dex-connector.json** produces **connector_manifest_missing**. The message names the package and the expected manifest path. The same diagnostic reports a package that is not installed. A malformed manifest, or one with a wrong-typed field, produces **connector_manifest** and names the failing field. Two Steps with one Step type produce **duplicate_step_type**. That includes two factory calls with one Step type, and a factory Step type that matches a local Step.

Connector nodes emit **connectorId**, **releaseTag**, and **package** inside **metadata.connector**, together with operation identity, connection name, **configurationUI**, and **configurationEnabled**. A non-empty static connection name enables automatic configuration; a dynamic name emits a warning and disables it. Dex Web resolves the exact release tag and verifies its release metadata. Existing Go **modulePath** / **moduleVersion** metadata remains supported, and Go graph output is unchanged. The manifest only provides metadata for analysis. It adds no Connector API to any SDK.

## Flow and Step names {#flow-and-step-names}

The graph uses the Flow type and Step type that the SDK registers. Dex Web uses these names to search runs, match run history to Steps, and start Flows. Go Flows therefore work in Dex Web without a **GetFlowType** or **GetStepType** override, unless the analyzer reports one of the diagnostics below.

For Go, the default name is the Go type name without its package or pointer. A Flow type **ThreadApprovalFlow** and a Step type **initializeThread** keep those exact names. For Python, the default name is the class name.

Name each Flow type after its domain, such as **ApprovalFlow** or **ReplyFlow**. Do not name a Flow type just **Flow**. The package is not part of the name, so every Flow registered with one Worker needs a different type name. Dex Web, run history, and Flow searches show the name as written.

For Go, a generic Flow or Step type has no default name. Declare a **GetFlowType** or **GetStepType** override that returns a non-empty name.

A **GetFlowType** or **GetStepType** override can be declared in any file of the package or promoted from an embedded type, including one from another package. Every return statement in the override must return the same compile-time string. An empty string keeps the default name. Dex rejects a Step type that contains **/**, **$**, or **:**. A **StepRef** target names the registered Step type, not the Go type.

The analyzer reports a blocking diagnostic when it cannot know the registered name or cannot give each Step its own node:

- **dynamic_type_name**: an override returns different strings, a value that is not a compile-time string, or a name promoted from an embedded interface.
- **generic_flow_type_name**: a generic Flow type has no non-empty override.
- **generic_step_type_name**: a generic Step type has no non-empty override.
- **duplicate_step_type**: two registrations use one Step type, or one Go type is registered more than once. Step nodes are keyed by Go type, so a generic Step can be registered with only one type argument.

Go node IDs use the Go type, as in **step:initializeThread**, even when an override changes the Step type.

Python and TypeScript can register several instances of the same Step class when each instance has a distinct static Step type. **get_step_type** or **getStepType** can return a string literal, a class attribute initialized with a string literal, or an instance field assigned from a constructor argument whose value is a string literal at registration. Constructor defaults and static variable aliases are also readable. Each node ID uses that instance's Step type, such as **step:First** and **step:Second**.

The analyzer reads Step methods only from the registered class itself. A Python Step class must extend only **Step** and **Generic**. A TypeScript Step class must not extend another class. Otherwise the analyzer reports **step_inheritance_unsupported**. Move the shared logic into a helper function and keep each Step method on the registered class.

An instance field is readable only when the class assigns it exactly once. The assignment must be a class attribute, a TypeScript property initializer or parameter property, or a direct statement in the constructor. A field assigned in another method, through **setattr**, **vars**, or **Object.assign**, or from outside the class is not readable. A Python Step class with a decorator, such as **dataclass**, also has unreadable fields. Construction code that reads a field must run after the field is assigned. A TypeScript property initializer therefore cannot read a field that the constructor assigns. Assign each field in the constructor, or return a string literal from **get_step_type** or **getStepType**.

The SDKs resolve an instance target by object identity. A target must be the registered object itself, not another object with the same Step type. Transitions, **StepMovement**, Execute failure routing, and cancellation accept these targets:

- The registered instance, read through names that are each bound exactly once. These names include module variables, Flow class attributes or property initializers, Flow fields assigned once in the constructor, Step fields assigned in the constructor, and local variables.
- A Step class when exactly one instance of that class is registered.
- A **StepRef** constructed with a string literal that names a registered Step type. TypeScript must construct it with **new**.

A constructor call written in a decision creates a new object that is not registered. The SDK rejects that target at runtime, so the analyzer reports **unknown_step_target**. Target the registered instance or a **StepRef** instead. Separate Connector factory calls also produce separate nodes when their static Step types differ.

The analyzer accepts an instance only when it can prove which object a name holds. A name bound twice in one function or module is not provable. A reassignment, augmented assignment, loop variable, **with** target, walrus target, destructuring, **global** rebinding, or a second declaration in a nested TypeScript block all count as another binding. A constructor parameter that the constructor reassigns is not provable either.

Fields also depend on how the Flow or Step object is used. In Python, use **self** only to read or assign a field, or pass it to the constructor of a class in the same file. Passing it to another function, storing it in a variable, or rebinding **self** makes the class fields unreadable and reports **dynamic_class**. In both languages, a Flow class with a decorator, or a constructor that returns a value, also has unreadable fields.

TypeScript proves fields by checking every use of each tracked object. A tracked object is **this** inside a class body, an instance that a class in the same file constructs, or a Connector Step that a factory call returns. A tracked object may appear only in these positions:

- A field read, such as **this.target** or **first.target**, including inside callbacks. A getter in the class body may return a tracked object, and reading that getter counts as a field read.
- A call of a method that its class body declares, such as **this.retryOptions()**.
- A field assignment through **this**, such as **this.target = target**.
- Registration with **StepList.startStep**, **otherSteps**, or **withoutStartStep**.
- A Dex target: **goTo**, **StepMovement.of**, **ExecuteFailure.proceedTo**, **FlowTimeoutHandlerFailure.proceedTo**, the Steps that **withCancelingSteps** or **withCancelingSiblingSteps** cancel, or the Execute failure or branch field of a Connector factory config.
- An alias: a variable, a parameter default, a class field, or a constructor parameter of a class in the same file. Every use of an alias must follow the same rule. An alias may hold several objects.

Any other use is an escape. These uses are escapes:

- Passing the object to a function or to a constructor of a class outside the file, including **Object.assign**, **Reflect.set**, and **new Object**.
- Storing it in an array, a **Map**, a **Set**, an object literal, or a spread.
- Returning it, exporting it, or destructuring it.
- Casting it with **as**, **satisfies**, or a type assertion.
- Reading it with a computed key, or writing through it, such as **first.target = value** or **this[key] = value**.
- Assigning it to a field name that a setter in the class body handles.
- Using it in any other expression, such as a comparison.

An escape reports **dynamic_class** at the escaping use. The fields of the escaped object, and of every object it can reach through its fields, become unreadable. An escaped Connector Step reports **dynamic_step_target**. A computed-key write on any other value, such as **words[index] = value**, does not affect the graph.

A Flow object created outside its class, such as **export const approvalFlow = new ApprovalFlow()**, may be exported, returned, or passed to an imported function or constructor, such as **new Registry([approvalFlow])**. A field read through it, such as **approvalFlow.review**, is a tracked object. Any other use of the Flow object, such as a cast, a write, a reflective call, or a call of a helper in the same file, is an escape. A class from the same file that is used as a value other than with **new**, **extends**, **instanceof**, a static field read, an export, or a Dex target has unreadable static fields. Tracked objects that its instances store in fields, other than constructor arguments, escape too.

Any access to **prototype**, **__proto__**, **globalThis**, **window**, **self**, or **global** makes every Flow and Step field unreadable. So does an assignment to an undeclared global name. A reflective write, such as **Object.assign**, **Object.defineProperty**, or **Reflect.set**, whose target is not an object or array literal also makes fields unreadable. A TypeScript getter or setter with a field's name makes that field unreadable.

These checks rely on three assumptions. First, code in other modules does not modify Flow or Step objects. This includes code that receives a Flow object through an export, a return value, or an imported function such as a Registry. Second, the source does not run dynamic code or use reflection that the analyzer cannot see. Third, the source does not change prototypes or global objects in ways that the analyzer cannot see. The analyzer does not follow objects into other modules, so do not pass Flow or Step objects to code outside the source file.

The analyzer reads Flow and Step methods only from the class body. A Python Flow or Step class that defines **__getattr__**, **__getattribute__**, **__setattr__**, **__delattr__**, **__get__**, **__set__**, **__delete__**, **__set_name__**, **__new__**, **__init_subclass__**, or **__class_getitem__** reports **dynamic_class**. A Flow or Step method reassigned outside the class body reports **dynamic_class** in both languages. A decorator on a Flow or Step class or on one of its members reports it too, because the decorator can replace the class or the member. The exceptions are the Dex **rpc** decorator, Python **typing.final** and **dataclasses.dataclass** on a class, and Python **staticmethod**, **classmethod**, and **typing.override** on a method. The built-in Python **property** is also allowed when it is the method's only decorator. Its name must not be a field or a Step or Flow method that Dex calls. A property **setter** or **deleter** still reports **dynamic_class**. So do Python **__dict__**, **vars**, **__setattr__**, and **__class__** assignments, and the TypeScript escapes and reflective writes described above.

The analyzer recognizes Dex APIs only through imports of **dex** or **@superdurable/dex**. Rebinding a Dex import alias or the **dex** module name in any scope reports **dex_alias_rebinding**. Assigning an attribute of a Dex import reports it too. A Python wildcard import from any module reports **wildcard_import**, because it can rebind Dex names. Python **exec**, **eval**, **globals**, **locals**, **getattr**, **setattr**, **delattr**, and the **builtins** module report **dynamic_python**. So do these names and **vars** when they are used as values instead of called directly, such as through an alias or as a **map** argument. TypeScript **eval** and **Function** report **dynamic_typescript**.

Computed Step types, unprovable targets, unknown **StepRef** names, and ambiguous class targets produce blocking diagnostics. Resolving the Step type does not make a callback's decision readable. See the **hidden_dex_decision** rules in [Supported source profile](#supported-source-profile).

## Start inputs {#start-inputs}

Go **StartFlow** validates its payload against the registered starting Step before sending a request. **dexcli visualize** reports **start_flow_input_type_mismatch** when a known payload type does not match that Step's input. This is a blocking error with or without **--lint app**.

Pass a value of the required input type. When the starting Step needs no input, declare **dex.None** and pass **nil**. An empty struct is a different type. A pointer and its value type are also different; **nil** remains valid for an input type that permits it.

The check covers calls in the Flow file and same-package helpers reached by handlers. The target Flow's **GetSteps** must directly return a Step slice literal with one **DefineStartStep**. Target declarations may be in another file or imported package. Dynamically chosen Flows, generic Flow types, interface-valued payloads, and unresolved registrations are not checked.

## State loads {#state-loads}

A Step method, RPC, or Flow timeout handler receives ordinary Attributes and Channel sizes. It does not receive AttributeMap values or pending Channel messages unless it selects them. See [Selective state loading](/reference/python/step-options#selective-state-loading) and [Selective RPC state loading](/reference/server/runtime-data#load-collection-state). A read of unselected state fails at run time, and a failing Step method is retried until its retry policy ends. For Go sources, **dexcli visualize** reports these reads as blocking diagnostics:

- **attribute_map_read_not_loaded**: **AttributeMap.Get** reads a map that no whole-map or instance load selects for this method.
- **attribute_map_enumeration_not_loaded**: **AllInstanceKeys** or **MapSize** runs without a whole-map load. Exact-instance loads cannot enumerate, and the SDK panics.
- **attribute_map_instance_not_loaded**: **Get** reads a constant instance key, while every load of that map names other constant keys.
- **channel_messages_not_loaded**: **PendingMessages** or **FindPendingMessage** reads a Channel or ChannelMap that no load selects.

Writes never need a load. **Set**, **Delete**, **Publish**, Channel message deletion, **Size**, ChannelMap keys and sizes, WaitFor conditions, and **GetConditionResults** are not reported.

The analyzer reads loads from the declarations in the Flow's package. For a Step, they are **GetStepOptions**, every **GoTo** or **MovementOf** that moves to the Step with **WithStepOptions**, and every **ProceedToOnExecuteFailure** that names it. **Execute** uses the **ExecuteLoad** fields and **WaitFor** uses the **WaitForLoad** fields. For an RPC, they are the **RPCOptions** passed to **DefineRPC**, and the exact instances selected by a call in the package that passes the RPC method value with **Load** or **LoadMessages**, such as **InvokeRPCWithOptions**. For **HandleTimeout**, they are the **FlowTimeoutHandlerOptions** values in the package.

Options may be literals, package variables, local variables with field assignments, or the results of same-package functions whose parameters come from the call site. A read in a same-package helper is attributed to the handler that calls it. Its diagnostic points at the call in the Flow file and names the helper's file and line.

When another package chooses an RPC's map instance at invocation, declare that on the RPC method:

```text
// dex:invocation-load attribute-map:customer-profiles
```

Use **channel-map** to name a ChannelMap. The directive satisfies instance reads of the named map, but not enumeration. A name that is not an AttributeMap or ChannelMap of the Flow produces **invocation_load_directive**.

The analysis does not track paths: a load declared on one movement into a Step counts for every movement into it. Calls through interfaces, function values, and reflection are not followed. When load options cannot be evaluated, such as options returned by another package, the default mode reports nothing for that read.

## Declared lock requirements {#declared-lock-requirements}

**Since dexcli 1.48.1.** An Attribute, AttributeMap, Channel, or ChannelMap can declare the lock that every write or publish requires. In Go, the options are **dex.WritesRequireLock** and **dex.WritesRequireAttributeLock** on **DefineAttribute** and **DefineAttributeMap**, and **dex.PublishesRequireAttributeLock** on **DefineChannelWithOptions** and **DefineChannelMapWithOptions**. When several lock options are given, the last one applies. In Python, they are **writes_require_lock** and **publishes_require_lock**. The Worker enforces the requirement at run time; see [Declared lock requirements](/reference/server/runtime-data#declared-lock-requirements). For Go and Python sources, **dexcli visualize** also checks it in every mode and reports three warnings. They point out problems before deployment, and they leave the graph valid, because the runtime check already rejects a write without the required lock:

- **declared_lock_missing** (warning): a **WaitFor**, **Execute**, or RPC handler writes a declared Attribute or AttributeMap instance with **Set** or **Delete**, or publishes to a declared Channel. Its registration locks do not include the required lock. The analyzer reports it only when every fact is proven: the declaration and its last lock option; the write, which must call the SDK method on the package variable (Go) or the module or Flow class attribute (Python) that defines the resource, outside a nested function or a constant-false branch; and the registration locks, which must be literal options with literal lock lists. A write with a dynamic instance key is reported when no registration lock names that AttributeMap at all.
- **declared_lock_unresolved** (warning): the same write when one of those facts is not proven. For example, the lock list is computed or held in a variable, a lock or the write names a dynamic AttributeMap instance of a held map, the receiver is a local alias, an unknown decorator wraps the **@rpc**, or the declaration names a lock Attribute the analyzer cannot resolve.
- **lock_requirement_not_declared** (warning): an Attribute or AttributeMap without a lock requirement may lose an update. Either two or more handlers write it, at least one of them an RPC, and one writer does not register the Attribute's own lock; or an RPC both reads and writes it without that lock. Writes by Steps alone are not reported, because Steps of one Flow often run in sequence. A Flow timeout handler can be the second writer. A handler whose registration locks the analyzer cannot read counts as holding the lock. The check does not compare read and write order or AttributeMap instances, and it does not credit a shared coordination lock. If the writes can run concurrently, declare the requirement and register the lock.

Only registration locks count, as at run time. They are **StepOptions.WaitForLockAttributes** and **StepOptions.ExecuteLockAttributes** from **GetStepOptions** and **RPCOptions.LockAttributes** in Go, and **wait_for_lock_attributes**, **execute_lock_attributes**, and the outermost **@rpc(lock_attributes=...)** in Python. Locks passed with one movement or one RPC call do not count. Flow timeout handlers are not checked. A resource whose definition options the analyzer cannot read, such as unpacked options, is neither checked nor reported as undeclared. The Go analyzer follows writes in same-package helpers; the Python analyzer reads only the handler body.

## Application lints {#application-lints}

**--lint app** adds checks for application mistakes that compile and pass the default analysis. The application checks below apply to Go. Python, TypeScript, Java, and Rust accept the flag and enforce the same FDG 2.0 group and explanation requirements. The state-load diagnostics above are reported in every mode.

```bash
dexcli visualize ./order_flow.go --schema-version 2.0 --json --lint app
```

- **state_load_unresolved**: a read needs a load, but the load options of its handler cannot be evaluated. Declare the loads in **GetStepOptions**, **RPCOptions**, or a variable of the Flow's package.
- **connector_branches_merged_unread**: a Step receives two or more branches of one Connector Step, one of them **defect** or **uncertain**. It uses the result but never reads **result.Branch** or **result.Failure**, so a failure would be handled as a success.
- **action_state_not_rechecked**: an Action RPC never reads the Attribute of its **WhenAttributeMatches** condition or an Attribute it locks. The condition selects candidate runs; it does not authorize the write. Read the state under the lock and reject a stale or repeated decision.
- **start_flow_request_id_missing**: a **StartFlow** call in the Flow file, or in a helper that a handler calls, has options without **RequestID**. A retried start cannot be recognized. Derive the RequestID from the business identity and set **AlreadyStarted** with **IgnoreError**.
- **cross_flow_read_not_found_unhandled**: a Step calls **InvokeRPC** or **InvokeRPCWithOptions** without an **errors.As** check for **FlowNotActiveOrNotFoundError** or **FlowNotFoundError** on its call path. A missing Flow then makes the Step retry until its retry policy ends.

## Unknown nodes and diagnostics

A blocking diagnostic can add an Unknown node to the graph. The Python analyzer can also omit some unsupported decisions, Wait returns, and fan-out targets without a blocking diagnostic. See [Python Waits, movements, and resource access](#python-waits-movements-and-resource-access). With a blocking diagnostic, the default renderer still shows the partial graph. With **--json**, a partial JSON artifact is written, and the command exits with status 1.

Warnings do not invalidate the graph. For example, an Attribute whose value type cannot be determined uses **unknown** and produces a warning. A registered Step that cannot be reached from the start Step or an RPC also produces a warning. Invalid command arguments exit with status 2.

The JSON **valid** field is false when any blocking diagnostic is present. A tool that reads the graph should not edit or deploy from an invalid graph. It can still use the known nodes and edges to explain the Flow.

## JSON contract

Source spans, parent-child relationships, structured WaitFor and decision details, resource types, branch conditions, edge direction, diagnostics, ordered groups, and Dex Web metadata are defined in the [Flow Definition Graph 2.0 schema](https://github.com/superdurable/dex/blob/main/cli/schema/flow-definition-graph.v2.schema.json).

### Generation time {#generated-at}

Since 1.45.0, every Version 2.0 graph from **dexcli visualize** has a top-level **generatedAt** field. It records when the graph was generated, as an RFC 3339 timestamp in UTC with second precision, such as **2026-11-10T08:30:00Z**.

The field is optional in the v2 schema. Dex Web accepts graphs without it, so graphs from older dexcli releases stay valid. When the field is present, it must be an RFC 3339 timestamp. Dex Web older than 1.45 rejects a graph that has **generatedAt**. Upgrade Dex Web together with dexcli.

By default, **generatedAt** is the current time. Set the standard **SOURCE_DATE_EPOCH** environment variable to make the output reproducible. Its value is a whole number of seconds since the Unix epoch. For example, use the last commit time of the source file:

```bash
SOURCE_DATE_EPOCH="$(git log -1 --format=%ct -- ./refund_flow.go)" \
  dexcli visualize ./refund_flow.go --schema-version 2.0 --json --out ./build/refund-flow
```

An empty **SOURCE_DATE_EPOCH** is ignored. A negative or non-integer value is a usage error, and the command exits with status 2.

See [Dex CLI](/reference/cli) for commands that operate on running Flows.
