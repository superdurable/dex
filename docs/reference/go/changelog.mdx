### 1.45.16 (2026-11-20) {#v1-45-16}

**Added**

- Client-side payload encryption. Set **PayloadEncryptionOptions** on **ClientOptions** and **WorkerOptions**, and the SDK encrypts every value it sends, so the Dex server stores only ciphertext. Readers decrypt values after loading them and pass plaintext values through, so encrypted and plaintext Flows can share one Worker.
- The built-in **AESGCMPayloadCodec** uses AES-256-GCM, with optional gzip compression. **FilePayloadEncryptionKeyProvider** reads keys from a JSON key file and supports key rotation. Implement **PayloadCodec** or **PayloadEncryptionKeyProvider** to use your own key management.
- Worker error details and stack traces, ForceFail reasons, and Stop, Time Travel, and clone-fork reasons are encrypted too, in a **dex-encoded:** text format.
- The **Plaintext** Attribute option keeps an Attribute in clear. **WaitForAttributeMatch** and Action conditions need an Indexed or **Plaintext** Attribute when encryption is on. An encrypted Attribute synced to the Attribute Store needs a bytea column.
- The Java and Rust SDKs cannot read encrypted Flows yet.

### 1.45.8 (2026-11-18) {#v1-45-8}

No user-visible changes.

### 1.45.7 (2026-11-18) {#v1-45-7}

**Added**

- **PullWorkerOptions.MinOpenSlots** makes a pull Worker adaptive when it is below **MaxConcurrentTasks**. The Worker keeps between the two counts of slot streams open, both including the reserved RPC slots: it doubles its Step-and-RPC streams when a task takes the last idle one, and every 30 seconds it half-closes half of the idle surplus. An idle adaptive Worker holds only its floor of Server streams. The default equals **MaxConcurrentTasks**, which keeps the Worker fixed with unchanged behavior.
- An adaptive Worker clamps **MaxConcurrentTasks** above the Server's **matching.maxConcurrentTasksCap** to the cap with a WARN log. It treats a **RESOURCE_EXHAUSTED** registration of a growth stream, or of a reconnect after readiness, as a soft limit, without a **PullRegistrationError**. A soft-rejected stream retries when another registered stream of the Worker ends, or at the next 30-second window; while growth rejections persist, the Worker grows at most one batch per window.
- **Worker.PullSlotStreamState** returns a snapshot of the slot streams: open, registering, busy, and idle streams, orphaned handlers, the floor and capacities, and grow and shrink counters.
- **SupportedServerProtocolVersionRange** returns the inclusive range of Dex Server protocol versions the Go SDK negotiates with, so a tool can check compatibility before it connects.

**Changed**

- A fixed pull Worker with **MaxConcurrentTasks** unset now opens one stream first, learns the Server's **matching.maxConcurrentTasksCap** from its registration, and clamps its CPU-count default to the cap with a WARN log instead of failing to start. Its other streams open after that first registration. An explicit **MaxConcurrentTasks** above the cap still fails to start, and a fixed Worker with an explicit value still opens all its streams at once.

### 1.45.6 (2026-11-16) {#v1-45-6}

**Added**

- **GracefulCompletionRequested** returns a Condition that completes once the Flow has a graceful completion request, from **Client.StopFlow** with **GracefulCompleteFlow** or a **GracefulComplete** Step decision. **IsGracefulCompletionConditionCompleted** tells **Execute** whether it completed, so a Step that waits for the next message can return **DeadEnd**. It needs Server protocol 7, server-zd 0.1.34 or later; against an older Server, WaitFor fails with **GracefulCompletionConditionUnsupportedError**. The SDK supports Server protocol 7. [Reference](/reference/go/waits#graceful-completion-requests).
- **GracefulCompleteFlow** and **ForceCompleteFlow** stop types and **StopOptions.Output** let **Client.StopFlow** complete a Flow with a result, like the **GracefulComplete** and **ForceComplete** Step decisions. They need a server that supports the complete stop types.
- **SupportsGracefulCompletionCondition** reports whether the connected Server supports **GracefulCompletionRequested**, from the protocol version the Worker negotiated, without a request. **WaitFor** can add the condition only when it returns true and keep working with Servers older than protocol 7. [Reference](/reference/go/waits#graceful-completion-requests).

### 1.45.5 (2026-11-15) {#v1-45-5}

**Added**

- **Client.CloneForkFlow** creates a new Flow whose first run starts from a copy of another Flow run's state at one point, while the source run keeps running. **CloneForkFlowOptions** selects the point as **TimeTravelOptions** does, plus the new **TimeTravelToCurrent**, and sets the request ID, ID reuse policy, already-started options, Flow configuration and task queue, initial Attributes, Flow timeout, reason, and SubFlow reset policy. **CloneForkFlowResult** returns the new run ID and the copied source run, run attempt, and event ID. It needs Server protocol 6, server-zd 0.1.33 or later; against an older Server it returns **CloneForkFlowUnsupportedError**.
- **Client.TimeTravel** returns to the point after one history event with **TimeTravelByEventID** and **TimeTravelOptions.EventID**, and takes a **SubFlowResetPolicy** that decides what happens to the SubFlow conditions of restored Steps.
- **FlowErrorSubFlowAbandoned** marks a failed SubFlow result whose parent Flow stopped waiting for the child, because a Time Travel's SubFlow reset policy failed the restored SubFlow condition. **Execute** reads it from **SubFlowResult** like any other failed child.

**Fixed**

- A Flow result with an error type this SDK version does not recognize no longer fails the Worker invocation or the read. **FlowResult.ErrorType** is then the zero value.

### 1.45.4 (2026-11-15) {#v1-45-4}

**Changed**

- A pull Worker ignores the Server's busy-stream keepalive, a response with no frame, without a debug log line.

### 1.45.3 (2026-11-14) {#v1-45-3}

**Added**

- **RPCInvokeOptions.RequestID** sets the request ID of **Client.InvokeRPCWithOptions**. Pass the same ID on every attempt, such as the ID of an event that is delivered at least once, and Dex Server applies the RPC's Flow changes at most once. A transactional or locking RPC answers a repeat with the recorded reply without running its handler again, and a different request under the same ID fails with **ServiceError** and INVALID_ARGUMENT. Any other RPC runs its handler again on a repeat; when that attempt changes no Flow state and records no event, it returns the new output and keeps no request ID. Nil keeps the SDK-generated request ID. [API reference](pathname:///api/go/latest/dex/#type-rpcinvokeoptions).

### 1.45.2 (2026-11-14) {#v1-45-2}

**Added**

- **ClientOnlyFlow** marks a Flow that only a Client uses: it types the RPCs and Streams of a Flow type that Workers of another application or language serve, so **Client.InvokeRPC** and **Client.ReadStream** can call them. **NewRegistry** rejects a client-only Flow that declares Steps, **NewWorker** returns **ClientOnlyFlowError** for a Registry that holds one, and **IsClientOnlyFlow** reports the marker. [API reference](pathname:///api/go/latest/dex/#type-clientonlyflow).
- Named task queues give one Flow type separate Worker pools. **PullWorkerOptions.TaskQueue** names the one task queue a Worker serves, **StartFlowOptions.TaskQueue** places a Flow on a task queue for its whole run, and **SubFlowOptions.TaskQueue** moves a SubFlow off its parent's task queue; **DefaultTaskQueue** selects the default task queue explicitly. Named task queues require Server protocol 5: against an older Server, **Worker.Start**, **Client.StartFlow**, and a WaitFor that starts such a SubFlow return **TaskQueueUnsupportedError** instead of using the default task queue. A Worker stream that the Server registers on another task queue is closed and reported as a permanent rejection, and **PullRegistrationState** entries and **PullRegistrationError** carry the task queue. [Go Workers](/reference/go/workers#task-queue) and [API reference](pathname:///api/go/latest/dex/#type-pullworkeroptions).

### 1.45.0 (2026-11-11) {#v1-45-0}

**Breaking**

- A Step whose Step type contains "-" can no longer start SubFlows. The child Flow ID joins the parent Flow ID, Step execution ID, and SubFlow index with "-", so a dash made it ambiguous. When such a Step returns a **SubFlow** Condition from **WaitFor**, Dex Server rejects the result and fails the attempt without retry. The Worker logs a warning. Default Step types are Go type names and are not affected; only a **GetStepType** override can contain "-". To migrate, change the **GetStepType** override to return a name without "-". [Reference](/reference/go/subflow#step-type-rule).

**Added**

- **WorkerOptions.FlowDefinitionPaths** and **WorkerOptions.FlowDefinitions** upload the Flow Definition Graph 2.0 documents of the Worker's registered Flow types when the Worker starts. A failed upload only logs a warning. **ReadFlowDefinitionFiles** reads documents with the same rules, and **Client.UploadFlowDefinitions** uploads them from a deployment script and reports each **FlowDefinitionUploadOutcome**. [Reference](/reference/go/workers#flow-definitions).

**Fixed**

- The **Join** documentation no longer recommends reporting a result for a cancelled branch from the cancelling RPC, which could count that branch twice. A cancelled branch never reports, and no other code can safely report for it. [API reference](pathname:///api/go/latest/dex/#type-join).

### 1.44.0 (2026-11-10) {#v1-44-0}

**Added**

- **Join** and **JoinRound** synchronize parallel branches of one Flow. **DefineJoin** defines a Join over a ChannelMap of branch results. **Join.Fork** starts the branches and the join Step with one **JoinRound**; **Join.ForkWithRoundKey** takes an explicit round key for RPCs. Branches report with **Join.EndBranch** or **Join.ReportBranchResult**. The join Step waits with **Join.ForAllBranches**, **Join.ForFirstBranch**, or **Join.ForBranches** and reads **Join.BranchResults**. The next round's split Step resets the previous round with **Join.ForRemainingBranches** and reads **Join.RemainingBranchResults**. **Join.ChannelMap** returns the underlying ChannelMap for reading or loading a round's pending results. [API reference](pathname:///api/go/latest/dex/#type-join).

### 1.40.0 (2026-11-09) {#v1-40-0}

**Added**

- **FlowConfig.OffloadHistory** chooses whether a run offloads its history to object storage. Nil means true. Set it to false for many short runs that close soon. Set it at start through **StartFlowOptions.ConfigOverride** or in **SubFlowOptions.ConfigOverride**. A SubFlow otherwise inherits its parent's value, and **Client.UpdateFlowConfig** rejects it with INVALID_ARGUMENT. It requires server-zd 0.1.23 or later. [Reference](/reference/server/configuration#history-offload).

**Changed**

- **FlowConfig.DeleteExpiredHistoryObjects** is deprecated. It has no effect, and the SDK no longer sends it. Existing code that sets it still compiles.
- The Worker error type now reports the original error's type for an error wrapped by **dex.ErrorWithStack**, instead of the wrapper type. The message and stack are unchanged. This arrived in 1.40.2.

### 1.35.0 (2026-11-06) {#v1-35-0}

**Breaking**

- Workers and the Client’s first call now require server-zd 0.1.17 or later (protocol version 4). Upgrade all server processes before upgrading the SDK. [Reference](/reference/server/upgrades).
- Worker startup fails when **MaxConcurrentTasks** exceeds **matching.maxConcurrentTasksCap** (256 by default). Lower the Worker setting or raise the server cap and **matching.maxStreams** first. [Reference](/reference/go/workers#capacity-and-shutdown).
- **RetryPolicy.TotalDuration** now starts at the first hand-out and only gates scheduling another retry. Set method timeouts to bound running attempts. [API reference](pathname:///api/go/latest/dex/#type-retrypolicy).
- A Step with no available or supporting Worker waits durably without consuming a retry. Set a Flow timeout to bound that wait. [Reference](/reference/server/workers#step-task-queue).
- A Step attempt interrupted after its hand-out was committed fails with **NOT_COMPLETED** and consumes a retry. Review retry policies and side effects before upgrading. [Reference](/reference/go/failure-and-retries#same-attempt-redelivery).

**Added**

- **RecoveryErrorInfo.AttemptProgress** distinguishes a failed Step method that never started from one that may have run. [API reference](pathname:///api/go/latest/dex/#type-recoveryerrorinfo).
- **RPCOptions.Name** sets an RPC’s protocol name while Go callers continue referring to its bound method. [API reference](pathname:///api/go/latest/dex/#type-rpcoptions).

**Changed**

- Workers open one execution stream per slot; **ReservedRPCTasks** selects RPC-only slots. By default, a Worker with at least two slots reserves one for RPCs. [Reference](/reference/go/workers#capacity-and-shutdown).
- **Stop** drains running handlers and returns tasks that did not start without consuming a retry. [Reference](/reference/go/workers#capacity-and-shutdown).

**Deprecated**

- **IdleStreamsPerQueue** is accepted but ignored, and **PullReservedRPCDeclines()** always reports zero. Use execution-slot capacity and queue metrics instead. [Reference](/reference/go/workers#reserved-rpc-capacity).

**Fixed**

- A Worker accepts omitted input for an RPC whose input type is **dex.None**, allowing TypeScript Clients to invoke it. Missing input for other RPC types still fails with **INVALID_ARGUMENT**. [API reference](pathname:///api/go/latest/dex/).
