# TypeScript Workers

This page shows how to start a TypeScript Worker and lists the TypeScript names of its
settings. [Workers and the task queue](/reference/server/workers) describes
how these settings behave in every SDK.

## Start a Worker

This example serves a Greeting Flow through a pull Worker. Its Step stores a
greeting, and the greeting RPC reads it. The Worker allows eight concurrent tasks
and keeps one slot for RPCs.

```typescript
export async function startPullGreeting(
  cache: BlobCache,
  serverAddress: string,
): Promise<{ flow: GreetingFlow; worker: Worker; client: Client }> {
  const flow = new GreetingFlow();
  const registry = new Registry([flow]);
  const worker = new Worker(registry, cache, {
    serverAddress,
    pull: {
      maxConcurrentTasks: 8,
      // Keep one slot for RPCs so Flows stay responsive.
      reservedRpcTasks: 1,
    },
  });
  try {
    await worker.start();
    await worker.waitPullRegistered({ timeoutMs: 30_000 });
  } catch (failure) {
    try {
      await worker.close();
    } catch (cleanupFailure) {
      throw new AggregateError([failure, cleanupFailure], "pull Worker startup and cleanup failed");
    }
    throw failure;
  }
  const client = new Client(registry, cache, { serverAddress });
  return { flow, worker, client };
}

export async function stopPullGreeting(worker: Worker, client: Client): Promise<void> {
  await client.close();
  await worker.close();
}
```

Example: [examples/typescript/src/production/pull-workers.ts](https://github.com/superdurable/dex/blob/main/examples/typescript/src/production/pull-workers.ts)

## Readiness

**waitPullRegistered** waits until the Worker's slot streams have registered with
Dex. **pullRegistrationState** reports the current registration state. By default,
a Worker keeps retrying when Dex permanently rejects a slot stream. Set
**stopOnPermanentStreamRejection** to stop and drain the Worker instead when a permanent
rejection leaves a slot kind without registered streams. Since 1.14.0.

The wait accepts an AbortSignal or a timeout in milliseconds. With the stop
option on, **run** reports the permanent rejection after draining.

A **PullRegistrationError** reports **STEP_AND_RPC** or **RPC_ONLY** as its slot
kind.

Since 1.45.2, each **PullQueueRegistrationState** in the snapshot and each
**PullRegistrationError** also carry **taskQueue**, the Worker's task queue. The
empty string means the default task queue. See [Task queues](#task-queues).

Call the boolean helper from your probe endpoint and return 200 when true or
503 when false.

```typescript
export function isPullGreetingReady(worker: Worker): boolean {
  return worker.pullRegistrationState().isReady;
}
```

Example: [examples/typescript/src/production/pull-workers.ts](https://github.com/superdurable/dex/blob/main/examples/typescript/src/production/pull-workers.ts)

## Task queues {#task-queues}

Since 1.45.2. A named task queue chooses which Workers execute a Flow,
independently of its Flow type. Only Workers that pull the Flow's task queue and
register its Flow type run its Steps and RPCs. Workers on other task queues
never take that work, even for the same Flow type. A Flow without a task queue
runs on the default task queue, as before.

| Setting | TypeScript name |
| --- | --- |
| Task queue a Worker pulls | **taskQueue** of [PullWorkerOptions](pathname:///api/typescript/latest/interfaces/PullWorkerOptions.html#taskqueue) |
| Task queue a Flow starts on | **taskQueue** of [StartFlowOptions](./start-flow-options.mdx#task-queue) |
| Task queue of a SubFlow | **taskQueue** of [SubFlowOptions](./subflow.mdx#task-queue) |
| Task queue in readiness | **taskQueue** of **PullQueueRegistrationState** and **PullRegistrationError** |

- One Worker pulls exactly one task queue. To serve several task queues,
  construct one Worker per task queue. The Workers can share one Registry and
  one blob cache.
- A name has 1 to 63 ASCII letters, digits, dots, underscores, or hyphens.
  Names that start with **dex.** are reserved. A Worker rejects every reserved
  name, including **dex.default**: its constructor throws **TypeError**.
- Omitting **taskQueue**, or setting the empty string, pulls the default task
  queue.
- A sticky Worker serves a Flow again only when it pulls the Flow's task queue.
  Otherwise Dex routes the Flow to any Worker of that task queue.

### Server protocol 5 {#task-queue-protocol}

A non-empty task queue requires Server protocol 5. The SDK checks it in three
places:

- **Worker.start** rejects before it opens task streams when the Server reports
  an older protocol.
- **Client.startFlow** throws **Error** before it sends the request.
- A **waitFor** that returns a SubFlow with a task queue fails its attempt.

The Worker also checks every registration. The Server echoes the task queue it
registered each stream under. When the echo differs from the Worker's task
queue, the Worker half-closes that stream and records a permanent rejection,
so Dex returns tasks already sent to it without spending an attempt. The
rejection's gRPC code is **FAILED_PRECONDITION**:

- **waitPullRegistered** rejects with a **PullRegistrationError**, and so does
  **start** when every stream is rejected before any registers. With
  **stopOnPermanentStreamRejection**, **run** rejects with it after draining.
- In **pullRegistrationState**, the slot kind's **lastPermanentError** holds the
  gRPC error, and **isReady** is false while no stream of that slot kind is
  registered.
- The Worker retries the stream after the usual delay for a permanent
  rejection, about one minute.

## Capacity and shutdown

| Setting | TypeScript name |
| --- | --- |
| Concurrent tasks | **maxConcurrentTasks** |
| Reserved RPC slots | **reservedRpcTasks** |
| Stop drain timeout | **stopDrainTimeoutMs** |
| Shutdown | **close** |

The idle stream option, **idleStreamsPerQueue**, is deprecated. It is still accepted and
has no effect.

## Reserved RPC capacity

The reserve-decline counter, **pullReservedRpcDeclines**, is deprecated. It remains for
source compatibility and always reads zero.

Report registration readiness instead, as this diagnostics helper does. A Worker with every slot busy stays ready.

```typescript
export interface PullGreetingDiagnostics {
  readonly isReady: boolean;
}

export function getPullGreetingDiagnostics(worker: Worker): PullGreetingDiagnostics {
  return {
    isReady: worker.pullRegistrationState().isReady,
  };
}
```

Example: [examples/typescript/src/production/pull-workers.ts](https://github.com/superdurable/dex/blob/main/examples/typescript/src/production/pull-workers.ts)

## Flow definitions {#flow-definitions}

Since 1.45. A Worker can upload Flow Definition Graph (FDG 2.x) documents to
Dex so that Dex Web can draw its Flows without a definition directory.
[Flow definitions](/reference/server/runtime-client#flow-definitions) describes
how the server stores them.

| Setting | TypeScript name |
| --- | --- |
| Files or directories to upload | **flowDefinitionPaths** |
| In-memory documents to upload | **flowDefinitions**, a list of **FlowDefinitionDocument** with **flowType**, **content**, and **generatedAt** |
| Upload from a deploy script | **uploadFlowDefinitions** on the Client, with optional **force** |

**flowDefinitionPaths** accepts files and directories:

- An explicitly listed file must be an FDG 2.x document, whatever its
  extension: a strict UTF-8 JSON object, without **NaN**, **Infinity**, or text
  after it, whose **schemaVersion** starts with **2.** and that has a
  **flow.name** string.
- A directory is searched recursively for files whose extension is **.json** in
  any letter case. A file there that is not an FDG 2.x document, such as
  **package.json** or an FDG 1.x file, is skipped and logged.
- Each file's **flow.name** is its Flow type. Its top-level **generatedAt** is
  the generation time. It must be strict RFC 3339: a **T** or **t** separator,
  an optional fraction with at least one digit, and a **Z**, **z**, **+HH:MM**,
  or **-HH:MM** offset, as in **2026-11-01T08:00:00Z** or
  **2026-11-01T03:00:00.5-05:00**. Every field must be in range: no leap second,
  no hour 24, and offsets up to 23:59. A file without it uses its modification
  time.
- Every Dex SDK truncates the generation time to whole milliseconds, including
  the time of an in-memory document.

Use **flowDefinitions** when the application renders its graph in code. Give the same
content the same generation time on every start.

Workers upload the documents once per start, after the server protocol
check and before opening task streams. All upload requests of one start share
one deadline, **attributeIndexSyncTimeoutMs**, and **close** cancels an upload in flight:

- Only documents whose Flow type the Worker registers are uploaded. The others
  are skipped and logged.
- **source.path** is rewritten only when the top-level object has exactly one
  **source** key, its value is an object with exactly one **path** key, and that
  value is a string. An absolute top-level **source.path** (one that starts with **/**, a drive
  such as **C:\\**, or **\\\\**) is replaced by a path relative to the
  working directory, joined with **/**. The comparison is lexical: **.** and
  **..** are resolved and symbolic links are not. A path outside the working
  directory, or any path when the working directory is unknown, becomes its file
  name. A relative path and the rest of the document are sent unchanged.
- The uploader is **sdk-typescript/&lt;version&gt;**.
- Upload messages never go to stdout, so they never mix with protocol output
  there. Skipped, created, and replaced definitions are written to stderr as
  lines that start with **dex info:**. A kept newer definition, an unknown
  outcome, and a failure are logged with **console.warn**. Unchanged
  definitions are not logged.
- A failed upload, including a server older than 0.1.26 that returns
  **UNIMPLEMENTED**, is logged. The Worker still starts.

The Worker constructor throws an **Error** for a missing or unreadable path,
an explicitly listed file or an in-memory document that is not an FDG 2.x
document, a **generatedAt** that is not strict RFC 3339 (also inside an
in-memory document, whose caller-supplied time is still the one uploaded), an in-memory document
whose **flow.name** differs from its Flow type, or the same Flow type in two
documents.

**uploadFlowDefinitions** sends documents without a Worker and returns each outcome. It sends
at most 256 documents and 16 MiB of content per request; a larger single
document goes alone. An outcome the SDK does not know is reported as
**UNSPECIFIED**. Pass **force** set to true to roll a definition back.
