### 1.45.16 (2026-11-20) {#v1-45-16}

**Added**

- Set **payloadCodec** in **ClientOptions** and **WorkerOptions** to encrypt payloads before storage and keep keys out of Dex. **AesGcmPayloadCodec** uses AES-256-GCM, and **FilePayloadEncryptionKeyProvider** reads JSON keys. [Reference](/reference/server/payload-encryption).
- Worker error text and the reasons of **stopFlow**, **timeTravel**, and **cloneForkFlow** are encrypted too. Switch string, primitive, and error-text encryption off with **encryptStringValues**, **encryptPrimitiveValues**, and **encryptErrorText**.
- Indexed Attributes remain plaintext for search. Use **plaintext()** when the Server must read an Attribute or AttributeMap, as **waitForAttributeMatch** and Action conditions reject encrypted Attributes. [Reference](/reference/server/payload-encryption#plaintext-attributes).
- The Go, Python, and TypeScript SDKs share the encryption format. The Java and Rust SDKs cannot read encrypted Flows yet.

### 1.45.8 (2026-11-18) {#v1-45-8}

**Fixed**

- **Client.invokeRPC** and **Client.invokeRPCWithOptions** now send null for inputless RPCs. Omitted input caused **Value has no concrete kind** on Python and Java Workers before 1.45.8 and on Rust Workers. (#2034)

### 1.45.7 (2026-11-18) {#v1-45-7}

**Added**

- **PullWorkerOptions.minOpenSlots** lets a pull Worker vary open streams with load when set below **maxConcurrentTasks**. The default equals **maxConcurrentTasks**, keeping the stream count fixed. [Reference](/reference/typescript/workers#capacity-and-shutdown).
- Adaptive Workers warn and clamp **maxConcurrentTasks** to **matching.maxConcurrentTasksCap**. Growth and post-readiness reconnects retry after **RESOURCE_EXHAUSTED** without reporting **PullRegistrationError**. [Reference](/reference/server/workers#adaptive-slot-streams).
- **Worker.pullSlotStreamState** returns a snapshot of the slot streams: open, registering, busy, and idle streams, orphaned handlers, the floor and capacities, and grow and shrink counters. **NODE_DEBUG=dex** logs each grow and shrink.

**Changed**

- **Worker.start** now waits for one registered stream of each slot kind. It rejects with **PullRegistrationError** if every stream of a kind is rejected before one registers. [Reference](/reference/server/workers#adaptive-slot-streams).
- Fixed pull Workers with unset **maxConcurrentTasks** now warn and clamp the CPU-count default to **matching.maxConcurrentTasksCap**. An explicit limit above the cap still prevents startup. [Reference](/reference/server/workers#adaptive-slot-streams).
- A pull Worker opens its RPC-only streams by slot kind instead of as the last slots, and an unset **reservedRpcTasks** reserves no slot when **minOpenSlots** is 1.

### 1.45.6 (2026-11-16) {#v1-45-6}

**Added**

- **GracefulCompletion.requested** lets a Step wait for a request and **isGracefulCompletionConditionCompleted** reads the result from Context. Requires Dex Server 0.1.34 or later and protocol 7. [Reference](/reference/typescript/waits#graceful-completion-requests).
- **StopType.GRACEFUL_COMPLETE**, **StopType.FORCE_COMPLETE**, and **StopFlowOptions.output** let **Client.stopFlow** complete a Flow with a result, like the **gracefulComplete** and **forceComplete** Step decisions. They need Dex Server 0.1.34 or newer.
- **supportsGracefulCompletionCondition** checks negotiated support for **GracefulCompletion.requested** before **waitFor** uses it, including on Servers older than protocol 7. It returns false for Contexts created outside Dex. [Reference](/reference/typescript/waits#graceful-completion-requests).

### 1.45.5 (2026-11-15) {#v1-45-5}

**Added**

- **Client.cloneForkFlow** copies run state into a new Flow while the source keeps running, with **CloneForkFlowOptions** defaulting to **CURRENT**. Requires Server protocol 6 (server-zd 0.1.33 or later). [Reference](/reference/server/runtime-client#clone-fork).
- **Client.timeTravel** accepts **TimeTravelType.EVENT_ID** with **TimeTravelOptions.eventId**, and **TimeTravelOptions.subFlowResetPolicy** with the new **SubFlowResetPolicy** values decides what happens to SubFlow conditions that restored Steps wait on.
- The SDK now negotiates Server protocol version 6.
- **FlowErrorType.SUB_FLOW_ABANDONED** marks a restored SubFlow wait failed by the Time Travel reset policy. Read it via **SubFlow.getConditionResults** and handle it in exhaustive **FlowErrorType** matches. [Reference](/reference/server/runtime-client#sub-flows-across-a-time-travel).

**Fixed**

- The TypeScript SDK package includes legacy notices and third-party license texts.
- Reading a SubFlow result with an error type this SDK version does not recognize no longer throws **TypeError**. **FlowResult.errorType** is then **undefined**.

### 1.45.4 (2026-11-14) {#v1-45-4}

**Added**

- Reuse **RPCInvokeOptions.requestId** with **Client.invokeRPCWithOptions** for at-most-once Flow changes and the recorded reply for transactional or locking RPCs. The default is a new random ID per call. [Reference](/reference/server/runtime-data#rpc-request-ids).

### 1.45.3 (2026-11-14) {#v1-45-3}

**Added**

- **FlowState.taskQueue** names the task queue of the Flow that **Client.getFlowState** reads. An empty string means the default task queue. A Client without a Worker can read it to see which Workers must serve the Flow.

### 1.45.2 (2026-11-14) {#v1-45-2}

**Added**

- Set named queues with **PullWorkerOptions.taskQueue**, **StartFlowOptions.taskQueue**, and **SubFlowOptions.taskQueue**. Named queues require Server protocol 5, and SubFlows inherit the parent's queue by default. [Reference](/reference/typescript/workers).

### 1.45.1 (2026-11-13) {#v1-45-1}

**Added**

- **Client.getFlowState** returns a **FlowState** with open Step executions, their current WaitFor or Execute attempts, and their latest attempt failures. [Reference](/reference/typescript/client#api-names).

### 1.45.0 (2026-11-11) {#v1-45-0}

**Breaking**

- Steps with "-" in their Step type can no longer start SubFlows, and a **SubFlow.run** condition from **waitFor** logs a warning and fails without retry, failing the Flow under the default policy. If the Step starts SubFlows, change **getStepType** to return a name without "-". [Reference](/reference/typescript/subflow#step-types-that-start-subflows).

**Added**

- **WorkerOptions.flowDefinitionPaths** and **WorkerOptions.flowDefinitions** upload registered Flow graphs at startup, exposing **source.path** only as a relative path. Requires server-zd 0.1.26 or later. [Reference](/reference/typescript/workers#flow-definitions).
- **Client.uploadFlowDefinitions** uploads Flow definitions from a deploy script and returns a **FlowDefinitionUploadResult** with a **FlowDefinitionUploadOutcome** for each document. [Reference](/reference/typescript/workers#flow-definitions).

**Fixed**

- The **Join** documentation no longer recommends reporting a result for a cancelled branch from the cancelling RPC, which could count that branch twice. A cancelled branch never reports, and no other code can safely report for it. [Reference](/reference/typescript/waits).

### 1.38.0 (2026-11-07) {#v1-38-0}

**Added**

- **FlowConfig.historyWindowEvents** controls recent history for reads and Time Travel at start or via **updateFlowConfig**. It requires server-zd 0.1.21 or later and defaults to **history.windowEvents**. [Reference](/reference/server/configuration#history-window).

**Changed**

- The gRPC receive limit rises from 4 MiB to **DEFAULT_GRPC_MAX_MESSAGE_BYTES** (32 MiB) on every FlowService channel and Worker task stream. Set **grpcMaxMessageBytes** on **ClientOptions** or **WorkerOptions** to change it. A negative or non-integer value throws RangeError.

**Fixed**

- A LoadBlobs request splits in half when its response exceeds a gRPC message size limit, so a Worker with an empty blob cache no longer fails on a long Flow. A single blob that does not fit rejects with the new **BlobMessageTooLargeError**.

### 1.35.0 (2026-11-06) {#v1-35-0}

**Breaking**

- Workers and the Client’s first call now require server-zd 0.1.17 or later (protocol version 4). Upgrade all server processes before upgrading the SDK. [Reference](/reference/server/upgrades).
- Worker startup fails when **maxConcurrentTasks** exceeds **matching.maxConcurrentTasksCap** (256 by default). Lower the Worker setting or raise the server cap and **matching.maxStreams** first. [Reference](/reference/typescript/workers#capacity-and-shutdown).
- **RetryPolicy.totalDurationMs** now starts at the first hand-out and only gates scheduling another retry. Set method timeouts to bound running attempts. [API reference](pathname:///api/typescript/latest/interfaces/RetryPolicy.html#totaldurationms).
- A Step with no available or supporting Worker waits durably without consuming a retry. Set a Flow timeout to bound that wait. [Reference](/reference/server/workers#step-task-queue).
- A Step attempt interrupted after its hand-out was committed fails with **NOT_COMPLETED** and consumes a retry. Review retry policies and side effects before upgrading. [Reference](/reference/typescript/failure-and-retries#same-attempt-redelivery).

**Added**

- **RecoveryErrorInfo.attemptProgress** distinguishes a failed Step method that never started from one that may have run. [API reference](pathname:///api/typescript/latest/interfaces/RecoveryErrorInfo.html).
- **declareRPCMethod** declares RPC handlers without decorators. **RPCMethodName** checks eligible method names at compile time. [API reference](pathname:///api/typescript/latest/functions/declareRPCMethod.html).
- **flowServiceTls** on Client and Worker options enables verified TLS, with optional **additionalRootCAsPem** and **serverName**. Omitting it keeps plaintext connections. [API reference](pathname:///api/typescript/latest/interfaces/FlowServiceTlsOptions.html).

**Changed**

- Workers open one execution stream per slot; **reservedRpcTasks** selects RPC-only slots. By default, a Worker with at least two slots reserves one for RPCs. [Reference](/reference/typescript/workers#capacity-and-shutdown).
- **close** drains running handlers and returns tasks that did not start without consuming a retry. [Reference](/reference/typescript/workers#capacity-and-shutdown).

**Deprecated**

- **idleStreamsPerQueue** is accepted but ignored, and **pullReservedRpcDeclines** always reports zero. Use execution-slot capacity and queue metrics instead. [Reference](/reference/typescript/workers#reserved-rpc-capacity).
