# SubFlow

This page lists the Rust SDK names for [SubFlows](/concepts/primitives/subflow).
The doc comment of each API gives its parameters, defaults, and errors. Read
them in the [Rust SDK API reference](./index.mdx#api-reference).

## API names {#api-names}

| Task | Rust API | Dex behavior |
| --- | --- | --- |
| Start a child Flow and wait for it | **SubFlow::run** in **wait_for** | [SubFlows](/reference/server/runtime-data#subflows) |
| Set the child timeout, Attributes, and configuration | **SubFlowOptions**, with **SubFlow::run_with_options** | [SubFlowOptions](/reference/server/runtime-data#subflow-options) |
| Run the child on another task queue | **task_queue** of **SubFlowOptions** | [Task queue](#task-queue) |
| Choose what happens to an existing child | **reuse_policy** of **SubFlowOptions**, with **SubFlowReusePolicy** | [SubFlowReusePolicy](/reference/server/runtime-data#subflow-reuse-policy) |
| Read the child result | **SubFlow::condition_result** or **SubFlow::condition_result_at** in **execute**. It returns a **FlowResult**. | [SubFlow results](./waits.mdx#subflow-results) |
| Read the generated child Flow ID | **SubFlow::flow_id** or **SubFlow::flow_id_at** | [SubFlowReusePolicy](/reference/server/runtime-data#subflow-reuse-policy) |
| Stop a child that lost an **AnyOf** | **Client::stop_flow** with the child Flow ID | [Stop a Flow](/reference/server/runtime-client#stop-a-flow) |

## Task queue {#task-queue}

A SubFlow runs on its parent's task queue by default. **SubFlowOptions::task_queue**
picks another one. Since 1.45.1.

- The empty name, the default, keeps the parent's task queue.
- **dex.default** runs the SubFlow on the default task queue while the parent
  runs on a named one.
- Any other name follows the rules of
  [StartFlowOptions::task_queue](./start-flow-options.mdx#task-queue).
- The Worker checks the name when **wait_for** returns the **Wait**. An invalid
  name, or a non-empty name while the Server protocol is older than 5, fails
  that Step attempt like any other invalid Step result.

API reference: [SubFlowOptions::task_queue](https://docs.rs/dex-sdk/1.45.1/dex_sdk/struct.SubFlowOptions.html#method.task_queue).

## Step types that start SubFlows {#step-type-rule}

Changed in 1.45.0: a Step whose Step type contains a dash (-) cannot start
SubFlows.

Dex builds each child Flow ID from the parent Flow ID, the Step execution ID,
and the SubFlow index. It joins them with a dash. The Step execution ID starts
with the Step type. A dash in the Step type therefore lets two parents generate
the same child Flow ID.

If such a Step returns a **Wait** with a **SubFlow** Condition from
**wait_for**, the Worker logs a warning and sends the result unchanged. The
server rejects it as an invalid Worker response. It fails the attempt without
retry, so under the default policy the Flow fails. Steps with a dash in their
Step type can still use every other Condition.

To start SubFlows from the Step, rename its Step type. Override
**Step::step_type** to return a name without a dash. The default Step type is
the Rust type name, which never contains a dash.
