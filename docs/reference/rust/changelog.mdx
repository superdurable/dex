### 1.45.8 (2026-11-23) {#v1-45-8}

**Added**

- Set **RpcInvokeOptions::request_id** to reuse a stable request ID across RPC attempts and apply the call's Flow changes at most once while Dex retains the request ID.

**Changed**

- Pull Workers are adaptive by default. **max_concurrent_tasks** now defaults to 100 instead of the CPU count, and **min_open_slots** defaults to min(**max_concurrent_tasks**, max(**reserved_rpc_tasks** + 1, CPU count)).
- An idle Worker keeps about the CPU count of slot streams open and grows up to the ceiling under load. A Worker that sets only **max_concurrent_tasks** is adaptive too.
- A ceiling above the Server's **matching.maxConcurrentTasksCap** is clamped with a WARN log; defaults use the clamped value. An adaptive Worker with unset **min_open_slots**, or a fixed Worker with unset **max_concurrent_tasks**, opens one stream to learn the cap.
- Migration: set **min_open_slots** equal to **max_concurrent_tasks** to keep a fixed Worker. Set **max_concurrent_tasks** to the CPU count to keep the earlier default slot count.
- The **FlowConfig::history_window_events** documentation states that 0 sets an unlimited window with server-zd 0.1.38 or later, its limits, and the current **history.windowEvents** and **history.maxWindowEvents** defaults. [Reference](/reference/server/configuration#history-window)

**Fixed**

- A Worker serves an RPC bound without input, with **RpcList::function_without_input** or **RpcList::procedure_without_input**, when the request leaves the input unset, as TypeScript Clients before 1.45.8 send it. Before, the Worker failed the call with **Value has no concrete kind**. An RPC bound with an input still needs one; an unset input fails the call with a value mapping error that names the RPC. (#2034)

### 1.45.7 (2026-11-18) {#v1-45-7}

**Added**

- **PullWorkerOptions::min_open_slots** lets a pull Worker vary open streams with load when set below **max_concurrent_tasks**. The default equals **max_concurrent_tasks**, keeping the stream count fixed. [Reference](/reference/rust/workers#capacity-and-shutdown).
- Adaptive Workers warn and clamp **max_concurrent_tasks** when it exceeds **matching.maxConcurrentTasksCap**. Growth and post-readiness reconnects retry after **RESOURCE_EXHAUSTED** without a **PullRegistrationError**. [Reference](/reference/server/workers#adaptive-slot-streams).
- **Worker::pull_slot_stream_state** returns a **PullSlotStreamState** snapshot of the slot streams: open, registering, busy, and idle streams, orphaned handlers, the floor and capacities, and grow and shrink counters.

**Changed**

- Fixed pull Workers with unset **max_concurrent_tasks** now warn and clamp the CPU-count default to **matching.maxConcurrentTasksCap**. An explicit limit above the cap still prevents startup. [Reference](/reference/server/workers#adaptive-slot-streams).

### 1.45.3 (2026-11-16) {#v1-45-3}

**Added**

- **Condition::graceful_completion_requested** waits for a graceful completion request and **Context::is_graceful_completion_condition_completed** reads the result. Requires Dex Server 0.1.34 or later and protocol 7. [Reference](/reference/rust/waits#graceful-completion-requests).
- **StopFlowOptions::graceful_complete**, **StopFlowOptions::force_complete**, and **StopFlowOptions::output** let **Client::stop_flow** complete a Flow with a result, like the **graceful_complete** and **force_complete** Step decisions. They need Dex Server 0.1.34 or newer.
- **Context::supports_graceful_completion_condition** checks the negotiated protocol. Add **Condition::graceful_completion_requested** to **wait_for** only when it returns true, so the Step also works on pre-protocol-7 Servers. [Reference](/reference/rust/waits#graceful-completion-requests).

### 1.45.2 (2026-11-15) {#v1-45-2}

**Breaking**

- **FlowErrorType** is **#[non_exhaustive]**. A **match** on it outside the SDK needs a wildcard arm. This change lets later releases add error types without another breaking change.

**Added**

- **Client::clone_fork_flow** copies run state into a new Flow without stopping the source. **CloneForkFlowOptions** selects the point and **CloneForkFlowResult** identifies it. Requires server-zd 0.1.33+. [Reference](/reference/server/runtime-client#clone-fork).
- **TimeTravelOptions::from_event_id** time-travels to the point right after one history event, and **TimeTravelOptions::sub_flow_reset_policy** chooses a **SubFlowResetPolicy** for the SubFlow conditions that restored Steps wait on.
- The Client negotiates Server protocol 6.
- **FlowErrorType::SubFlowAbandoned** marks a failed SubFlow result whose parent Flow stopped waiting for the child, because a Time Travel's SubFlow reset policy failed the restored SubFlow condition. Earlier versions report such a result with a **None** error type.

### 1.45.1 (2026-11-14) {#v1-45-1}

**Added**

- Set **PullWorkerOptions::task_queue**, **StartFlowOptions::task_queue**, and **SubFlowOptions::task_queue** for named queues on Server protocol 5. **Worker::task_queue** reports the queue. The default queue still works with protocol 4. [Reference](/reference/rust/workers#task-queue).

### 1.45.0 (2026-11-11) {#v1-45-0}

**Breaking**

- Steps with a dash (-) in their Step type can no longer start SubFlows. If **wait_for** returns a **SubFlow** Condition, the Worker logs a warning and Dex Server fails the attempt without retry. The Flow fails under the default policy. Rename the Step type, for example by overriding **Step::step_type** with a name without a dash. [Reference](/reference/rust/subflow#step-type-rule).

**Added**

- **WorkerOptions::flow_definition_paths** and **WorkerOptions::flow_definitions** upload Flow graphs at startup for Dex Web and warn on failure. Use **FlowDefinitionDocument** for in-memory graphs. [Reference](/reference/rust/workers#upload-flow-definitions).
- **Client::upload_flow_definitions** uploads documents from a deploy or CI script and returns a **FlowDefinitionUploadResult** with a **FlowDefinitionUploadOutcome** for each document. [Reference](/reference/rust/client#api-names).

**Fixed**

- The **Join** documentation no longer recommends reporting a result for a cancelled branch from the cancelling RPC, which could count that branch twice. A cancelled branch never reports, and no other code can safely report for it. [Reference](/reference/rust/waits).

## 1.35 {#v1-35}

| Version | Released | Changes | Release |
| --- | --- | --- | --- |
| [1.35.0](#v1-35-0) | 2026-11-06 | 5 breaking, 1 added, 2 changed, 1 deprecated | [sdk-rust/v1.35.0](https://github.com/superdurable/dex/releases/tag/sdk-rust%2Fv1.35.0) |

Reference: [1.35.x](/reference/rust/1.35.x/).

### 1.35.0 (2026-11-06) {#v1-35-0}

**Breaking**

- Workers and the Client’s first call now require server-zd 0.1.17 or later (protocol version 4). Upgrade all server processes before upgrading the SDK. [Reference](/reference/server/upgrades).
- Worker startup fails when **max_concurrent_tasks** exceeds **matching.maxConcurrentTasksCap** (256 by default). Lower the Worker setting or raise the server cap and **matching.maxStreams** first. [Reference](/reference/rust/workers#capacity-and-shutdown).
- **RetryPolicy::total_duration** now starts at the first hand-out and only gates scheduling another retry. Set method timeouts to bound running attempts. [API reference](https://docs.rs/dex-sdk/1.35.0/dex_sdk/struct.RetryPolicy.html#method.total_duration).
- A Step with no available or supporting Worker waits durably without consuming a retry. Set a Flow timeout to bound that wait. [Reference](/reference/server/workers#step-task-queue).
- A Step attempt interrupted after its hand-out was committed fails with **NOT_COMPLETED** and consumes a retry. Review retry policies and side effects before upgrading. [Reference](/reference/rust/failure-and-retries#same-attempt-redelivery).

**Added**

- **RecoveryErrorInfo::attempt_progress()** distinguishes a failed Step method that never started from one that may have run. [API reference](https://docs.rs/dex-sdk/1.35.0/dex_sdk/struct.RecoveryErrorInfo.html#method.attempt_progress).

**Changed**

- Workers open one execution stream per slot; **reserved_rpc_tasks** selects RPC-only slots. By default, a Worker with at least two slots reserves one for RPCs. [Reference](/reference/rust/workers#capacity-and-shutdown).
- **stop** drains running handlers and returns tasks that did not start without consuming a retry. [Reference](/reference/rust/workers#capacity-and-shutdown).

**Deprecated**

- **idle_streams_per_queue** is accepted but ignored, and **pull_reserved_rpc_declines()** always reports zero. Use execution-slot capacity and queue metrics instead. [Reference](/reference/rust/workers#reserved-rpc-capacity).

### 1.25.0 (2026-10-28) {#v1-25-0}

**Breaking**

- Push Workers and **WorkerTarget** are removed, along with Worker listener and target settings on **WorkerOptions**, **ClientOptions**, and **FlowConfig**. Delete these settings and use outbound pull Workers. [API reference](https://docs.rs/dex-sdk/1.25.0/dex_sdk/struct.WorkerOptions.html).

**Changed**

- **StartFlow** and **SubFlow** always select pull Workers. **UpdateFlowConfig** preserves existing Worker routing instead of replacing it. [Release notes](https://github.com/superdurable/dex/releases/tag/sdk-rust%2Fv1.25.0).

**Fixed**

- Pull Workers reject late Step progress after cancellation, completion, or task reassignment, while preserving the task’s final result. [Release notes](https://github.com/superdurable/dex/releases/tag/sdk-rust%2Fv1.25.0).
