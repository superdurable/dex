# Rust Workers

This page shows how to start a Rust Worker and lists the Rust names of its
settings. [Workers and the task queue](/reference/server/workers) describes
how these settings behave in every SDK.

## Start a Worker

This example serves a Greeting Flow through a pull Worker. Its Step stores a
greeting, and the greeting RPC reads it. The Worker allows eight concurrent tasks
and keeps one slot for RPCs. See the [Rust SDK README](https://github.com/superdurable/dex/blob/main/sdk-rust/README.md#pull-mode) for
startup details.

```rust
pub type RunningPullGreeting = (Arc<Worker>, Client, JoinHandle<SdkResult<()>>);

pub fn start_pull_greeting(
    cache: Arc<BlobCache>,
    server_address: &str,
) -> Result<RunningPullGreeting, Box<dyn Error + Send + Sync>> {
    let registry = Registry::new().register(GreetingFlow::default())?;
    let worker = Arc::new(Worker::try_new(
        registry.clone(),
        Arc::clone(&cache),
        WorkerOptions::new().server_address(server_address).pull(
            PullWorkerOptions::new()
                .max_concurrent_tasks(8)
                // This slot accepts only RPCs; the other seven accept Steps and RPCs.
                .reserved_rpc_tasks(1),
        ),
    )?);
    let client = Client::try_new(
        registry,
        cache,
        ClientOptions::new().server_address(server_address),
    )?;
    let startup_runtime = tokio::runtime::Builder::new_current_thread()
        .enable_all()
        .build()?;
    let running_worker = Arc::clone(&worker);
    let worker_thread = thread::spawn(move || running_worker.start());
    let startup_result: Result<(), Box<dyn Error + Send + Sync>> =
        startup_runtime.block_on(async {
            tokio::time::timeout(Duration::from_secs(30), worker.wait_pull_registered()).await??;
            Ok(())
        });
    if let Err(failure) = startup_result {
        match stop_pull_greeting(worker, client, worker_thread) {
            Ok(Ok(())) => {}
            Ok(Err(cleanup_failure)) => {
                eprintln!("pull Worker cleanup failed: {cleanup_failure}");
            }
            Err(panic) => std::panic::resume_unwind(panic),
        }
        return Err(failure);
    }
    Ok((worker, client, worker_thread))
}

pub fn stop_pull_greeting(
    worker: Arc<Worker>,
    client: Client,
    worker_thread: JoinHandle<SdkResult<()>>,
) -> thread::Result<SdkResult<()>> {
    worker.stop();
    let worker_result = worker_thread.join();
    drop(client);
    worker_result
}
```

Example: [examples/rust/src/production/pull_workers.rs](https://github.com/superdurable/dex/blob/main/examples/rust/src/production/pull_workers.rs)

## Readiness

**wait_pull_registered** waits until the Worker's slot streams have registered with
Dex. **pull_registration_state** reports the current registration state. By default,
a Worker keeps retrying when Dex permanently rejects a slot stream. Set
**stop_on_permanent_stream_rejection** to stop and drain the Worker instead when a permanent
rejection leaves a slot kind without registered streams. Since 1.14.0.

Cancel the wait by dropping its future, or bound it with a Tokio timeout. With
the stop option on, **start** returns the permanent rejection after draining.

A **PullRegistrationError** reports **STEP_AND_RPC** or **RPC_ONLY** as its slot
kind.

Call the boolean helper from your probe endpoint and return 200 when true or
503 when false.

```rust
pub fn is_pull_greeting_ready(worker: &Worker) -> bool {
    worker.pull_registration_state().is_ready
}
```

Example: [examples/rust/src/production/pull_workers.rs](https://github.com/superdurable/dex/blob/main/examples/rust/src/production/pull_workers.rs)

## Upload Flow definitions {#upload-flow-definitions}

A Worker can upload Flow Definition Graph documents when it starts, so Dex Web
can draw the graph of each Flow type. Since 1.45.0.

| Setting | Rust name |
| --- | --- |
| Files and directories of documents | **WorkerOptions::flow_definition_paths** |
| In-memory documents | **WorkerOptions::flow_definitions** |

- Each configured path must exist and be readable. An explicitly listed file
  must be a Flow Definition Graph 2.x: a strict UTF-8 JSON object whose
  **schemaVersion** starts with **2.** and whose **flow.name** is a non-empty
  string. The file extension is not checked.
- A directory is read recursively for files whose extension is **.json** in
  any case. A file that is not a Flow Definition Graph 2.x, such as
  **package.json** or a 1.x document, is skipped with an info line.
- A file's Flow type is its **flow.name**. Its generation time is its
  top-level **generatedAt**, or the file modification time when it has none.
  **generatedAt** must be strict RFC 3339, such as
  **2026-11-01T00:00:00Z** or **2026-11-01T02:00:00.5+02:00**. A space
  separator, a missing offset, a date alone, or an offset such as **+0200** is
  an error, also for a file found in a directory.
- A **FlowDefinitionDocument** carries its Flow type, JSON bytes, and
  generation time. Pass a fixed time for a document built from a template.
- Every generation time is truncated to whole milliseconds before upload.
- **Worker::try_new** reads the files. It returns **SdkError::FlowDefinition** for a missing or unreadable path, an invalid explicit file, an invalid **generatedAt**, two sources with the same Flow type, or an in-memory document that is not a Flow Definition Graph 2.x naming its Flow type with a valid **generatedAt**, if any.
- **Worker::start** uploads the documents after protocol negotiation and Attribute index synchronization, before it opens task streams. It uploads only the Flow types that the **Registry** registers
  and logs the others at info. When nothing is left, it sends no request.
- Before upload, an absolute top-level **source.path** becomes relative.
  Paths starting with **/**, a drive such as **C:\\**, or **\\\\** count as
  absolute on every operating system. Under the working directory, the result
  is the remaining segments joined with **/**. Elsewhere, or when the working
  directory is unknown, it is the file name. The rewrite needs exactly one
  top-level **source** object with exactly one string **path**; otherwise the
  original bytes are sent. Only the bytes of that string
  change. A relative path is sent unchanged.
- Documents are sent in requests of at most 256 documents and 16 MiB of
  content. All requests share one deadline, **attribute_index_sync_timeout**. Stopping
  the Worker cancels an upload in progress.
- The uploader is **sdk-rust/** followed by the SDK version.
- Results are logged through **tracing**: CREATED and REPLACED at info,
  UNCHANGED at debug, and KEPT_EXISTING at warn with both digests and
  generation times. An outcome the SDK does not know is logged at warn as an
  unknown upload outcome.
- Every upload failure is logged at warn and the Worker keeps starting.
  This includes a Server without Flow definition storage, which returns
  UNIMPLEMENTED.

Deploy scripts can call **Client::upload_flow_definitions** instead. See
[Flow definitions](/reference/server/runtime-client#flow-definitions) for how
the Server decides between a stored and an uploaded document.

## Capacity and shutdown

| Setting | Rust name |
| --- | --- |
| Concurrent tasks | **max_concurrent_tasks** |
| Reserved RPC slots | **reserved_rpc_tasks** |
| Stop drain timeout | **stop_drain_timeout** |
| Shutdown | **stop** |

The option names are builder methods.

The idle stream option, **idle_streams_per_queue**, is deprecated. It is still accepted and
has no effect.

## Reserved RPC capacity

The reserve-decline counter, **pull_reserved_rpc_declines()**, is deprecated. It remains for
source compatibility and always reads zero.

Report registration readiness instead, as this diagnostics helper does. Its reserve-decline field
is always zero. A Worker with every slot busy stays ready.

```rust
pub struct PullGreetingDiagnostics {
    pub is_ready: bool,
    /// Deprecated: reserved slots never decline for capacity; this value is always zero.
    pub reserved_rpc_declines: u64,
}

pub fn get_pull_greeting_diagnostics(worker: &Worker) -> PullGreetingDiagnostics {
    PullGreetingDiagnostics {
        is_ready: worker.pull_registration_state().is_ready,
        reserved_rpc_declines: 0,
    }
}
```
