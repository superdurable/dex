# 客户退款

Go customer-refund 示例包含两个互相独立的 Flow。两者都会发布 Flow Definition Graph 2.0 元数据，供 Dex Web 使用。

## 确定性策略

`CustomerRefundFlow` 运行七个 Step。它先确认订单存在，再应用 30 天规则。调用支付 provider 之前，它会先记录幂等 key。如果 provider 拒绝退款，或者结果未知，Flow 会把这个结果记为 case 状态。

<DocsFlowDefinitionGraph graph={deterministicFlow} />

Summary 展示 charge reference、请求金额和 recommendation。Display 额外展示证据、计费结果和可编辑的 operator note。这个 Flow 有意不声明任何 Action，用来说明 Action 列表为空的 Flow 在 Dex Web 中同样有效。

## Agentic 审核

`AgenticCustomerRefundFlow` 在一个由 Step 组成的循环里收集证据。随后由 guardrail 决定：要么自动执行决定，要么等待经理审批。每次等待经理审批都有自己的 gate key。Flow 会先记录要执行的操作，再执行 billing、subscription 和 customer-message 操作。这些操作都是幂等的。

<DocsFlowDefinitionGraph graph={agenticFlow} />

批准 Action 没有输入，因此直接显示为按钮。拒绝 Action 要求填写原因。Dex Web 会自动填入一个隐藏的 gate key，取自详情页打开时读到的 Attribute 值。RPC 发布 verdict 之前，会把这个 key 与当前 gate 比较。如果 gate 已经变了，RPC 会返回错误，操作员需要刷新页面。

两个 Action 也会读取当前 case status。Flow Definition Graph 2.0 中的可见性条件只控制按钮是否出现，不做权限控制。
