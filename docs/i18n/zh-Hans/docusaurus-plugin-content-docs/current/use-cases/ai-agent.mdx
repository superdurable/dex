# AI Agent

这个 application 是一个长期运行的通用 AI Agent，有 Python 与 TypeScript 两个版本。它可以与用户聊天、调用受信任的 MCP tool、在修改外部系统前等待审批、向用户提问、通过 durable Timer 暂停，并在执行前先制定计划供用户审阅。

它基于 Dex Agents：Python 版使用 **dex-agents** package，TypeScript 版使用 **@superdurable/dex-agents**。这个 Agent 是一个 Stepwise agent：使用库内置的 agent loop，不依赖任何 agent framework。会话由 Dex 管理。每次模型调用都是一个 **RunModel** Step，并从 durable state 重新构造模型输入，因此 Agent 不依赖 LLM provider 的 conversation API。每次 tool call 都是独立的 Step，因此崩溃最多只会重复当时正在运行的那一次调用。

## Agent framework {#agent-frameworks}

已经用 Pydantic AI、LangGraph、OpenAI Agents SDK、Google ADK、Vercel AI SDK、Mastra 或 Claude Agent SDK 等 agent framework 写好的 Agent，不需要重写就能运行在同一个 session Flow 上。参见 [Agent Framework](/agent-frameworks)。在生产环境中运行 agent session，参见 [Durable Agents](/agent-frameworks/deploy-agents)。

Step、Attribute、Channel、RPC 与 event 都与其他 Dex Agents session 相同：

```text
StartAgentSession -> AwaitUserMessage -> RunModel
AwaitUserMessage -> steer or cancel_turn -> ApplyTurnControl
RunModel -> final answer -> AwaitUserMessage
RunModel -> failed after three attempts -> RecordTurnFailure -> AwaitUserMessage
RunModel -> CompactContext -> RunModel
RunModel -> tool calls -> AwaitToolApproval -> CallTool or CallSingleAttemptTool
                          CallTool or CallSingleAttemptTool
                          AwaitQuestionAnswer      for ask_user
                          AwaitTimer               for durable_wait
                          ResumeTurn -> RunModel, or ApplyTurnControl when steered
ApplyTurnControl -> RunModel with the steered messages, else AwaitUserMessage
```

这里是简化视图。[Dex Agents README](https://github.com/superdurable/dex/tree/main/agents/python/core) 列出了每个 Step 及其重试与 failure route。

允许的 model、system prompt、context window 与 MCP server 都是 Worker 配置，由所有 session 共享。每个 session 在启动时从允许的 model 中选择一个。它的 session settings 只保存 model 名称，由 Worker 把名称映射到 model client，因此 credential 和 server command 永远不会来自 browser 或 Flow input。修改后的 prompt 或 model client 会在每个 session 的下一次模型调用时生效，包括正在等待的 turn，因为 Dex 不会重放 Flow。

## Durable context

Session 会把每条 user message、模型输出 item 与 tool result 分别保存为一条 message。最新的 message 是 **AgentMessages** AttributeMap instance，较早的 message 会移入不可变的 **AgentMessageChunks** instance。模型输出 item 会按 provider 返回的原样保存，包括加密的 reasoning item 与 thinking signature，并原样重放。

当模型输入接近配置的 context window 时，**CompactContext** Step 会在下一次模型调用前摘要较早的 message。之后模型收到 summary 与最近的 message。Compaction 不会把 tool call 与它的 result 分开。保留策略之后可以删除较早的已摘要 message，因此长 session 的 state 保持有界。触发阈值、保留上限以及如何保留完整对话，参见 [Compaction 与存储上限](/agent-frameworks/deploy-agents#compaction)。

## 排队消息与 Steer {#queued-messages-and-steer}

Turn 运行期间发送的 message 会在 durable **QueuedUserMessages** queue 中等待。Message 处于 pending 时，UI 会显示 **Steer** 与 **Delete** 控件。

**Steer** 会在 turn 的下一个 safe Step boundary 应用 message。它不会停止已经开始的模型调用或 tool call。尚未开始的 tool call，以及仍在等待的 approval、question 与 durable wait，会记录结构化的 cancellation result。随后 turn 结束，新的 turn 以所有 steered message 开始。**Stop** 调用 **cancel_turn**，以同样方式结束 turn，但不会开始新的 turn。

## 提问与 durable wait {#questions-and-durable-waits}

内置 **ask_user** tool 会向用户提问，并在 **AwaitQuestionAnswer** 中等待。UI 会用选择按钮或文本框显示问题，答案会在同一个 turn 中成为该 tool 的 result。

内置 **durable_wait** tool 会在 **AwaitTimer** 中等待一个 [Timer](/concepts/primitives/timer)。等待期间不占用模型调用或 Worker，并且可以跨 Worker 与 engine 重启。Steer 或 **Stop** 会中断等待，queued message 不会。

## Durable plan {#durable-plans}

为一条 message 开启 **Plan mode**，即可让 Agent 制定计划。Planning turn 只能调用内置 **write_todos** tool，它会替换 **AgentPlan** Attribute 并增加 revision。UI 会展示 draft，**Execute plan** 会用审阅过的 revision 调用 **execute_plan**。过期的 revision 会被拒绝。如果 plan 在仍有未完成 task 时停止，它会保持 active，并可以继续执行。Plan 处于 active 时，其他 turn 可以调用所有 tool；只有 draft plan 会把 turn 限制为只能调用 **write_todos**。

## MCP tool 与审批 {#mcp-tools-and-approvals}

Worker 从本地配置加载受信任的 stdio 或 Streamable HTTP MCP server。Agent 把 Dex Agents 的 **McpToolSource** 作为 tool source，因此模型能看到每个 server 的 tool。Worker 会拒绝它不认识的配置 key，包括这个 example 早期版本中按 tool 设置的配置。每次 MCP 调用都在自己的 tool Step 中运行。无法列出 tool 的 server 会在这次模型调用中被略过，并在下一次调用时重试，因此所有 server 都不可用时，Agent 仍会继续回答。

Tool 的 effect 决定它如何运行。当 server 的 annotation 受信任时，read-only tool 会立即运行，并在崩溃后重试。其他 tool 会在 **AwaitToolApproval** 中等待用户批准，然后最多运行一次。被崩溃打断的写操作会记录为结果未知，并且不会重复执行。每次 MCP 调用都带有 idempotency key，server 可以据此丢弃重复请求。

开启 **resource_and_prompt_tools_enabled** 后，tool source 还会提供三个 read tool，用于列出并读取 server 的 resource 与 prompt。

## 实时 event {#live-events}

文本、reasoning summary、tool activity、approval 与 plan 更新会出现在 session 的 **AgentEvents** [Stream](/concepts/primitives/stream) 上。Python example 使用库提供的 browser stream helper，把它以 Server-Sent Events 的形式提供给浏览器。TypeScript example 把它作为供 **useChat** 使用的 AI SDK UI message stream：一个 route 发送用户消息或 tool 审批，并把这一轮的内容流式写入浏览器中的 chat。

## Session 访问 {#session-access}

Session ID 不是秘密：它会出现在页面 URL 中。因此，每个指定 session 的 route 在调用 Dex 之前，都会先检查该 session 的 token。**POST /sessions** 会检查所请求的 model 是否在 Worker 允许的 model 之中，选择新的 session ID，并返回它的 token。Token 是用 **DEX_AGENT_SESSION_KEY** 对 session ID 计算的 HMAC-SHA256，因此 example 不存储任何 token，使用同一个 key 的每个进程都接受它。如果请求缺少 **X-Agent-Session-Token** header，或 header 不匹配，route 返回 403。

    def authorize_session(session_id: str) -> str:
        # Every route that names a session checks its token before any Dex call.
        expected = sign_session_id(app_state.config.agent_session_key, session_id)
        if not hmac.compare_digest(request.headers.get(SESSION_TOKEN_HEADER, ""), expected):
            raise Forbidden("this browser has no token for the AI Agent session")
        return session_id

    @blueprint.post("/sessions")
    async def start_session() -> Response:
        body = await request.get_json(silent=True)
        if not isinstance(body, dict):
            raise BadRequest("the request body must be a JSON object")
        model = body.get("model", app_state.config.agent_models[0])
        if model not in app_state.config.agent_models:
            raise BadRequest("model must be one of the models in /settings")
        # The server picks the session ID, so a caller cannot claim an existing session.
        session_id = f"ai-agent-{uuid.uuid4()}"
        # Settings carry only the model name; the Worker resolves it, and keys stay on the Worker.
        await sessions().start_session(session_id, session_settings={"model": model})
        session_token = sign_session_id(app_state.config.agent_session_key, session_id)
        return jsonify(session_id=session_id, session_token=session_token)

两个页面都把每个 token 按 session ID 保存在 local storage 中，页面 URL 中只放 session ID，因此复制的 URL 不会授予访问权限。两个页面都在每个请求中发送这个 header。Python 页面用 **fetch** 读取 event stream，而不是 **EventSource**，因为 EventSource 无法发送 header。TypeScript 页面把这个 header 交给 **useChat** transport，用于它的请求和重新连接。AI Agent 的 route 不发送 CORS header，因此其他 origin 的页面无法调用它们。

如果没有设置 **DEX_AGENT_SESSION_KEY**，进程会在启动时选择一个随机 key，重启之后，之前启动的 session 就无法再访问。真实的应用会用自己的登录替换这个 token，并检查用户是否可以使用该 session。

## 运行 example {#run-the-example}

Flow 与 HTTP route 位于 [examples/python/dex_examples/products/ai-agent](https://github.com/superdurable/dex/tree/main/examples/python/dex_examples/products/ai-agent)。React UI、MCP 配置示例与运行说明位于 [examples/python/ai-agent](https://github.com/superdurable/dex/tree/main/examples/python/ai-agent)。

第一页会显示 Worker 的 model、prompt、context window 与 MCP tool。启动表单从 Worker 允许的 model 中为 session 选择 model。要使用真实模型，把 **DEX_AGENT_MODEL** 设为 LiteLLM model 名称，在 **DEX_AGENT_MODELS** 中列出更多 model，把它们的 credential 加到 **examples/.env**，然后重启 Worker。默认的本地 demo model 不需要 credential，并支持 **/ask**、**/choose**、**/wait** 与 **/tool** 等斜杠命令，因此无需 key 就能体验所有功能。

TypeScript example 的 Flow、route 与 React UI 位于 [examples/typescript/src/products/ai-agent](https://github.com/superdurable/dex/tree/main/examples/typescript/src/products/ai-agent)。它读取相同的 **DEX_AGENT_MODEL**、**DEX_AGENT_MODELS**、**DEX_AGENT_SYSTEM_PROMPT**、**DEX_AGENT_CONTEXT_TOKENS** 与 **DEX_AGENT_MCP_CONFIG** 设置，以及相同的 MCP 配置文件，它的启动表单也以同样的方式为 session 选择模型。真实模型是 AI SDK model，例如 **openai/gpt-5-mini**。默认的 **mock/dex** 与 **mock/dex-mini** demo model 支持相同的斜杠命令，**/model** 会说出 session 的模型。它的 route 在调用 Dex 之前会检查每个 session 的 token。
