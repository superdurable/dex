# AI agent email

这个 Python application 会把自然语言请求转换为 email draft，durably 等待发送时间，并在 LLM call 仍在执行时，把 non-critical agent progress stream 到浏览器。

## 为什么这样设计

这个 example 把正确性与 UI 展示分开：

- [Channel](/primitives/channel) 把每条 user request 传入 durable Flow。
- [Attribute](/primitives/attribute) 保存 recipient、subject、body、send time 与 conversation ID。
- Durable [Timer](/primitives/timer) 等待指定的发送时间。
- [Stream](/primitives/stream) 低延迟地把 reasoning summary 发送到 UI。

即使 progress chunk 丢失，email draft 和发送决策也不会改变。因此这个 progress feed 很适合 best-effort Stream retention。

## 从 Agent Step streaming

Agent Step 会把每个 LLM progress chunk 直接写入 Stream。在 async handler 中，**Stream.write** 会把每条消息放入本地队列，然后直接返回，不会等待 Stream Store acknowledgement。Stream Store 写入失败不会让 Step 失败。

Step message 使用 **#StepExecutionID** 作为 source。Source 只说明消息来自哪里，不是 idempotency key。每次写入都会 append，因此 retry 可能产生重复 progress chunk。这对展示用 feed 没有影响，最终 draft 仍保存在 durable Attribute 中。

OpenAI call 请求的是可以展示给用户的 reasoning summary，而不是 private chain-of-thought。没有配置 OpenAI 时，local fallback 也会通过同一条 Stream path 发送 progress message。

## 浏览器续读

HTTP handler 通过 blocking **ReadStream** 读取一条 chunk，并把它和 resume token 一起返回。React UI 收到后立刻用这个 token 发起下一次请求。页面 reload 时使用空 token，从当前保留的头部重放；long-poll timeout 只需要开始下一次读取。

这个设计既能提供低延迟，又不会把 progress 变成 durable Flow state。过慢或断线的浏览器可能错过已经 trim 的 chunk，但仍可从 durable Attributes 读取最终 email draft。
