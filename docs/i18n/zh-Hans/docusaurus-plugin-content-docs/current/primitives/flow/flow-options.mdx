# Flow options

Dex 允许你自定义 Flow execution 的行为。

启动时，**ConfigOverride** 会把提供的 **FlowConfig** 字段覆盖到服务端默认值上。省略的字段保留其服务端默认值。

- **StartFlowOptions** 在客户端启动 Flow（或 SubFlow）时生效，启动后不可变。
  - 它们控制 timeout、ID reuse、cron schedule、初始 Attribute、request 幂等，以及该次 execution 的可选 config override。
- **FlowConfig** 提供运行时行为，启动后可变。
  - 包括 Step durability 默认值、Worker 路由、active-Step 搜索索引、continue-as-new 阈值与 Attribute Store projection target。

通过 [Client APIs](/primitives/client-apis) 启动 Flow，并在 SDK 提供 **UpdateFlowConfig** 时更新运行中 execution 的 config。

## StartFlowOptions {#start-flow-options}

| 字段 | 作用 |
|------|------|
| **Timeout** | durable 的 soft Flow timeout。省略或设为零可禁用。 |
| **TimeoutPolicy** | 正数 timeout 到期时的行为。 |
| **IDReusePolicy** | 新启动能否使用已有 Flow ID。 |
| **RequestID** | 重试同一次启动请求的幂等键。省略时 SDK 会生成 UUID。 |
| **AlreadyStartedOptions** | 幂等重试遇到已启动的 Flow 时的处理方式。 |
| **CronSchedule** | 由 backend 支持、用于周期性启动的 cron 表达式。 |
| **RetryPolicy** | 单次 Flow execution 失败后的重试策略。 |
| **StartDelay** | start Step 变为可执行前的延迟。 |
| **Attributes** | 初始 Attribute 与 Attribute-map 值。 |
| **FlowConfig** | 每次 execution 的 Flow 配置，通过 **ConfigOverride** 提供。 |

		},

### Timeout 与 TimeoutPolicy {#timeout-and-timeout-policy}

**Timeout** 是整个 Flow 的 durable timer。只有正数 timeout 才能指定 policy。**FAIL** 会以 timeout error 失败 Flow，随后可由 **RetryPolicy** 重试。**CANCEL** 会取消 Flow，不会重试。**HANDLER** 会调用一次 Flow timeout handler。

SDK 能检查 Flow 定义时，默认 policy 是：Flow 实现 timeout handler 时使用 **HANDLER**，否则使用 **FAIL**。没有 timeout handler 时使用 **HANDLER** 无效。continue-as-new 会保留已有 timeout deadline；一次 retry 会获得新的 timeout budget。

### Flow ID、RequestID 与 AlreadyStartedOptions {#flow-id-request-id-and-already-started}

**IDReusePolicy** 回答业务生命周期问题：新的启动是否可以使用这个 Flow ID？**RequestID** 回答传输问题：这次调用是否是同一启动请求的重试？

| ID reuse policy | 结果 |
|-----------------|------|
| **IDReuseDefault** | 使用服务端 policy。StartFlow 的默认值允许在没有 active run 时复用。 |
| **IDReuseAllowIfPreviousFailed** | 仅在上次 run 失败后复用。 |
| **IDReuseAllowIfNotRunning** | 任意 closed run 后都可复用，但不能在 active run 期间复用。 |
| **IDReuseDisallow** | 拒绝 Flow ID 的所有复用。 |
| **IDReuseTerminateIfRunning** | 启动 replacement 前终止 active run。 |

调用方在丢失 StartFlow response 后可能重试时，应使用稳定的 **RequestID**。再次发送相同的 Flow ID、start input、options 与 RequestID。启用 **AlreadyStartedOptions.IgnoreError** 后，Dex 只会在已有 Flow 使用相同 RequestID 启动时返回其 Run ID。不同 RequestID 仍是 already-started conflict；**AlreadyStartedOptions** 不会 attach 到无关的 Flow。

### RetryPolicy 与 CronSchedule {#retry-policy-and-cron-schedule}

**RetryPolicy** 控制一次 Flow execution 失败后的重试。**MaximumAttempts** 包含首次 execution。**InitialInterval**、**BackoffCoefficient** 与 **MaximumInterval** 定义指数退避。使用 **FAIL** 的 timeout 是可使用该策略的一次 failure；使用 **CANCEL** 的 timeout 不会重试。

**CronSchedule** 请求已配置的 backend 启动周期性 execution。它与 Flow retry 独立：retry 用于恢复失败的 execution，cron 用于创建未来计划执行。包括 overlap 与漏掉运行在内的 backend 调度行为由 backend 定义。生产使用前请阅读 [cron schedule pattern](/design-patterns/cron)。

### StartDelay {#start-delay}

**StartDelay** 会立即接受 Flow start，并推迟 start Step 何时变为可执行。适合一次性延迟启动，例如新订单创建后五分钟再处理。它不会创建周期性 schedule；请使用 **CronSchedule** 实现周期性运行。

### Attributes {#attributes}

**Attributes** 在 start Step 运行前初始化 durable state。每个初始值必须对应 Flow persistence schema 中已声明的 Attribute 或 Attribute map。Attribute-map 值还必须提供 instance key。Dex 会拒绝未声明的名称、同一 physical key 的重复值，以及 map、index 或同步设置与已注册 Attribute 不一致的定义。

请通过 SDK 的 **InitialAttribute** 与 Attribute-map helper 创建初始值，而不是手动编码。start Step 可按常规方式读取已初始化的值。

## FlowConfig {#flow-config}

在 **StartFlowOptions** 中使用 **ConfigOverride** 定制一个 Flow 的初始有效配置。其字段会覆盖 deployment 的默认 **FlowConfig**，并非整体替换该配置。

| 字段 | 行为 |
|------|------|
| **ActiveStepSearchMode** | 索引所有 active Step、仅索引已运行 **WaitFor** 的 Step，或不索引 active Step。默认只索引带 **WaitFor** 的 Step。 |
| **ContinueAsNewThreshold** | Dex 自动 continue-as-new 前追踪的事件数。零会禁用自动 continue-as-new。 |
| **ContinueAsNewPageSizeBytes** | continue-as-new 期间传输状态的页大小。零使用 1 MiB。 |
| **StepDurability** | Step 写入的默认 durability。Step 级别 override 优先；恢复路径除非显式覆盖，否则使用 synchronous durability。 |
| **WorkerTarget** | 后续 Step 与 RPC 调用的 WorkerService endpoint。可用它将未来工作移到新 Worker。 |
| **AttributeStoreName** | 为 opt-in 异步投影的 Attribute 选择服务端已配置的 Attribute Store。显式空值会禁用未来投影。 |

### 用 Client 更新 FlowConfig {#update-flow-config-with-a-client}

Flow 活跃时可调用 **UpdateFlowConfig**。这是 partial update：只发送要修改的字段。更新影响之后的 Flow decision，不会撤回 Dex 已派发的工作。

## SubFlow options {#subflow-options}

[SubFlow](/primitives/subflow) condition 通过 **SubFlowOptions** 使用 timeout、retry、初始 Attribute 与 **FlowConfig** override。SubFlow 还有其生成 Flow ID 的 reuse policy。Dex 负责 SubFlow start ID，调用方无法覆盖。

## Operational APIs {#operational-apis}

启动和配置 Flow 只是生命周期的一部分。[Client APIs](/primitives/client-apis) 还涵盖 search、RPC 与 Channel interaction、wait、stop、timer skip、time travel 与 continue-as-new。
