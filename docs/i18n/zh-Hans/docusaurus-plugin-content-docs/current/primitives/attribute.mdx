# Attribute

一个 **Attribute** 让你可以在一个 Flow execution 内存储数据，作为 persistence storage。

这尤其适合在 Flow execution 期间存储中间数据，省去设置和管理 database dependency 的工作。

Dex Attribute 不是用来替代 database 的。一个明显的限制是，Attribute 只在它所属的 Flow execution 生命周期内存在。Dex 会在 Flow 关闭后的 configurable retention period 结束后删除 Flow execution history 时，一并删除 Attribute。

不过，Dex 允许你将 Attribute values 同步到 application database，作为 permanent storage。这也让你可以构建更强大的 database indexes 来查询 Attribute。

## 使用 Attribute {#define-an-attribute}

将 Attribute 定义为 Flow persistence schema 的一部分。

之后就可以在 Step 或 RPC implementation 内读写 Attribute。Attribute 必须先通过 PersistenceSchema 声明，否则 Worker 会拒绝这些操作。

更新 Attribute 时，将它设为 null 会删除它。

    fn default() -> Self {

        let email = Attribute::new("primitive-attribute-email").sync_to_attribute_store();
        let progress = AttributeMap::new("primitive-attribute-progress");
        Self {
            start: AttributeStep {
                status: status.clone(),
                progress: progress.clone(),

            progress,

    type StartInput = String;

    fn steps(&self) -> StepList<'_, Self::StartInput> {
        StepList::start(&self.start)

        PersistenceSchema::new()
            .attribute(&self.status)
            .attribute(&self.email)
            .attribute_map(&self.progress)

    status: Attribute<String>,
    progress: AttributeMap<String>,

impl Step for AttributeStep {
    type Input = String;

        self.status.set(context, "processing".to_owned())?;

        self.status.set(context, "completed".to_owned())?;
        Ok(StepDecision::graceful_complete(input))
    }

## AttributeMap {#attributemap}

**AttributeMap** 是一组 key 在运行时才确定的 Attribute。它适合 Flow 需要一组不断变化的小值的场景，例如订单中每笔 payment 或每个 item 的 status。

**AttributeMap** 的原因是为了高效存储一组数据。每个 Attribute 在 Dex Server 中都作为一个 blob 存储。把所有数据放进一个 Attribute，意味着每次更新都会重写整个 blob。AttributeMap 让 Dex Server 将每个 instance 作为独立 blob 存储，从而获得更高效率。

## Initial Attribute values {#initial-attribute-values}

**StartFlowOptions** 可以在创建 Flow 时设置初始 Attribute。初始值与创建 Flow 是一个操作，所以第一个 Step 立刻能看到它们。见 [Flow options](/primitives/flow/flow-options#attributes)。

Client 使用同一个已注册的 Attribute definition 调用 **GetAttributes** 和 **SetAttributes**。Client 也可以用 **WaitForAttributeEqual**，等待一个 singleton Attribute 或某个 AttributeMap instance 变成指定 scalar value。这些都是通过 Dex Server 的 Flow operation，不会直接读写 application database。见 [Client APIs](/primitives/client-apis)。

## Indexed Attribute {#indexed-attributes}

没有 **AttributeIndex** 的 Attribute 不能被搜索。Worker 启动时 Dex 会把 index 注册到配置好的 backend；之后 Attribute 每次变化，Dex 都会更新 index。你可以在 **SearchFlows** query 中使用这个 field。

根据准备写入的值选择 index type。index type 是 Attribute contract 的一部分。index 用来找 Flow；它不是第二份 source of truth，也不能替代 **GetAttributes**。

| Index type | 值 |
| --- | --- |
| **KEYWORD** | 一个精确字符串。 |
| **FULL_TEXT** | 用于 tokenized search 的文本。 |
| **KEYWORD_ARRAY** | 一组精确字符串。 |
| **INT**、**DOUBLE**、**BOOL** | 对应的 scalar value。 |
| **DATETIME** | 一个日期与时间值。 |

singleton Attribute 默认用 Attribute name 作为 index field，除非设置显式 index key。indexed **AttributeMap** 必须设置显式 index key，因为所有动态 instance 共用一个 search field。

## Attribute Store projection {#attribute-store-projection}

有些 application 需要把同一份 Flow state 放到已有的 MySQL 或 PostgreSQL read model。Dex 可以把选中的 Attribute write 异步 projection 到 Server 配置的 **Attribute Store**。

Server 配置 Store 和 destination table。Flow 通过 **FlowConfig** 选择它，每个 Attribute 或 AttributeMap definition 显式 opt in **SyncToAttributeStore** 或对应 SDK API。之后，初始值与 Step、RPC、Client 的写入都会被 projection。Flow Attribute 仍然是 authoritative：projection failure 不会 rollback Flow write，Dex 也不会 backfill 漏掉的写入。

SQL row 是 latest-state projection。删除 synced Attribute 时，如果 column 允许，Dex 会 projection SQL **NULL**。修改 Attribute Store target 只影响之后的 write；已经排队的 mutation 保留 Dex 接收它时选择的 target。

这适合 read model、reporting table，或者每个业务实体由一个长运行 Flow 编排的场景。如果 external update 必须和另一次 database write 处于同一个 business transaction，它就不合适。完整 pattern 见 [Entity Store](/design-patterns/entity-store)。

## Locking {#locking}

一次 Attribute write 会和 Step 或 RPC result 一起 durable。但这不代表 read-modify-write sequence 就安全。在执行这个 sequence 的 Step method 或 RPC 上声明 Attribute lock。Dex 会在调用 handler 前一起获取请求的 lock，并在这次 invocation 结束时释放。

**WaitFor** 与 **Execute** 有各自的 lock option。lock 应加在实际读取并修改值的 method 上。Client 先 **GetAttributes** 再 **SetAttributes** 不是 locked read-modify-write；需要 serialization 时，把这个 operation 放进 RPC。

保持 locked set 尽量小。锁无关的 Attribute 会降低 concurrency；漏掉冲突的 Attribute 会留下 race。RPC Attribute locking 使用 Temporal synchronous Update，在 Cadence 中不可用。Step Attribute lock 正常走 Step execution。
