# Attribute 高级用法

这页讲 Attribute 会影响 Flow 运维方式的部分：search index、把状态 projection 到 application database，以及并发修改时的 serializing。

## Indexed Attribute {#indexed-attributes}

没有 **AttributeIndex** 的 Attribute 不能被搜索。Worker 启动时 Dex 会把 index 注册到配置好的 backend；之后 Attribute 每次变化，Dex 都会更新 index。你可以在 **SearchFlows** query 中使用这个 field。

同一份 definition 也可以 opt into Attribute Store synchronization。启动 Flow 或更新 Flow configuration 时，用 **FlowConfig** 选择 Server-configured Store。

根据准备写入的值选择 index type：

| Index type | 值 |
| --- | --- |
| **KEYWORD** | 一个精确字符串。 |
| **FULL_TEXT** | 用于 tokenized search 的文本。 |
| **KEYWORD_ARRAY** | 一组精确字符串。 |
| **INT**、**DOUBLE**、**BOOL** | 对应的 scalar value。 |
| **DATETIME** | 一个日期与时间值。 |

index type 是 Attribute contract 的一部分，之后不要写入不同形状的值。singleton Attribute 默认用 Attribute name 作为 index field，除非设置显式 index key。indexed **AttributeMap** 必须设置显式 index key，因为所有动态 instance 共用一个 search field。

index 用来找 Flow。它不是第二份 source of truth；需要当前 durable value 时，还是用 **GetAttributes**。

## Attribute Store projection {#attribute-store-projection}

有些 application 需要把同一份 Flow state 放到已有的 MySQL 或 PostgreSQL read model。Dex 可以把选中的 Attribute write 异步 projection 到 Server 配置的 **Attribute Store**。

需要三部分：

1. Server 配置一个命名的 Attribute Store 和 destination table。
2. Flow 通过 **FlowConfig** 选择这个 name。新 Flow 在 **StartFlowOptions** 设置；active Flow 用 **UpdateFlowConfig** 设置。
3. 每个 Attribute 或 AttributeMap definition 显式 opt in **SyncToAttributeStore** 或对应 SDK API。

三者都具备时，初始 Attribute value、Step、RPC 与 Client 的写入都会被 projection。Flow Attribute 仍然是 authoritative。SQL row 是 latest-state projection：写入是异步的，projection 失败不会 rollback Flow write，Dex 也不会 backfill 漏掉的写入。删除 synced Attribute 时，如果 column 允许，Dex 会 projection SQL **NULL**。

修改 Attribute Store target 只影响之后的 write。已经排队的 mutation 保留 Dex 接收它时选择的 target。

这适合 read model、reporting table，或者每个业务实体由一个长运行 Flow 编排的场景。如果 external update 必须和另一次 database write 处于同一个 business transaction，它就不合适。

完整 pattern 见 [Entity Store](/design-patterns/entity-store)；table requirement、type、retry 与 shutdown behavior 见 [Custom Attribute Store operations](/production/attribute-store)。

## Locking {#locking}

一次 Attribute write 会和 Step 或 RPC result 一起 durable。但这不代表 read-modify-write sequence 就安全。两个并发 handler 可能读到同一个旧值，然后写出不同结果。

在执行这个 sequence 的 Step method 或 RPC 上声明 Attribute lock。Dex 会在调用 handler 前一起获取请求的 lock，并在这次 handler invocation 结束时释放。singleton Attribute 有一个 lock；AttributeMap 的 lock 只针对一个 map instance。

**WaitFor** 与 **Execute** 有各自的 lock option。**WaitFor** 持有的 lock 会在 Flow 开始 waiting 前释放，不会一直持有到之后 **Execute** 运行。lock 应加在实际读取并修改值的 method 上。

locked set 要小。lock 无关的 Attribute 会降低并发；漏掉冲突的 Attribute 则仍会有 race。Client 先 **GetAttributes** 再 **SetAttributes** 不是 locked read-modify-write；需要 serializing 时，把这个 operation 放进 RPC。
