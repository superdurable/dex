# RPC

**RPC**（Remote Procedure Call）让 Flow 外的代码与正在运行的 Flow execution 交互。web handler、另一个服务或运维工具通过 [Client](/primitives/client) 调用它。

**Client** 发起 RPC。**Dex Server** 将它发送给 **Worker**。**Worker** 执行后，将结果返回给 **Dex Server** 持久化。**Dex Server** 再将输出返回给 **Client**。

## 什么时候用 RPC

Flow 外的事情要改变 Flow，或者要问 Flow 一个问题时，用 RPC。例如一次审批、用户按下 Stop，或者请求查看 Flow 状态。

RPC handler 可以做四件事：

- 读写 [Attribute](/primitives/attribute)；
- 向 [Channel](/primitives/channel) 发布消息；
- 启动新的 [Step](/primitives/step)；
- 取消正在运行的 Step。

Client 不用 RPC 也能读取已存储的 Attribute。只有读取需要 Flow 逻辑时，例如校验、授权或派生视图，才用 RPC 来读。

## 保证

每次 RPC 调用都是一个 commit 边界。Dex Server 暂存 RPC 中的 Attribute 写入和 Channel 发布。只有 method 成功返回后，它才把这些变更和 RPC 结果一起 commit。RPC 失败时，这些 durable 变更都不会 commit。外部 API 调用不在这个原子边界内。

RPC 和 Step 一样在 Worker 上运行。每次 handler 调用都受 timeout 限制。

## 取消正在运行的 Step {#cancel-running-steps}

RPC 的结果可以按 Step type 取消所在 Flow 中的活跃 Step。外部请求让进行中的工作失去意义时用它，例如报告或模型调用运行时用户按下 Stop。Dex 在 commit 这个 RPC 时执行取消。Step 代码必须检查取消并停下。示例、与已完成 Step 的竞争，以及各 SDK 如何传递取消，见 [Cancel running Steps](/reference/server/runtime-data#cancel-running-steps)。

## Lock 和 transactional RPC {#transactional-reads-and-writes}

并发的 Step 和 RPC 可能修改同一份状态。RPC 可以获取 [Attribute lock](/primitives/attribute#locking)，与它们依次执行。RPC 拿不到 lock 会立即失败，由调用方重试。

**transactional** RPC 在 Dex commit 它时多做一次检查。如果它删除的 Channel 消息已经不在队列中，RPC 失败，什么也不 commit。非 transactional RPC 会跳过缺失的删除，commit 其余变更。持有 lock 的 RPC 总是 transactional。见 [Transactional RPCs](/reference/server/runtime-data#transactional-reads-and-writes)。

## 加载集合

RPC 会收到普通 Attribute 和 Channel 大小。只有声明之后，它才加载 AttributeMap 条目和待处理的 Channel 消息。这样不用这些大集合的 RPC 就不会带上它们。见 [Selective state loading](/reference/server/runtime-data#load-collection-state)。
