# Primitives

Dex 提供一组精简的 Primitive。你把它们组合成 Flow，再由几个 Component 运行这些 Flow。本页说明这些部分如何配合。每个 Primitive 都有自己的页面。

## Primitive 一览

| Primitive | 是什么 | 用来做什么 |
| --- | --- | --- |
| [Flow](/primitives/flow) | 带业务 ID 的 durable program。它拥有自己的 Step、状态和消息。 | 建模一个业务流程或实体。 |
| [Step](/primitives/step) | Flow 中的一个工作单元。它先等待，再执行，然后决定接下来运行什么。 | 完成工作，推进流程。 |
| [Attribute](/primitives/attribute) | 属于一个 Flow 的 durable 状态。 | 在 Step 之间保存数据，从外部读取，并按它搜索。 |
| [RPC](/primitives/rpc) | 对 Flow 的同步调用。 | 从应用发送命令、读取视图。 |
| [Channel](/primitives/channel) | Flow 中的 durable 消息队列。 | 投递 Step 等待的消息。 |
| [Stream](/primitives/stream) | 读取方可以续读的 best-effort feed。 | 向 UI 推送实时进度。 |
| [Timer](/primitives/timer) | 等到某个时间的 durable 等待。 | 设置截止时间、提醒和定时任务。 |
| [SubFlow](/primitives/subflow) | 由另一个 Flow 作为子 Flow 启动的 Flow。 | 把大量或并行的工作拆成子 Flow。 |
| [Connector](/primitives/connector) | 与外部 provider 的 typed integration。 | 在 Step 中调用第三方服务。 |
| [Client](/primitives/client) | 应用在 Worker 之外使用的 API。 | 启动、调用、读取、等待和运维 Flow。 |

## 它们如何配合

```text
 Your application                      One Flow (one Flow ID)
 ┌────────────┐   StartFlow, RPC      ┌──────────────────────────────────┐
 │   Client   │ ────────────────────▶ │  Step ──▶ Step ──▶ Step ...      │
 │            │   GetAttributes, wait │   waits on Channel, Timer,       │
 │            │ ◀──────────────────── │   SubFlow; calls Connectors      │
 │            │   Stream (live)       │                                  │
 │            │ ◀──────────────────── │  Attributes  Channels  Streams   │
 └────────────┘                       └──────────────────────────────────┘
```

**Flow** 是容器。每个 Flow ID（例如一个订单号）对应一个 Flow execution。

**Step** 推进 Flow。Step 可以等待 Channel 消息、Timer 或 SubFlow，然后执行自己的工作，例如通过 Connector 调用外部服务。最后它返回一个 decision，指定接下来的 Step，或者关闭 Flow。Step 失败时，Dex 会重试。

**Attribute** 和 **Channel** 是 Flow 的 durable 状态。Step 和 RPC 读写它们。每次等待、每次执行和每个 RPC，Dex 都会与它的状态变更一起提交。

应用通过 **Client** 启动 Flow、调用 RPC、读取 Attribute 和等待变化。RPC 是写入运行中 Flow 的边界。**Stream** 把实时更新送回 UI。

## Component

Primitive 是编程模型。[Component](/primitives/components) 是运行它的进程：

- 你的 **application** 在 Worker 中运行 Flow 代码，并通过 Client 调用 Dex。
- **server-zd** 保存 Flow 状态，并把 Step 和 RPC 交给 Worker。
- **dexcli** 在本地运行 Dex，**Dex Web** 让运维人员查看 Flow。
