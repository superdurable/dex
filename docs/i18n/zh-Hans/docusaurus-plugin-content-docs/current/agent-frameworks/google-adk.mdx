# Google ADK

Google ADK（Agent Development Kit）为 Gemini 和其他模型构建 Agent 与多 Agent 树。Dex adapter 把 ADK Agent 放进 durable session 中运行。它支持 Python。

## 何时使用 {#when-to-use-it}

Agent 已经用 Google ADK 编写时，使用它，包括 sequential、loop 和 parallel Agent。保留 Agent 树和它的 tool，由 Dex 管理 session。

## Session 如何运行 {#how-a-session-runs}

Adapter 给 ADK App 加上一个 plugin。对每个 tool call，plugin 都会向 ADK 请求确认，因此 ADK 会在 tool 运行之前暂停。每个 **RunModel** Step 调用一次模型，并保存这个 turn 的 ADK event。

每个 tool call 在自己的 Step 中并行运行：read 或 idempotent write 用 **CallTool**，其他写操作用 **CallSingleAttemptTool**。需要审批的调用先在 **AwaitToolApproval** 中等待。Tool Step 运行 tool 一次。下一个 **RunModel** 确认暂停的调用，plugin 返回记录下来的结果，而不会再次运行 tool。

查询订单的 turn 依次运行 **RunModel**、**CallTool**、**ResumeTurn** 和 **RunModel**。

```python
def build_google_adk_order_support_flow(
    order_desk: OrderDesk, model: str | BaseLlm, slack_connection: slack.Connection | None
) -> AgentSessionFlow:
    """Builds the session Flow; ``model`` is a Gemini model name, such as "gemini-2.5-flash"."""

    # The tools are closures, so they call the OrderDesk passed in here.
    def look_up_order(order_id: str) -> str:
        """Look up one order by its order ID and return its items and status."""
        return order_desk.describe_order(order_id)

    def cancel_order(order_id: str, reason: str) -> str:
        """Cancel one order that has not shipped yet."""
        return order_desk.cancel_order(order_id, reason)

    agent = LlmAgent(
        name="order_support",
        model=model,
        instruction=ORDER_SUPPORT_INSTRUCTIONS,
        tools=[look_up_order, cancel_order],
    )
    return adk_agent_session_flow(
        agent,
        flow_type=GOOGLE_ADK_ORDER_SUPPORT_FLOW_TYPE,
        tool_sources=build_slack_tool_sources(slack_connection),
        tool_policies={
            "look_up_order": ToolPolicy(ToolEffect.READ),
            "cancel_order": ToolPolicy(ToolEffect.NON_IDEMPOTENT_WRITE),
        },
    )
```

```python
    @blueprint.post("/sessions")
    async def start_session() -> Response:
        # The server picks the session ID, so a caller cannot claim an existing session.
        session_id = f"{harness_name}-order-support-{uuid.uuid4()}"
        await sessions.start_session(session_id)
        session_token = sign_session_id(app_state.config.session_key, session_id)
        return jsonify(session_id=session_id, session_token=session_token)

    @blueprint.post("/messages")
    async def send_user_message() -> Response:
        body, session_id = await session_request()
        accepted = await sessions.send_user_message(session_id, _required_string(body, "text"))
        return jsonify(accepted=accepted)

    @blueprint.post("/interrupts/resolve")
    async def resolve_interrupt() -> Response:
        body, session_id = await session_request()
        interrupt_id = _required_string(body, "interrupt_id")
        if not isinstance(approved := body.get("approved"), bool):
            raise BadRequest("approved must be a boolean")
        rejection_message = body.get("rejection_message")
        if rejection_message is not None and not isinstance(rejection_message, str):
            raise BadRequest("rejection_message must be a string")
        accepted = await sessions.resolve_interrupt(
            session_id, interrupt_id, approved=approved, rejection_message=rejection_message
        )
        return jsonify(accepted=accepted)

    @blueprint.get("/snapshot")
    async def get_agent_snapshot() -> Response:
        session_id = request.args.get("session_id", "")
        if not session_id:
            raise BadRequest("session_id is required")
        authorize_session(session_id)
        try:
            snapshot = await read_agent_event_stream_snapshot(
                app_state.client, example.session_flow, session_id
            )
        except FlowNotActiveOrNotFoundError as error:
            raise NotFound("the agent session is missing or no longer retained") from error
        return jsonify(snapshot.to_json())
```

### 调用 session {#call-the-session}

启动一个 session，让 Agent 取消订单 1002，然后批准这次调用：

<SdkTabs
  examples={{
    python: 'examples/python/agent-harnesses/README.md',
  }}>
<SdkSnippet lang="python">

```bash
base=http://127.0.0.1:8081/products/agent-harnesses/google-adk
session=$(curl -s -X POST "$base/sessions" -H 'Content-Type: application/json' -d '{}')
id=$(echo "$session" | jq -r .session_id)
token=$(echo "$session" | jq -r .session_token)
curl -s -X POST "$base/messages" -H 'Content-Type: application/json' \
  -H "X-Agent-Session-Token: $token" -d "{\"session_id\": \"$id\", \"text\": \"Cancel order 1002\"}"
until interrupt=$(curl -s "$base/snapshot?session_id=$id" -H "X-Agent-Session-Token: $token" \
  | jq -re '.snapshot.pending_interrupts[0].interrupt_id'); do sleep 1; done
curl -s -X POST "$base/interrupts/resolve" -H 'Content-Type: application/json' \
  -H "X-Agent-Session-Token: $token" \
  -d "{\"session_id\": \"$id\", \"interrupt_id\": \"$interrupt\", \"approved\": true}"
```

</SdkSnippet>
</SdkTabs>

循环会反复读取 snapshot，直到 Agent 请求运行 **cancel_order**。这次调用先等待审批，批准后只运行一次。再读一次 snapshot 即可看到 Agent 的回答。

### 调用如何运行 {#connector-tool-calls}

每次调用 **slack_post_thread_reply** 都要先经人批准，然后在自己的 **CallSingleAttemptTool** Step 中只运行一次。原因见 [Slack Connector tool](/agent-frameworks#slack-connector-tool)。

Adapter 给 agent 树中每个 **LlmAgent** 的 tool 加上一个 **SourceToolset**。它只在 runner 的 **RunModel** 内提供 Connector tool。在其他地方，agent 照常运行。Agent 的 **before_tool_callback** 链仍然最先看到每次调用。

### 配置 connection {#configure-connector-connection}

Worker 从哪里找到 connection **support-slack**、Slack app 需要什么，见 [Connection](/agent-frameworks/deploy-agents#connector-tools-connection)。

试用时，先设置 **DEX_CONNECTOR_CONFIG_FILE** 再启动 example。然后让 agent 在 Slack thread 中回复，并给出 channel ID 和 thread timestamp：

```text
Reply in Slack thread C0123456789 1710000000.000100: Order 1002 ships on Thursday.
```

这次发帖和 **cancel_order** 一样，会先等待审批。

## 限制 {#limits}

- App 的根必须是 **BaseAgent**。不支持以 ADK **Workflow** 为根。
- Tool 在 ADK run 之外运行，使用全新的 **ToolContext**。它对 state 和 artifact 的修改会被丢弃。请通过参数传入它需要的内容。
- 在自己的 Step 中请求确认或 credential 的 tool 会失败。
- 不调用 tool 就继续执行的 Agent，会在同一个 **RunModel** 中调用模型。
- **before_tool_callback** 在请求该调用的 **RunModel** 中运行，这个 Step 重试时会再次运行。
- 除 **BuiltInCodeExecutor** 外的 code executor 会被拒绝。请改为从 tool 中运行这类代码。
- **app:** 与 **user:** state key 只存在于当前 Dex session 中，不会跨 session 共享。

Adapter README 列出了全部限制。Server 的限制参见 [Durable Agents](/agent-frameworks/deploy-agents#limits)。
