# 框架支持

Dex 可以运行用八个框架构建的 Agent，还有它自己的内置 Agent Loop。每一个都有持久化 Session、tool policy、审批、Connector 作为 tool、带 **Steer** 和 `cancel_turn` 的排队消息，以及 AgentEvents Stream 上的实时事件。

## 框架与功能 {#features-by-harness}

<a id="how-each-framework-runs-a-turn"></a>

| 框架 | 语言 | 每个 tool call 有自己的 Step | Dex 压缩 | 提问和计划 |
| --- | --- | --- | --- | --- |
| Claude Agent SDK | Python、TypeScript | 写入和 Connector 调用。读取在模型调用的 Step 里运行。 | 否。Claude Code 自己压缩 transcript。 | 否 |
| Google ADK | Python | 是 | 是 | 否 |
| LangChain 和 LangGraph | Python | 是。提供方运行的 tool 在提供方运行。 | 是 | 否 |
| Mastra | TypeScript | 是，Mastra 自己运行的 tool 除外 | 是 | 否 |
| OpenAI Agents SDK | Python、TypeScript | Function tool。Hosted tool 在提供方运行。 | 是 | 否 |
| Pi | TypeScript | 是 | 是 | 是 |
| Pydantic AI | Python | 是。提供方运行的 tool 在提供方运行。 | 是 | 否 |
| Vercel AI SDK | TypeScript | 是。提供方执行的 tool 在提供方运行。 | 是 | 否 |
| 内置 Agent Loop | Python、TypeScript | 是 | 是 | 是 |

在自己 Step 里运行的 tool call，写入只运行一次，读取可以由 Dex 重试。在模型调用的 Step 里或在提供方运行的 tool，会在那个 Step 重试时再运行一次。

## 限制 {#limits}

这些限制会影响你写 Agent 的方式。[各框架如何在 Dex 上运行](/agent-frameworks/framework-details#limits)里每个框架的标签页给出完整列表和替代做法。

| 框架 | 主要限制 |
| --- | --- |
| Claude Agent SDK | 同一个模型回复里的写入调用逐个运行。Claude Code CLI 内部的 tool，例如 **Bash** 和 **Edit**，可能再运行一次。 |
| Google ADK | App 的根必须是 `BaseAgent`。tool 对 state 和 artifact 的修改会被丢弃。 |
| LangChain 和 LangGraph | 只有消息列表会带到下一个 turn。tool 不能使用 `ToolRuntime`、`InjectedState` 或 `InjectedStore`。 |
| Mastra | Session 取代 Mastra Memory。调用 `suspend()` 的 tool 会失败。 |
| OpenAI Agents SDK | MCP server 通过 `tool_sources` 传入，而不是 `mcp_servers`。不使用服务端管理的对话状态和 SDK session。 |
| Pi | tool 必须可以并行运行。Pi 的 `beforeToolCall` 和 `afterToolCall` hook 不会运行。 |
| Pydantic AI | Output function 在模型调用的 Step 里运行。`UsageLimits` 按 Step 计算。 |
| Vercel AI SDK | 每个 tool 都需要自己的 **execute**。审批由 Dex 负责，不使用 AI SDK 的 `toolApproval`。 |
| 内置 Agent Loop | 见[内置 Agent Loop 的限制](/agent-frameworks/built-in-agent-loop#limits)。 |

[长 Session 的限制](/reference/agents/session-limits)列出适用于所有框架的 server 限制。
