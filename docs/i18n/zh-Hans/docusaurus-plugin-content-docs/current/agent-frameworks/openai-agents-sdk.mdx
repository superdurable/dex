# OpenAI Agents SDK

OpenAI Agents SDK 用 instructions、function tool 和 handoff 定义 Agent。Dex adapter 把 SDK 的 runner 放进 durable session 中运行。它支持 Python 和 TypeScript。

## 何时使用 {#when-to-use-it}

Agent 已经用 OpenAI Agents SDK 编写时，无论是否使用 handoff，都可以使用它。保留 SDK 的 Agent 定义、tool 和 guardrail，由 Dex 管理 session。

## Session 如何运行 {#how-a-session-runs}

Adapter 会把 Agent graph 复制一次，并为每个 function tool 加上闸门。因此 SDK 在每次模型调用之后立即停下，带回模型请求的 tool call。每个 **RunModel** Step 调用一次模型。

每个 function tool call 在自己的 Step 中并行运行：read 或 idempotent write 用 **CallTool**，其他写操作用 **CallSingleAttemptTool**。需要审批的调用先在 **AwaitToolApproval** 中等待。下一个 **RunModel** 恢复 SDK 的 run state，并把记录下来的结果交给它。Tool 不会再次运行。

Handoff 不是 function tool。它在 **RunModel** 内运行，因此发生 handoff 的 Step 也会调用下一个 Agent 的模型。

查询订单的 turn 依次运行 **RunModel**、**CallTool**、**ResumeTurn** 和 **RunModel**。

## Example {#the-example}

这个 example 是一个订单客服 Agent。它在一个内存中的订单系统上有两个 tool。**look_up_order** 读取订单。它的 policy 是 read，因此无需审批就会运行，失败时会重试。**cancel_order** 取消一个仍在处理中的订单。它的 policy 是 non-idempotent write，因此会先等待审批，然后最多运行一次。

Flow type 是 **OpenAIAgentsOrderSupport**（Python），**OpenAIAgentsOrderSupportAgent**（TypeScript）。完整 example 位于 [examples/python/agent-harnesses](https://github.com/superdurable/dex/tree/main/examples/python/agent-harnesses) 和 [examples/typescript/src/products/agent-harnesses](https://github.com/superdurable/dex/tree/main/examples/typescript/src/products/agent-harnesses)。

### Agent 与 tool {#agent-and-tools}

Tool 是 SDK 的 function tool。Agent 是普通的 SDK Agent。Tool policy 指定每个 tool。

```python
def build_openai_agents_order_support_flow(
    order_desk: OrderDesk, model: str | Model
) -> AgentSessionFlow:
    """Builds the session Flow; ``model`` is an OpenAI model name, such as "gpt-5.2"."""

    # The tools are closures, so they call the OrderDesk passed in here.
    @function_tool
    def look_up_order(order_id: str) -> str:
        """Look up one order by its order ID and return its items and status."""
        return order_desk.describe_order(order_id)

    @function_tool
    def cancel_order(order_id: str, reason: str) -> str:
        """Cancel one order that has not shipped yet."""
        return order_desk.cancel_order(order_id, reason)

    agent = Agent(
        name="OrderSupport",
        instructions=ORDER_SUPPORT_INSTRUCTIONS,
        model=model,
        tools=[look_up_order, cancel_order],
    )
    return openai_agents_session_flow(
        agent,
        flow_type=OPENAI_AGENTS_ORDER_SUPPORT_FLOW_TYPE,
        tool_policies={
            "look_up_order": ToolPolicy(ToolEffect.READ),
            "cancel_order": ToolPolicy(ToolEffect.NON_IDEMPOTENT_WRITE),
        },
    )
```

</SdkSnippet>

```typescript
export function createOpenAIAgentsOrderSupportFlow(orderDesk: OrderDesk, model: string | Model): AgentSessionFlow {
  const lookUpOrder = tool({
    name: "look_up_order",
    description: "Look up one order by its order ID and return its items and status.",
    parameters: z.object({ order_id: z.string() }),
    // Without errorFunction: null, tool() turns every thrown error into model-visible text.
    errorFunction: null,
    execute: ({ order_id }) => orderDesk.describeOrder(order_id),
  });
  const cancelOrder = tool({
    name: "cancel_order",
    description: "Cancel one order that has not shipped yet.",
    parameters: z.object({ order_id: z.string(), reason: z.string() }),
    errorFunction: null,
    execute: ({ order_id, reason }) => orderDesk.cancelOrder(order_id, reason),
  });
  const agent = new Agent({
    name: "OrderSupport",
    instructions: orderSupportInstructions,
    model,
    tools: [lookUpOrder, cancelOrder],
  });
  return createOpenAIAgentsSessionFlow(agent, openAIAgentsOrderSupportFlowType, {
    toolPolicies: {
      look_up_order: { effect: "read" },
      cancel_order: { effect: "non_idempotent_write" },
    },
  });
}
```

### Session route {#session-routes}

每个 harness 都提供相同的 HTTP route。每个 route 对应 session Flow 上的一次调用：启动 session、发送消息或处理审批。启动 session 会返回 session token，它是用 **DEX_AGENT_SESSION_KEY** 对 session ID 计算的 HMAC。其他每个 route 都会检查 **X-Agent-Session-Token** header 中的 token，缺少时返回 403。真实的应用会改用自己的登录。

<SdkTabs
  examples={{

    typescript: 'examples/typescript/src/products/agent-harnesses/order-support/order-support-routes.ts',
  }}>
<SdkSnippet lang="python">

```python
    @blueprint.post("/sessions")
    async def start_session() -> Response:
        # The server picks the session ID, so a caller cannot claim an existing session.
        session_id = f"{harness_name}-order-support-{uuid.uuid4()}"
        await sessions.start_session(session_id)
        session_token = sign_session_id(app_state.config.session_key, session_id)
        return jsonify(session_id=session_id, session_token=session_token)

    @blueprint.post("/messages")
    async def send_user_message() -> Response:
        body, session_id = await session_request()
        accepted = await sessions.send_user_message(session_id, _required_string(body, "text"))
        return jsonify(accepted=accepted)

    @blueprint.post("/interrupts/resolve")
    async def resolve_interrupt() -> Response:
        body, session_id = await session_request()
        interrupt_id = _required_string(body, "interrupt_id")
        if not isinstance(approved := body.get("approved"), bool):
            raise BadRequest("approved must be a boolean")
        rejection_message = body.get("rejection_message")
        if rejection_message is not None and not isinstance(rejection_message, str):
            raise BadRequest("rejection_message must be a string")
        accepted = await sessions.resolve_interrupt(
            session_id, interrupt_id, approved=approved, rejection_message=rejection_message
        )
        return jsonify(accepted=accepted)
```

Python 应用监听 **127.0.0.1:8081**。TypeScript 应用监听 **127.0.0.1:8080**。Dex Web 位于 **127.0.0.1:8802**。

没有设置 **DEX_OPENAI_AGENTS_MODEL** 时，Python Agent 使用 **mock/order-support**，这是一个不需要 key 的本地 demo model。收到 "look up order 1001" 时它调用 **look_up_order**，收到 "cancel order 1002" 时它调用 **cancel_order**。TypeScript example 没有 demo model，因此需要 **OPENAI_API_KEY**。

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| **DEX_OPENAI_AGENTS_MODEL** | Python：**mock/order-support**。TypeScript：**gpt-5-mini**。 | OpenAI 模型名称，例如 **gpt-5.2**。 |
| **OPENAI_API_KEY** | 无 | OpenAI API key，使用真实模型时需要。 |
| **DEX_AGENT_SESSION_KEY** | 随机 key | 签发 session token 的 key。 |

### 调用 session {#call-the-session}

启动一个 session，让 Agent 取消订单 1002，然后批准这次调用：

```bash
base=http://127.0.0.1:8081/products/agent-harnesses/openai-agents
session=$(curl -s -X POST "$base/sessions" -H 'Content-Type: application/json' -d '{}')
id=$(echo "$session" | jq -r .session_id)
token=$(echo "$session" | jq -r .session_token)
curl -s -X POST "$base/messages" -H 'Content-Type: application/json' \
  -H "X-Agent-Session-Token: $token" -d "{\"session_id\": \"$id\", \"text\": \"Cancel order 1002\"}"
until interrupt=$(curl -s "$base/snapshot?session_id=$id" -H "X-Agent-Session-Token: $token" \
  | jq -re '.snapshot.pending_interrupts[0].interrupt_id'); do sleep 1; done
curl -s -X POST "$base/interrupts/resolve" -H 'Content-Type: application/json' \
  -H "X-Agent-Session-Token: $token" \
  -d "{\"session_id\": \"$id\", \"interrupt_id\": \"$interrupt\", \"approved\": true}"
```

循环会反复读取 snapshot，直到 Agent 请求运行 **cancel_order**。这次调用会等待审批。它只在批准之后运行，并且只运行一次。再读一次 snapshot 即可看到 Agent 的回答。

### 在 Dex Web 中审批 {#approve-in-dex-web}

也可以不执行最后一条命令，而是在 Dex Web 中审批。打开这个 session 的 run：它的 Flow ID 就是 session ID。选择 **Agent session** tab。把 **Working as** 设为渲染时指定的 permission **order-support.operate**。然后在 **cancel_order** 卡片上选择 **Approve** 或 **Reject**。Dex Web 会替你调用 **resolve_interrupt**。生产环境的做法参见 [在 Dex Web 中显示 session](/agent-frameworks/deploy-agents#dex-web)。

## 限制 {#limits}

- 只有 function tool 拥有自己的 Step。Hosted tool，例如 web search，在模型调用期间由 provider 运行。**RunModel** 重跑时它们会重复执行。
- SDK 自己运行的 tool，例如 MCP server tool 和本地 shell tool，无法等待审批。Adapter 默认拒绝它们。把写操作包装成 function tool，它就有了自己的 Step。
- Function tool 的名称在整个 Agent graph 中必须唯一。Graph 在构建 Flow 时被复制，之后对它的修改不会影响 Flow。
- Session 就是历史记录。不要使用 server 管理的 conversation state 或 SDK session。
- 在 Python 中，作为 tool 使用的 Agent 会在一个 tool Step 中运行整个嵌套 run。TypeScript 会拒绝它；请改用 handoff。

每次模型调用和每次 tool call 都会增加一次 Step 往返。Adapter README 列出了全部限制。Server 的限制参见 [Durable Agents](/agent-frameworks/deploy-agents#limits)。
