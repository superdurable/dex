# Claude Agent SDK

Claude Agent SDK 把 Claude Code 作为 Agent 运行。它的 agent loop 运行在 Claude Code CLI 中，CLI 是 Worker 的子进程。Dex adapter 把这个 loop 放进 durable session 中运行。它支持 Python 和 TypeScript。

## 何时使用 {#when-to-use-it}

需要 Claude Code 的 agent loop、上下文管理和它的 tool 时，使用它。Agent 已经用 Claude Agent SDK 编写时，也使用它。

如果需要每个 Step 只调用一次模型、并行的 tool Step 或 Dex compaction，请使用 [内置 agent loop](/agent-frameworks/built-in-agent-loop)。

## Session 如何运行 {#how-a-session-runs}

Claude Code 一次运行整个 turn，因此 adapter 把一个 turn 拆成多个 segment。一个 **RunModel** Step 为一个 segment 运行 CLI。模型调用在 segment 内运行。Read tool 也在 segment 内运行：把 read 移出 segment 会让 CLI 重新启动。Connector tool call 是例外：它总是离开 segment，读操作也一样。参见 [连接 Connector](#connect-connectors)。

写操作的 tool call 会结束当前 segment。需要审批时，它在 **AwaitToolApproval** 中等待。然后它在自己的 Step 中运行：idempotent write 用 **CallTool**，其他写操作用 **CallSingleAttemptTool**。之后 **ResumeTurn** 回到 **RunModel**，由它恢复同一个 Claude session。CLI 拿到记录下来的结果，不会再次运行这个 tool。

失败的 segment 会重试，最多三次，并且整体重跑。其中的模型调用和 read 会再次运行。已经在自己的 Step 中运行过的写操作不会再次运行。

查询订单的 turn 只运行一个 **RunModel** Step。取消订单的 turn 依次运行 **RunModel**、**AwaitToolApproval**、**CallSingleAttemptTool**、**ResumeTurn** 和 **RunModel**。

## 认证 {#authentication}

Worker 用 **ANTHROPIC_API_KEY** 为 Claude Code CLI 认证。把它设置在 Worker 的环境中。它永远不会进入 Flow state。

Example 为 CLI 构建的环境中，**ANTHROPIC_API_KEY** 是唯一的 credential。没有这个 key 时，example 不会注册 Claude Agent，但仍会提供其他 harness。

## Example {#the-example}

这个 example 是一个订单客服 Agent。它在一个内存中的订单系统上有两个 tool。**look_up_order** 读取订单。它的 policy 是 read，因此无需审批就会运行，失败时会重试。**cancel_order** 取消一个仍在处理中的订单。它的 policy 是 non-idempotent write，因此会先等待审批，然后最多运行一次。

Flow type 是 **ClaudeAgentSDKOrderSupport**（Python），**ClaudeAgentSdkOrderSupportAgent**（TypeScript）。完整 example 位于 [examples/python/agent-harnesses](https://github.com/superdurable/dex/tree/main/examples/python/agent-harnesses) 和 [examples/typescript/src/products/agent-harnesses](https://github.com/superdurable/dex/tree/main/examples/typescript/src/products/agent-harnesses)。

```python
def build_claude_agent_sdk_order_support_flow(
    order_desk: OrderDesk, model: str, slack_connection: slack.Connection | None
) -> AgentSessionFlow:
    """Builds the session Flow; ``model`` is a Claude model name, such as "claude-opus-5-5"."""

    # The tools are closures, so they call the OrderDesk passed in here.
    @tool(
        "look_up_order",
        "Look up one order by its order ID and return its items and status.",
        {"order_id": str},
    )
    async def look_up_order(arguments: dict[str, Any]) -> dict[str, Any]:
        order = order_desk.describe_order(arguments["order_id"])
        return {"content": [{"type": "text", "text": order}]}

    @tool(
        "cancel_order",
        "Cancel one order that has not shipped yet.",
        {"order_id": str, "reason": str},
    )
    async def cancel_order(arguments: dict[str, Any]) -> dict[str, Any]:
        result = order_desk.cancel_order(arguments["order_id"], arguments["reason"])
        return {"content": [{"type": "text", "text": result}]}

    # Every session gets the same options, so the factory does not read its context.
    def build_options(context: ClaudeAgentOptionsContext) -> ClaudeAgentOptions:
        return ClaudeAgentOptions(
            model=model,
            env=build_claude_cli_environment(os.environ),
            system_prompt=ORDER_SUPPORT_INSTRUCTIONS,
            # No Claude Code built-in tools: the agent uses only the order tools.
            tools=[],
            # Settings files could approve a tool before Dex asks for approval.
            setting_sources=[],
        )

    return claude_agent_session_flow(
        build_options,
        [look_up_order, cancel_order],
        flow_type=CLAUDE_AGENT_SDK_ORDER_SUPPORT_FLOW_TYPE,
        tool_sources=build_slack_tool_sources(slack_connection),
        tool_policies={
            "look_up_order": ToolPolicy(ToolEffect.READ),
            "cancel_order": ToolPolicy(ToolEffect.NON_IDEMPOTENT_WRITE),
        },
    )
```

  orderDesk: OrderDesk,
  model: string,
  cliEnvironment: Readonly<Record<string, string>>,
  slack: Connection | undefined,
): AgentSessionFlow {
  const lookUpOrder = tool(
    "look_up_order",
    "Look up one order by its order ID and return its items and status.",
    { order_id: z.string() },
    async ({ order_id }) => ({ content: [{ type: "text", text: orderDesk.describeOrder(order_id) }] }),
  );
  const cancelOrder = tool(
    "cancel_order",
    "Cancel one order that has not shipped yet.",
    { order_id: z.string(), reason: z.string() },
    async ({ order_id, reason }) => ({ content: [{ type: "text", text: orderDesk.cancelOrder(order_id, reason) }] }),
  );
  return createClaudeAgentSessionFlow(
    {
      options: {
        model,
        systemPrompt: orderSupportInstructions,
        // No Claude Code built-in tools: the agent uses only the order tools.
        tools: [],
        // Settings files could approve a tool before Dex asks for approval.
        settingSources: [],
        // Only the variables in cliEnvironment reach the CLI, so no other Claude credential can take over.
        env: { ...cliEnvironment },
      },
      customTools: [lookUpOrder, cancelOrder],
      toolPolicies: {
        look_up_order: { effect: "read" },
        cancel_order: { effect: "non_idempotent_write" },
      },
      toolSources: createSlackConnectorToolSources(slack),
    },

  );
}

### Session route {#session-routes}

每个 harness 都提供相同的 HTTP route。每个 route 对应 session Flow 上的一次调用：启动 session、发送消息或处理审批。启动 session 会返回 session token，它是用 **DEX_AGENT_SESSION_KEY** 对 session ID 计算的 HMAC。其他每个 route 都会检查 **X-Agent-Session-Token** header 中的 token，缺少时返回 403。真实的应用会改用自己的登录。

```python
    @blueprint.post("/sessions")
    async def start_session() -> Response:
        # The server picks the session ID, so a caller cannot claim an existing session.
        session_id = f"{harness_name}-order-support-{uuid.uuid4()}"
        await sessions.start_session(session_id)
        session_token = sign_session_id(app_state.config.session_key, session_id)
        return jsonify(session_id=session_id, session_token=session_token)

    @blueprint.post("/messages")
    async def send_user_message() -> Response:
        body, session_id = await session_request()
        accepted = await sessions.send_user_message(session_id, _required_string(body, "text"))
        return jsonify(accepted=accepted)

    @blueprint.post("/interrupts/resolve")
    async def resolve_interrupt() -> Response:
        body, session_id = await session_request()
        interrupt_id = _required_string(body, "interrupt_id")
        if not isinstance(approved := body.get("approved"), bool):
            raise BadRequest("approved must be a boolean")
        rejection_message = body.get("rejection_message")
        if rejection_message is not None and not isinstance(rejection_message, str):
            raise BadRequest("rejection_message must be a string")
        accepted = await sessions.resolve_interrupt(
            session_id, interrupt_id, approved=approved, rejection_message=rejection_message
        )
        return jsonify(accepted=accepted)

    @blueprint.get("/snapshot")
    async def get_agent_snapshot() -> Response:
        session_id = request.args.get("session_id", "")
        if not session_id:
            raise BadRequest("session_id is required")
        authorize_session(session_id)
        try:
            snapshot = await read_agent_event_stream_snapshot(
                app_state.client, example.session_flow, session_id
            )
        except FlowNotActiveOrNotFoundError as error:
            raise NotFound("the agent session is missing or no longer retained") from error
        return jsonify(snapshot.to_json())
```

### 在 Dex Web 中审批 {#approve-in-dex-web}

也可以不执行最后一条命令，而是在 Dex Web 中审批。打开这个 session 的 run：它的 Flow ID 就是 session ID。选择 **Agent session** tab。把 **Working as** 设为渲染时指定的 permission **order-support.operate**。然后在 **cancel_order** 卡片上选择 **Approve** 或 **Reject**。Dex Web 会替你调用 **resolve_interrupt**。生产环境的做法参见 [在 Dex Web 中显示 session](/agent-frameworks/deploy-agents#dex-web)。

## 连接 Connector {#connect-connectors}

Connector tool 是 agent 当作 tool 调用的 [Connector](/components/connector) operation。**ConnectorToolSource** 提供你指定的 operation。Agent 通过 Python 的 **tool_sources** 或 TypeScript 的 **toolSources** 把它作为 tool source 接收。Effect class、审批、结果和写操作顺序的规则见 [Connector tool](/agent-frameworks/deploy-agents#connector-tools)。

Example 把 Slack Connector 的 operation **postThreadReply** 作为 tool **slack_post_thread_reply** 提供。Agent 用它在 Slack thread 中回复。

### 提供 tool {#offer-connector-tools}

在 Python 中，安装 **dex-agents** 的 **connectors** extra，以及 Connector 包，例如 **dex-connector-slack**。在 TypeScript 中，安装 **@superdurable/connectors-sdk** 以及 Connector 包，例如 **@superdurable/connector-slack**。安装命令见 [Connector tool](/agent-frameworks/deploy-agents#connector-tools)。

Worker 从项目配置中打开 Slack connection **support-slack**。Python 的 **connector_tool** 或 TypeScript 的 **connectorTool** 把 operation 变成 tool，由 **ConnectorToolSource** 持有。没有这个 connection 时，agent 不会得到 Slack tool。

### 调用如何运行 {#connector-tool-calls}

每次调用 **slack_post_thread_reply** 都在自己的 tool Step 中通过 Connector SDK 运行一个 Slack operation。调用保留 Connector 的 Call ID 和幂等键。调用运行前，模型给出的参数会先按 operation 的 input schema 检查。

Connector 的 manifest 决定 effect class。**postThreadReply** 是 Mutation，它的 manifest 没有把它标为可安全重试，所以调用只在 **CallSingleAttemptTool** 中运行一次。Worker 崩溃永远不会让同一条消息发两次。参见 [崩溃](/agent-frameworks/deploy-agents#connector-tools-crashes)。

Manifest 还会建议调用是否需要审批。Slack 的 manifest 没有建议 **postThreadReply** 需要审批，所以 example 传入 Python 的 **requires_approval=True** 或 TypeScript 的 **requiresApproval: true**。每次发帖都在 **AwaitToolApproval** 中等待，直到有人批准。Connector tool 的 **tool_policies**（**toolPolicies**）条目只改变它的审批，从不改变它的 effect class。

在 Claude Agent SDK 中，Connector tool call 从不在 CLI 内运行，读操作也一样。每次调用都会结束当前 segment，并在自己的 tool Step 中运行，因为 Connector 需要这个 Step 来得到它的 Call ID。之后恢复的 CLI 拿到记录下来的结果。CLI 看到的 tool 名是 **mcp__tools__slack_post_thread_reply**；tool policy、审批和记录使用 **slack_post_thread_reply**。

同一次回复中的写操作逐个运行，因为每个 segment 只有一个调用会离开 turn。同一次回复中后面的写操作会在 turn 内被拒绝，不留下记录。模型读到前一个结果后，再决定是否重新调用后面的写操作。不要把 Connector tool 列进 **allowed_tools**（**allowedTools**）：它的调用必须离开 CLI，所以这样的条目会让 **RunModel** 这次尝试失败。

### 配置 connection {#configure-connector-connection}

Connection 来自项目配置，和 Dex 应用中的任何 Connector connection 一样。Connector 在每次调用前解析凭证，所以凭证永远不会进入 Flow state。调用只保存 connection 名称。

- **本地开发。**把 **DEX_CONNECTOR_CONFIG_FILE** 设为本地 Connector 配置的 **connections.json** 文件，默认是 **$HOME/.dex/connectors/connections.json**。其中必须有一个名为 **support-slack** 且已授权的 Slack connection。[Local Connector setup](/reference/web/local-connector-setup) 介绍了这个文件。
- **部署后。** **DEX_PROJECT_\*** 设置选择托管平台或运维人员写入的项目配置。

设置 **DEX_CONNECTOR_CONFIG_FILE** 或任何一个 **DEX_PROJECT_\*** 设置，就表示要求使用项目配置。配置不完整或无效时，Worker 在启动时停止。没有项目配置，或项目配置中没有 **support-slack** connection 时，Worker 记录一行日志，agent 在没有 Slack tool 的情况下运行。Worker 在启动时读取配置，所以修改配置后要重启 Worker。

有发帖在等待审批时，让每个 Worker 保持相同的配置。任何 Worker 都可能运行已批准的发帖，它需要相同的 tool 和 connection。

Slack app 需要 bot scope **chat:write**，并且它的 bot 必须是该 channel 的成员。Worker 在发帖途中停止后，Connector 用 user scope **channels:history** 和 **groups:history** 读回 thread，以确认回复是否已经发出。没有这些 scope 时，这样的发帖会记录为结果未知。

试用时，先设置 **DEX_CONNECTOR_CONFIG_FILE** 再启动 example。然后让 agent 在 Slack thread 中回复，并给出 channel ID 和 thread timestamp：

```text
Reply in Slack thread C0123456789 1710000000.000100: Order 1002 ships on Thursday.
```

这次发帖和 **cancel_order** 一样，会先等待审批。

## 限制 {#limits}

- 每个 segment 只有一个写操作调用会离开 turn。一次回复中有两个写操作时，会多花一个 segment 和一次模型调用。同一次回复中的写操作永远不会作为并行 Step 运行。
- 在 CLI 内运行的 tool，例如 **Bash** 或 **Edit**，至少运行一次。segment 重跑时它们会再次运行。CLI 修改的文件不会被记录。
- 一个 segment 必须在 **RunModel** 的 method timeout 内完成，默认 15 分钟。在 Python 中用 **run_model_limit**、在 TypeScript 中用 **runModelLimit** 调大它。
- 不支持 Dex compaction。Claude Code 自己压缩它的 transcript。长 session 会在达到 state 上限时结束，而不是在达到 context window 时结束。
- 记录下来的 tool result 只保留文本。
- Subagent 中的写操作调用会被拒绝。模型会被要求从主对话中调用它。

每次模型调用和每次 tool call 都会增加一次 Step 往返。Adapter README 列出了全部限制。Server 的限制参见 [Durable Agents](/agent-frameworks/deploy-agents#limits)。
