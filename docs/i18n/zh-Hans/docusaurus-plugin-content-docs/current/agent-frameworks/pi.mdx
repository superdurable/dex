# Pi

Pi 是一个用于 Agent 的 TypeScript 工具集。它的 **pi-ai** 包调用多个 provider 的模型，例如 OpenAI、Anthropic、Google 和 Bedrock。它的 agent core 定义 tool。Dex 的这个包把 Pi Agent 作为 durable session 运行。它支持 TypeScript。

## 何时使用 {#when-to-use-it}

Agent 已经使用 pi-ai 模型和 Pi tool 时，使用它。保留模型和 tool，由 Dex 管理 session 和 loop。

从 **pi-durable** 把 Agent 迁到 Dex 时，也使用它。迁移步骤见[从 pi-durable 迁移](/agent-frameworks/migrate-from-pi-durable)。

## Session 如何运行 {#how-a-session-runs}

Agent loop 由 Dex 运行，不由 Pi 运行。Session 就是 Dex Agents 的[内置 agent loop](/agent-frameworks/built-in-agent-loop)。何时调用模型、何时运行 tool、何时等待审批、turn 何时结束，都由 Dex 决定。

Pi 只提供两样东西：

- **模型调用。** 每次 **RunModel** attempt 发出一次 pi-ai 请求。pi-ai 自己的重试已关闭，所以一次重试就是一次新的 **RunModel** attempt，Flow 历史中可以看到。Bedrock 是例外：AWS SDK 会在一次 attempt 内重试，默认 3 次，次数由 AWS 配置决定。所以 Flow 历史中的 attempt 数不等于 Bedrock 的请求数。见包的 README 中的 [Not supported](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#not-supported)。
- **Tool。** 每个 tool 是一个 Pi **AgentTool**。每个 tool call 在自己的 Step 中并行运行：read 或 idempotent write 用 **CallTool**，其他写操作用 **CallSingleAttemptTool**。需要审批的调用先在 **AwaitToolApproval** 中等待。

不使用 Pi 的 **Agent**、**agentLoop** 和 **pi-durable** harness。这一点与其他 adapter 不同：其他 adapter 在 session 中运行各自 framework 的 loop。

查询订单的 turn 依次运行 **RunModel**、**CallTool**、**ResumeTurn** 和 **RunModel**。

每次模型回复都保存为一条 pi-ai 消息，只包含之后的模型调用需要的字段：带 thinking signature 的内容、生成它的 provider 和模型，以及 token 用量。不保存本地 telemetry，例如时间戳和费用。之后的每次调用都重放这些字段。pi-ai 会为另一个 provider 转换它们，所以 session 可以在两个 turn 之间更换模型。字段列表见包的 README 中的 [Stored messages](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#stored-messages)。

### Agent 与 tool {#agent-and-tools}

Tool 是 Pi **AgentTool** 对象。**piAgentFunctionTool** 把每个 tool 转成内置 loop 的 tool。**createPiAiModelClient** 把 pi-ai 模型转成 session 的 model client。

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/pi/pi-order-support-flow.ts',
  }}>
<SdkSnippet lang="typescript">

```typescript
export function createPiOrderSupportFlow(
  orderDesk: OrderDesk,
  model: Model<Api>,
  slack: Connection | undefined,
): OrderSupportSessionFlow {
  const lookUpOrder: AgentTool<typeof lookUpOrderArguments> = {
    name: "look_up_order",
    label: "Look up order",
    description: "Look up one order by its order ID and return its items and status.",
    parameters: lookUpOrderArguments,
    execute: async (_toolCallId, { order_id }) => textResult(orderDesk.describeOrder(order_id)),
  };
  const cancelOrder: AgentTool<typeof cancelOrderArguments> = {
    name: "cancel_order",
    label: "Cancel order",
    description: "Cancel one order that has not shipped yet.",
    parameters: cancelOrderArguments,
    // Not safe to repeat, so Dex asks for approval first and runs it at most once.
    replay: "never",
    execute: async (_toolCallId, { order_id, reason }) => textResult(orderDesk.cancelOrder(order_id, reason)),
  };
  return createBuiltinAgentSessionFlow(
    {
      name: "order-support",
      instructions: orderSupportInstructions,
      model: createPiAiModelClient(model),
      tools: [piAgentFunctionTool(lookUpOrder, { effect: "read" }), piAgentFunctionTool(cancelOrder)],
      toolSources: createSlackConnectorToolSources(slack),
    },
    piOrderSupportFlowType,
  );
}
```

</SdkSnippet>
</SdkTabs>

### Effect class {#effect-classes}

每个 Dex tool 都要声明自己的 [effect class](/agent-frameworks#effect-classes)。Pi tool 的 **replay** 字段决定它，除非传入 **effect**：

| Tool 声明了 | 传入 **effect** | Effect class |
| --- | --- | --- |
| 任意 | 是 | 传入的 effect |
| **replay: "safe"** | 否 | **idempotent_write**：运行被中断时会重新运行 |
| **replay: "never"** | 否 | **non_idempotent_write**：先审批，最多运行一次 |
| 没有 **replay** | 否 | 构建 session Flow 时报错 |

在这个 example 中，**look_up_order** 传入 **effect: "read"**，所以它无需审批。**cancel_order** 声明了 **replay: "never"**，所以它先等待审批，最多运行一次。

Effect class 决定运行被中断时怎么办，例如 Worker 崩溃。被中断的 **read** 或 **idempotent_write** 调用，Dex 会在它的 **CallTool** Step 中重新运行。**non_idempotent_write** 调用从不重新运行。

Tool 报告的错误不会重试。结果带 **isError**，或者抛出 **ToolExecutionError** 时，这次调用记为 **failed**。模型会看到错误信息，session 继续运行。

Tool 有 **prepareArguments** 时，它会在 schema 检查之前修复原始参数，与 Pi 一致。

抛出的普通错误按这次调用实际使用的 effect 分类，也就是应用 tool policy 之后的 effect。**read** 或 **idempotent_write** 调用抛出的普通错误记为 **failed**，同上。其他调用，例如 **non_idempotent_write** 或 **unclassified** 调用，抛出的普通错误可能发生在写入之后，所以这次调用记为 **outcome_unknown**，并且不会再运行。写操作要报告确定的失败，请返回 **isError** 或抛出 **ToolExecutionError**。

### 模型 {#the-model}

Worker 从 pi-ai 的内置 catalog 中选择模型。pi-ai 从 Worker 的环境中读取 provider 的 key，所以 key 从不进入 Flow 状态。

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/pi/pi-order-support-flow.ts',
  }}>
<SdkSnippet lang="typescript">

```typescript
export function loadPiOrderSupportModel(): Model<Api> {
  const name = environmentOr("DEX_PI_MODEL", "openai/gpt-5-mini");
  const separator = name.indexOf("/");
  const provider = name.slice(0, separator) as BuiltinProvider;
  const modelId = name.slice(separator + 1);
  const model = separator > 0 ? getBuiltinModels(provider).find((candidate) => candidate.id === modelId) : undefined;
  if (model === undefined) {
    throw new Error(`DEX_PI_MODEL ${name} is not a <provider>/<model ID> of pi-ai's built-in catalog`);
  }
  return model;
}
```

</SdkSnippet>
</SdkTabs>

**createPiAiModelClient** 还接受 **apiKey**，以及一个 **prepareRequest** hook，用来修改单次请求的 context。说明见[包的 README](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#the-model-client)。

### 调用 session {#call-the-session}

启动一个 session，让 Agent 取消订单 1002，然后批准这次调用：

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/README.md',
  }}>
<SdkSnippet lang="typescript">

```bash
base=http://127.0.0.1:8080/products/agent-harnesses/pi
session=$(curl -s -X POST "$base/sessions" -H 'Content-Type: application/json' \
  -d '{"message": "Please cancel order 1002"}')
id=$(echo "$session" | jq -r .session_id)
token=$(echo "$session" | jq -r .session_token)
until interrupt=$(curl -s "$base/sessions/$id/snapshot" -H "X-Agent-Session-Token: $token" \
  | jq -re '.pending_interrupts[0].interrupt_id'); do sleep 1; done
curl -s -X POST "$base/sessions/$id/interrupts/$interrupt/approve" -H "X-Agent-Session-Token: $token"
```

</SdkSnippet>
</SdkTabs>

循环会反复读取 snapshot，直到 Agent 请求运行 **cancel_order**。这次调用先等待审批，批准后只运行一次。再读一次 snapshot 即可看到 Agent 的回答。

## 用 CLI 运行 {#run-it-with-the-cli}

**dex-agents-pi** 命令把 Pi coding agent 作为 durable session 运行，并在终端中与它对话。它在 npm 包 **@superdurable/dex-agents-pi-cli** 中。和 example 一样，loop 由 Dex 运行。这个命令会启动或复用 **dexcli dev**。

```bash
export ANTHROPIC_API_KEY=sk-ant-...
npx -p @superdurable/dex-agents-pi-cli dex-agents-pi
```

第一次运行时，它会问几个问题，并写出 **~/.dex/agents/pi.yaml**。然后输入消息。用 **y** 或 **n** 批准或拒绝 tool call。Session 保存在 Dex 中，命令会打印继续这个 session 的方法。

模型写成 pi-ai catalog 中的 provider 和 model ID，例如 **anthropic/claude-opus-5-5**。命令只从环境变量读取 provider 的 API key，例如 **ANTHROPIC_API_KEY** 或 **OPENAI_API_KEY**。它从不读取 Pi 保存的登录信息。

配置文件的 **pi** 小节保存 Pi 的选项：

```text
model: anthropic/claude-opus-5-5
workspace: ~/dex-agent-workspace
local_tools:
  files: true
  shell: {enabled: true, allow: ["git status", "ls"]}
pi:
  load_project_context: true
  bash_timeout_seconds: 120
```

Agent 使用 Pi 自己的 coding tool，每次调用都是独立的 tool Step：

| Tool | Effect | 审批 |
| --- | --- | --- |
| **read**、**grep**、**find**、**ls** | read | 不需要 |
| **write**、**edit** | 只运行一次 | 每次调用都要 |
| **bash** | 只运行一次 | 除非 **local_tools.shell.allow** 包含完整命令 |

文件 tool 只能访问 workspace 内的文件。和 Pi 一样，每次模型调用都会把项目的 **AGENTS.md** 加到 instruction 中：先是 Pi 全局目录中的那一份，然后是 workspace 及其上层目录中的。设置 **pi.load_project_context: false** 可以不加载。

全部选项、文件规则和 AGENTS.md 规则见[命令的 README](https://github.com/superdurable/dex/tree/main/agents/cli/typescript/pi)。

## Pi 的功能由什么代替 {#pi-feature-mapping}

| Pi 的功能 | 在 Dex 中 |
| --- | --- |
| **steer()** 和 **followUp()** | **sendUserMessage** RPC 和 session 的 steering |
| **beforeToolCall**，用来审批或拦截调用 | Tool policy 和 **AwaitToolApproval** Step。审批可以等待任意长的时间。 |
| **afterToolCall**，用来修改结果 | 在你自己的 tool 中修改结果。 |
| **transformContext**，用来裁剪或压缩 | Session 的 context compaction。**prepareRequest** 修改单次请求。 |
| **prepareRequest** | **createPiAiModelClient** 的 **prepareRequest** 选项 |
| **finishTurn** 返回 **end**：tool 运行完后结束 turn | Agent 定义的 **decideTurnContinuation** hook 返回 **"end"**。 |
| **finishTurn** 返回 **continue**：回答之后再运行一轮 | **decideTurnContinuation** 返回 **\{ action: "continue", message \}**。message 必填，模型在同一个 turn 中把它作为用户文本收到。回答之后最多连续 continue 8 次。 |
| **subscribe()** 事件 | **AgentEvents** Stream 和 UI stream |
| **abort()** | Session 的 **cancel_turn** |
| **pi-durable** | Dex 本身。见[从 pi-durable 迁移](/agent-frameworks/migrate-from-pi-durable)。 |

**decideTurnContinuation** 的说明见 core README 中的 [Ending or continuing a turn](https://github.com/superdurable/dex/tree/main/agents/typescript/core#ending-or-continuing-a-turn)。

## 限制 {#limits}

- Dex 并行运行同一次模型回复中的 tool call。带 **executionMode: "sequential"** 的 tool 会被拒绝。
- **AgentToolResult.terminate** 会被忽略。在 tool 之后结束 turn，请用 **decideTurnContinuation**。
- pi-ai 的 tool choice 只有 **auto** 或 **none**，所以强制使用某个 tool 的请求会失败。
- Tool 结果中的图片以一条文本说明交给模型。
- 不保存 tool 的 **details**。模型看到的是结果中的文本部分。
- 不使用 Pi 的 **Agent**、**agentLoop** 和 session 文件。

[包的 README](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#not-supported) 列出了全部限制。Server 的限制参见 [Limits for long sessions](/reference/agents/session-limits)。

## 从 pi-durable 迁移 {#move-from-pi-durable}

Dex 替代的是 **pi-durable**，不是 Pi。你的 pi-ai 模型和 Pi tool 继续使用。Harness 的入口代码要改写：**Harness.open**、root conversation、**submit** 和 **wait** 改为 session Flow、Worker 和 Client 调用。迁移步骤见[从 pi-durable 迁移](/agent-frameworks/migrate-from-pi-durable)。

**pi-durable** API 的兼容层由 [issue #1571](https://github.com/superdurable/dex/issues/1571) 跟踪。
