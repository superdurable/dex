# Vercel AI SDK

Vercel AI SDK 为 TypeScript 提供一套对接多家模型 provider 的 API，并支持有类型的 tool。Dex adapter 把 AI SDK 的 Agent 定义放进 durable session 中运行。它支持 TypeScript。

## 何时使用 {#when-to-use-it}

TypeScript 应用已经在使用 AI SDK 的模型和 tool 时，使用它。保留模型、tool 和 **stopWhen**，由 Dex 管理 session。

## Session 如何运行 {#how-a-session-runs}

每个 tool 交给模型时都不带 **execute**，因此 AI SDK 会返回 tool call，而不是运行它们。每个 **RunModel** Step 用 **streamText** 调用一次模型。

每个 tool call 在自己的 Step 中并行运行 tool 原本的 **execute**：read 或 idempotent write 用 **CallTool**，其他写操作用 **CallSingleAttemptTool**。需要审批的调用先在 **AwaitToolApproval** 中等待。下一个 **RunModel** 加入记录下来的结果，检查 **stopWhen**，然后再次调用模型。

查询订单的 turn 依次运行 **RunModel**、**CallTool**、**ResumeTurn** 和 **RunModel**。

## Example {#the-example}

这个 example 是一个订单客服 Agent。它在一个内存中的订单系统上有两个 tool。**look_up_order** 读取订单。它的 policy 是 read，因此无需审批就会运行，失败时会重试。**cancel_order** 取消一个仍在处理中的订单。它的 policy 是 non-idempotent write，因此会先等待审批，然后最多运行一次。

Flow type 是 **VercelAiOrderSupportAgent**（TypeScript）。完整 example 位于 [examples/typescript/src/products/agent-harnesses](https://github.com/superdurable/dex/tree/main/examples/typescript/src/products/agent-harnesses)。

### Agent 与 tool {#agent-and-tools}

定义中包含模型、instructions、AI SDK tool 和 tool policy。Dex 根据 policy 决定是否需要审批。

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/vercel-ai/vercel-ai-order-support-flow.ts',
  }}>
<SdkSnippet lang="typescript">

```typescript
export function createVercelAiOrderSupportFlow(
  orderDesk: OrderDesk,
  model: LanguageModel,
  slack: Connection | undefined,
): AgentSessionFlow {
  return createVercelAiAgentSessionFlow(
    {
      model,
      instructions: orderSupportInstructions,
      tools: {
        look_up_order: tool({
          description: "Look up one order by its order ID and return its items and status.",
          inputSchema: z.object({ order_id: z.string() }),
          execute: ({ order_id }) => orderDesk.describeOrder(order_id),
        }),
        cancel_order: tool({
          description: "Cancel one order that has not shipped yet.",
          inputSchema: z.object({ order_id: z.string(), reason: z.string() }),
          execute: ({ order_id, reason }) => orderDesk.cancelOrder(order_id, reason),
        }),
      },
      toolPolicies: {
        look_up_order: { effect: "read" },
        cancel_order: { effect: "non_idempotent_write" },
      },
      toolSources: createSlackConnectorToolSources(slack),
    },
    vercelAiOrderSupportFlowType,
  );
}
```

</SdkSnippet>
</SdkTabs>

### Session route {#session-routes}

每个 harness 都提供相同的 HTTP route。每个 route 对应 session Flow 上的一次调用：启动 session、发送消息或处理审批。启动 session 会返回 session token，它是用 **DEX_AGENT_SESSION_KEY** 对 session ID 计算的 HMAC。其他每个 route 都会检查 **X-Agent-Session-Token** header 中的 token，缺少时返回 403。真实的应用会改用自己的登录。

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/order-support/order-support-routes.ts',
  }}>
<SdkSnippet lang="typescript">

```typescript
  router.post("/sessions", async (request, response) => {
    const initialMessage = optionalString(requireBody(request), "message");
    // The server picks the session ID, so a caller cannot name another session.
    const sessionId = `order-support-${randomUUID()}`;
    await startAgentSession(client, flow, sessionId, { initialMessage }, { timeoutMs: 30 * DAY_MS });
    response.json({ session_id: sessionId, session_token: issueSessionToken(sessionId) });
  });
  router.get("/sessions/:id/snapshot", async (request, response) => {
    response.json(convertAgentSnapshotToJson(await client.invokeRPC(flow.getAgentSnapshot, sessionIdOf(request))));
  });
  router.post("/sessions/:id/messages", async (request, response) => {
    const sessionId = sessionIdOf(request);
    const message = { text: requireString(requireBody(request), "text") };
    sendAccepted(response, await client.invokeRPC(flow.sendUserMessage, sessionId, message));
  });
  router.post("/sessions/:id/interrupts/:interruptId/approve", async (request, response) => {
    const sessionId = sessionIdOf(request);
    const approval = { interruptId: String(request.params.interruptId), approved: true, rejectionMessage: null };
    sendAccepted(response, await client.invokeRPC(flow.resolveInterrupt, sessionId, approval));
  });
```

</SdkSnippet>
</SdkTabs>

### 调用 session {#call-the-session}

启动一个 session，让 Agent 取消订单 1002，然后批准这次调用：

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/README.md',
  }}>
<SdkSnippet lang="typescript">

```bash
base=http://127.0.0.1:8080/products/agent-harnesses/vercel-ai
session=$(curl -s -X POST "$base/sessions" -H 'Content-Type: application/json' \
  -d '{"message": "Please cancel order 1002"}')
id=$(echo "$session" | jq -r .session_id)
token=$(echo "$session" | jq -r .session_token)
until interrupt=$(curl -s "$base/sessions/$id/snapshot" -H "X-Agent-Session-Token: $token" \
  | jq -re '.pending_interrupts[0].interrupt_id'); do sleep 1; done
curl -s -X POST "$base/sessions/$id/interrupts/$interrupt/approve" -H "X-Agent-Session-Token: $token"
```

</SdkSnippet>
</SdkTabs>

循环会反复读取 snapshot，直到 Agent 请求运行 **cancel_order**。这次调用会等待审批。它只在批准之后运行，并且只运行一次。再读一次 snapshot 即可看到 Agent 的回答。

### 在 Dex Web 中审批 {#approve-in-dex-web}

也可以不执行最后一条命令，而是在 Dex Web 中审批。打开这个 session 的 run：它的 Flow ID 就是 session ID。选择 **Agent session** tab。把 **Working as** 设为渲染时指定的 permission **order-support.operate**。然后在 **cancel_order** 卡片上选择 **Approve** 或 **Reject**。Dex Web 会替你调用 **resolve_interrupt**。生产环境的做法参见 [在 Dex Web 中显示 session](/agent-frameworks/deploy-agents#dex-web)。

## 连接 Connector {#connect-connectors}

Connector tool 是 agent 当作 tool 调用的 [Connector](/components/connector) operation。**ConnectorToolSource** 提供你指定的 operation。Agent 通过 **toolSources** 把它作为 tool source 接收。Effect class、审批、结果和写操作顺序的规则见 [Connector tool](/agent-frameworks/deploy-agents#connector-tools)。

Example 把 Slack Connector 的 operation **postThreadReply** 作为 tool **slack_post_thread_reply** 提供。Agent 用它在 Slack thread 中回复。

### 提供 tool {#offer-connector-tools}

安装 **@superdurable/connectors-sdk** 以及 Connector 包，例如 **@superdurable/connector-slack**。安装命令见 [Connector tool](/agent-frameworks/deploy-agents#connector-tools)。

Worker 从项目配置中打开 Slack connection **support-slack**。**connectorTool** 把 operation 变成 tool，由 **ConnectorToolSource** 持有。没有这个 connection 时，agent 不会得到 Slack tool。

### 调用如何运行 {#connector-tool-calls}

每次调用 **slack_post_thread_reply** 都在自己的 tool Step 中通过 Connector SDK 运行一个 Slack operation。调用保留 Connector 的 Call ID 和幂等键。Operation 如何变成 tool、参数如何检查，见 [提供哪些 operation](/agent-frameworks/deploy-agents#connector-tools-offered)。

Connector 的 manifest 决定 effect class。**postThreadReply** 是 Mutation，它的 manifest 没有把它标为可安全重试，所以调用只在 **CallSingleAttemptTool** 中运行一次。Worker 崩溃永远不会让同一条消息发两次。参见 [崩溃](/agent-frameworks/deploy-agents#connector-tools-crashes)。

Slack 的 manifest 没有建议 **postThreadReply** 需要审批，所以 example 传入 **requiresApproval: true**。每次发帖都在 **AwaitToolApproval** 中等待，直到有人批准。Manifest 和应用如何决定审批，见 [审批](/agent-frameworks/deploy-agents#connector-tools-approval)。

Adapter 在 agent 的 tool 之后提供 Connector tool，它们是没有 **execute** 的 AI SDK tool。调用从不在模型调用内运行。AI SDK 的 **needsApproval** 对它不起作用；审批由 source 决定。

同一个回复中的 Connector 写操作按顺序运行，见 [写操作顺序](/agent-frameworks/deploy-agents#connector-tools-write-order)。

### 配置 connection {#configure-connector-connection}

Worker 从项目配置中打开 Slack connection **support-slack**：本地开发时用 **DEX_CONNECTOR_CONFIG_FILE**，部署后用 **DEX_PROJECT_\*** 设置。两种方式、没有 connection 时会怎样以及 Slack app 需要什么，见 [Connection](/agent-frameworks/deploy-agents#connector-tools-connection)。

试用时，先设置 **DEX_CONNECTOR_CONFIG_FILE** 再启动 example。然后让 agent 在 Slack thread 中回复，并给出 channel ID 和 thread timestamp：

```text
Reply in Slack thread C0123456789 1710000000.000100: Order 1002 ships on Thursday.
```

这次发帖和 **cancel_order** 一样，会先等待审批。

## 限制 {#limits}

- **RunModel** 中发生崩溃时，会重跑那次模型调用以及其中由 provider 执行的 tool。
- Tool 的 **execute** 会收到 **toolCallId** 和 **abortSignal**。它的 **messages** 为空，**context** 为 **undefined**。
- 审批由 Dex 负责。不开放 AI SDK 的 **toolApproval**，**needsApproval** 函数会被拒绝。由 provider 执行的 tool 永远不会等待审批。
- 每个 tool 都在 Dex 中运行，因此没有 **execute** 的 tool，例如浏览器端 tool，会被拒绝。
- Tool 的输入和输出必须能经受 JSON 序列化。
- 不开放 **prepareStep**、**activeTools**、**output** 和 stream transform。

每次模型调用和每次 tool call 都会增加一次 Step 往返。Adapter README 列出了全部限制。Server 的限制参见 [Durable Agents](/agent-frameworks/deploy-agents#limits)。
