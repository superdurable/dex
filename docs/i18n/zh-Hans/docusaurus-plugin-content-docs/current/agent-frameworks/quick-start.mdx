# Agent 快速开始

把你所用框架的 Agent 作为持久化 Dex Session 运行，然后在对话中途停止它，看它继续运行。整个过程大约 10 分钟。

这个 Agent 是一个小型订单客服 Agent，有两个 tool。`look_up_order` 读取订单，因此 Dex 可以重试它。`cancel_order` 取消尚未发货的订单；它是写操作，所以最多运行一次，并且要等人批准后才运行。

## 2. 批准一次写操作 {#approve-a-write}

用消息 **Cancel order 1002** 运行同一条命令。程序会停下来询问：

```text
cancel_order wants to run with {"order_id":"1002","reason":"requested by the customer"}. Approve? [y/N]
```

Session 在 `AwaitToolApproval` 中等待。输入 **y**，Agent 就会取消订单并回复。[审批](/agent-frameworks/approvals) 介绍应用如何读取并答复正在等待的调用，以及人如何在 Dex Web 中批准它。

## 3. 在 Agent 等待时停止程序 {#stop-the-worker}

再次要求取消订单 1002；每次不带 `--session-id` 运行都会启动一个新 Session。程序请你批准时，按 Ctrl+C。程序、它的 Worker 和 Client 都会停止，而 Session 仍在 Dex 中等待。

在同一个文件夹中再次运行第 1 步的命令，用 `--session-id SESSION_ID` 替换消息。新的 Worker 启动，程序会询问同一个 `cancel_order` 调用。输入 **y**。订单只取消一次，重启之前的模型调用仍然是已完成状态。

## 4. 在 tool 运行时停止 {#stop-while-a-tool-runs}

在 Tool Call 中途崩溃是更难处理的情况。示例可以放慢每次 Tool Call，让你有时间停止它。

1. 在第 1 步的命令前加上 `DEX_ORDER_DESK_TOOL_DELAY_SECONDS=20`，询问订单 1001。
2. 在 20 秒内像崩溃那样杀掉程序。崩溃相当于 kill 信号；Ctrl+C 会先让正在运行的调用完成。

3. 带上 `--session-id`、不带消息，再次运行程序。Agent 会回复订单信息。
4. 查看这次 Tool Call 是如何运行的：

```bash
dexcli flow history --all SESSION_ID | jq '.events[]
  | select(.payload.context.stepType == "CallTool")
  | .payload.context | {finalAttempt, failure: .lastFailureInfo.details.detail}'
```

`finalAttempt` 是 **2**。第一次尝试在 Worker 断开时失败；因为 `look_up_order` 是读操作，Dex 在新的 Worker 上再次运行了它。它之前的模型调用只运行了一次。

现在对写操作做同样的事：设置延迟后要求取消订单 1002，批准它，在 20 秒内杀掉程序，再带上 `--session-id` 运行。Dex 把 `cancel_order` 记录为 `outcome_unknown`，并且不会再运行第二次，因为它是非幂等写操作。Agent 会告诉用户结果未知，由你的应用在任何人重试之前先检查订单系统。[核对 outcome_unknown](/agent-frameworks/tool-calls#reconcile-outcome-unknown) 介绍具体做法。

/** Returns the agent's options as the Claude Agent SDK alone writes them. */
export function buildPlainAgent(orderDesk: OrderDesk, model: string): Options {
  const orders = createSdkMcpServer({ name: "orders", tools: buildOrderTools(orderDesk) });
  return {
    model,
    systemPrompt: orderSupportInstructions,
    mcpServers: { orders },
    allowedTools: ["mcp__orders__look_up_order", "mcp__orders__cancel_order"],
  };
}

/** Returns the same agent as a durable Dex agent session. Dex passes the tools to the CLI itself. */
export function buildDurableAgent(
  orderDesk: OrderDesk,
  model: string,
  cliEnvironment: Readonly<Record<string, string>>,
): AgentSessionFlow {
  return createClaudeAgentSessionFlow(
    {
      options: { model, systemPrompt: orderSupportInstructions, tools: [], settingSources: [], env: { ...cliEnvironment } },
      customTools: buildOrderTools(orderDesk),
      toolPolicies: {
        look_up_order: { effect: "read" },
        cancel_order: { effect: "non_idempotent_write" },
      },
    },
    "ClaudeAgentSdkQuickStart",
  );
}

/** Returns the agent as Mastra alone writes it. */
export function buildPlainAgent(orderDesk: OrderDesk, model: MastraModelConfig): Agent {
  const lookUpOrder = createTool({
    id: "look_up_order",
    description: "Look up one order by its order ID and return its items and status.",
    inputSchema: z.object({ order_id: z.string() }),
    execute: async ({ order_id }) => orderDesk.describeOrder(order_id),
  });
  const cancelOrder = createTool({
    id: "cancel_order",
    description: "Cancel one order that has not shipped yet.",
    inputSchema: z.object({ order_id: z.string(), reason: z.string() }),
    execute: async ({ order_id, reason }) => orderDesk.cancelOrder(order_id, reason),
  });
  return new Agent({
    id: "order-support",
    name: "OrderSupport",
    instructions: orderSupportInstructions,
    model,
    tools: { look_up_order: lookUpOrder, cancel_order: cancelOrder },
  });
}

    toolPolicies: {
      look_up_order: { effect: "read" },
      cancel_order: { effect: "non_idempotent_write" },
