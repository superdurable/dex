# 开发者参考

开发者参考记录随版本变化的细节：配置项、flag、默认值、限制、指标、边界情况和版本差异。概念请看 [概念](/concepts) 和 [运行 Dex](/components)。开发者参考只有英文版。

## 先确认版本 {#check-your-version-first}

每个组件有自己的参考。依赖某个细节之前，先确认你运行的组件版本。每份参考默认打开最新版本。要看其他版本，用左侧栏中该组件下方的版本选择器。[兼容性矩阵](#compatibility-matrix) 列出支持的组件组合。

Dex 按一个共享的 release train 发版。每次发版只给有改动的组件打 tag，所以组件的 minor 版本号可能跳过。参考里说某个组件的 N 版本时，指的是该组件不超过 N 的最新版本。

## SDK 主题页 {#flows-and-steps}

每个 SDK 参考为[概念](/concepts)中的每个主题各写一页：Flow、Step、Attribute、RPC、Channel、Stream、Timer、SubFlow 和 Client。另外几页讲 StartFlowOptions、StepOptions、Step decision、wait、失败与重试，以及 Worker。每页都用该语言的名称和代码：[Go](/reference/go/)、[Python](/reference/python/)、[Java](/reference/java/)、[TypeScript](/reference/typescript/) 和 [Rust](/reference/rust/)。

## 兼容性矩阵 {#compatibility-matrix}

每个 server-zd 版本接受一个协议版本范围。每个客户端版本需要一个最低协议版本，有些还需要更新的 server-zd 版本。较新的 server 会一直接受较旧的客户端，直到它提高最低协议版本。

每一行是一个受支持的 server-zd 版本。每个单元格给出能和这个 server 一起使用的某个客户端的最旧和最新版本。两者之间的版本只要已发布到对应的 registry，也可以使用。Dex Agents 包和 Agents CLI 按 registry 分开列出，因为一个版本可能只发布到一个 registry。

<ServerZdCompatibilityMatrix />

每一行都有锚点 **server-zd-MAJOR-MINOR-PATCH**，例如 **server-zd-0-1-31**，链接可以直接打开某个 server-zd 版本的那一行。每个 server-zd 参考版本在它的 [Upgrades and compatibility](/reference/server/upgrades#compatible-client-releases) 页面上显示自己的那一行。

程序可以从 [server-zd.json](https://docs.superdurable.io/compatibility/server-zd.json) 读取同样的数据。它的 [JSON Schema](https://docs.superdurable.io/compatibility/server-zd.schema.json) 说明每个字段和兼容规则。新字段可能出现而 `schemaVersion` 不变，所以程序应忽略不认识的字段。要固定某个 Agents CLI 命令包的版本，从 `agentsCliCommands` 读取它的范围。

Dex Web 1.45, 1.43, 1.41, 1.40, 1.37 需要 server-zd 0.1.17 或更新（协议版本 4）。

先升级 server，再升级 SDK。见 [Upgrades and compatibility](/reference/server/upgrades)。

每个 `dexcli` 版本打包一个 server-zd 版本，**dexcli dev** 运行的就是它：

| dexcli | 打包的 server-zd |
| --- | --- |
| 1.45 | 0.1.26 |
| 1.43 | 0.1.25 |
| 1.41 | 0.1.25 |
| 1.40 | 0.1.25 |
| 1.37 | 0.1.20 |

## 发版说明 {#release-notes}

每个组件都在 GitHub 的 [Dex releases](https://github.com/superdurable/dex/releases) 发布发版说明。server-zd 每个版本的说明都列出 breaking change、新功能、修复和升级步骤。
