# 快速开始

运行你的第一个 Flow，在它等待的中途停掉 Worker，然后看 Dex 在重启后继续这个 Flow。整个过程大约 10 分钟。

<a id="before-you-start"></a>

## 1. 安装 Dex 并获取代码 {#1-install-dex-and-get-the-code}

你需要 macOS 或 Linux，以及三个终端：一个运行 `dexcli dev`，一个运行 Worker，一个用来启动 Flow。

在第一个终端里安装 `dexcli` 并启动 Dex。[本地运行](/components/run-locally)介绍不用 Homebrew 的安装方式。

```bash
brew install superdurable/tap/dexcli
dexcli dev
```

**dexcli dev** 会启动 Dex Server 和 Dex Web。准备就绪后，第一个终端打印：

```text
Dex development environment is ready

Dex Web:       http://127.0.0.1:8802
Connectors MCP: http://127.0.0.1:8802/mcp
Dex Server:    127.0.0.1:8801
State dir:     /Users/you/.dex/zd/8801

Press Ctrl+C to stop.
```

让它一直运行，server 的日志会在这段输出上方滚动。本教程用不到 **Connectors MCP** 地址。

在第二个终端里下载示例。这条命令下载仓库的归档文件，只解压出示例所在的文件夹，不需要 clone 仓库：

## 2. 阅读 Flow {#2-read-the-flow}

<a id="what-you-will-build"></a>

这个示例是一个订单 Flow，有两个 Step：

- **Charge** 通过一个 mock 支付 API 为订单扣款。
- **Ship** 在 Timer 上等待 60 秒，然后通过一个 mock 物流 API 为订单发货。

mock API 会打印每一次调用，所以从 Worker 的输出就能看出哪些 Step 运行过。你启动一个 Flow，在 Ship 等待时停掉 Worker，再重新启动 Worker。Timer 触发时 Ship 运行，而 Charge 只运行一次。

<CrashTimeline variant="quick-start" />

这一步和下一步讲解你下载的文件夹里的代码。

Flow 是 Dex 一直运行到完成的流程。其中每个 Step 是一个工作单元。Dex 保存每个 Step 的结果，所以已经完成的 Step 不会再运行。

**Charge** 调用支付 API，然后转到 **Ship**。**Ship** 在 Timer 上等待（默认 60 秒），然后调用物流 API。每次调用都传入一个幂等键，第 6 步会展示它的作用。mock API 通过构造函数传入。

```python
class Charge(Step[str]):
    def __init__(self, shop: ShopApi) -> None:
        self.shop = shop

    def execute(self, context: Context, input: str) -> StepDecision:
        self.shop.charge(input, idempotency_key=f"charge-{input}")
        return go_to(Ship, input)


class Ship(Step[str]):
    def __init__(self, shop: ShopApi) -> None:
        self.shop = shop

    def wait_for(self, context: Context, input: str) -> Wait:
        return Wait.until(
            Timer.by_duration(SHIP_DELAY, condition_id=SHIP_DELAY_TIMER)
        )

    def execute(self, context: Context, input: str) -> StepDecision:
        self.shop.ship(input, idempotency_key=f"ship-{input}")
        return graceful_complete(f"shipped {input}")


class OrderFlow(Flow[str]):
    def __init__(self, shop: ShopApi) -> None:
        self.charge = Charge(shop)
        self.ship = Ship(shop)

    def get_steps(self) -> StepList[str]:
        return StepList.start_step(self.charge).other_steps(self.ship)
```

Step 返回的决定（decision）用类来指定下一个 Step：`go_to(Ship, input)`。

`Timer.by_duration` 的 `condition_id` 参数 **ship-delay** 为这个 Timer 命名。这样测试或运维人员可以用 **skip-timer** 提前结束等待，不必等到时间结束。

`graceful_complete` 会在没有其他 Step 运行时让 Flow 成功结束，并返回 Flow 的结果。

</SdkSnippet>
<SdkSnippet lang="go">

```go
// OrderFlow charges an order, waits 60 seconds, and then ships it.
type OrderFlow struct {
	dex.FlowDefaults
	shop *ShopAPI
}

// NewOrderFlow returns an OrderFlow whose Steps call shop.
func NewOrderFlow(shop *ShopAPI) *OrderFlow {
	return &OrderFlow{shop: shop}
}

// GetSteps returns Charge as the start Step, then Ship.
func (flow *OrderFlow) GetSteps() []dex.StepDef {
	return []dex.StepDef{
		dex.DefineStartStep(Charge{shop: flow.shop}),
		dex.DefineStep(Ship{shop: flow.shop}),
	}
}

// GetPersistenceSchema returns an empty schema: OrderFlow keeps no Attributes.
func (*OrderFlow) GetPersistenceSchema() dex.PersistenceSchema {
	return dex.PersistenceSchema{}
}

// Charge charges the order and moves to Ship.
type Charge struct {
	dex.StepDefaultsNoWaitFor[string]
	shop *ShopAPI
}

// Execute charges the order.
func (step Charge) Execute(_ dex.Context, orderID string) (*dex.StepDecision, error) {
	if err := step.shop.Charge(orderID, "charge-"+orderID); err != nil {
		return nil, err
	}
	return dex.GoTo(Ship{}, orderID), nil
}

// Ship waits on a Timer, 60 seconds by default, then ships the order.
type Ship struct {
	dex.StepDefaults
	shop *ShopAPI
}

// WaitFor waits on the ship-delay Timer.
func (Ship) WaitFor(_ dex.Context, _ string) (*dex.Wait, error) {
	return dex.Until(dex.Timer(ShipDelay(), dex.WithConditionID(ShipDelayTimer))), nil
}

// Execute ships the order and completes the Flow.
func (step Ship) Execute(_ dex.Context, orderID string) (*dex.StepDecision, error) {
	if err := step.shop.Ship(orderID, "ship-"+orderID); err != nil {
		return nil, err
	}
	return dex.GracefulComplete("shipped " + orderID), nil
}
```

Step 返回的决定（decision）用类型来指定下一个 Step：`dex.GoTo` 接收一个空的 `Ship` 结构体值。

Timer 的 `dex.WithConditionID` 选项 **ship-delay** 为它命名。这样测试或运维人员可以用 **skip-timer** 提前结束等待，不必等到时间结束。

`dex.GracefulComplete` 会在没有其他 Step 运行时让 Flow 成功结束，并返回 Flow 的结果。

```java
public final class OrderFlow implements Flow<String> {
    public static final String SHIP_DELAY_TIMER = "ship-delay";

    private final Charge charge;
    private final Ship ship;

    public OrderFlow(final ShopApi shop) {
        this.charge = new Charge(shop);
        this.ship = new Ship(shop);
    }

    @Override
    public StepList<String> getSteps() {
        return StepList.startStep(charge).otherSteps(ship);
    }

    static final class Charge implements Step<String> {
        private final ShopApi shop;

        Charge(final ShopApi shop) {
            this.shop = shop;
        }

        @Override
        public Class<String> getInputType() {
            return String.class;
        }

        @Override
        public StepDecision execute(final Context context, final String orderId) {
            shop.charge(orderId, "charge-" + orderId);
            return StepDecision.goTo(Ship.class, orderId);
        }
    }

    static final class Ship implements Step<String> {
        private final ShopApi shop;

        Ship(final ShopApi shop) {
            this.shop = shop;
        }

        @Override
        public Class<String> getInputType() {
            return String.class;
        }

        @Override
        public Wait waitFor(final Context context, final String orderId) {
            return Wait.until(Timer.byDuration(QuickStartConfig.SHIP_DELAY, SHIP_DELAY_TIMER));
        }

        @Override
        public StepDecision execute(final Context context, final String orderId) {
            shop.ship(orderId, "ship-" + orderId);
            return StepDecision.gracefulComplete("shipped " + orderId);
        }
    }
}
```

```rust
#[derive(Clone)]
pub struct Charge {
    shop: ShopApi,
}

impl Step for Charge {
    type Input = String;

    fn execute(&self, _context: &mut Context, order_id: String) -> HandlerResult<StepDecision> {
        self.shop
            .charge(&order_id, &format!("charge-{order_id}"))
            .map_err(HandlerError::from_error)?;
        let ship = Ship {
            shop: self.shop.clone(),
        };
        Ok(StepDecision::go_to(&ship, order_id))
    }
}

#[derive(Clone)]
pub struct Ship {
    shop: ShopApi,
}

impl Step for Ship {
    type Input = String;

    fn wait_for(&self, _context: &mut Context, _order_id: String) -> HandlerResult<Wait> {
        let delay = Timer::by_duration(ship_delay_from_environment()).with_id(SHIP_DELAY_TIMER);
        Ok(Wait::until(delay))
    }

    fn execute(&self, _context: &mut Context, order_id: String) -> HandlerResult<StepDecision> {
        self.shop
            .ship(&order_id, &format!("ship-{order_id}"))
            .map_err(HandlerError::from_error)?;
        Ok(StepDecision::graceful_complete(format!(
            "shipped {order_id}"
        )))
    }
}

#[derive(Clone)]
pub struct OrderFlow {
    pub charge: Charge,
    pub ship: Ship,
}

impl OrderFlow {
    pub fn new(shop: ShopApi) -> Self {
        Self {
            charge: Charge { shop: shop.clone() },
            ship: Ship { shop },
        }
    }
}

impl Flow for OrderFlow {
    type StartInput = String;

    fn steps(&self) -> StepList<'_, String> {
        StepList::start(&self.charge).and(&self.ship)
    }
}
```

`StepDecision::graceful_complete` 会在没有其他 Step 运行时让 Flow 成功结束，并返回 Flow 的结果。

Timer 是持久的。Dex 在 server 上保存这次等待，所以等待不依赖正在运行的 Worker。

## 3. 添加 Worker 和 Client {#3-add-a-worker-and-a-client}

Worker 运行 Step。它主动连接 Dex 来领取工作，所以不需要开放端口。Client 负责启动 Flow。

两个程序构建同一个 Flow，并把它注册到 `Registry` 中。`Registry` 是 Worker 运行、Client 可以启动的 Flow 列表。所以启动 Flow 的 Web 服务也需要 Flow 的代码：它注册 Flow 定义，但从不运行其中的 Step。[从 API 服务启动 Flow](/concepts/client#start-from-an-api-service)展示了这种做法。

:::note 细节

两个 Step 都是默认的 SYNC：Dex 先保存每个结果，Flow 才继续往下走。[SYNC 和 ASYNC Step](/concepts/step/advanced-guarantees#sync-and-async)介绍另一种选择。

Client 用注册的 Flow 来确定 Flow type 并编码输入，所以它持有的那份 mock API 永远不会被调用。在你自己的 API 服务中，也用同样的方式传入替身；见[从 API 服务启动 Flow](/concepts/client#start-from-an-api-service)。要只凭 type 名称启动 Flow，可以在终端里用 **dexcli flow start -flow-type**，SDK 的 Client 没有这样的调用。每个程序还会打开一个本地 [blob cache](/components/application#blob-cache)，用来保存大值的副本。

:::

```go
func run() (err error) {
	shop, err := quickstart.NewShopAPIFromEnvironment()
	if err != nil {
		return err
	}
	registry, err := dex.NewRegistry([]dex.Flow{quickstart.NewOrderFlow(shop)})
	if err != nil {
		return err
	}
	cache, err := quickstart.OpenCache(".dex-blob-cache/worker")
	if err != nil {
		return err
	}
	defer func() { err = errors.Join(err, cache.Close()) }()
	worker, err := dex.NewWorker(registry, cache, dex.WorkerOptions{
		FlowServiceAddress: quickstart.ServerAddress(),
	})
	if err != nil {
		return err
	}
	workerResult := make(chan error, 1)
	go func() { workerResult <- worker.Start() }()

	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()
	startupCtx, cancel := context.WithTimeout(ctx, 30*time.Second)
	defer cancel()
	if err := worker.WaitPullRegistered(startupCtx); err != nil {
		return errors.Join(err, worker.Stop(context.Background()), <-workerResult)
	}
	fmt.Printf("Worker is ready (process %d). Press Ctrl+C to stop it.\n", os.Getpid())

	select {
	case err := <-workerResult:
		return err
	case <-ctx.Done():
		fmt.Println("Stopping the Worker.")
		return errors.Join(worker.Stop(context.Background()), <-workerResult)
	}
}
```

```java
public static void main(final String[] args) throws Exception {
    final OrderFlow orderFlow = new OrderFlow(QuickStartConfig.newShopApi());
    final Registry registry = new Registry(List.of(orderFlow));
    final BlobCache cache = QuickStartConfig.openCache(Paths.get(".dex-blob-cache", "worker"));
    final Worker worker = new Worker(
            registry,
            cache,
            WorkerOptions.newBuilder().serverAddress(QuickStartConfig.SERVER_ADDRESS).build());
    final Thread workerThread = new Thread(worker::start, "dex-worker");
    workerThread.setDaemon(true);
    Runtime.getRuntime().addShutdownHook(new Thread(() -> {
        System.out.println("Stopping the Worker.");
        worker.close();
        cache.close();
    }));
    workerThread.start();
    worker.waitPullRegistered(Duration.ofSeconds(30));
    System.out.println("Worker is ready (process " + ProcessHandle.current().pid()
            + "). Press Ctrl+C to stop it.");
    workerThread.join();
}
```

```rust
fn main() -> Result<(), Box<dyn Error>> {
    let config = QuickStartConfig::from_environment();
    let registry = Registry::new().register(OrderFlow::new(config.new_shop_api()))?;
    let cache = open_blob_cache(".dex-blob-cache/worker")?;
    let options = WorkerOptions::new().server_address(config.server_address);
    let worker = Arc::new(Worker::try_new(registry, cache, options)?);
    let running_worker = Arc::clone(&worker);
    let worker_thread = thread::spawn(move || running_worker.start());

    let runtime = tokio::runtime::Builder::new_current_thread()
        .enable_all()
        .build()?;
    let outcome = runtime.block_on(async {
        tokio::time::timeout(Duration::from_secs(30), worker.wait_pull_registered()).await??;
        println!(
            "Worker is ready (process {}). Press Ctrl+C to stop it.",
            std::process::id()
        );
        tokio::signal::ctrl_c().await?;
        println!("Stopping the Worker.");
        Ok::<(), Box<dyn Error>>(())
    });

    worker.stop();
    let stopped = worker_thread
        .join()
        .map_err(|_| "the Worker thread panicked")?;
    outcome?;
    Ok(stopped?)
}
```

`src/bin/start.rs` 中的 Client：

```rust
fn main() -> Result<(), Box<dyn Error>> {
    let config = QuickStartConfig::from_environment();
    let order_id = std::env::args()
        .nth(1)
        .unwrap_or_else(|| format!("order-{:08x}", fastrand::u32(..)));
    let order_flow = OrderFlow::new(ShopApi::default());
    let registry = Registry::new().register(order_flow.clone())?;
    let cache = open_blob_cache(".dex-blob-cache/client")?;
    let options = ClientOptions::new().server_address(config.server_address);
    let client = Client::try_new(registry, cache, options)?;
    client.start_flow(&order_flow, &order_id, order_id.clone())?;
    println!("Started Flow {order_id}. Ship runs in 60 seconds.");
    Ok(())
}
```

## 5. 停掉 Worker {#5-stop-the-worker}

在 60 秒内，在 Worker 的终端里按 Ctrl+C。然后用同一条命令再次启动 Worker。如果错过了这段时间，就用更长的等待重启 Worker，比如在命令前加上 `QUICK_START_SHIP_DELAY_SECONDS=120`，再启动一个新的 Flow。

Timer 触发时，新的 Worker 打印发货信息：

```text
Worker is ready (process 41388). Press Ctrl+C to stop it.
Shipped order-1a2b3c4d with key ship-order-1a2b3c4d
```

只有 Ship 运行了：Dex 已经保存了 Charge 的结果，所以 **Charged** 只出现一次。

### 排查问题 {#if-nothing-happens}

- **缺少 “Worker is ready”。** 检查 **dexcli dev** 是否仍在运行，并且打印过 “Dex development environment is ready”。
- **Dex 运行在其他地址上。** 在 Worker 和启动命令各自的终端里都设置 `DEX_FLOW_SERVICE_ADDRESS`，比如 **127.0.0.1:8801**。
- **启动命令失败。** 在示例文件夹中运行它，并且先运行第 1 步的安装命令。
- **停掉 Worker 之前 Ship 已经运行了。** 你错过了 60 秒的时间窗口。用 `QUICK_START_SHIP_DELAY_SECONDS=120` 重启 Worker，并启动一个新的 Flow。
- **按 Ctrl+C 后 Worker 仍在运行。** 它会先完成正在运行的 Step。要立即停止它，用 **kill -9** 加上它的进程号。

## 6. 在 Step 内部停掉 Worker {#6-stop-the-worker-inside-a-step}

第 5 步是在两个 Step 之间停掉 Worker。这一步在 Charge 内部停掉它：在支付调用之后、Dex 记录这个 Step 之前。随后 Dex 会再次运行 Charge，幂等键保证不会付款两次。[幂等键](/concepts/step#idempotency-keys)说明怎样构造这个键。

mock API 会像支付服务商那样，把每个键记在 `.shop-api-keys` 中。用 Ctrl+C 停掉 Worker。然后重新启动它，让它在每次新扣款之后暂停 20 秒：


</SdkSnippet>


</SdkSnippet>

```bash

```

</SdkSnippet>
<SdkSnippet lang="typescript">

```bash

```

</SdkSnippet>
<SdkSnippet lang="rust">


用第 4 步的启动命令再启动一个 Flow。Worker 打印 **Charged** 时，立即在第三个终端里停掉它。把 **PID** 换成这个 Worker 启动时打印的进程号。用 Ctrl+C 的话，Charge 会先运行完。

```bash
kill -9 PID
```

用第 4 步的命令再次启动 Worker。Dex 从未记录第一次 Charge，所以会再次运行 Charge。mock API 看到同一个键，不会扣款两次：

```text
Worker is ready (process 41502). Press Ctrl+C to stop it.
Charge for order-5e6f7a8b already done (key charge-order-5e6f7a8b); not charged again
```

Ship 的 Timer 触发时（默认在 Charge 完成 60 秒后），Worker 为订单发货。
