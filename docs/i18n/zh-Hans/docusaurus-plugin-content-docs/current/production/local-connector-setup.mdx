# 本地 Connector 配置

Dex Web 可以为本地 Go 应用配置官方 Connector release。此功能只在使用本地
Flow Definition Graph、并绑定 loopback 地址的 **dexcli dev** 中启用。生产环境
Dex Web、非 loopback listener 和 blobstore definition source 不会开放这些配置
API。

## 启动 Dex Web

先生成 Flow Definition Graph 2.0 文件，再启动本地 stack：

```bash
dexcli dev --flow-rendering-dir ./build
```

打开 **/v2/connections** 的 **Connections** 页面。Dex Web 按 Connector ID 和
connection name 对 Step 与 Trigger binding 分组，并显示 Flow、Step、operation、
binding、精确 module version，以及 **Missing**、**Ready**、**Expired**、
**Conflict** 或 **Unsupported** 状态。

自动配置要求使用 operation-specific 的 Connector 生成工厂或 Trigger-binding
definition、编译期可确定的 connection name 和 binding name，以及精确的已发布
module version。Generic factory、本地 module replacement、未发布 module、缺少
name 或版本冲突仍会显示，但不能自动配置。

## 选择存储目录

默认目录是 **$HOME/.dex/connectors**，文件名固定为 **connections.json**。需要
隔离某个 stack 时可以覆盖目录：

```bash
dexcli dev \
  --flow-rendering-dir ./build \
  --connector-config-dir ./local-dex-secrets
```

Dex 会把目录解析为绝对路径。Connections 页面会显示目录和最终 JSON 路径。
多个本地 stack 默认共享同一个文件；如果不能共享账号，应为每个 stack 指定
不同目录。

Dex 以 **0700** 创建目录，以 **0600** 创建文件。Symlink 文件、非普通文件和
权限过宽的已有 credential 文件会被拒绝。更新过程使用同目录临时文件、sync
和原子 rename，因此应用不会读到只写了一部分的文档。

重启 Dex Web 会重新加载已有 connection 和缓存的 UI artifact，不会清空 JSON
文件。进行中的 OAuth flow 与 Connector UI session 只存在内存中；重启后需要
重新发起。

## 配置账号

选择命名 connection。Dex Web 会校验官方 release metadata 和 checksum。有兼容
Studio UI 时，它会在 opaque-origin sandbox 中加载；否则根据 manifest 渲染通用
表单。

OAuth 始终使用 state 和十分钟一次性 session。Provider 支持对应授权流程时，
Connector 还会使用 PKCE。OAuth client ID 与 client secret 只存在内存中，不会
写入磁盘。Dex 检查 granted scope 后保存短期 access token，不保存 refresh
token，也不会自动刷新。Connection 变为 **Expired** 后需要重新授权。

删除本地 credential 只删除本地记录，不会远程 revoke provider grant。

## 配置 Slack Trigger binding

Slack connection 与每个 Trigger binding 分开配置。因此，一个
**slack-workspace** connection 可以被多个 Flow 复用，而每个 Flow 分别保存自己的
频道、发起人、批准短语和 approver 列表。

Slack OAuth 会同时保存 bot token 和 user token。App-level token 无法通过 OAuth
签发。请创建具有 **connections:write** scope 的 **xapp-** token，并把它填入
secret 字段。Token 只留在 Dex Web host 中，不会发送给 sandboxed Studio UI。

Slack Studio 会显示：

- 单选频道、公开或私有状态，以及稳定的 **C…** ID；
- 可选的 Flow 发起成员，或选择 **任意真人**；
- 至少一名允许批准的成员；
- 可选且不区分大小写的消息 substring filter。

Picker 虽然显示名称和头像，但保存的是稳定 Slack ID；每个原始 ID 都可以查看和
复制。如果 Slack API 不可用，可以手工输入 ID。在 Slack 中打开 channel details
并选择 **Copy channel ID**；打开成员 profile 菜单并选择 **Copy member ID**。
Private channel 只有先邀请 bot 加入后才会出现在 picker 中。

Slack thread approval 示例的默认 approval substring 是 **approve**。Substring
匹配也会接受 **disapprove** 等文本；如果必须使用明确的批准措辞，请改成更独特
的短语。

Trigger binding 不保存 RPC name。应用负责把 Slack thread identity 映射为 Flow
ID，并注册 Trigger runner 调用的 typed RPC definition。

## 启动 Go 应用

配置完成后复制 Dex Web 显示的启动命令。默认路径为：

```bash
DEX_CONNECTOR_CONFIG_FILE="$HOME/.dex/connectors/connections.json" <your-app-command>
```

Connector Go SDK 在应用构造命名 Connection 时读取 configuration，因此
configuration 变化后需要重启应用。每次 provider call 前都会重新读取
credential，所以重新授权会在下一次调用生效，不需要重启应用。

该 JSON 文件以明文保存 secret，只适用于本地开发。不要提交或上传，也不要把它
当作生产 secret broker。Connector secret 在应用边界变为 **SecretString**，不得
进入 Flow state 或日志。

同一个文件还会在 workspace connection 之外保存 **triggerBindings**。每个
binding 由 Connector ID、connection name、Trigger name 和 binding name 唯一
标识。修改一个 Flow 的 binding 不会影响共享该账号的其他 Flow。
