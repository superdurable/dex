# 概念

Dex 的编程模型很小。Flow 是一个持久化程序。Step 推动它前进。Primitive 保存它的状态，并把它和外部世界连起来。你的应用通过 Client 驱动 Flow。

## Flow 和 Step {#flow-and-step}

| 概念 | 它是什么 | 用它来 |
| --- | --- | --- |
| [Flow](/concepts/flow) | 一个带业务 ID 的持久化程序。它拥有自己的 Step、状态和消息。 | 建模一个业务流程或一个实体。 |
| [Step](/concepts/step) | Flow 里的一个工作单元。它等待、执行，并决定接下来运行什么。 | 做工作，推动流程前进。 |

## Primitive {#the-primitives}

Primitive 是 Flow 使用的构件。每个 Primitive 都属于一个 Flow。

| Primitive | 它是什么 | 用它来 |
| --- | --- | --- |
| [Attribute](/concepts/primitives/attribute) | 属于一个 Flow 的持久化状态。 | 在 Step 之间保存数据，从外部读取它，并按它搜索。 |
| [RPC](/concepts/primitives/rpc) | 对一个 Flow 的同步调用。 | 从你的应用发送命令、读取视图。 |
| [Channel](/concepts/primitives/channel) | Flow 里的一个持久化消息队列。 | 投递 Step 等待的消息。 |
| [Stream](/concepts/primitives/stream) | 一个尽力而为、读者可以续读的数据流。 | 把实时进度推送给 UI。 |
| [Timer](/concepts/primitives/timer) | 一个等到某个时间点的持久化等待。 | 设置截止时间、提醒和计划任务。 |
| [SubFlow](/concepts/primitives/subflow) | 由另一个 Flow 作为子 Flow 启动的 Flow。 | 把大块或并行的工作拆成子 Flow。 |

## Client {#client}

[Client](/concepts/client) 是你的应用在 Worker 之外使用的 API。用它来启动、调用、读取、等待和操作 Flow。

## Connector {#connector}

[Connector](/concepts/connector) 把 Flow 连接到外部服务商，例如邮件或支付服务。它为你的 Flow 提供调用该服务商的现成 Step，以及根据服务商事件启动或更新 Flow 的 Trigger。

<a id="它们如何配合"></a>

## 它们如何配合 {#how-they-fit-together}

```text
 Your application                      One Flow (one Flow ID)
 ┌────────────┐   StartFlow, RPC      ┌──────────────────────────────────┐
 │   Client   │ ────────────────────▶ │  Step ──▶ Step ──▶ Step ...      │
 │            │   GetAttributes, wait │   waits on Channel, Timer,       │
 │            │ ◀──────────────────── │   SubFlow; calls Connectors      │
 │            │   Stream (live)       │                                  │
 │            │ ◀──────────────────── │  Attributes  Channels  Streams   │
 └────────────┘                       └──────────────────────────────────┘
```

**Flow** 是容器。一个 Flow ID（例如订单号）同一时间最多只有一个活跃的 run。

**Step** 推动 Flow 前进。Step 可以等待 Channel 消息、Timer 或 SubFlow。然后它执行自己的工作，例如通过 Connector 发起调用。它返回一个决定，指定接下来的 Step，或者结束 Flow。Step 失败时 Dex 会重试。

**Attribute** 和 **Channel** 是 Flow 的持久化状态。Step 和 RPC 读写它们。Dex 把一个 Step 方法或 RPC 的状态修改和它的结果一起保存。见 [Step 的保证](/concepts/step#guarantees)。

你的应用用 **Client** 启动 Flow、调用 RPC、读取 Attribute，以及等待变化。要修改一个正在运行的 Flow，你的应用调用 RPC。**Stream** 把实时更新带回 UI。

<a id="component"></a>

## 组件 {#components}

概念是编程模型。下面这些进程运行它，[运行 Dex](/components) 逐一介绍：

- 你的**应用**在 Worker 里托管 Flow 代码，并通过 Client 调用 Dex。
- [Dex Server](/components/server) 保存 Flow 状态，并把 Step 和 RPC 交给 Worker。
- `dexcli` 在本地运行 Dex，**Dex Web** 让运维人员查看 Flow。

## Dex 保证什么 {#guarantees}

Dex 把每个 Step 的结果和转到下一个 Step 的动作一起保存。已经完成的 Step 不会再运行；唯一的例外是 [ASYNC Step](/concepts/step/advanced-guarantees#sync-and-async)，如果 server 节点在写入它的结果之前故障，它可能再运行一次。被中途打断的 Step 可能再运行一次；见[幂等键](/concepts/step#idempotency-keys)。重试读取的是第一次尝试的[状态快照](/concepts/step#guarantees)，而不是之后更新的写入。[Step](/concepts/step#guarantees) 列出了每一条保证和它的限制。

并行的 Step 和 RPC 共享 Attribute，彼此之间不隔离；见 [Attribute lock](/concepts/primitives/attribute#locking)。[故障转移和部署](/concepts/failover-and-deploys)列出崩溃、server 故障转移或部署之后哪些工作会再运行。

## 修改 Flow 代码 {#change-flow-code}

部署之后，未结束的 Flow 可能遇到改变了的规则或改了名的 Step。[Flow 代码的版本管理](/concepts/change-flow-code#versioning-flow-code)说明怎样让它们继续工作。修复之后，[Time Travel](/concepts/change-flow-code#time-travel)可以让 Flow 从更早的某个点重新运行。
