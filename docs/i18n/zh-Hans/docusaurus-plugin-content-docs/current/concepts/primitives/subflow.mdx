# SubFlow

**SubFlow** 是父 Flow 从它的某个 Step 启动的 Flow run。子 Flow 是一个普通的 Flow，有自己的 Step、Attribute 和 Channel。父 Flow 像等待 `WaitFor` 中的其他 condition 一样等待它。

## 什么时候用 SubFlow

SubFlow 主要有两种用途：

1. 把复杂逻辑拆到更小的 Flow 中。这让业务逻辑更容易维护。
2. 扇出工作。一个 Flow run 不能同时运行太多操作，但可以把工作交给很多 SubFlow。这些 SubFlow 同时运行，父 Flow 因此能达到高得多的并发。

## 保证

Dex Server 根据父 Flow ID、Step execution 和 condition 序号计算 SubFlow ID。因此重试或重复启动会找到同一个子 Flow，而不是再启动一个。默认情况下，父 Flow 继续等待运行中的子 Flow，使用已完成子 Flow 的结果，并重启异常结束的子 Flow。

SubFlow ID 用短横线连接各个部分。所以 Step type 含短横线的 Step 不能启动 SubFlow，否则两个父 Flow 可能算出同一个 SubFlow ID，共用一个子 Flow。Dex 会让这样的 WaitFor attempt 直接失败，不再重试。启动 SubFlow 的 Step，Step type 里不要有短横线。

用同一个父 Flow ID 再启动一次时，新的 run 通常会算出和之前的 run 相同的 SubFlow ID。这时 Dex 按 reuse policy 处理。使用默认 policy 时，新的 run 会拿到之前 run 的子 Flow（无论它还在运行还是已经完成），直到 Dex 删除那个子 Flow。要让每个 run 都启动新的子 Flow，就用 `ALWAYS_RESTART`。如果之前的子 Flow 还在运行，它会被终止。两个子 Flow 都要继续运行时，换一个父 Flow ID。

父 Step 被取消或父 Flow 关闭时，子 Flow 会继续运行。你需要自己停止它，或者给子 Flow 设置 Flow timeout，让它到时自行结束。

## 启动并等待 SubFlow

目标 Flow 必须注册在 Worker 上。它的 start Step 必须接受传给 **SubFlow** 的输入。`WaitFor` 启动子 Flow。子 Flow 完成后，`Execute` 读取它的结果。

```python
    def __init__(self, target: Flow[int]) -> None:

        self.options = SubFlowOptions(
```

```go
type subFlowParent struct {
	dex.StepDefaults
	child *SubFlowChildFlow
}

func (step subFlowParent) WaitFor(_ dex.Context, input int) (*dex.Wait, error) {
	timeout := time.Hour
	return dex.Until(dex.SubFlow(step.child, input, dex.SubFlowOptions{
		Timeout:       &timeout,
		TimeoutPolicy: dex.TimeoutCancel,
	})), nil
}

func (subFlowParent) Execute(ctx dex.Context, _ int) (*dex.StepDecision, error) {
	result, err := dex.SubFlowResult(ctx)
	if err != nil {
		return nil, err
	}
	var output int
	if err := result.DecodeSingleOutput(&output); err != nil {
		return nil, err
	}
	flowID, err := dex.SubFlowID(ctx)
	if err != nil {
		return nil, err
	}
	return dex.GracefulComplete(fmt.Sprintf("%s|%d", flowID, output)), nil
}
```

```java
static final class SubFlowParent implements Step<Integer> {
    private final SubFlowOptions options = SubFlowOptions.newBuilder()
            .timeout(Duration.ofHours(1))
            .timeoutPolicy(FlowTimeoutPolicy.CANCEL)
            .build();

    @Override
    public Class<Integer> getInputType() {
        return Integer.class;
    }

    @Override
    public Wait waitFor(final Context context, final Integer input) {
        return Wait.until(SubFlow.run(SubFlowChildFlow.class, input, options));
    }

    @Override
    public StepDecision execute(final Context context, final Integer input) {
        final Integer output =
                SubFlow.getConditionResults(context).getSingleOutput(Integer.class);
        return StepDecision.gracefulComplete(SubFlow.getFlowId(context) + "|" + output);
    }
}
```

```typescript
  }

        timeoutPolicy: FlowTimeoutPolicy.CANCEL,

  }
```

<SdkSnippet lang="rust">

```rust
#[derive(Default)]
struct SubFlowParent;

impl Step for SubFlowParent {
    type Input = i32;

    fn wait_for(&self, _context: &mut Context, input: Self::Input) -> HandlerResult<Wait> {
        let child = SubFlowChildFlow::default();
        let condition = SubFlow::run_with_options(
            &child,
            input,
            SubFlowOptions::new()
                .timeout(Duration::from_secs(3600))
                .timeout_policy(FlowTimeoutPolicy::Cancel),
        )
        .map_err(HandlerError::from_error)?;
        Ok(Wait::until(condition))
    }

    fn execute(&self, context: &mut Context, _input: Self::Input) -> HandlerResult<StepDecision> {
        let result = SubFlow::condition_result(context)?;
        let output: i32 = result.single_output().map_err(HandlerError::from_error)?;
        let flow_id = SubFlow::flow_id_at(context, 0)?;
        Ok(StepDecision::graceful_complete(format!(
            "{flow_id}|{output}"
        )))
    }
}
```

## 等待多个 SubFlow

用 `allOf` 让父 Flow 等待所有 SubFlow 完成。

父 Flow 不需要等待全部 SubFlow 时，用 `anyOf`。`WaitFor` 停止等待后，SubFlow 仍会继续运行。`Execute` 仍然可以拿到 SubFlow ID 来停止它，或者把 ID 传给另一个 Step 决定如何处理。SubFlow 与其他 condition 的组合见 [SubFlow results](/reference/python/waits#subflow-results)。
