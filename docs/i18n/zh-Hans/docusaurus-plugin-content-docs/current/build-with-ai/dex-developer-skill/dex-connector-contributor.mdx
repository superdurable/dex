# Dex Connector Contributor

Dex Connector Contributor 是一个专用 sub-skill，用于在官方
[Dex Connectors Library](https://github.com/superdurable/dex-connectors-library)
中创建、验证并提交一个便于 review 的 capability。

只有独立的官方 Connector library 工作才直接调用它：

~~~text
$dex-connector-contributor Add this Trigger to the official Slack Connector.
~~~

仅使用已发布 Connector 的应用应使用 [Dex App Builder](./dex-app-builder.mdx) 或
[Dex SDK](./dex-sdk.mdx)。

## 范围与 Source 要求

该 skill 只在官方 Connector library 中工作。它以 provider 的公开文档 API 或官方
SDK 为起点，并验证 auth scope、rate limit、idempotency support、pagination、event
acknowledgement 和 failure behavior。

它不会抓取 private endpoint、复制 browser credential、reverse-engineer 内部 protocol，
也不会声称支持 provider 未公开的能力。

## Repository 与 Fork 工作流

该流程会先查找并验证用户的 **superdurable/dex-connectors-library** GitHub fork。如果
fork 不存在，它会先询问许可并打开 GitHub fork 页面。用户完成 **Create fork** 后，
agent 才会 clone 并开始开发。

本地 checkout 使用用户 fork 作为 **origin**、官方 repository 作为 **upstream**，并
基于最新 **upstream/main** 创建隔离的 **codex/** branch。无关 working-tree change
会被保留。

## 贡献工作流

该 skill 按以下顺序执行：

1. 确认 provider capability 及其公开 contract。
2. 在 provider implementation 前更新 **connector.yaml**。
3. 运行 code generation，确保 Config、Credentials、definition、branch、operation
   factory、UI constant 和 default 继续由 manifest 生成。
4. 实现 provider adapter 和 provider-facing test。
5. 在需要时增加 Trigger 和 configuration UI behavior。
6. 在 Connector module 内增加或扩展可运行示例。
7. 运行完整 verification matrix，并检查 registry 或 catalog drift。
8. 提交一个干净的 module-scoped change，push 用户 fork，打开 ready-for-review upstream
   pull request，并持续监控 required CI。

## Durability 与 Security 边界

- provider call 只在 Connector Step **Execute** 中执行。
- RPC 负责路由或修改 Dex state，不调用 provider。
- provider mutation 保持 idempotent，并对 unknown outcome 先 query 后 reconcile。
- credential 和 raw secret 不进入 Flow input、Attribute、Result、receipt、Stream、log、
  fixture、generated value 或 release artifact。
- 每个 module pin 精确发布的 Dex Go SDK version，不提交 branch、SHA、pseudo-version
  或本地 replacement。
- 每个 pull request 发布一个 Connector module；只有真正的 repository-wide mechanical
  change 才能例外。

如果 Connector 暴露了 Dex SDK contract gap，可以在本地一起验证 SDK 和 Connector，
但 SDK change 必须先发布，Connector pull request 才能使用它。

## 示例与验证 Gate

新 Connector 或重要 capability 通常需要 module 内的可运行示例。包含 Trigger 时，示例
应展示真实 provider event 交付到 typed Flow start 或 RPC target，并覆盖 duplicate
delivery 和 restart recovery。不包含 Trigger 时，应生成有效 FDG 2.0，并通过 Dex Web v2
的 **Start Flow** 运行。

在 module-isolated race test 和 vet、generated-code check、catalog check、真实 Dex
integration、current-version compatibility、相关 UI test/build 和 repository check 全部
通过前，贡献不能视为完成。有 credential 时运行安全的 live-provider test；否则 pull
request 必须写明尚未验证的具体 live behavior。

## 与 App Builder 的关系

只有确认所需官方 Connector capability 缺失或有缺陷后，App Builder 才会路由到这里。
贡献接受 review 时，应用可以使用未提交的 local workspace override，但 production
handoff 必须等待精确发布的 Connector version。
