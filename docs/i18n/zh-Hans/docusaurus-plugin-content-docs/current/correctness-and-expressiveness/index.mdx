# 正确性与表达能力

两个经计算机检查的证明合起来，覆盖一门小型并发语言中每个格式良好的程序。这样的程序在 Dex 上产生的是一次无故障运行的事件，只是外部副作用可能重复，重复也可能来得很晚。[这对你的代码意味着什么](/correctness-and-expressiveness/failure-transparency-proof#what-it-means-for-you)说明怎样让重复变得安全。

证明针对的是 Dex 的模型，并且只在有限的范围内成立，例如只有一个 Flow、只用 **SYNC** 方法、重试永远不会用完。[证明的前提](/correctness-and-expressiveness/failure-transparency-proof#what-the-proof-assumes)列出了每个条件。

## 表达能力 {#expressiveness}

[表达能力证明](/correctness-and-expressiveness/expressiveness-proof)说明：一门带线程、锁、Timer 和取消的小型并发语言中，任何程序都能写成行为相同的 Dex Flow。证明的每一步都由计算机检查。完整论证见[论文](/papers/dex-expressiveness.pdf)。

[Workflow Patterns 评估](/correctness-and-expressiveness/workflow-patterns)按 43 个 control-flow Workflow Patterns 为 Dex 评级。研究者用这些模式比较各种 workflow 语言和引擎。每个评级都配有可运行的示例和集成测试。

## 正确性 {#correctness}

[Step 的进阶保证](/correctness-and-expressiveness/step-guarantees)说明 Step 方法失败或重复运行时 Dex 的承诺。

[故障透明性证明](/correctness-and-expressiveness/failure-transparency-proof)表明：server 崩溃、接管、重试、迟到的 Worker 和重复的结果，只会带来重复的外部副作用。在公平的运行中，结局也不变。证明页面列出了它的条件。

## 每项功能的覆盖情况 {#coverage}

| 功能 | Lean 故障证明 | 确定性模拟 | Server 集成测试 |
| --- | --- | --- | --- |
| SYNC Step | 是 | 是 | 是 |
| ASYNC Step | 否 | 否 | 是 |
| RPC，包括事务性 RPC | 否 | 是 | 是 |
| Attribute lock | 否 | 是 | 是 |
| SubFlow | 否 | 是 | 是 |
| Failure policy 和 recovery Step | 否 | 是，在 apply-level 阶段 | 是 |
| Heartbeat | 部分：从 heartbeat 检查点恢复不在证明范围内 | 是，带值和不带值都有 | 是 |
| Time Travel | 否 | 否：模拟的客户端不调用它 | 是 |
| StopFlow | 否 | 是 | 是 |

证明一列依据[证明的前提](/correctness-and-expressiveness/failure-transparency-proof#what-the-proof-assumes)。[如何验证](/correctness-and-expressiveness/failure-transparency-proof#how-it-was-checked)介绍了模拟，并列出每项功能对应的集成测试。
