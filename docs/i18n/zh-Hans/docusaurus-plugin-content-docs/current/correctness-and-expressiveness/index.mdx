# Correctness and expressiveness

本节回答关于 Dex 的两个问题。

- **表达能力（expressiveness）**：Dex 能否表达你需要的程序？
- **正确性（correctness）**：进程、机器或网络出故障时，Dex 是否仍然正确？

## 表达能力 {#expressiveness}

[表达能力证明](/correctness-and-expressiveness/expressiveness-proof)说明：一门带线程、锁、Timer 和取消的小型并发语言中，任何程序都能写成行为相同的 Dex Flow。证明的每一步都由计算机检查。完整论证见[论文](/papers/dex-expressiveness.pdf)。

[Workflow Patterns 评估](/correctness-and-expressiveness/workflow-patterns)按 43 个 control-flow Workflow Patterns 为 Dex 评级。研究者用这些模式比较各种 workflow 语言和引擎。每个评级都配有可运行的示例和集成测试。

## 正确性 {#correctness}

[Step 的保证](/concepts/step#guarantees)说明 Step 方法失败或重复运行时 Dex 的承诺。

[故障透明性证明](/correctness-and-expressiveness/failure-transparency-proof)覆盖 server 崩溃、备用 server 接管、重试、Dex 放弃后仍在运行的 Worker，以及重复的结果。从 Flow 在这些故障下产生的事件中去掉重复的外部副作用，证明表明剩下的就是这个 Flow 在没有故障时能做的事。它还表明结局不变，但有一个限制，页面中有说明。它只在明确列出的假设下成立。例如，它只覆盖 **SYNC** 方法，而且重试不能用完。这个证明的每一步也都由计算机检查。完整论证见同一篇[论文](/papers/dex-expressiveness.pdf)。

两个证明合起来覆盖那门小型并发语言中格式良好的程序。这样的程序在 Dex 上运行时，产生的是一次无故障运行的事件，只是外部副作用可能重复。重复也可能来得很晚。[这对你的代码意味着什么](/correctness-and-expressiveness/failure-transparency-proof#what-it-means-for-you)说明了怎样让重复变得安全。
