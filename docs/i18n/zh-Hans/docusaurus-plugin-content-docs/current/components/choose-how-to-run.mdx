# 选择 Dex 的运行方式

Dex Server 可以运行在两个地方：Dex Cloud（由 Super Durable 替你运行），或者你自己的基础设施。两种方式下，Worker 都运行你的 Flow 代码，可以在你的服务器、你的云或者你的笔记本上。开发时，`dexcli dev` 会在本机启动一个本地 server。

| | Dex Cloud | 自托管 |
| --- | --- | --- |
| 谁运维 Dex Server | Super Durable：存储、升级、容量和监控 | 你自己 |
| Flow 状态存在哪里 | 存在 Dex Server 的存储中，由 Super Durable 运维。Flow 输入、Attribute 和 Step 结果都存在这里。 | 存在你提供的对象存储 bucket 中 |
| 你的代码在哪里运行 | 在你的 Worker 中，可以在你的服务器、你的云或者你的笔记本上。你的代码和 API 凭证都留在那里。 | 同左 |
| Worker 怎样连接 | 通过 TLS，使用这个 server 的 API key | 使用你配置的认证和 TLS |
| 升级 | Super Durable 升级 server | 由你升级，升级只能向前。见 [Upgrades and compatibility](/reference/server/upgrades)（英文） |
| 你需要准备什么 | 在 Dex Cloud 创建一个 server，它有自己的 endpoint 和 API key | [最小的真实部署](/components/production#smallest-deployment)：一个 server 节点、对象存储、认证和 TLS |
| 价格、区域和 SLA | [联系 Super Durable](https://superdurable.io/about/#contact) | 由你决定：你的云、你的区域和你自己的可用性目标 |
| 从哪里开始 | [注册 Dex Cloud](https://dex.superdurable.io/register) | [Run Dex in Production](/components/production)（英文） |

## Dex Cloud {#dex-cloud}

Super Durable 为你的应用运行 Dex Server。你在 Dex Cloud 创建的每个 server 都有自己的 endpoint 和 API key。Worker 和 Client 通过 TLS、使用这个 key 连接到这个 endpoint。

你的代码在 Worker 中运行，所以代码和它调用你自己的 API 时使用的凭证都留在你这边。Flow 状态，也就是 Flow 输入、Attribute 和 Step 结果，由 Dex Server 存储，所以在 Dex Cloud 中它存在 Super Durable 运维的存储里。

连接 Worker 或 Client 时，传入 endpoint 和 key：

- key 放在 [API key credential](/reference/server/authentication#sdk-credentials) 里。
- TLS 用 SDK 的 [TLS 选项](/reference/server/authentication#tls)。

[注册 Dex Cloud](https://dex.superdurable.io/register)，然后创建一个 server。

## 自托管 {#self-hosted}

你在 Worker 旁边运行 **dex-server-zd**。它把每个 Flow 保存在对象存储里，比如 Amazon S3；活动节点停止时，热备节点可以接管。认证、TLS、保留期和监控由你自己配置。[Run Dex in Production](/components/production)（英文）逐项列出。

[Sustainable Use License](/intro/limits#license) 允许你为自己的业务运行 Dex。
