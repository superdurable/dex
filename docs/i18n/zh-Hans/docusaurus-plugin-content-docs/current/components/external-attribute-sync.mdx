# External Attribute Sync

External Attribute Sync 把选定的 Flow Attribute 复制到你自己的 PostgreSQL 表中。每个目标称为一个 Attribute Store。

目前只支持 PostgreSQL 作为 Attribute Store。Redis 支持由 [issue 616](https://github.com/superdurable/dex/issues/616) 跟踪。

Dex 不会创建、迁移或回填目标。请在启动 server 前创建 SQL 表。

## 与其他组件的关系

External Attribute Sync 是 [server](/components/server) 的功能。Flow 用 **syncToAttributeStore** 标记 Attribute，并在 **FlowConfig** 中列出已配置的 store 名称。server-zd 随后把这个 Attribute 写入该 store 的表。你的 [应用](/components/application) 和报表用 SQL 查询这些表。

## 配置

```yaml
attributeStore:
  stores:
    reporting:
      type: postgres
      dsn: postgres://user:password@host/database
      tableName: public.flow_attributes
    orders:
      type: postgres
      dsn: postgres://user:password@host/database
      tableName: public.orders
      rowKey: order-{customer_id}-{order_id}
      columnNaming: snake_case
      attributeMaps:
        LineItems:
          tableName: public.order_line_items
          instanceKeyColumn: line_item_id
  schemaSyncInterval: 1m
  syncBatchSize: 100
  syncAttemptTimeout: 30s
  syncRetryPolicy:
    initialInterval: 100ms
    maximumInterval: 30s
    backoffCoefficient: 2
    maximumAttempts: 0
    totalDuration: 1h
```

每个 store 都必须配置 **type: postgres**、**tableName** 和 DSN（写在 **dsn** 或环境变量中）。server-zd 从不把 DSN 写进日志。**tableName** 接受 **table** 或 **schema.table**。Dex 会解析表名和列名并加引号，Attribute 的值始终作为 driver 参数传递。每个键及其默认值见英文的 [Attribute Store sync configuration](/reference/server/attribute-store-sync#attribute-store-configuration)。

## 交付与重试

Dex 异步写入，一次处理一个 Flow。表中的一行保存 Attribute 的最新值，而不是事件历史。结果未知的失败之后，同一次写入可能重复，所以 Dex 按 Flow ID 对行做 upsert。

同步写入从不拖慢 Step、RPC 或 SetAttributes 调用。失败的写入会一直重试到 **syncRetryPolicy.totalDuration**，之后丢弃并输出 error 日志。Dex 不会自动重放旧的 Attribute，也不会为新配置的 store 回填数据。被过滤的写入、目标缺失和重试耗尽都会输出 error 日志。

fencing 表、关闭行为、重试、metrics、row key、AttributeMap 表和 SQL 类型契约详见英文 Server 参考中的 [Attribute Store sync](/reference/server/attribute-store-sync)。

## 本地开发 {#attribute-store-local-development}

**dex-server-zd dev** 在本地运行一个使用内嵌对象存储的节点。它的 **--attribute-store-config** 参数只读取 YAML 文件中的 **attributeStore** 一节。这一节至少要定义一个 store。**--config** 覆盖文件不能同时设置 **attributeStore**。

~~~bash
dex-server-zd dev --data-dir ./zd-data --attribute-store-config ./attribute-store.yaml
~~~

数据库仍然需要这些表和 fencing 表。**dexcli dev --attribute-store-config** 会把文件传给这个参数。
