# 在生产环境运行 Dex

上线之前逐项检查。在 Dex Cloud 中，server 由 Super Durable 运行；Worker、Step 重试、代码变更和数据库这几项仍然适用。每一项都链接到有详细说明的页面。

## 上线之前 {#before-you-launch}

下面的[最小配置](#minimal-configuration)涵盖身份验证、一个节点、它的 bucket、保留期和 metrics。

| 事项 | 要做什么 | 详细说明 |
| --- | --- | --- |
| 身份验证和 TLS | 公共 API 的身份验证默认关闭，所以任何能连到 server 的 Client 都能调用它。在开放端口之前配置一个 authenticator。API 端口提供明文 gRPC：在它前面加 TLS，或者使用私有网络。 | [Authentication](/reference/server/authentication)（英文），[TLS](/reference/server/authentication#tls)（英文）|
| 拓扑 | 一个 active 节点服务整个集群。需要快速故障转移时，加一个 hot standby。 | [自托管 Dex](/components/self-host)，[Lease, hot standby, and step down](/reference/server/high-availability)（英文）|
| 存储和备份 | 集群使用一个对象存储 bucket 和 prefix，保存 server 的全部状态。可以用 db9 代替它；普通 PostgreSQL 不受支持。bucket prefix 是唯一的数据来源：为它开启版本控制或复制，并演练一次恢复。 | [Object storage and backup](/reference/server/object-storage)（英文），[Backup and restore](/reference/server/object-storage#backup-and-restore)（英文）|
| 保留期 | 已关闭的 run 和它的 Step 历史默认在 7 天后删除。删除的 run 会释放它的 Flow ID。把 `retention.closedFlowDuration` 设得足够覆盖最长的 Client 重试窗口，并把需要保留更久的数据复制到[你自己的数据库](/components/your-database)。每个 run 保留它启动时的值；新值只作用于重启之后启动的 run。 | [Retention 参考](/reference/server/configuration#retention)（英文）|
| 监控 | 在单独的监听端口上提供 metrics。节点停止服务和 lease 续约失败时告警。 | [Metrics and alerts](/reference/server/metrics)（英文）|
| Worker | Worker 主动建立出站连接。设定它们的任务槽数量，部署时优雅地停止它们。 | [Workers and the task queue](/reference/server/workers)（英文）|
| Step 重试 | Step 重试默认在 4 小时后停止，然后 Flow 失败。设置重试策略或失败路由。 | [StepOptions](/concepts/step#stepoptions) |
| 升级 | 升级只向前滚动。先读每个版本的发布说明，有些升级需要停止所有进程。 | [Upgrades and compatibility](/reference/server/upgrades)（英文），[Agent release notes](/reference/agents/upgrades#release-notes)（英文）|
| 代码变更 | 保留旧的 Step 类型和 RPC，直到使用它们的 Flow 关闭。 | [部署代码变更](/concepts/change-flow-code) |
| 你的数据库 | Step 里的写入必须可以安全地重复。 | [Dex 和你的数据库](/components/your-database) |
| 搜索后端 | 内置搜索不需要数据库。大量搜索可以用 PostgreSQL 或 ParadeDB。 | [Search backends](/reference/server/search)（英文）|
| Kubernetes | 把 server 作为 StatefulSet 运行，并配置优雅关闭。 | [Kubernetes deployment](/reference/server/kubernetes)（英文）|
| 容量和成本 | 瓶颈是 CPU。从小规模开始，见 [容量规划](#sizing)。 | [性能](/intro/performance)，[超出一个节点](/intro/limits#grow-past-one-node) |

### 容量规划 {#sizing}

作为从 benchmark 得出的起点：2 vCPU 的节点峰值接近每秒 1,800 个 SYNC Step，16 vCPU 的节点接近 8,400 个。从小规模开始，观察 CPU。超出一个节点后，运行多个独立的集群。

## 最小配置 {#minimal-configuration}

这份配置在 Amazon S3 上运行一个 Dex Server 节点，并开启身份验证：

~~~yaml
cluster:
  nodeId: dex-zd
objectStore:
  region: us-east-1
  bucket: BUCKET
  prefix: PREFIX
localStorage:
  directory: /var/lib/dex-server-zd/store
lease:
  duration: 60s
retention:
  closedFlowDuration: 7days
metrics:
  listen: 0.0.0.0:9090
auth:
  authenticators:
    - kind: staticTokens
      file: /etc/dex-server-zd/tokens.yaml
~~~

把 `BUCKET` 和 `PREFIX` 换成你的 bucket 和 key prefix。token 文件列出 Worker 和 Client 发送的 bearer token 的 SHA-256 哈希；[Authentication](/reference/server/authentication)（英文）给出它的格式和 JWT 选项。`cluster.nodeId`、`objectStore.bucket` 和 `localStorage.directory` 是必填项，节点 ID 和分区数在首次启动后就不能再改。60 秒的 lease 适合单节点；有 hot standby 时，保留 10 秒的默认值。[Install and configure server-zd](/reference/server/configuration#minimal-production-configuration)（英文）解释每个 key。

通过 SDK 的 `credential` 选项把 token 交给每个 Worker 和 Client；文件凭证会重新读取 token 文件，所以轮换 token 时不用重启。[Send credentials from Workers and Clients](/reference/server/authentication#sdk-credentials)（英文）列出每个 SDK 中的这个选项，[TLS](/reference/server/authentication#tls)（英文）列出 TLS 连接对应的 SDK 选项。
