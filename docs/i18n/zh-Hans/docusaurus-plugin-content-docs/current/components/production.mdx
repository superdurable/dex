# 在生产环境运行 Dex

这一页列出上线前要决定和配置的事项，每一项都链接到有详细说明的页面。大多数事项针对[自托管](/components/self-host)的 server。在 [Dex Cloud](/components/dex-cloud) 中，server 由 Super Durable 运行，关于 Worker、代码变更和数据库的事项仍然适用。

## 最小的真实部署 {#smallest-deployment}

- 一个 Dex Server 节点。需要快速故障转移时，再加一个 hot standby。
- 集群使用一个对象存储 bucket 和 prefix。
- 在 API 可以被访问之前开启身份验证。
- 在 API 端口前加 TLS，或者使用私有网络。见 [TLS](/reference/server/authentication#tls)（英文）。
- [保留期](#retention)足够覆盖 Client 的重试。
- 提供 metrics，并针对节点和它的 lease 设置告警。

下面的[最小配置](#minimal-configuration)搭建的就是这种部署。

### 需要修改的默认值 {#defaults-to-change-before-production}

| 默认值 | 怎么改 |
| --- | --- |
| 已关闭的 run 和它的 Step 历史会在 7 天后删除。删除的 run 会释放它的 Flow ID。 | 设置更长的[保留期](#retention)，并把必须保留的数据复制到[你自己的数据库](/components/your-database)。 |
| 公共 API 的身份验证是关闭的，所以任何能连到 server 的 Client 都能调用它。 | 在开放端口之前配置一个 authenticator，就像[最小配置](#minimal-configuration)那样。见 [Authentication](/reference/server/authentication)（英文）。 |
| Step 重试在 4 小时后停止，然后 Flow 失败。 | 在 [StepOptions](/concepts/step#stepoptions) 中设置重试策略或失败路由。 |

### 容量规划 {#sizing}

作为从 benchmark 得出的起点：2 vCPU 的节点峰值接近每秒 1,800 个 SYNC Step，16 vCPU 的节点接近 8,400 个。从小规模开始，观察 CPU。超出一个节点后，运行多个独立的集群。

### 保留期 {#retention}

把 `retention.closedFlowDuration` 设得足够覆盖最长的 Client 重试窗口，因为删除的 run 会释放它的 Flow ID。需要保留更久的数据，用 [Attribute Store sync](/components/your-database) 复制到你自己的表里。

## 最小配置 {#minimal-configuration}

这份配置在 Amazon S3 上运行一个 Dex Server 节点，并开启身份验证：

~~~yaml
cluster:
  nodeId: dex-zd
objectStore:
  region: us-east-1
  bucket: BUCKET
  prefix: PREFIX
localStorage:
  directory: /var/lib/dex-server-zd/store
lease:
  duration: 60s
retention:
  closedFlowDuration: 7days
metrics:
  listen: 0.0.0.0:9090
auth:
  authenticators:
    - kind: staticTokens
      file: /etc/dex-server-zd/tokens.yaml
~~~

把 `BUCKET` 和 `PREFIX` 换成你的 bucket 和 key prefix。token 文件列出 Worker 和 Client 发送的 bearer token 的 SHA-256 哈希；[Authentication](/reference/server/authentication)（英文）给出它的格式和 JWT 选项。`cluster.nodeId`、`objectStore.bucket` 和 `localStorage.directory` 是必填项，节点 ID 和分区数在首次启动后就不能再改。60 秒的 lease 适合单节点；有 hot standby 时，保留 10 秒的默认值。[Install and configure server-zd](/reference/server/configuration#minimal-production-configuration)（英文）解释每个 key。

通过 SDK 的 `credential` 选项把 token 交给每个 Worker 和 Client；文件凭证会重新读取 token 文件，所以轮换 token 时不用重启。[Send credentials from Workers and Clients](/reference/server/authentication#sdk-credentials)（英文）列出每个 SDK 中的这个选项。API 端口提供明文 gRPC：在它前面加 TLS，或者把它留在私有网络里。[TLS](/reference/server/authentication#tls)（英文）列出对应的 SDK 选项。
