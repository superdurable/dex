# 运行 Dex

一个 Dex 应用由四个组件组成：你的应用、Dex Server、dexcli 和 Dex Web。应用由你编写，其余由 Dex 提供。

<a id="how-they-fit-together"></a>
<a id="组件之间的关系"></a>

<DexSystemDiagram withOperatorTools markdownDescription="你的应用包含 Client 和 Worker，两者都用 Dex SDK 构建。Client 通过 startFlow 和 invokeRPC 调用 Dex Server；Dex Server 调用 Worker 运行 Step 和 RPC，并持久化每个 Flow。dexcli 和 Dex Web 也连接 Dex Server，用来在本机运行 Dex，以及查看和操作 Flow。" />

## Dex Server 运行在哪里 {#where-to-run}

<a id="dex-cloud"></a>
<a id="self-hosted"></a>

Dex Server 可以运行在 Dex Cloud（由 Super Durable 运维），也可以运行在你自己的基础设施上。两种方式下，Worker 都运行你的 Flow 代码，可以在你的服务器、你的云或者你的笔记本上。

| | Dex Cloud | 自托管 |
| --- | --- | --- |
| 谁运维 Dex Server | Super Durable：存储、升级、容量和监控 | 你自己 |
| Flow 状态存在哪里 | 存在 Dex Server 的存储中，由 Super Durable 运维 | 存在你提供的对象存储 bucket 中 |
| Worker 怎样连接 | 通过 TLS，使用这个 server 的 API key | 使用你配置的认证和 TLS |
| 从这里开始 | [在 Dex Cloud 上运行](/components/dex-cloud) | [自托管 Dex](/components/self-host) |

## 组件 {#components}

<a id="your-application"></a>
<a id="dex-server"></a>
<a id="dexcli"></a>
<a id="dex-web"></a>

| 组件 | 作用 | 详情 |
| --- | --- | --- |
| 你的应用 | 你的代码。Worker 运行你的 Step 和 RPC handler，Client 启动 Flow、调用 RPC。 | [你的应用](/components/application) |
| Dex Server | 把每个 Flow 的状态保存在对象存储中，并把 Step 和 RPC 交给 Worker。 | [Dex Server](/components/server) |
| dexcli | 命令行工具。它在本机运行 Dex，并查看和操作 Flow。 | [CLI（dexcli）](/components/cli) |
| Dex Web | 运维界面。它查找 Flow、显示每次 run、启动 Flow、调用 RPC。 | [Web（Dex Web）](/components/web) |

## 本地和生产环境 {#local-and-production}

<a id="本地和生产环境"></a>

| 组件 | 本地开发 | 生产环境 |
| --- | --- | --- |
| Server | **dexcli dev** 启动 server-zd | 使用对象存储运行 **dex-server-zd serve**，或使用 Dex Cloud |
| Web | **dexcli dev** 启动 Dex Web | 单独的 **dex-web** 进程，或 **dexcli web** |
| 应用 | 你的 Worker 进程 | 你的 Worker 服务，像其他服务一样扩缩容 |

[快速开始](/quick-start)在本地运行所有组件。[本地运行](/components/run-locally)介绍 **dexcli dev** 的安装选项和问题排查。
