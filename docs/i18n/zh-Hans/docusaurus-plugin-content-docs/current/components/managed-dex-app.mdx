# Managed Dex App

Managed Dex App 是一个由 Dex Cloud 从你的 GitHub 仓库构建、预览并在 Live 中运行的 Dex 应用。如果你希望 Super Durable 运行整个应用（包括 Worker），而你只维护代码，就用它。

## 何时使用 {#when-to-use}

Dex Cloud 提供两种产品：

| | Managed Dex Server | Managed Dex App |
| --- | --- | --- |
| Super Durable 运行 | Dex Server | Dex Server、你的 Worker 和你的 web server |
| 你运行 | 你的 Worker，部署在你选择的地方 | 无需运行。你把代码推送到 GitHub。 |
| 你提供 | Worker 代码和它的部署 | 一个符合 Dex app 结构的 GitHub 仓库 |
| 从这里开始 | [在 Dex Cloud 上运行](/components/dex-cloud) | 本页 |

新应用如果符合它支持的 stack，就选 Managed Dex App：用 Go 或 TypeScript 写的 process，或使用 [Dex Cloud 支持构建的 stack](/reference/server/dex-app-manifest#template-manifest) 的 agent。如果你已经自己部署 Worker，或者代码用的是其他语言，就选 Managed Dex Server。

## 从示例开始 {#example}

最小示例是 [`superdurable-apps/cloud-dex-app-example`](https://github.com/superdurable-apps/cloud-dex-app-example)。它是一个满足所有仓库规则的小型 TypeScript process。复制它，或者逐个文件对照你的仓库。

## 遵守仓库规则 {#repository-rules}

Dex Cloud 导入符合 Dex app 结构的仓库。简要来说：

- 默认分支是 `main`，并且至少有一个 commit。
- 根目录的 `.superverse/template.json` 写明 kind、stack、build profile 和 `make` 命令。
- 根目录的 `dex-app.yaml` 写明端口、健康检查路径、Flow 源文件和 connector。
- 每个 Flow 源文件都已提交，并使用 build profile 对应的语言。
- connector 是 Dex connector library 中已发布的版本，由应用的 lockfile 固定版本。
- build profile 需要的文件都已提交，根目录 `Makefile` 定义了命令用到的每个 target。
- 仓库只包含普通文件，没有 submodule、符号链接或提交进去的密钥文件，并且在大小限制之内。

每条规则都有编号，从 S1 到 S8。[Dex app manifest and repository layout](/reference/server/dex-app-manifest) 列出了每个字段、规则和限制。

## 导入仓库 {#import}

Dex Cloud 通过 **SuperDurable Dex Cloud** GitHub App 读取你的仓库。这个 app 申请以下权限：

- **Contents**：读写。
- **Metadata**：只读。
- **Members**：只读。

导入仓库的步骤：

1. 在拥有该仓库的 GitHub 组织或账号上安装 [SuperDurable Dex Cloud](https://github.com/apps/superdurable-dex-cloud) GitHub App，并授予它访问该仓库的权限。
2. 登录 Dex Cloud，或者[注册](https://dex.superdurable.io/register)。在开始页面选择 **Import project**。
3. 从列表中选择仓库，或者输入 `owner/name`。
4. 查看检查结果。Dex Cloud 读取 `main`，显示 kind、stack，以及仓库违反的每条规则。
5. 检查通过后，创建 project。

导入时，你的仓库保持原样。删除 project 只会断开与仓库的连接。

## 构建、Preview 和 Live {#build-preview-live}

Dex Cloud 按 build profile 构建应用镜像。你的仓库里不需要 Dockerfile。

- **Preview** 在它自己的 Dex Server 上运行 `main`，你的代码无需任何改动。有新的 commit 进入 `main` 时，Preview 会提示你跟进。
- **Live** 运行一个 release。在 **Release** 页面选择 `main` 的一个 commit，Dex Cloud 构建并部署它。

两者都用同一个镜像运行你的 web server 和 Worker。Dex Cloud 根据 `dex-app.yaml` 声明的 Flow 源文件发布 Flow 定义。Dex Web 显示每个 Preview 和 Live 部署的 Flow。

你和团队照常向 `main` 推送代码。

## 修复被拒绝的导入 {#fix-refused-import}

导入检查把每个问题列为一条 finding。每条 finding 写明它的规则、代码、路径和修复方法。它的链接打开 reference 页面上对应的规则。

每个代码在[finding 列表](/reference/server/dex-app-manifest#import-report)中都有一个同名锚点的小节，例如 [`flow_source_missing`](/reference/server/dex-app-manifest#flow_source_missing)。修复仓库，推送到 `main`，然后再检查一次。

如果检查结果说无法读取仓库，就在 GitHub 上给 SuperDurable Dex Cloud GitHub App 授予该仓库的访问权限。
