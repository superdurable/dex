# 响应式更新

交互式调用方不应只能等整个 Flow 结束，或者轮询它的状态。使用响应式更新，调用方只等到自己需要的那个点。其余工作由 Flow 继续完成。如果是 Flow 自己在等待外部系统，请使用 [Polling](/design-patterns/polling)。

选择要等待的点：

- [等待 Step 完成](/design-patterns/responsive-update/step-completion) 会在一个指定 Step 完成后返回。当这个 Step 完成后，客户端就能安全地读取或使用结果时，选择它。
- [等待 Attribute 匹配](/design-patterns/responsive-update/attribute-match) 返回当前命中的 Attribute 值。当调用方需要在业务状态变化后刷新时，使用 revision watermark。
- [等待并流式接收更新](/design-patterns/responsive-update/stream) 会长轮询下一条增量更新，并从 token 继续读取。它适用于进度或持续变化的 feed。

前两种等待读取 durable 状态，不能代替应用超时，也不能代替最终的 Flow 结果。超时与上限见[等待超时与上限](/reference/server/runtime-client#wait-timeouts-and-limits)。
