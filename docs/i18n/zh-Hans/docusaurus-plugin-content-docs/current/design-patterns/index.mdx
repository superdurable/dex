# 设计模式

每个模式用一种可复用的 Flow 结构解决一类常见问题。每页都链接到各 SDK 语言的可运行代码。

分组先讲 Flow 内部的结构，再讲和外部的交互，然后是数据，最后是失败处理。

- <a id="flow-控制"></a>[并行 Step](/design-patterns/parallel)：并发运行 Step：数量固定或动态，等全部完成或只等第一个。让并行分支轮流执行一段跨多个 Step 的流程。
- [子 Flow](/design-patterns/subflows)：把工作分给多个 SubFlow，限制一个父 Flow 同时运行的数量，分散到多个父 Flow，加上持久化背压，并在取消时停止子 Flow。
- [持久化定时器](/design-patterns/durable-timer)：按计划运行工作、发送提醒，或在一个长时间运行的 Step 中等待外部系统。
- [外部交互](/design-patterns/external-interaction)：带截止时间地等待一个决定，在一段时间没有活动后执行动作，持续接收外部消息，或按请求控制长时间运行的工作。
- <a id="消息"></a>[响应式更新](/design-patterns/responsive-update)：让调用方等待某个 Step、某个 Attribute 值或一串更新，而不是等整个 Flow 结束。
- [排空 Channel](/design-patterns/drain-channels)：Channel 消息都处理完之后才结束 Flow。
- <a id="数据"></a>[数据存储](/design-patterns/data-storage)：每个实体一个 Flow，把它的 Attribute 投影到 SQL，或把不断增长的集合拆到有上限的 AttributeMap instance 中。
- <a id="可靠性"></a>[失败处理](/design-patterns/failure-handling)：从 `Execute` 或 `WaitFor` 失败中恢复、交给操作人员处理，或强制执行业务截止时间。

完整示例位于 `examples/` 下。可在 [examples playground](https://github.com/superdurable/dex/tree/main/examples/playground) 中试用 HTTP 示例。
