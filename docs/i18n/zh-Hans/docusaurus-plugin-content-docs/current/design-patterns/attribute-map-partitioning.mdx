# AttributeMap 分区

把不断增长的集合放在一个 Attribute 里，它会变成一个很大的 value，每次写入都要整个重写。这两种模式都把数据拆到有大小上限的 **AttributeMap** instance 中，每次读取或写入只涉及一个 instance。

- [顺序分块 AttributeMap](/design-patterns/sequentially-chunked-attribute-map)：将有序历史 append 到有大小上限的不可变 chunk。
- [Hash 分区 AttributeMap](/design-patterns/hash-partitioned-attribute-map)：通过稳定业务 key 直接查找和更新结构化记录。

按访问方式选择：

- 只追加且要保持顺序的数据：Sequentially Chunked。
- 按稳定 key 查找或更新：Hash-Partitioned。

## 对比

| 维度 | Sequentially Chunked | Hash-Partitioned |
|---|---|---|
| 主要目标 | 高效 append 和按顺序分页 | 按稳定业务 key 直接 lookup 和 upsert |
| 顺序 | 天然保留写入顺序 | 没有自然全局顺序 |
| 按 key 查找 | 通常需要扫描多个 chunk 或额外索引 | 直接计算一个 partition |
| 更新旧数据 | 不适合；archive chunk 应保持不可变 | 适合在目标 bucket 内 upsert |
| 写入并发 | 所有 append 竞争同一个活动 chunk | 不同 partition 使用独立 lock |

完整对比见 [Attribute：拆分不断增长的集合](/concepts/primitives/attribute#attributemap-partitioning)。
