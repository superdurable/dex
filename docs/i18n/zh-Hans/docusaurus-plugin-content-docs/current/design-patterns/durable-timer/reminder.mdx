# 提醒

`ReminderFlow` 按固定间隔发送提醒，直到接收者退订。`ReminderStep` 等待间隔 Timer 或 `OptOut` Channel。Timer 先触发时，Step 发送提醒并转回自身。`OptOut` 先到达时，Step 完成 Flow。

class ReminderStep(Step[None]):
    def __init__(
        self,
        service: ServiceDependency,
        opt_out: Channel[None],
    ) -> None:
        self.service = service
        self.opt_out = opt_out

    def wait_for(self, context: Context, input: None) -> Wait:
        return Wait.any_of(
            Timer.by_duration(REMINDER_INTERVAL),
            self.opt_out.for_one(),
        )

    def execute(self, context: Context, input: None) -> StepDecision:
        if not context.has_timer_fired():
            return graceful_complete()
        self.service.send_email("Reminder: please respond", "Hello, ...")
        return go_to(ReminderStep, None)

## 生产环境说明 {#production-notes}

示例只有一个 `OptOut` 消费者，并使用相对 Timer。它的发送调用没有幂等键。生产环境的提醒需要处理重试和退订：

- 用稳定的 occurrence ID（例如 Flow ID 加上第几次提醒）作为每次发送的键。`Execute` 重试时，接收方用这个键避免重复送达。
- Timer 胜出时，检查 `Execute` 首次状态快照里的 `OptOut`。重试沿用这个快照。快照里有退订时，这条提醒不发送。快照之后才提交的退订可能让这条提醒发出一次；下一次等待仍包含 `OptOut`，所以会阻止之后的提醒。
- 如果退订必须在决定提交之前都能阻止提醒，退订 RPC 和做决定的 Step 共享一把 lock，提交之后由不持有 lock 的 Step 发送。
