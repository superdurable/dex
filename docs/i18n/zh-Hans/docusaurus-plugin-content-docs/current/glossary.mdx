# 术语表

Dex 术语的简短定义。Dex 源自 iWF，iWF 把 Flow 叫作 Workflow，把 Step 叫作 State。本文档只使用 Dex 的叫法。

#### [Activation](/reference/agents/tracing)（激活） {#activation}

Agent Session 在两次持久化等待之间连续运行的一组 Step。Session 收到一条用户消息或一个审批答复时开始，Session 再次进入等待时结束。Tracing 为每个 activation 生成一条 trace。

#### [Agent session](/agent-frameworks/sessions)（Agent Session） {#agent-session}

与一个持久化 Agent 的一次对话。它是一次 Flow run，Session ID 就是它的 Flow ID。对话内容和 Tool Call 都保存在 Attribute 里。

#### [Agent 的 Step 名称](/agent-frameworks/sessions) {#agent-step-names}

持久化 Agent Session 中的各个 Step，例如 `RunModel`、`CallTool`、`AwaitToolApproval` 和 `ResumeTurn`。Session 页面逐一介绍了它们。

#### [App Worker ID](/reference/server/workers#routing-and-availability)

一个正在运行的 Worker 进程的 ID。Dex 会优先把一条 Flow 的下一个 Step 或 RPC 发给同一个 app Worker ID。SDK 每次进程启动时都会生成一个新 ID。如果你自己设置它，每次重启后都要换一个新值。

#### [Attribute](/concepts/primitives/attribute)

Flow 上一个持久化、有类型的变量。可以为它建索引，用于搜索。

#### [Attribute Store](/concepts/primitives/attribute#attribute-store-projection)

一组由你自己管理的 PostgreSQL 表，Dex Server 会把选定的 Attribute 复制进去。复制是单向的，Flow 始终是数据的权威来源。

#### [Blob cache](/components/application#blob-cache)（Blob 缓存） {#blob-cache}

本地磁盘上一个有容量上限的缓存，用来存放较大的 Dex 值。Dex 用引用来传递大值，缓存保留这些值，Worker 或 Client 就不用重复下载。每个 Worker 和 Client 进程各自打开一个缓存目录。缓存丢失也不会丢数据。

#### [Channel](/concepts/primitives/channel)

持久化的消息管道。它把消息从 Flow 外部送进来，或者在同一条 Flow 的各部分之间传递。

#### [ChannelMap](/concepts/primitives/channel#channelmap)

同一个名字下的一组 Channel，每个实例键对应一个 FIFO 队列，例如每个订单或每个任务一个队列。

#### [Client](/concepts/client)

应用中在 Worker 之外与 Dex 通信的部分。它启动 Flow、调用 RPC、读取 Attribute、等待 Step。它不运行 Flow 代码。

#### [Condition](/concepts/step#waitfor-and-execute)

Step 要等待的东西，由 WaitFor 返回：一个 Timer、一条 Channel 消息、一个完成的 SubFlow，或它们的组合。

#### [Connector](/concepts/connector)

把 Flow 连接到外部服务商的软件包。它为 Flow 提供现成的 Step，以及 Trigger，Trigger 把服务商的事件转成 Flow 启动或 RPC 调用。

#### [db9](/reference/server/object-storage#db9)

一个独立的数据库产品，使用 PostgreSQL 线协议。Dex Server 可以把数据存在 db9 里，代替对象存储。原生 PostgreSQL 不在列出的生产存储之列。

#### [Dex Server](/components/server)

保存每条 Flow 的状态、把工作分发给 Worker 的服务器。它的二进制文件是 **dex-server-zd**，参考文档里称它为 **server-zd**。

#### [dexcli](/components/run-locally)

Dex 的 CLI。它在本机运行 Dex Server 和 Dex Web，也用来查看和操作 Flow。

#### [持久化执行（Durable Execution）](/intro/what-is-dex) {#durable-execution}

让一个流程在崩溃、重启和长时间等待之后依然能继续运行的执行方式。引擎记录流程的进度，失败之后流程从中断处继续，而不是从头开始。

#### [Execute](/concepts/step#waitfor-and-execute)

Step 的一个方法。WaitFor 的条件满足后运行；Step 没有 WaitFor 时直接运行。

#### [故障转移](/concepts/failover-and-deploys) {#failover}

当前活跃的 Dex Server 进程停止后，由备用进程接管。Worker 已经收到的每次尝试都会重新运行。

#### [Flow](/concepts/flow)

最外层的持久化程序，包含 Step、Attribute、Channel 和 RPC。

#### [Flow Definition Graph](/components/server)

某个 Flow type 的 Step 以及其代码可能做出的每一种转移构成的图。**dexcli visualize** 直接从源代码生成它，无需运行代码。Worker 或 dexcli 发布这张图，Dex Web 根据它绘制 Flow。

#### [Flow ID](/concepts/flow#identifiers)

你的应用为一次 Flow run 指定的 ID。

#### [GetAttributes](/reference/server/runtime-client#read-attributes)

一个 Client API，从 Flow 外部读取已提交的 Attribute 值，不需要 Worker。

#### [Hard-delete Attribute](/concepts/primitives/attribute#hard-delete-attributes)

用于短期密钥的 Attribute。删除它会永久抹掉存储的值。Dex 每次尝试都重新读取它，而不是从该尝试的快照中读取。

#### [Harness](/agent-frameworks#choose-a-harness)（运行框架） {#harness}

在 Dex 上运行 Agent Loop 的代码：可以是 Dex Agents 的内置 Agent Loop，也可以是某个 Agent 框架的适配器。

#### [幂等键](/concepts/step#idempotency-keys) {#idempotency-key}

调用其他系统时附带的一个值，让对方能识别重复请求并跳过。用每次尝试都保持不变的值来构造它，例如 Flow ID 加上这次调用的名字。

#### [索引槽位](/concepts/primitives/attribute#read-and-search-attributes) {#index-slot}

带编号的搜索键，例如 `keyword1` 或 `int2`，供建了索引的 Attribute 使用。槽位有类型，由一个 namespace 中的所有 Flow type 共用，数量有限。

#### [Interrupt](/agent-frameworks/approvals)（中断） {#interrupt}

Agent turn 中等待人来处理的点。审批就是一种 interrupt：Session 快照把它列在 `pending_interrupts` 下，由 `resolve_interrupt` 来答复。另一种是向用户提问。

#### [InvokeRPC](/concepts/primitives/rpc)

一个 Client API，调用 Worker 上某个 Flow 的 RPC handler。

#### [Join](/design-patterns/parallel/await)（汇合） {#join}

等待多个并行分支的辅助工具。每个分支向一个 [ChannelMap](/concepts/primitives/channel#channelmap) 报告，等待的 Step 在这个 ChannelMap 上等待，直到所有分支或所需数量的分支都已报告。

#### [Locking](/concepts/primitives/attribute#locking)（加锁） {#locking}

让访问同一组 Attribute 的 Step 和 RPC 逐个运行。

#### [Movement](/concepts/step#stepdecision-movements)（流转） {#movement}

转到另一个 Step，或者让 Flow 完成或失败的决定。

#### [Persistence schema](/concepts/flow#implement-a-flow)（持久化 schema） {#persistence-schema}

Flow 声明的 Attribute 和 Channel 列表。Worker 会拒绝 schema 中未列出的 Attribute。

#### [Registry](/components/application#registry)（注册表） {#registry}

Worker 或 Client 注册的一组 Flow。Worker 运行这些 Flow 的 Step 和 RPC，Client 用同样的定义来编码输入、解码结果。

#### [RPC](/concepts/primitives/rpc)

Worker 上的 handler，供外部读写一条正在运行的 Flow。

#### [Run ID](/concepts/flow#identifiers)

引擎为同一个 Flow ID 的每次 run 分配的 ID。

#### [server-zd](/components/server)

当前 Dex Server 实现的名字。它的二进制文件是 **dex-server-zd**。发布说明和参考页面都使用这个名字。

#### [状态快照](/concepts/step#guarantees) {#state-snapshot}

一次 Step 方法尝试读取到的 Flow 状态，即 Dex 把这次尝试交给 Worker 时的 Attribute 值。`Execute` 重试时沿用第一次尝试的快照。Hard-delete Attribute 是例外，Dex 每次尝试都重新读取它们。

#### [Step](/concepts/step)

持久化控制流的基本单元，包含可选的 WaitFor 和一个 Execute。

#### [Step durability](/concepts/step/advanced-guarantees#sync-and-async)（Step 持久性） {#step-durability}

Dex 保存 Step 进度的时机。默认的 **SYNC** 在 Flow 继续之前保存每次尝试的开始和结果。**ASYNC** 先让 Flow 继续，所以服务器故障时这次尝试可能会再运行一次。

#### [Step execution](/reference/server/runtime-client#wait-for-a-step)（Step 执行） {#step-execution}

某个 Step 类型的一次运行，用 `step_type` 加一个序号标识。

#### [StepDecision](/concepts/step#stepdecision-movements)

Execute 的返回值：接下来要运行的 Step，或者 Flow 完成或失败。其中每一部分都是一个 Movement。

#### [粘性路由](/reference/server/workers#routing-and-availability) {#sticky-routing}

Dex 把一条 Flow 的下一个 Step 或 RPC 优先发给之前服务过这条 Flow 的 Worker，最多保留 5 秒，之后其他 Worker 才能接手。这是尽力而为的机制，所以状态要保存在 Dex 里，而不是 Worker 内存里。

#### [Stream](/concepts/primitives/stream)

从 Flow 发给读取方的有序消息流，尽力投递，例如给 UI 的实时进度。读取方可以从上次停下的地方继续读。

#### [SubFlow](/concepts/primitives/subflow)

父 Flow 在它的某个 Step 中启动的一次 Flow run。父 Flow 可以像等待其他 Condition 一样等待它。

#### [Time Travel](/concepts/change-flow-code#time-travel)

让一次 Flow run 从历史中更早的某个点重新运行，通常在修复问题之后使用。这次 run 保留原来的 Run ID。它的状态回到那个点，之后的 Step 连同外部调用会再运行一次，之后的外部输入也会重新应用，除非你跳过写入重放。对应的 FlowService 调用是 `ResetFlow`。

#### [Timer](/concepts/primitives/timer)

持久化的 sleep 条件。它触发后，正在等待的 Step 继续运行。

#### [Transactional RPC](/concepts/primitives/rpc#transactional-reads-and-writes)

一种 RPC，只有当它要删除的每条 Channel 消息仍处于待处理状态时，Dex 才保存它的修改。持有锁的 RPC 总是 transactional 的。

#### [Turn segment](/agent-frameworks/framework-support#how-each-framework-runs-a-turn)（Turn 分段） {#turn-segment}

在 Claude Agent SDK harness 中，一次 turn 里由一次 CLI 运行处理的部分，对应一个 `RunModel` Step。写入类 Tool Call 会结束一个 segment。

#### [Versioning](/concepts/change-flow-code#versioning-flow-code)（版本管理） {#versioning}

在 Flow 仍未结束时修改 Flow 代码。Dex 不重放代码，所以部署不会引发重放错误。保留旧的 Step 类型和 RPC，直到使用它们的 Flow 结束。

#### [WaitFor](/concepts/step#waitfor-and-execute)

Step 的一个方法，在 Execute 之前登记要等待的持久化 Condition。

#### [Worker](/components/application)

托管 Flow 定义的进程，运行 WaitFor、Execute 和 RPC handler。
