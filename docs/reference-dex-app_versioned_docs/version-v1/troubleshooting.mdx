# Dex app troubleshooting and FAQ {#dex-app-troubleshooting-and-faq}

This page lists common problems of a [Managed Dex App](/components/managed-dex-app), with the cause and the fix of each. Each heading states the problem as you see it. For a finding of the import check, start with its section in [Read an import report](/reference/dex-app/v1/manifest#import-report).

## Import refused with `template_manifest_missing` and `app_manifest_invalid` on an older repository {#old-manifest-location}

**Cause.** The repository uses the earlier manifest location and schema. It keeps the template manifest at `.superverse/template.json`, and `dex-app.yaml` has `schemaVersion: superverse.dev/dex-app/v1`. Dex Cloud reads `.dex/template.json` ([S1](/reference/dex-app/v1/manifest#s1)) and accepts only `schemaVersion: dex.superdurable.io/dex-app/v1` ([S2](/reference/dex-app/v1/manifest#top-level-fields)).

**Fix.** Move the template manifest and set the new schema version:

~~~bash
mkdir -p .dex && git mv .superverse/template.json .dex/template.json
~~~

~~~yaml
# dex-app.yaml
schemaVersion: dex.superdurable.io/dex-app/v1
~~~

Push to `main` and check again. In an existing project, a running coding workspace may skip reinstalling dependencies until it is recreated.

## A connector package is not found {#connector-package-not-published}

**Cause.** Dex Cloud installs only published `@superdurable/connector-*` packages from npm, at the exact version that `dex-app.yaml` and `package-lock.json` pin. A local tarball in the repository, such as one under `.local-packages/`, is outside what the build installs. A misspelled package name fails the same way.

**Fix.** Check the package name and version on npm, then pin that release in `package.json`, `package-lock.json`, and the [`connectors`](/reference/dex-app/v1/manifest#connectors) entry. For example, the Hacker News connector is `@superdurable/connector-hackernews`:

~~~bash
npm view @superdurable/connector-hackernews versions
~~~

## Two copies of `@superdurable/dex` or `@superdurable/connectors-sdk` after adding a connector {#duplicate-sdk-packages}

**Cause.** The connector needs a newer `@superdurable/dex` or `@superdurable/connectors-sdk` than the application pins. npm then installs a second copy for the connector.

**Fix.** Raise the application's pins to the versions the connector needs, run `npm install`, and check that each package appears in one version:

~~~bash
npm ls @superdurable/dex @superdurable/connectors-sdk
~~~

## `dex-app.yaml` is refused for a YAML value {#strict-yaml}

**Cause.** `dex-app.yaml` is strict YAML. The decoder refuses plain values that YAML libraries read differently, such as a version `0.6.0`, `yes` and `no`, and a number with a leading zero. It also refuses anchors, aliases, tags, and a repeated key.

**Fix.** Quote each value that must be a string, such as `version: "0.6.0"`, and write each key once. The [YAML rules](/reference/dex-app/v1/manifest#yaml-rules) list every refused form.

## An environment variable is refused as reserved {#reserved-environment-variable}

**Cause.** Dex Cloud reserves names that start with `SUPERVERSE_`, `DEX_`, `AWS_`, `LD_`, `GIT_`, or `GO`, and a list of exact names. The `GO` prefix also covers names such as `GOOGLE_API_KEY` today. A fix for that case is planned.

**Fix.** Rename the variable in [`application.environment`](/reference/dex-app/v1/manifest#application-environment) and in the code that reads it, such as `MAPS_API_KEY` instead of `GOOGLE_API_KEY`.

## The import says the repository cannot be read {#repository-cannot-be-read}

**Cause.** The SuperDurable Dex Cloud GitHub App lacks access to the repository, or the GitHub organization is not connected to the Teamspace.

**Fix.**

- When the app is installed with **Only select repositories**, add the repository to that list in the app's settings on GitHub.
- When the organization is missing under **Import from**, a Teamspace admin connects it in the Teamspace's **Connections**. See [Connect GitHub is refused](#connect-github-refused).

## **Connect GitHub** is refused {#connect-github-refused}

**Cause.** Only a Teamspace admin connects GitHub. For an organization, that admin's GitHub account must be an owner of the organization. A plain member of the organization is refused.

**Fix.** Ask a Teamspace admin who owns the GitHub organization to choose **Connect GitHub** in **Connections**.

## A Gmail connection cannot be selected {#auth-method-not-selectable}

**Cause.** Gmail, like every connector with several authentication methods, needs `authMethodId` to name the method. An entry with `authMethodId: ""` names no method, so no connection matches it.

**Fix.** Set `authMethodId` to the method of the connection, such as `google-oauth` for Gmail. Keep `""` only for a connector release with one authentication method. See [`connectors`](/reference/dex-app/v1/manifest#connectors).

## `make test-app` fails with "the test engine is not configured" {#test-engine-not-configured}

**Cause.** The application tests start a Dex Server for the run ([S5](/reference/dex-app/v1/manifest#s5)). On your machine, they find its binary through the environment variable `DEX_SERVER_ZD_BINARY`, and it is unset.

**Fix.** Set `DEX_SERVER_ZD_BINARY` to the path of a `dex-server-zd` binary, then run the tests again:

~~~bash
DEX_SERVER_ZD_BINARY=/path/to/dex-server-zd make test-app
~~~

## Publish is blocked {#publish-blocked}

**Cause.** **Setup** is incomplete for Live: a required connection is not chosen, or a required environment value is not set. Live has its own values. Dex Cloud never copies secrets from Preview to Live.

**Fix.** Open **Setup**, choose each connection, and set each required value for Live, secrets included. Then publish again.

## A Dex Agents session ends as Canceled instead of Completed {#agent-session-canceled}

**Cause.** The application cancels the session to end it. A cancel ends the session as **CANCELED**.

**Fix.** End the session with a graceful complete:

~~~typescript
await client.stopFlow(sessionId, {type: StopType.GRACEFUL_COMPLETE});
~~~

Graceful complete needs Dex Agents 0.6.14 or later and server-zd 0.1.34 or later. A session that was idle before the upgrade completes this way after its next turn. See [End a session](/reference/agents/session-limits#end-a-session).

## A connector write has an unknown outcome {#connector-write-outcome-unknown}

**Cause.** The connector cannot tell whether the provider applied the write, such as after a timeout. The connector already resends such a write within its bounded limit, and reads back first where the operation supports it.

**Fix.** Keep the application from resending the write on its own. Read the provider's state back, or reconcile it, before you act on the write. See [Bounded resends](/reference/agents/connector-tools#bounded-resends).
