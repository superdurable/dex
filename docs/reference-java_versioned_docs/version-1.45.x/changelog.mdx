# Change log

This page lists user-visible changes to the Java SDK, newest first; each section covers the changes since the previous release of this component.

## 1.45 {#v1-45}

Released 2026-11-11 as [sdk-java/v1.45.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.45.0); 1.45.1 released 2026-11-14 as [sdk-java/v1.45.1](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.45.1); 1.45.2 released 2026-11-15 as [sdk-java/v1.45.2](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.45.2); 1.45.3 released 2026-11-16 as [sdk-java/v1.45.3](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.45.3); 1.45.7 released 2026-11-18 as [sdk-java/v1.45.7](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.45.7); 1.45.8 released 2026-11-18 as [sdk-java/v1.45.8](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.45.8).

### Added

- **WorkerOptions.Builder.flowDefinitionPaths** and **WorkerOptions.Builder.flowDefinitions** make a **Worker** upload Flow Definition Graph documents when it starts, so Dex Web can draw the Flow types it registers. **FlowDefinitionDocument** holds an in-memory document. Upload failures, including a Server without Flow definition storage, are logged as warnings and never stop the Worker. [Reference](/reference/java/1.45.x/workers#upload-flow-definitions).
- **Client.uploadFlowDefinitions** uploads documents from a deploy or CI script and returns a **FlowDefinitionUploadResult** with a **FlowDefinitionUploadOutcome** for each document. [Reference](/reference/java/1.45.x/client#api-names).
- **PullWorkerOptions.Builder.taskQueue** makes a Worker pull one named task queue, and **StartFlowOptions.Builder.taskQueue** starts a Flow on one. Only Workers of that task queue run the Flow's Steps and RPCs, even when Workers of other task queues register the same Flow type. **SubFlowOptions.Builder.taskQueue** sends a SubFlow to another task queue; a SubFlow without it inherits its parent's task queue, and **dex.default** selects the default task queue. To serve several task queues, run one Worker per task queue. **PullQueueRegistrationState.getTaskQueue** and **PullRegistrationError.getTaskQueue** report the Worker's task queue. A named task queue requires Server protocol 5: the Worker and Client refuse it on an older Server, and a stream that the Server registers on a different task queue becomes a permanent rejection. [Reference](/reference/java/1.45.x/workers#task-queues). Since 1.45.1.
- **Client.cloneForkFlow** creates a new Flow whose first run starts from a copy of another Flow run's state, at the current point or at a time travel point, while the source run keeps running. **CloneForkFlowOptions** selects the point, the source run, the new Flow's ID reuse policy, request ID, configuration, task queue, Attributes, Flow timeout, reason, and SubFlow reset policy; **CloneForkFlowResult** returns the new run ID and the copied source point. The call requires Dex server-zd 0.1.33 or later; against an older Server it throws **IllegalStateException** before sending the request. Since 1.45.2.
- **TimeTravelType.EVENT_ID** with **TimeTravelOptions.Builder.eventId** returns a Flow to the point right after a history event, and **TimeTravelOptions.Builder.subFlowResetPolicy** takes a **SubFlowResetPolicy** that decides what happens to SubFlow conditions that restored Steps wait on. **TimeTravelType.CURRENT** selects the current point for **cloneForkFlow** only. Since 1.45.2.
- **FlowErrorType.SUB_FLOW_ABANDONED** marks a failed SubFlow result whose parent Flow stopped waiting for the child, because a Time Travel's SubFlow reset policy failed the restored SubFlow condition. Earlier versions report such a result with a **null** error type. Code that matches every **FlowErrorType** value exhaustively, such as a switch expression, must handle the new value. Since 1.45.2.
- **GracefulCompletion.requested()** creates a wait condition that completes once the Flow has a graceful completion request, from **Client.stopFlow** with **StopType.GRACEFUL_COMPLETE** or from a Step's **gracefulComplete** decision. **Context.isGracefulCompletionConditionCompleted()** reports its result in execute. A Step can wait for its next message or the request with **Wait.anyOf**, handle a consumed message first, and return **deadEnd** otherwise. The condition needs Dex Server 0.1.34 or newer; with an older Server, the Step's waitFor fails with **GracefulCompletionConditionUnsupportedException**. The SDK now supports Server protocol 7. Since 1.45.3.
- **StopType.GRACEFUL_COMPLETE**, **StopType.FORCE_COMPLETE**, and the **StopFlowOptions(StopType, String, Object)** constructor let **Client.stopFlow** complete a Flow with a result, like the **gracefulComplete** and **forceComplete** Step decisions. They need Dex Server 0.1.34 or newer. Since 1.45.3.
- **Context.supportsGracefulCompletionCondition** reports whether the connected Server supports **GracefulCompletion.requested**, from the protocol version the Worker negotiated, without a request. **waitFor** can add the condition only when it returns true and keep working with Servers older than protocol 7. The default method returns false. [Reference](/reference/java/1.45.x/waits#graceful-completion-requests). Since 1.45.3.
- **PullWorkerOptions.Builder.minOpenSlots** makes a pull Worker adaptive when it is below **maxConcurrentTasks**. The Worker keeps between the two counts of slot streams open, both including the reserved RPC slots: it doubles its Step-and-RPC streams when a task takes the last idle one, and every 30 seconds it half-closes half of the idle surplus. An idle adaptive Worker holds only its floor of Server streams. The default equals **maxConcurrentTasks**, which keeps the Worker fixed with unchanged behavior. Since 1.45.7.
- An adaptive Worker clamps **maxConcurrentTasks** above the Server's **matching.maxConcurrentTasksCap** to the cap with a warning. It treats a **RESOURCE_EXHAUSTED** registration of a growth stream, or of a reconnect after readiness, as a soft limit, without a **PullRegistrationError**. After a soft rejection the Worker waits for another of its registered streams to end, or for the next 30-second shrink window, before it opens a stream again. While rejections continue, it grows by at most one batch per window. Since 1.45.7.
- **Worker.getPullSlotStreamState** returns a **PullSlotStreamState** snapshot of the slot streams: open, registering, busy, and idle streams, orphaned handlers, the floor and capacities, and grow and shrink counters. Since 1.45.7.

### Breaking

- A Step whose Step type contains **-** can no longer start SubFlows. The child Flow ID joins the parent Flow ID, Step execution ID, and SubFlow index with **-**, so a dash made two parents share one child. When such a Step's **waitFor** returns a **SubFlow.run** condition, the server rejects the result as an invalid Worker response and fails the attempt without retry; with the default failure policy, the Flow fails. Steps that start no SubFlows are unaffected. To migrate, rename the Step type, for example by overriding **getStepType**; the rename changes the child Flow IDs of new SubFlow starts. [Reference](/reference/java/1.45.x/subflow#step-types-that-start-subflows).

### Changed

- A fixed pull Worker with **maxConcurrentTasks** unset now opens one stream first, learns the Server's **matching.maxConcurrentTasksCap** from its registration, and clamps its CPU-count default to the cap with a warning instead of failing to start. Its other streams open after that first registration. An explicit **maxConcurrentTasks** above the cap still fails to start, and a fixed Worker with an explicit value still opens all its streams at once. Since 1.45.7.

### Fixed

- The **Join** documentation no longer recommends reporting a result for a cancelled branch from the cancelling RPC, which could count that branch twice. A cancelled branch never reports, and no other code can safely report for it. [Reference](/reference/java/1.45.x/waits).
- Maven POM metadata links the Apache 2.0 license text shipped with the Java SDK. Since 1.45.2.
- A Worker serves an RPC declared without input when the request leaves the input unset, as TypeScript Clients before 1.45.8 send it. Before, the Worker failed the call with **Value has no concrete kind**. An RPC declared with an input still needs one; an unset input fails the call with **ValueMappingException**. (#2034) Since 1.45.8.

## 1.44 {#v1-44}

Released 2026-11-10 as [sdk-java/v1.44.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.44.0).

### Added

- **Join** and **JoinRound** synchronize parallel branches of one Flow. **Join.fork** starts a round from a split Step and derives the round key and branch count; **Join.forkWithRoundKey** takes an application key, for example in an RPC. Branches report with **endBranch** or **reportBranchResult**. The join Step waits with **forAllBranches**, **forFirstBranch**, or **forBranches**, and the next round resets with **forRemainingBranches**. A Join is stored as a ChannelMap with the same name; **Join.getChannelMap** returns it for reading a round's pending results, never for publishing. [Reference](/reference/java/1.45.x/waits).
- **StepDecision.goToMany(List)** and **RPCResult.of(output, List)** accept a list of movements, such as the result of **Join.fork**, and behave like the varargs forms. A call with a literal **null** argument is now ambiguous and no longer compiles; it always threw at run time. [Reference](/reference/java/1.45.x/step-decisions#gotomulti).

## 1.43 {#v1-43}

Released 2026-11-10 as [sdk-java/v1.43.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.43.0).

### Breaking

- Removed **Client.triggerContinueAsNew**, **FlowStatus.CONTINUED_AS_NEW**, **FlowConfig.Builder.continueAsNewThreshold**, **FlowConfig.Builder.continueAsNewPageSizeBytes**, **SearchFlowsOptions**, and the four-argument **Client.searchFlows** overload. Use the three-argument search method. [Reference](/reference/java/1.45.x/flow#flow-config).
- Removed **WaitForStepCompletionOptions.Builder.internalHandlerTimeout** and **WaitForAttributeOptions.Builder.internalHandlerTimeout**. Request IDs remain accepted but the server does not read them for these waits. [Reference](/reference/server/runtime-client#wait-timeouts-and-limits).
- Generated bindings rename **FlowExecutionID** to **FlowRunID** and **getFlowExecutionId** to **getFlowRunId**. ProtoJSON uses **flowRunId**. [Reference](/reference/server/runtime-client#describe-a-flow).

## 1.40 {#v1-40}

Released 2026-11-09 as [sdk-java/v1.40.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.40.0).

### Added

- **FlowConfig.Builder.offloadHistory(boolean)** chooses whether a run offloads its history to object storage. Omitting it means true. Pass false for many short runs that close soon. Set it at start through **StartFlowOptions.Builder.configOverride** or in **SubFlowOptions**. A SubFlow otherwise inherits its parent's value, and **Client.updateFlowConfig** rejects it with INVALID_ARGUMENT. It requires server-zd 0.1.23 or later. [Reference](/reference/server/configuration#history-offload).

### Changed

- **FlowConfig.Builder.deleteExpiredHistoryObjects(boolean)** is deprecated. It has no effect, and the SDK no longer sends it. Existing code that sets it still compiles.

## 1.39 {#v1-39}

Released 2026-11-09 as [sdk-java/v1.39.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.39.0).

### Added

- **FlowConfig.Builder.deleteExpiredHistoryObjects(boolean)** controls expired history object deletion at start, on update, and for SubFlows. It requires history offload and server-zd 0.1.22 or later.

### Changed

- A LoadBlobs request names at most 1,000 entries. The SDK batches larger requests and keeps the input order.

## 1.38 {#v1-38}

Released 2026-11-07 as [sdk-java/v1.38.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.38.0).

### Added

- **FlowConfig.Builder.historyWindowEvents** sets about how many of the newest history events a run keeps for history reads and Time Travel. Set it at start, change it with **Client.updateFlowConfig**, or override it for a SubFlow. Omitting it uses the server's **history.windowEvents** setting. Dex rejects a value that is not positive or exceeds **history.maxWindowEvents** with INVALID_ARGUMENT. It requires server-zd 0.1.21 or later. [Reference](/reference/server/configuration#history-window).

Released 2026-11-06 as [sdk-java/v1.37.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.37.0). Reference: [1.37.x](/reference/java/1.37.x/).

## 1.35 {#v1-35}

Released 2026-11-06 as [sdk-java/v1.35.0](https://github.com/superdurable/dex/releases/tag/sdk-java%2Fv1.35.0). Reference: [1.35.x](/reference/java/1.45.x/).

### Breaking

- Workers and the Client’s first call now require server-zd 0.1.17 or later (protocol version 4). Upgrade all server processes before upgrading the SDK. [Reference](/reference/server/upgrades).
- Worker startup fails when **maxConcurrentTasks** exceeds **matching.maxConcurrentTasksCap** (256 by default). Lower the Worker setting or raise the server cap and **matching.maxStreams** first. [Reference](/reference/java/1.45.x/workers#capacity-and-shutdown).
- **RetryPolicy.Builder.totalDuration** now starts at the first hand-out and only gates scheduling another retry. Set method timeouts to bound running attempts. [API reference](pathname:///api/java/latest/io/superdurable/dex/RetryPolicy.Builder.html).
- A Step with no available or supporting Worker waits durably without consuming a retry. Set a Flow timeout to bound that wait. [Reference](/reference/server/workers#step-task-queue).
- A Step attempt interrupted after its hand-out was committed fails with **NOT_COMPLETED** and consumes a retry. Review retry policies and side effects before upgrading. [Reference](/reference/java/1.45.x/failure-and-retries#same-attempt-redelivery).

### Added

- **RecoveryErrorInfo.getAttemptProgress()** distinguishes a failed Step method that never started from one that may have run. [API reference](pathname:///api/java/latest/io/superdurable/dex/RecoveryErrorInfo.html).

### Changed

- Workers open one execution stream per slot; **reservedRpcTasks** selects RPC-only slots. By default, a Worker with at least two slots reserves one for RPCs. [Reference](/reference/java/1.45.x/workers#capacity-and-shutdown).
- **stop** drains running handlers and returns tasks that did not start without consuming a retry. [Reference](/reference/java/1.45.x/workers#capacity-and-shutdown).

### Deprecated

- **idleStreamsPerQueue** is accepted but ignored, and **getPullReservedRpcDeclines()** always reports zero. Use execution-slot capacity and queue metrics instead. [Reference](/reference/java/1.45.x/workers#reserved-rpc-capacity).
