# Parent–child Flows

Use a durable SubFlow when a Java parent Flow must start and wait for another Flow. SubFlows are
normal Temporal or Cadence Workflows with their own Flow IDs, history, retries, and lifecycle.

```java
final class ProcessInvoice implements Step<Invoice> {
    public Wait waitFor(Context context, Invoice invoice) {
        return Wait.until(SubFlow.run(InvoiceFlow.class, invoice));
    }

    public StepDecision execute(Context context, Invoice invoice) {
        FlowResult result = SubFlow.getConditionResults(context);
        Receipt receipt = result.getSingleOutput(Receipt.class);
        return StepDecision.gracefulComplete(receipt);
    }
}
```

`Wait.allOf` provides fan-out/fan-in without manual dynamic Channels. `Wait.anyOf` returns a
`RUNNING` snapshot for an unfinished loser; its generated Flow ID lets application code inspect or
stop that independent execution.

Dex resolves an existing execution using `SubFlowReusePolicy`, safely survives local activity
retries, and carries partial results across continue-as-new. Parent completion does not cancel
SubFlows.

See [Durable SubFlows](/capabilities/advanced/subflows) for reuse behavior, lifecycle limitations,
options, and cleanup. The runnable Java sample is under
`examples/java/src/main/java/io/superdurable/dex/patterns/workflow/parentchild`.

Every SDK exposes the same timeout and timeout-policy fields on `SubFlowOptions`.
Use fail, cancel, or handler to override the child Flow's registered default. The
child completes terminal coordination and reports its failed, canceled, or
handler-produced result to the parent before closing. Continue-as-new preserves
the child's deadline; a child retry receives a fresh timeout budget.
