# Entity Flow with SQL Projection

Keep one Flow for each entity, such as a user. Dex projects (copies) selected
Attributes of that Flow into a SQL table that your application owns. The Flow
holds the authoritative state, and every write goes through it. Dex updates the
SQL table asynchronously, and the table holds only the latest values. Use it for
reads and queries.

The runnable example keeps one **UserProfileFlow** per user. Its Flow ID becomes
the **user_id** primary key in **public.user_profiles**. The Server configuration
names the target Attribute Store **entityStore**.

## When to use this pattern

Use this pattern when an entity needs durable state or updates through RPCs, and
your application also needs to query its latest state in a database. Do not make
Flow decisions from the SQL table. Read the Flow state instead.

## How it works

Use the entity ID as the Flow ID. Mark each projected Attribute and select the Attribute Store when you start the Flow. Update or delete Attributes through the Flow, and Dex projects the resulting values to SQL. See [External Attribute Sync](/components/external-attribute-sync) for the setup.

The example projects text, boolean, integer, double, datetime, and JSON values. Deleting an Attribute keeps the SQL row and projects **NULL** to its column. The [Attribute Store sync reference](/reference/server/attribute-store-sync) gives the column types, delivery timing, and retries.

## Core implementation

### Define synced Attributes

Each SDK marks the same profile fields for projection. The Flow's persistence
schema includes these Attributes, so Dex stores each value durably before it
syncs the value to SQL.

### Update through a Flow RPC

Clients update a profile by calling this RPC. It validates the profile, then
updates every projected Attribute.

func (flow *UserProfileFlow) GetRPCs() []dex.RPCDef {
	return []dex.RPCDef{

		dex.DefineRPC(flow.GetProfile, nil),
		dex.DefineRPC(flow.ClearProfile, nil),

func (*UserProfileFlow) UpdateProfile(
	ctx dex.Context,
	profile UserProfile,
) (*dex.RPCResult[dex.None], error) {
	if err := validateProfile(profile); err != nil {
		return nil, err
	}
	if err := DisplayName.Set(ctx, profile.DisplayName); err != nil {
		return nil, err
	}
	if err := Email.Set(ctx, profile.Email); err != nil {
		return nil, err
	}
	if err := MarketingOptIn.Set(ctx, profile.MarketingOptIn); err != nil {
		return nil, err
	}
	if err := Credits.Set(ctx, profile.Credits); err != nil {
		return nil, err
	}
	if err := Weight.Set(ctx, profile.Weight); err != nil {
		return nil, err
	}
	if err := LastLoggedIn.Set(ctx, profile.LastLoggedIn); err != nil {
		return nil, err
	}
	if err := Metadata.Set(ctx, profile.Metadata); err != nil {
		return nil, err
	}
	return &dex.RPCResult[dex.None]{}, nil
}

### Select the storage target at Flow start

The Attribute Store is configured on the Server. Select it in **FlowConfig**
when you start the Flow. The initial Attribute values in that start request are
projected to SQL too.

## API endpoints

- **POST /patterns/entity-store/profile** — create a profile Flow
- **POST /patterns/entity-store/profile/update** — update its synced fields
- **GET /patterns/entity-store/profile?userId=...** — read the profile from the Flow
- **POST /patterns/entity-store/profile/clear?userId=...** — delete the synced values

## Run with PostgreSQL

The [shared example setup](https://github.com/superdurable/dex/tree/main/examples/entity-store) creates **public.user_profiles** and starts **dexcli dev** with the **entityStore** configuration. It includes curl commands for every language example.
