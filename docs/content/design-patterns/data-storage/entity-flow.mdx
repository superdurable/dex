# Entity Flow

Keep one long-lived Flow for each business entity, such as a customer, an order, or an account. The Flow holds the entity's state for as long as the entity exists. Every change goes through the Flow, so Dex saves it durably.

The runnable example keeps one `CustomerAccountFlow` per customer account. It stores a display name, an email address, a credit balance, and whether the account is retired. Try its routes in the [examples playground](https://github.com/superdurable/dex/tree/main/examples/playground).

<DocsFlowDefinitionGraph graph={flowDefinition} />

## When to use this pattern

Use an Entity Flow when one business entity needs durable state that several callers change over time. Each change must be validated against the current state. Typical examples are a customer account, a shopping cart, a device, or a subscription record.

To also query the latest state of many entities with SQL, extend this pattern with [Entity Flow with SQL Projection](/design-patterns/entity-store).

## How it works

1. **Open the account.** The application starts a Flow whose ID comes from the account ID, such as `customer-account-42`. The start request sets the initial Attributes and an ID reuse policy that rejects every reused ID. A second start with the same account ID fails while Dex keeps the account's Flow, so each account has exactly one Flow.
2. **Change the contact details.** `UpdateContactDetails` checks that the account is open, validates the new name and email address, then writes both Attributes.
3. **Adjust the credit balance.** `AdjustCreditBalance` checks that the account is open, reads the balance, adds the amount, and rejects a result below zero. All three RPCs that change the account declare the same lock. Calls that get the lock run one at a time. A call that finds the lock held fails with a lock conflict, and the caller retries only that error, with backoff.
4. **Read the account.** The application reads the Attributes with the Client. No Worker runs for the read.
5. **Retire the account.** `RetireAccount` checks that the balance is zero, marks the account retired, and starts `CloseAccountStep`. A repeated retire changes nothing. `CloseAccountStep` archives the account and completes the Flow gracefully.

Between these calls the Flow has no active Step. It keeps running and holds no Worker, so it can live for months or years.

## Core implementation

### Open one Flow per entity

Derive the Flow ID from the entity ID. Start the Flow with no Flow timeout, and set the initial state as Attributes in the start request. Treat an already-started error as "this account exists".

### Change state through RPCs

Each RPC checks that the account is open, validates its input against the current state, then writes the Attributes. `UpdateContactDetails`, `AdjustCreditBalance`, and `RetireAccount` declare a lock on the balance Attribute. The lock makes each check and its write one step, so no change slips in after the account is retired and no adjustment overwrites another.

```python
@rpc(name="UpdateContactDetails", lock_attributes=(credit_balance.lock(),))
def update_contact_details(self, context: Context, input: ContactDetails) -> None:
    self.require_open_account(context)
    input.validate()
    self.display_name.set(context, input.display_name)
    self.email.set(context, input.email)

@rpc(name="AdjustCreditBalance", lock_attributes=(credit_balance.lock(),))
def adjust_credit_balance(
    self, context: Context, input: CreditAdjustment
) -> RPCResult[int]:
    self.require_open_account(context)
    if input.amount == 0:
        raise ValueError("amount must not be zero")
    balance = self.credit_balance.get(context) + input.amount
    if balance < 0:
        raise ValueError("credit balance cannot go below zero")
    self.credit_balance.set(context, balance)
    return RPCResult(balance)
```

```go
func (flow *CustomerAccountFlow) GetRPCs() []dex.RPCDef {
	accountLock := &dex.RPCOptions{
		LockAttributes: []dex.AttributeLock{dex.LockAttribute(CreditBalance)},
	}
	return []dex.RPCDef{
		dex.DefineRPC(flow.UpdateContactDetails, accountLock),
		dex.DefineRPC(flow.AdjustCreditBalance, accountLock),
		dex.DefineRPC(flow.RetireAccount, accountLock),
	}
}

func (*CustomerAccountFlow) AdjustCreditBalance(
	ctx dex.Context,
	adjustment CreditAdjustment,
) (*dex.RPCResult[int64], error) {
	if err := requireOpenAccount(ctx); err != nil {
		return nil, err
	}
	if adjustment.Amount == 0 {
		return nil, errors.New("amount must not be zero")
	}
	balance, err := CreditBalance.Get(ctx)
	if err != nil {
		return nil, err
	}
	balance += adjustment.Amount
	if balance < 0 {
		return nil, errors.New("credit balance cannot go below zero")
	}
	if err := CreditBalance.Set(ctx, balance); err != nil {
		return nil, err
	}
	return &dex.RPCResult[int64]{Output: balance}, nil
}
```

```rust
fn adjust_credit_balance(
    &self,
    context: &mut Context,
    adjustment: CreditAdjustment,
) -> HandlerResult<RpcResult<i64>> {
    require_open_account(context)?;
    if adjustment.amount == 0 {
        return Err(account_error("amount must not be zero"));
    }
    let balance = CREDIT_BALANCE
        .get_required(context)?
        .checked_add(adjustment.amount)
        .ok_or_else(|| account_error("credit balance is out of range"))?;
    if balance < 0 {
        return Err(account_error("credit balance cannot go below zero"));
    }
    CREDIT_BALANCE.set(context, balance)?;
    Ok(RpcResult::new(balance))
}

fn rpcs(&self) -> RpcList<Self> {
    RpcList::new()
        .procedure(
            UPDATE_CONTACT_DETAILS.lock(CREDIT_BALANCE.lock()),
            Self::update_contact_details,
        )
        .function(
            ADJUST_CREDIT_BALANCE.lock(CREDIT_BALANCE.lock()),
            Self::adjust_credit_balance,
        )
        .function_without_input(
            RETIRE_ACCOUNT.lock(CREDIT_BALANCE.lock()),
            Self::retire_account,
        )
}
```

Only calls that get the lock run, and they run one at a time. A locked RPC fails at once with a lock-conflict error when another call holds the lock. Retry only that error, with backoff, and pass any other error to the caller. See [RPC lock conflicts](/reference/server/runtime-data#rpc-lock-conflicts).

### Read state with the Client

Read stored Attributes with the Client's Attribute read. It returns committed values and runs no Worker. Use a read-only RPC instead when the read needs Flow code, such as authorization or a derived view; see [Read-only RPCs](/reference/server/runtime-data#read-only-rpcs-and-terminal-flows).

### Retire the entity

`RetireAccount` holds the same lock as the other RPCs. It checks the balance, sets the `retired` Attribute, and starts `CloseAccountStep`. When the account is already retired, it returns without starting another Step, so a retried retire is safe.

`CloseAccountStep` archives the account and returns `GracefulComplete`, and the Flow completes. Until then, RPCs still run, and each one sees `retired` under the lock and rejects the change. When the archive is unavailable, the Step fails and Dex retries it; the Flow stays running and the account stays retired. The completed Flow stays readable with the Client until Dex purges it.

```python
def execute(self, context: Context, input: None) -> StepDecision:
    self.archive.archive_account(context.flow_id)
    return graceful_complete()

@rpc(name="RetireAccount", lock_attributes=(credit_balance.lock(),))
def retire_account(self, context: Context) -> RPCResult[None]:
    if self.retired.get(context):
        return RPCResult(None)
    if self.credit_balance.get(context) != 0:
        raise ValueError("spend or refund the credit balance before retiring")
    self.retired.set(context, True)
    return RPCResult(None, next_steps=(StepMovement.of(CloseAccountStep, None),))

def require_open_account(self, context: Context) -> None:
    if self.retired.get(context):
        raise ValueError("account is retired")
```

```go
func (*CustomerAccountFlow) RetireAccount(
	ctx dex.Context,
	_ dex.None,
) (*dex.RPCResult[dex.None], error) {
	retired, err := Retired.Get(ctx)
	if err != nil {
		return nil, err
	}
	if retired {
		return &dex.RPCResult[dex.None]{}, nil
	}
	balance, err := CreditBalance.Get(ctx)
	if err != nil {
		return nil, err
	}
	if balance != 0 {
		return nil, errors.New("spend or refund the credit balance before retiring")
	}
	if err := Retired.Set(ctx, true); err != nil {
		return nil, err
	}
	return &dex.RPCResult[dex.None]{
		NextSteps: []dex.StepMovement{dex.MovementOf(CloseAccountStep{}, nil)},
	}, nil
}

func (step CloseAccountStep) Execute(ctx dex.Context, _ dex.None) (*dex.StepDecision, error) {
	if err := step.archive.ArchiveAccount(ctx.FlowID()); err != nil {
		return nil, err
	}
	return dex.GracefulComplete(nil), nil
}
```

```java
@RPC(name = "RetireAccount", lockAttributes = {"credit_balance"})
public RPCResult<Void> retireAccount(final Context context) {
    if (Boolean.TRUE.equals(retired.get(context))) {
        return RPCResult.of((Void) null);
    }
    if (creditBalance.get(context) != 0) {
        throw new IllegalArgumentException(
                "spend or refund the credit balance before retiring");
    }
    retired.set(context, true);
    return RPCResult.of((Void) null, StepMovement.of(CloseAccountStep.class, null));
}

public StepDecision execute(final Context context, final Void input) {
    archive.archiveAccount(context.getFlowId());

}
```

```rust
fn retire_account(&self, context: &mut Context) -> HandlerResult<RpcResult<()>> {
    if RETIRED.get(context)?.unwrap_or(false) {
        return Ok(RpcResult::new(()));
    }
    if CREDIT_BALANCE.get_required(context)? != 0 {
        return Err(account_error(
            "spend or refund the credit balance before retiring",
        ));
    }
    RETIRED.set(context, true)?;
    Ok(RpcResult::new(()).then(StepMovement::to(&self.close_account, ())))
}

fn execute(&self, context: &mut Context, _input: ()) -> HandlerResult<StepDecision> {
    self.archive
        .archive_account(context.flow_id())
        .map_err(|message| account_error(&message))?;
    Ok(StepDecision::graceful_complete(()))
}
```

An entity Flow can also have a Step that waits on something long, such as a Channel of incoming commands. Add the graceful completion condition to that wait where your SDK and Server provide it; a completion request then wakes the Step. Where they do not, have the retire RPC publish an explicit close message to that Channel, and let the Step end when it reads the message. See [Wait for a completion request](/reference/server/step-and-flow-close#graceful-completion-condition) for the SDK and Server support.

## Keep the state bounded

Each Attribute holds one value that the Flow rewrites on every change. Keep the entity's current state in plain Attributes. When the entity collects a growing history, such as its orders or audit events, store that history in a [Sequentially Chunked AttributeMap](/design-patterns/sequentially-chunked-attribute-map).
