# Cron schedule

Run cron-like fixed-interval work in one durable Flow.

## Problem and approach

Start one Flow with a positive interval and run count. An interval is expressed
in minutes, hours, or days. Each occurrence starts the next durable timer at
the same time it starts the work, so the interval is measured from one run start
to the next rather than from work completion. The sample starts ten hourly runs.
Stop the Flow to cancel its active timer and end the loop.

The Flow exposes **Trigger** and **Skip** Channels. Publish to Trigger to run
the pending occurrence now. Publish to Skip to consume the pending occurrence
without running its work. Both actions begin the next interval from that
occurrence. A skipped occurrence consumes one run from the configured limit.

This is a fixed-interval pattern, not calendar-aligned scheduling and not a
cron-expression API. Work can overlap when it runs longer than the interval.
