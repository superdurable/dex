# Stop Long-Running Work

Stop Long-Running Work, formerly Interruptible execution, stops work that runs for a long time when someone asks for it.

Use this pattern for work that loops for a long time, such as batch processing. To wait for an external system, use [Polling](/design-patterns/durable-timer/polling) instead.

## Choose how to stop {#choose-how-to-stop}

Dex has three built-in ways to stop work. Choose by what must stop and what must still run.

| Way | What stops | Use it when |
| --- | --- | --- |
| StopFlow | The whole run, at once | The run must end now, and no Step needs to report or clean up. |
| Graceful completion | Steps that wait on the graceful completion Condition; the Flow completes once no Step is active | The Flow should finish its current work and then complete. |
| Step cancellation | Chosen running Steps | One branch must stop while the rest of the Flow keeps running. |

### Stop the whole run with StopFlow {#stopflow}

A client calls `StopFlow` to cancel, fail, or terminate the run. Each type records a different terminal status. The run closes as soon as the stop commits.

After the stop commits, only handlers that were already running can still run. No later Step decision, failure route, or cleanup runs. Running Steps get a cancellation signal. A handler that ignores it keeps running, and its calls to external systems still take effect. Dex discards its uncommitted result. Whoever waits for the stopped Flow reads its terminal state instead of waiting for a report.

Use StopFlow when nothing in the Flow needs to finish its work or run cleanup. See [Stop a Flow](/reference/server/runtime-client#stop-a-flow) for every stop type.

### Ask the Flow to complete gracefully {#graceful-completion}

The Flow is asked to complete gracefully: a client calls `StopFlow` with graceful complete, or a Step returns `GracefulComplete`. Active Steps keep running, and their decisions still apply. The Flow completes once no Step is active.

A waiting Step that includes the graceful completion Condition stops waiting when the request arrives. Its `Execute` handles any message it consumed first. Otherwise it ends its branch. Steps whose wait lacks the Condition keep running and keep the Flow open. A loop that moves to its next unit through a Timer and `GoTo` keeps looping until it checks for the request itself.

Use graceful completion when each branch should finish its current unit and then stop. Add the Condition to every wait that would otherwise keep a branch alive. Every SDK has the graceful completion Condition: Go, Python, Java, TypeScript, and Rust. See [Wait for a completion request](/reference/server/step-and-flow-close#graceful-completion-condition).

### Cancel running Steps {#cancel-running-steps}

A Step decision or an RPC cancels chosen active Steps, for example by Step type. The rest of the Flow keeps running. The SDK passes a cancellation signal to each canceled handler. The handler checks the signal and returns. Dex discards the canceled Step's later result.

Use Step cancellation to stop one branch, such as one job that the user no longer needs. Keep each handler idempotent, because a canceled Step's consumed messages normally return to their Channels. See [Step cancellation](/reference/server/step-and-flow-close#step-cancellation).

## Finish the current unit, then stop {#finish-the-current-unit-then-stop}

This example stops looping work after the current unit finishes. It records the stop request in an Attribute, and each branch checks it between units. Graceful completion is the preferred signal where the SDK supports it: each branch waits on its Timer and the graceful completion Condition together. The Attribute flag works the same way with any SDK.

`InterruptibleFlow` starts `WorkA` and `WorkB` in parallel. To interrupt them, a client calls the **interrupt** RPC, which sets the `interruptSignal` Attribute. Each branch finishes its current unit of work. Before it starts the next one, it reads the signal and returns `GracefulComplete`. The Flow completes when both branches have stopped.

## Core implementation

Each sample shows `WorkA`; `WorkB` is the same. `WaitFor` pauses between units of work. `Execute` completes if the signal is set, and otherwise moves to the next unit. The runnable examples also include Flow registration and the **interrupt** RPC.

class WorkA(Step[WorkJobParametersInput]):
    def __init__(self, interrupt_signal: Attribute[str]) -> None:
        self.interrupt_signal = interrupt_signal

    def wait_for(self, context: Context, input: WorkJobParametersInput) -> Wait:
        return Wait.until(Timer.by_duration(timedelta(seconds=2)))

    def execute(
        self,
        context: Context,
        input: WorkJobParametersInput,
    ) -> StepDecision:
        if (self.interrupt_signal.get(context) or "") == INTERRUPT_VALUE:
            print("A: Interrupted!")
            return graceful_complete()

        if input.progress > input.job_upper_bound:
            print("WorkA completed")
            return graceful_complete()

        print(
            f"[{context.flow_id}][{context.step_execution_id}]: "
            f"Doing job {input.progress}"
        )
        return go_to(
            WorkA,
            WorkJobParametersInput(input.job_upper_bound, input.progress + 1),
        )

type workA struct {
	dex.StepDefaults
}

func (workA) WaitFor(
	ctx dex.Context,
	input WorkJobParametersInput,
) (*dex.Wait, error) {
	return dex.Until(dex.Timer(1500 * time.Millisecond)), nil
}

func (workA) Execute(
	ctx dex.Context,
	input WorkJobParametersInput,
) (*dex.StepDecision, error) {
	signal, err := InterruptSignal.Get(ctx)
	if err == nil && signal == "cancel" {
		fmt.Println("A: Interrupted!")
		return dex.GracefulComplete(nil), nil
	}
	if input.Progress > input.JobUpperBound {
		fmt.Println("WorkA completed")
		return dex.GracefulComplete(nil), nil
	}
	fmt.Printf(
		"[%s][%s]: Doing job %d\n",
		ctx.FlowID(),
		ctx.StepExecutionID(),
		input.Progress,
	)
	next := WorkJobParametersInput{
		JobUpperBound: input.JobUpperBound,
		Progress:      input.Progress + 1,
	}
	return dex.GoTo(workA{}, next), nil
}

final class WorkA implements Step<WorkJobParametersInput> {
    @Override
    public Class<WorkJobParametersInput> getInputType() {
        return WorkJobParametersInput.class;
    }

    @Override
    public Wait waitFor(final Context context, final WorkJobParametersInput input) {
        return Wait.until(Timer.byDuration(Duration.ofMillis(1500)));
    }

    @Override
    public StepDecision execute(
            final Context context,
            final WorkJobParametersInput input) {
        final String signal = interruptSignal.get(context);
        if (signal != null && signal.equals("cancel")) {
            System.out.println("A: Interrupted!");
            return StepDecision.gracefulComplete();
        }

        if (input.progress > input.jobUpperBound) {
            System.out.println("WorkA completed");
            return StepDecision.gracefulComplete();
        }
        System.out.printf(
                "[%s][%s]: Doing job %s%n",
                context.getFlowId(),
                context.getStepExecutionId(),
                input.progress);

        final WorkJobParametersInput next =
                new WorkJobParametersInput(input.jobUpperBound, input.progress + 1);
        return StepDecision.goTo(WorkA.class, next);
    }
}
