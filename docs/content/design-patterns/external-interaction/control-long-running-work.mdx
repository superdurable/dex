# Control Long-Running Work

Control Long-Running Work, formerly Stop Long-Running Work and Interruptible execution, changes or stops a loop while it runs.

Use this pattern for work that loops for a long time, such as a backfill or batch processing. A caller can change how the loop works, such as how many items each iteration loads. A caller can also ask the loop to stop. To wait for an external system, use [Polling](/design-patterns/durable-timer/polling) instead.

<DocsFlowDefinitionGraph graph={flowDefinition} />

## Control a running loop {#control-a-running-loop}

1. An RPC writes control Attributes, such as a batch size and a stop request.
2. The loop Step waits between iterations, for example on a Timer.
3. Each iteration reads the control Attributes at the start of `Execute`.
4. When a stop is requested, `Execute` completes. Otherwise it processes one unit with the current controls.
5. `Execute` moves back to the same Step with the next position as its input.

## Rules {#rules}

- Keep the loop position in the Step input. Keep the controls in Attributes.
- A new control value applies from the next iteration. The running iteration keeps the values it read.
- The RPC validates each value before it writes it. The loop then reads only valid controls.
- Apply the default when a control is unset, at read time. A default that the start Step writes could overwrite an RPC that arrives first.

## Choose an Attribute or a Channel {#attribute-or-channel}

| Control | Primitive | Why |
| --- | --- | --- |
| A parameter, such as a batch size, a rate, or a pause flag | Attribute | The latest value wins. The loop needs only the current value. |
| A command for one item, such as skip or retry | Channel | Every command is kept and processed in order. A later command does not replace an earlier one. |

To take commands from a Channel, the loop waits on the Timer and the Channel together with `AnyOf`. `Execute` then handles every command it consumed.

## Choose how to stop {#choose-how-to-stop}

Dex has three built-in ways to stop work. Choose by what must stop and what must still run.

| Way | What stops | Use it when |
| --- | --- | --- |
| StopFlow | The whole run, at once | The run must end now, and no Step needs to report or clean up. |
| Graceful completion | Steps that wait on the graceful completion Condition; the Flow completes once no Step is active | The Flow should finish its current work and then complete. |
| Step cancellation | Chosen running Steps | One branch must stop while the rest of the Flow keeps running. |

A stop request in a control Attribute, as in the example below, is a fourth option. The loop reads it with its other controls and stops before its next unit.

### Stop the whole run with StopFlow {#stopflow}

A client calls `StopFlow` to cancel, fail, or terminate the run. Each type records a different terminal status. The run closes as soon as the stop commits.

After the stop commits, only handlers that were already running can still run. No later Step decision, failure route, or cleanup runs. Running Steps get a cancellation signal. A handler that ignores it keeps running, and its calls to external systems still take effect. Dex discards its uncommitted result. Whoever waits for the stopped Flow reads its terminal state instead of waiting for a report.

Use StopFlow when nothing in the Flow needs to finish its work or run cleanup. See [Stop a Flow](/reference/server/runtime-client#stop-a-flow) for every stop type.

### Ask the Flow to complete gracefully {#graceful-completion}

The Flow is asked to complete gracefully: a client calls `StopFlow` with graceful complete, or a Step returns `GracefulComplete`. Active Steps keep running, and their decisions still apply. The Flow completes once no Step is active.

A waiting Step that includes the graceful completion Condition stops waiting when the request arrives. Its `Execute` handles any message it consumed first. Otherwise it ends its branch. Steps whose wait lacks the Condition keep running and keep the Flow open. A loop that moves to its next unit through a Timer and `GoTo` keeps looping until it checks for the request itself.

Use graceful completion when each branch should finish its current unit and then stop. Add the Condition to every wait that would otherwise keep a branch alive. Every SDK has the graceful completion Condition: Go, Python, Java, TypeScript, and Rust. See [Wait for a completion request](/reference/server/step-and-flow-close#graceful-completion-condition).

### Cancel running Steps {#cancel-running-steps}

A Step decision or an RPC cancels chosen active Steps, for example by Step type. The rest of the Flow keeps running. The SDK passes a cancellation signal to each canceled handler. The handler checks the signal and returns. Dex discards the canceled Step's later result.

Use Step cancellation to stop one branch, such as one job that the user no longer needs. Keep each handler idempotent, because a canceled Step's consumed messages normally return to their Channels. See [Step cancellation](/reference/server/step-and-flow-close#step-cancellation).

## Example {#example}

`RecordBackfillFlow` processes 1000 records in batches. `StartRecordBackfill` moves to `ProcessRecordBatch` at the first record. `ProcessRecordBatch` waits one second between batches. Each `Execute` reads the `stopRequested` and `batchSize` Attributes first. The batch size is 10 until the batch size RPC sets it.

The batch size RPC rejects a size below 1 or above 1000. The stop RPC sets `stopRequested`. The loop then completes gracefully before its next batch. The Flow completes once the loop has stopped.

```python
class ProcessRecordBatch(Step[BackfillProgress]):
    def wait_for(self, context: Context, progress: BackfillProgress) -> Wait:
        return Wait.until(Timer.by_duration(BATCH_INTERVAL))

    def execute(self, context: Context, progress: BackfillProgress) -> StepDecision:
        if STOP_REQUESTED.get(context):
            return graceful_complete(f"stopped before record {progress.next_record}")
        # An unset int Attribute reads as 0, and a set batch size is at least 1.
        size = BATCH_SIZE.get(context) or DEFAULT_BATCH_SIZE
        last = min(progress.next_record + size - 1, progress.last_record)
        print(f"processing records {progress.next_record} to {last}")
        if last == progress.last_record:
            return graceful_complete(f"processed {last} records")
        return go_to(ProcessRecordBatch, BackfillProgress(last + 1, progress.last_record))
```

```go
type ProcessRecordBatch struct {
	dex.StepDefaults
}

func (ProcessRecordBatch) WaitFor(dex.Context, BackfillProgress) (*dex.Wait, error) {
	return dex.Until(dex.Timer(BatchInterval)), nil
}

func (ProcessRecordBatch) Execute(ctx dex.Context, progress BackfillProgress) (*dex.StepDecision, error) {
	stop, err := StopRequested.Get(ctx)
	if err != nil && !isAttributeNotFound(err) {
		return nil, err
	}
	if stop {
		return dex.GracefulComplete(fmt.Sprintf("stopped before record %d", progress.NextRecord)), nil
	}
	size, err := BatchSize.Get(ctx)
	if isAttributeNotFound(err) {
		size, err = DefaultBatchSize, nil
	}
	if err != nil {
		return nil, err
	}
	last := min(progress.NextRecord+size-1, progress.LastRecord)
	fmt.Printf("processing records %d to %d\n", progress.NextRecord, last)
	if last == progress.LastRecord {
		return dex.GracefulComplete(fmt.Sprintf("processed %d records", last)), nil
	}
	next := BackfillProgress{NextRecord: last + 1, LastRecord: progress.LastRecord}
	return dex.GoTo(ProcessRecordBatch{}, next), nil
}
```

```java
static final class ProcessRecordBatch implements Step<BackfillProgress> {
    @Override
    public Class<BackfillProgress> getInputType() {
        return BackfillProgress.class;
    }

    @Override
    public Wait waitFor(final Context context, final BackfillProgress progress) {
        return Wait.until(Timer.byDuration(BATCH_INTERVAL));
    }

    @Override
    public StepDecision execute(final Context context, final BackfillProgress progress) {
        if (stopRequested.get(context)) {
            return StepDecision.gracefulComplete(
                    "stopped before record " + progress.nextRecord);
        }
        // An unset Integer Attribute reads as 0, and a set batch size is at least 1.
        final int storedSize = batchSize.get(context);
        final int size = storedSize == 0 ? DEFAULT_BATCH_SIZE : storedSize;
        final int last = Math.min(progress.nextRecord + size - 1, progress.lastRecord);
        System.out.printf("processing records %d to %d%n", progress.nextRecord, last);
        if (last == progress.lastRecord) {
            return StepDecision.gracefulComplete("processed " + last + " records");
        }
        return StepDecision.goTo(
                ProcessRecordBatch.class, new BackfillProgress(last + 1, progress.lastRecord));
    }
}
```

```rust
impl Step for ProcessRecordBatch {
    type Input = BackfillProgress;

    fn wait_for(&self, _context: &mut Context, _progress: Self::Input) -> HandlerResult<Wait> {
        Ok(Wait::until(Timer::by_duration(BATCH_INTERVAL)))
    }

    fn execute(&self, context: &mut Context, progress: Self::Input) -> HandlerResult<StepDecision> {
        if STOP_REQUESTED.get(context)? == Some(true) {
            return Ok(StepDecision::graceful_complete(format!(
                "stopped before record {}",
                progress.next_record

                "processed {last} records"

            BackfillProgress {
```
