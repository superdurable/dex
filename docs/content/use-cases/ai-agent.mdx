# AI Agent

This Python application is a general, long-running AI Agent. It chats with a user, calls trusted MCP tools, waits for approval before external writes, asks the user questions, suspends itself on a durable Timer, and drafts plans for review before it runs them.

It is built on Dex Agents, the **dex-agents** package. The agent is a Stepwise agent: the library's built-in agent loop, with no agent framework. Dex owns the conversation. Every model call is one **RunModel** Step and rebuilds the model input from durable state, so the agent does not depend on an LLM provider's conversation API. Every tool call is its own Step, so a crash repeats at most the one call that was running.

## Agent frameworks

An agent already written with an agent framework such as Pydantic AI, LangGraph, the OpenAI Agents SDK, Google ADK, the Vercel AI SDK, Mastra or the Claude Agent SDK runs on the same session Flow without a rewrite. See [Agent Frameworks](/agent-frameworks). To run agent sessions in production, see [Deploy agents](/production/agents).

## The session Flow

The application declares the agent in Dex terms and builds its Flow. The Flow type is **AIAgentSession**. One Flow execution is one session, and the Flow ID is the session ID.

<SdkTabs examples={{python: 'examples/python/dex_examples/products/ai-agent/ai_agent_session.py'}}>
<SdkSnippet lang="python">

```python
def build_ai_agent_session_flow(
    model: str, system_prompt: str, context_window_tokens: int, mcp_config: Path | None
) -> AgentSessionFlow:
    mcp_servers = load_mcp_servers(mcp_config)
    definition = AgentDefinition(
        name="ai-agent",
        instructions=system_prompt,
        # LiteLLM reads the provider key from the Worker's environment, never from Flow state.
        model=ScriptedModelClient(reply_as_demo_model)
        if model == DEMO_MODEL
        else LiteLLMModelClient(model),
        tool_sources=[McpToolSource(mcp_servers, resource_and_prompt_tools_enabled=True)]
        if mcp_servers
        else [],
        built_in_tools=frozenset(BuiltInTool),
        plan_mode_enabled=True,
        compaction=CompactionPolicy(context_window_tokens=context_window_tokens),
    )
    return stepwise_agent_session_flow(definition, flow_type=AI_AGENT_SESSION_FLOW_TYPE)
```

The Steps, Attributes, Channels, RPCs, and events are the ones every Dex Agents session uses:

```text
StartAgentSession -> AwaitUserMessage -> RunModel
AwaitUserMessage -> steer or cancel_turn -> ApplyTurnControl
RunModel -> final answer -> AwaitUserMessage
RunModel -> failed after three attempts -> RecordTurnFailure -> AwaitUserMessage
RunModel -> CompactContext -> RunModel
RunModel -> tool calls -> AwaitToolApproval -> CallTool or CallSingleAttemptTool
                          CallTool or CallSingleAttemptTool
                          AwaitQuestionAnswer      for ask_user
                          AwaitTimer               for durable_wait
                          ResumeTurn -> RunModel, or ApplyTurnControl when steered
ApplyTurnControl -> RunModel with the steered messages, else AwaitUserMessage
```

This view is simplified. The [Dex Agents README](https://github.com/superdurable/dex/tree/main/agents/python/core) lists every Step, its retries, and its failure route.

The model, the system prompt, the context window, and the MCP servers are Worker configuration, shared by every session. Sessions do not choose them, so no credential or server command comes from a browser or from Flow input. A changed prompt or model takes effect at the next model call of every session, including a turn that is waiting, because Dex does not replay a Flow.

## Durable context

The session stores each user message, model output item, and tool result as its own **AgentMessages** AttributeMap instance. Model output items are kept exactly as the provider returned them, including encrypted reasoning items and thinking signatures, and replayed unchanged.

When the model input reaches 85 percent of the configured context window, a **CompactContext** Step summarizes older messages before the next model call. The model then receives the summary and the recent messages. Compaction never separates a tool call from its result. Every message stays in the session, so the history remains complete. Compaction shortens the model input, not the stored history, so a long session's state grows toward the Dex Server's run budget. [Deploy agents](/production/agents#limits) gives the bound.

## Queued messages and Steer

A message sent while a turn runs waits in the durable **QueuedUserMessages** queue. The UI shows it with **Steer** and **Delete** controls while it is pending.

**Steer** applies a message at the turn's next safe Step boundary. It never stops a model call or a tool call that has started. Tool calls that have not started, and approvals, questions, and durable waits that are still waiting, record a structured cancellation result. The turn then ends, and a new turn starts with every steered message. **Stop** calls **cancel_turn**, which ends the turn the same way without a new one.

## Questions and durable waits

The **ask_user** built-in tool asks the user a question and waits in **AwaitQuestionAnswer**. The UI shows the question with choice buttons or a text box, and the answer becomes the tool's result in the same turn.

The **durable_wait** built-in tool waits in **AwaitTimer** on a [Timer](/primitives/timer). No model call or Worker holds the wait, and it survives Worker and engine restarts. Steering or **Stop** interrupts it. A queued message does not.

## Durable plans

Turn on **Plan mode** for a message to ask the agent for a plan. A planning turn can only call the **write_todos** built-in tool, which replaces the **AgentPlan** Attribute and advances its revision. The UI shows the draft, and **Execute plan** calls **execute_plan** with the reviewed revision. A stale revision is refused. A plan that stops with unfinished tasks stays active and can be continued. While a plan is active, other turns can call every tool; only a draft plan limits a turn to **write_todos**.

## MCP tools and approvals

The Worker loads trusted stdio or Streamable HTTP MCP servers from local configuration. The agent takes the **McpToolSource** of Dex Agents as a tool source, so the model sees every server's tools. The Worker refuses configuration keys it does not know, including the per-tool settings of earlier versions of the example. Each MCP call runs in its own tool Step. A server that cannot be listed is left out of that model call and tried again on the next one, so the agent keeps answering when every server is down.

A tool's effect decides how it runs. When a server's annotations are trusted, a read-only tool runs at once and is retried after a crash. Every other tool waits in **AwaitToolApproval** until the user approves it, then runs at most once. A write that a crash cut off is recorded with an unknown outcome and never repeated, and each MCP call carries an idempotency key so the server can drop a duplicate.

With **resource_and_prompt_tools_enabled**, the tool source also offers three read tools that list and read a server's resources and prompts.

## Live events

Text, reasoning summaries, tool activity, approvals, and plan updates arrive on the session's **AgentEvents** [Stream](/primitives/stream). The example serves it to the browser as Server-Sent Events with the library's browser stream helpers.

<SdkTabs examples={{python: 'examples/python/dex_examples/products/ai-agent/http_routes.py'}}>
<SdkSnippet lang="python">

```python
    @blueprint.get("/events")
    async def stream_agent_events() -> Response:
        session_id = required_query("session_id")
        resume_token = request.headers.get("Last-Event-ID") or request.args.get("resume_token", "")
        try:
            frames = await stream_agent_event_frames(
                app_state.client, app_state.ai_agent, session_id, resume_token=resume_token
            )
        except InvalidAgentEventResumeTokenError as error:
            raise BadRequest("the resume token is not valid; reload the snapshot") from error
        response = await make_response(frames, dict(AGENT_EVENT_STREAM_HEADERS))
        response.timeout = None
        return response
```

</SdkSnippet>
</SdkTabs>

The page first loads the session snapshot with the resume token to open the Stream from. A reconnecting browser resumes from the last event it saw. Stream delivery is best effort, so the page reloads the snapshot after every turn and every eight seconds. The conversation always comes from the snapshot, which holds the newest 200 messages. **Load older messages** pages back through **list_agent_messages**.

## Run the example

The Flow and HTTP routes are under [examples/python/dex_examples/products/ai-agent](https://github.com/superdurable/dex/tree/main/examples/python/dex_examples/products/ai-agent). The React UI, the MCP configuration examples, and the run instructions are under [examples/python/ai-agent](https://github.com/superdurable/dex/tree/main/examples/python/ai-agent).

The first page shows the Worker's model, prompt, context window, and MCP tools. Set **DEX_AGENT_MODEL** to a LiteLLM model name, add its credential to **examples/.env**, and restart the Worker to use a real model. The default local demo model needs no credential and reads slash commands such as **/ask**, **/choose**, **/wait**, and **/tool**, so every feature can be tried without a key.
