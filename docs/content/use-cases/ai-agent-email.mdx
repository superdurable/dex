# AI agent email

This Python application turns a natural-language request into an email draft, waits durably until its send time, and streams non-critical agent progress to the browser while the LLM call is still running.

## Why this shape

The example separates correctness from presentation:

- A [Channel](/primitives/channel) carries each user request into the durable Flow.
- [Attributes](/primitives/attribute) retain the recipient, subject, body, send time, and conversation ID.
- A durable [Timer](/primitives/timer) waits until the requested send time.
- A [Stream](/primitives/stream) carries low-latency reasoning summaries to the UI.

Losing a progress chunk does not change the email draft or send decision. That makes the progress feed a good fit for best-effort Stream retention.

## Streaming from the Agent Step

The Agent Step passes one buffered writer directly to the LLM helper. Small deltas are combined for up to one second and emitted as normal Stream messages. The SDK flushes the tail before the Step result or error. It never waits for a Stream Store acknowledgement, and a Stream Store failure does not fail the Step.

Step messages use **#StepExecutionID** as their source. The source describes where a message came from; it is not an idempotency key. All writes append, so a retry can produce duplicate progress chunks. That is acceptable because the feed is presentational and the final draft remains in durable Attributes.

The OpenAI call requests a user-visible reasoning summary. It does not expose private chain-of-thought. When OpenAI is not configured, the local fallback emits progress messages through the same Stream path.

## Resuming in the browser

The HTTP handler performs a blocking **ReadStream** call and returns one chunk plus its resume token. The React UI immediately issues the next request with that token. A page reload starts with an empty token and replays from the current retained head, while a long-poll timeout simply starts another read.

This design gives the browser low latency without turning progress into durable Flow state. A slow or disconnected browser may miss trimmed chunks and can still fetch the final email draft from durable Attributes.
