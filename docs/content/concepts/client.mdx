# Client

A **Client** is how your application talks to Dex from outside a Worker. An HTTP
handler, a background job, or a script uses it. The Client sends requests to
Dex Server. It does not run Flow code. Workers do that.

## When to use a Client

Use a Client at the boundary between your application and its Flows:

- <a id="start-a-flow"></a>**Start** a Flow when a request begins a business
  process. See [Start a Flow](/reference/server/runtime-client#start-a-flow).
- <a id="invoke-an-rpc"></a><a id="read-and-write-flow-state"></a>**Call an RPC**
  to send a command to a Flow, or to read a view that needs Flow logic. See
  [Invoke an RPC](/reference/server/runtime-client#invoke-an-rpc).
- <a id="read-attributes"></a>**Read Attributes** when you only need stored
  values. See [Read Attributes](/reference/server/runtime-client#read-attributes).
- **Wait** for a Flow to finish, a Step to complete, or an Attribute to reach a
  value.
- **Search** for Flows by Flow type, status, or indexed Attributes.
- <a id="stop-a-flow"></a>**Operate** a Flow: describe it, stop it, skip a
  Timer, update its configuration, or time travel it. See
  [Stop a Flow](/reference/server/runtime-client#stop-a-flow).

## How it relates to the other Primitives {#related-primitives}

- [Flow](/concepts/flow): **StartFlow** creates a Flow execution under a **Flow ID** that you
  choose. The Flow ID is the business identity, such as an order number. Dex
  creates the Run ID. Later calls address the Flow by its Flow ID.
- [RPC](/concepts/primitives/rpc): change a running Flow through RPCs. To change Attribute,
  AttributeMap, Channel, or ChannelMap state, define a typed RPC for each
  command and call it with **InvokeRPC**. Validation, authorization, locks, and
  transactions then stay inside the Flow.
- [Attribute](/concepts/primitives/attribute): **GetAttributes** reads stored values
  directly from the server. No Worker runs. Use an RPC instead when the read
  needs Flow-side validation, authorization, Channel messages, a derived view,
  or Attribute locks.
- [Step](/concepts/step): **WaitForStepCompletion** blocks until a Step
  completes. **WaitForAttributeMatch** blocks until an Attribute reaches a
  value. Use them to answer a request only after the Flow has made progress.
  See [Responsive Update](/design-patterns/responsive-update).
- [Stream](/concepts/primitives/stream): a Stream carries live updates, such as
  progress, to a UI. It is best effort. Read durable state again when it
  matters.
- Search: **SearchFlows** finds Flows with a search query, such as one on the
  Flow type or an indexed Attribute. **DescribeFlow** reads the status of one
  known Flow ID.

## Guarantees

- When **StartFlow** returns, Dex has stored the Flow. It runs even if your
  process exits.
- **GetAttributes** returns values that Dex saved together, at one point in
  time. It never returns changes that Dex has not saved yet.
- A wait checks the Flow's saved state. It returns when the condition holds, when the
  Flow closes, or when its request timeout expires. A later call waits again
  from the current state.
- A wait is not a final result. Read the Flow result or the business state to
  decide what happened.
- An error that says the Flow is closing does not prove that an earlier request
  succeeded. Read the Flow's stored state before you act again.

This handler starts a Flow. The query string supplies the Flow ID and the start
input.

flow_id = required_query("workflowId")

return started_flow(flow_id, run_id)
