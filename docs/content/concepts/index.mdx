# Concepts

Dex has a small programming model. A Flow is a durable program. Steps move it
forward. Primitives hold its state and connect it to the outside world. Your
application drives Flows through a Client.

## Flow and Step

| Concept | What it is | Use it to |
| --- | --- | --- |
| [Flow](/concepts/flow) | A durable program with a business ID. It owns its Steps, state, and messages. | Model one business process or entity. |
| [Step](/concepts/step) | A unit of work in a Flow. It waits, executes, and decides what runs next. | Do work and move the process forward. |

## Primitives {#the-primitives}

Primitives are the building blocks a Flow uses. Each one belongs to a Flow.

| Primitive | What it is | Use it to |
| --- | --- | --- |
| [Attribute](/concepts/primitives/attribute) | Durable state that belongs to one Flow. | Keep data between Steps, read it from outside, and search on it. |
| [RPC](/concepts/primitives/rpc) | A synchronous call into a Flow. | Send commands and read views from your application. |
| [Channel](/concepts/primitives/channel) | A durable message queue in a Flow. | Deliver messages that Steps wait for. |
| [Stream](/concepts/primitives/stream) | A best-effort feed that a reader can resume. | Push live progress to a UI. |
| [Timer](/concepts/primitives/timer) | A durable wait until a time. | Set deadlines, reminders, and schedules. |
| [SubFlow](/concepts/primitives/subflow) | A Flow that another Flow starts as a child. | Split large or parallel work into child Flows. |

## Client

The [Client](/concepts/client) is the API your application uses outside a
Worker. Use it to start, call, read, wait for, and operate Flows.

## Connector

A [Connector](/concepts/connector) connects a Flow to an external provider,
such as an email or payment service. It gives your Flow ready-made Steps that
call the provider, and Triggers that start or update Flows from provider
events.

## How they fit together

```text
 Your application                      One Flow (one Flow ID)
 ┌────────────┐   StartFlow, RPC      ┌──────────────────────────────────┐
 │   Client   │ ────────────────────▶ │  Step ──▶ Step ──▶ Step ...      │
 │            │   GetAttributes, wait │   waits on Channel, Timer,       │
 │            │ ◀──────────────────── │   SubFlow; calls Connectors      │
 │            │   Stream (live)       │                                  │
 │            │ ◀──────────────────── │  Attributes  Channels  Streams   │
 └────────────┘                       └──────────────────────────────────┘
```

A **Flow** is the container. A Flow ID, such as an order number, has at most
one active run at a time.

**Steps** move the Flow forward. A Step can wait for a Channel message, a Timer,
or a SubFlow. It then executes its work, such as a call through a Connector. It
returns a decision that names the next Steps or closes the Flow. Dex retries a
failed Step.

**Attributes** and **Channels** are the Flow's durable state. Steps and RPCs
read and write them. Dex saves the state changes of a Step method or RPC
together with its result. See [Step guarantees](/concepts/step#guarantees).

Your application uses a **Client** to start Flows, invoke RPCs, read
Attributes, and wait for changes. To change a running Flow, your application
calls an RPC. A **Stream** carries live updates back to a UI.

## Components

Concepts are the programming model. [Components](/components) are the
processes that run it:

- Your **application** hosts the Flow code in Workers and calls Dex through
  Clients.
- [Dex Server](/components/server) stores Flow state and hands Steps and RPCs
  to Workers.
- `dexcli` runs a local Dex, and **Dex Web** lets operators inspect Flows.

## What Dex guarantees {#guarantees}

Dex saves each Step's result together with the move to the next Step. A Step
that finished does not run again; the one exception is an
[ASYNC Step](/concepts/step/advanced-guarantees#sync-and-async), which can run again if a server
node fails before its result is written. A Step that was cut off can run again;
see [Idempotency keys](/concepts/step#idempotency-keys).
A retry reads the [state snapshot](/concepts/step#guarantees) of the first
attempt, not newer writes. [Step](/concepts/step#guarantees) lists every
guarantee and its limits.

Parallel Steps and RPCs share Attributes without isolation; see
[Attribute locks](/concepts/primitives/attribute#locking).
[Failover and Deploys](/concepts/failover-and-deploys) lists what runs again
after a crash, a server failover, or a deploy.

## Change Flow code {#change-flow-code}

Open Flows can meet changed rules or renamed Steps after a deploy.
[Versioning Flow code](/concepts/change-flow-code#versioning-flow-code) shows how
to keep them working. [Time Travel](/concepts/change-flow-code#time-travel) runs
a Flow again from an earlier point after a fix.
