# Timer

A **Timer** is a durable wait until a point in time. Dex Server keeps it. A
Step returns it from `WaitFor`, and `Execute` runs when it fires. While the
Step waits, no Worker holds memory, a thread, or a connection for it.

## When to use a Timer

Use a Timer for a delay, a reminder, or a deadline. Combine it with another
condition to build a timeout. For example, a Step that waits for either a
[Channel](/concepts/primitives/channel) message or a Timer proceeds with
whichever comes first. In `Execute`, the Step checks whether its Timer fired.

## Guarantees

The server stores the Timer with the Flow. It survives Worker restarts and
server failover.

class TimerExampleStep(Step[int]):
    def wait_for(self, _context: Context, input: int) -> Wait:

struct TimerExampleStep;

impl Step for TimerExampleStep {
    type Input = i32;

        Ok(Wait::until(Timer::by_duration(Duration::from_secs(

## Skip a Timer

A Client can skip a Timer with `SkipTimer`. It selects the Timer by Flow ID,
Step execution ID, and either the Timer's condition ID or the index of its
condition in `WaitFor`. A skipped
Timer acts as if it had fired. Use it in tests, or in production to run a
waiting Step early. See [Skip a Timer](/reference/server/runtime-client#skip-a-timer).

In this test of the order-processing example, the **Ship** Step waits on a
Timer, and the test skips it:
