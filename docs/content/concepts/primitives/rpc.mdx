# RPC

An **RPC** (Remote Procedure Call) lets code outside a Flow interact with a
running Flow. A web handler, another service, or an operator tool
calls it through a [Client](/concepts/client).

A Client calls the RPC. Dex Server routes it to a Worker, saves the result,
and returns the output.

<RpcRequestDiagram markdownDescription="A Client sends an RPC request to Dex Server, which routes it to the Application Worker. The Worker returns the result through Dex Server to the Client." />

## When to use an RPC

Use an RPC when something outside the Flow must change it or ask it a question.
Examples are an approval, a user who presses Stop, or a request for a view of
the Flow's state.

An RPC handler can do four things:

- read and write [Attributes](/concepts/primitives/attribute);
- publish messages to a [Channel](/concepts/primitives/channel);
- start new [Steps](/concepts/step);
- cancel running Steps.

<a id="read-only-rpcs-and-terminal-flows"></a>

For a plain read, a Client can skip the RPC. See
[when a read needs an RPC](/concepts/client#related-primitives). For RPCs that
only read, including on closed Flows, see [Read-only RPCs and terminal Flows](/reference/server/runtime-data#read-only-rpcs-and-terminal-flows).

## Guarantees

Dex saves an RPC like a Step method. It saves the RPC's Attribute writes and
Channel publications together with its result, and only when the RPC succeeds.
See [Step guarantees](/concepts/step#guarantees).

An RPC handler reads a snapshot of the Flow. Steps and other RPCs can change the
Flow between that read and the moment Dex saves the RPC's changes. When the
RPC's change depends on what it read, declare a lock on that
Attribute in this RPC and in every Step and RPC that writes it. Dex then runs
them one at a time. If the Flow closes while the handler runs, Dex rejects the
RPC's changes. The handler's calls to external systems have still happened.

<a id="request-ids"></a>Each RPC call carries a request ID. By default, the SDK
generates a new one for each call. Calling the RPC again from your code, such as
after a lost response, then runs the handler again and saves its changes a
second time, including its Channel publications. Make RPC handlers safe to
repeat; [Send a command at most once](/concepts/client#inbound-commands) gives
the pattern. A caller can instead pass the same request ID on every attempt,
where its SDK accepts one. Dex then saves the RPC's changes at most once.
[RPC request IDs](/reference/server/runtime-data#rpc-request-ids) covers which
repeats still run the handler and how long Dex keeps request IDs.

An RPC needs a Worker within 10 seconds. If no Worker of the Flow type takes it in that time,
the caller gets an **Unavailable** error. A Step waits in a durable queue
instead. See [Routing and availability](/reference/server/workers#routing-and-availability).

<a id="rpc-timeout"></a>

An RPC runs on a Worker, like a Step. A timeout limits each handler invocation.
See [RPC timeout](/reference/server/runtime-data#rpc-timeout).

## More RPC capabilities {#more-rpc-capabilities}

- <a id="cancel-running-steps"></a><a id="cancel-race"></a><a id="cancel-honour"></a>**Cancel
  running Steps.** An RPC result can cancel active Steps of its Flow, selected
  by Step type, such as when a user presses Stop while a report runs. Dex
  applies the cancellation when it saves the RPC's result. The Step code must
  check for cancellation and stop. See
  [Cancel running Steps](/reference/server/runtime-data#cancel-running-steps),
  [Resolve the race from committed state](/reference/server/runtime-data#cancel-race),
  and [Make the Step stop](/reference/server/runtime-data#cancel-honour).
- <a id="transactional-reads-and-writes"></a><a id="attribute-locks"></a>**Locks
  and transactional RPCs.** An RPC can declare
  [Attribute locks](/concepts/primitives/attribute#locking) and then runs one at
  a time with the Steps and RPCs that declare the same lock. A **transactional**
  RPC fails, and Dex saves none of its changes, if a Channel message that it
  deletes is no longer pending. A non-transactional RPC skips the missing
  deletion and Dex saves the rest. An RPC that holds a lock is always
  transactional. See [Locks](/reference/server/runtime-data#attribute-locks),
  [RPC lock conflicts](/reference/server/runtime-data#rpc-lock-conflicts), and
  [Transactional RPCs](/reference/server/runtime-data#transactional-reads-and-writes).
- <a id="load-collection-state"></a><a id="load-collections"></a><a id="runtime-selected-map-instances"></a>**Load
  collections.** An RPC receives regular Attributes and Channel sizes. It loads
  AttributeMap entries and pending Channel messages only when it declares them.
  See [Selective state loading](/reference/server/runtime-data#load-collection-state)
  and [Runtime-selected map instances](/reference/server/runtime-data#runtime-selected-map-instances).
