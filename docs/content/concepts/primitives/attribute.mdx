# Attribute

An **Attribute** is durable data that belongs to one Flow execution. Steps and
RPCs read and write it. Dex stores it with the Flow, so you do not need a
database for intermediate state.

An Attribute lives as long as its Flow. Dex deletes it when it deletes the Flow,
after the retention period that follows Flow closure. To keep the data longer,
sync it to your own database.

## When to use an Attribute

Use an Attribute for state that the Flow decides on: an order status, a
counter, a customer profile, or the result of an earlier Step. Use a
[Channel](/concepts/primitives/channel) for messages that a Step waits for and consumes.
Use a [Stream](/concepts/primitives/stream) for live progress that a user can afford to
lose.

## Use an Attribute {#define-an-attribute}

Declare each Attribute in the Flow's persistence schema. A Step or RPC can then
read or write it. The Worker rejects an Attribute that the schema does not
declare. Setting an Attribute to null deletes it.

Dex commits a handler's Attribute writes together with its result. When a Step
or RPC fails, its writes are discarded.

pub struct AttributeFlow {
    status: Attribute<String>,
    email: Attribute<String>,
    progress: AttributeMap<String>,
    start: AttributeStep,
}

impl Default for AttributeFlow {
    fn default() -> Self {
        let status = Attribute::new("primitive-attribute-status")
            .indexed(AttributeIndex::keyword().with_key("keyword1"));
        let email = Attribute::new("primitive-attribute-email").sync_to_attribute_store();
        let progress = AttributeMap::new("primitive-attribute-progress")
            .indexed(AttributeIndex::keyword().with_key("keyword2"));
        Self {
            start: AttributeStep {
                status: status.clone(),
                progress: progress.clone(),
            },
            status,
            email,
            progress,
        }
    }
}

impl Flow for AttributeFlow {
    type StartInput = String;

    fn steps(&self) -> StepList<'_, Self::StartInput> {
        StepList::start(&self.start)
    }

    fn persistence(&self) -> PersistenceSchema {
        PersistenceSchema::new()
            .attribute(&self.status)
            .attribute(&self.email)
            .attribute_map(&self.progress)
    }
}

struct AttributeStep {
    status: Attribute<String>,
    progress: AttributeMap<String>,
}

impl Step for AttributeStep {
    type Input = String;

    fn wait_for(&self, context: &mut Context, _input: Self::Input) -> HandlerResult<Wait> {
        self.status.set(context, "processing".to_owned())?;
        self.progress
            .set(context, "payment", "authorized".to_owned())?;
        Ok(Wait::skip_immediately())
    }

    fn execute(&self, context: &mut Context, input: Self::Input) -> HandlerResult<StepDecision> {
        self.status.set(context, "completed".to_owned())?;
        Ok(StepDecision::graceful_complete(input))
    }
}

## AttributeMap {#attributemap}

An **AttributeMap** is a set of Attributes with keys chosen at run time. Use it
for values that grow with your data, such as the status of each payment in an
order. Dex stores each key separately, so a write does not rewrite the whole
collection.

## Locks {#locking}

Two Steps or RPCs can write the same Attribute at the same time. Without a
lock, a read-modify-write can overwrite another update. See
[Step guarantees](/concepts/step#guarantees). Use an
**Attribute lock** to run them one after the other. Dex acquires the lock before
the Step method or RPC starts and releases it when it finishes. A Step waits for
its lock. An RPC that cannot get a lock fails, and you retry it.

A lock affects only the Steps and RPCs that declare it. A Step or RPC that does
not declare it can still write the Attribute. Steps get a lock in the order they started waiting for it. An RPC does
not queue. It takes a free lock even when Steps are waiting for it. So a steady
stream of locked RPCs can delay those Steps. Keep locked RPCs short.

**Execute** runs:

## Short-lived secrets {#hard-delete-attributes}

A **hard-delete Attribute** holds a short-lived secret, such as an API key that
a Flow uses a few times and then discards. Deleting it erases the stored value
permanently. Neither Dex APIs nor Flow history can recover it. Unlike other
writes, a hard-delete write takes effect before the handler's result commits.
See
[Hard-delete Attributes](/reference/server/runtime-data#hard-delete-attributes)
for the requirements and their consequences.

## Keep data after the Flow {#attribute-store-projection}

Attribute Sync copies selected Attributes to a PostgreSQL table that you own.
The table keeps the data after Dex deletes the Flow, and you can index it for
your own queries. Dex writes the latest values asynchronously. See
[External Attribute Sync](/components/external-attribute-sync) and
the [Entity Store](/design-patterns/entity-store) pattern.
