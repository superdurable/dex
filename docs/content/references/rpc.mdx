# RPC

Flow RPCs let external callers read/write durable state and optionally publish channels or move execution (via Worker-side RPC handlers).

RPCs run through the server to the Worker (`InvokeRPC` → Worker `InvokeWorkerRPC`). They are not Step executions; they do not upsert Step locals.

Non-locking RPCs use a query, Worker call, and optional result signal by default
on both backends. Set `api.useTemporalSynchronousUpdateForAllRPCs: true` to route
all Temporal RPCs through one synchronous `InvokeRpc` Workflow Update. Locking
RPCs always use that Update and are unavailable on Cadence. The Update validator
rejects new RPCs after terminal finalization begins. Leave the option disabled
when Temporal Update concurrency is the tighter constraint.

Successful Updates always contain RPC input and output. Signal history includes
them only when `api.includeRPCInputOutputIntoHistory` is enabled. Values above the
Blob Store threshold are stored as references and hydrated by Dex clients, Dex
Web, and dexcli.
