# Get Started

Dex keeps a process running through crashes, restarts, and long waits. You write the process as a Flow of Steps in your own language. Dex records each Step's result, so after a failure the Flow continues from the last recorded Step.

## Choose a path by goal

| Your goal | Start here | Time | What you have at the end |
| --- | --- | --- | --- |
| See Dex work | [Quick Start](/quick-start) | About 10 minutes | A Flow that survived a stopped Worker without charging twice, on your machine. |
| Make an agent durable | [Agent Quick Start](/agent-frameworks/quick-start) | About 10 minutes | An agent session in your framework that waited for approval through a Worker restart. |
| Add Dex to a service | [Your Application](/components/application) | About 15 minutes of reading | The Worker and Client setup and the rules for Flows in a real service. |
| Let a coding agent write the code | [Build with AI](/build-with-ai/dex-developer-skill) | About 5 minutes to install | Dex Skills in your coding agent, so it writes correct Dex code. |
| Learn the model first | [Concepts](/concepts) | About 20 minutes of reading | Flow, Step, and the six primitives, and the guarantees Dex gives. |
| Decide whether Dex fits | [Evaluate Dex](#evaluate-dex) | About 30 minutes of reading | How Dex compares with what you run today, its measured numbers, and its license. |

## Evaluate Dex {#evaluate-dex}

1. [Why Dex?](/intro/what-is-dex) walks through one order process.
2. [Compared to Database](/intro/compared-to-database) builds that process on a database and queues, then as a Flow.
3. [Compared to Existing Durable Execution](/intro/compared-to-durable-execution) maps other tools' terms onto Dex and says when another tool fits better.
4. [Performance and Maturity](/intro/performance-and-maturity) gives measured numbers, the release status, and the license.
