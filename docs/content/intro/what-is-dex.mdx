# What is Dex?

Dex is an open-source **Durable Execution** engine. You run it yourself with `dexcli`, Dex Server, Dex Web, and the SDKs for Go, Java, Python, and TypeScript.

If you have not read [What is Durable Execution?](/intro/what-is-durable-execution), start there — this page shows how Dex applies those ideas to real code.

## Structural, not replay-based

Dex programs are **Flows**: ordinary application objects made of **Steps**, **Attributes**, **Channels**, **Timers**, and **RPCs**. A Worker hosts your Step and RPC handlers as normal code. Dex Server keeps control-flow decisions durable on Temporal or Cadence — without forcing you to write event-sourced workflow functions.

| | Temporal / Cadence workflow code | Dex |
| --- | --- | --- |
| Shape | Event-sourced functions + activities | Structural Steps, Attributes, Channels, RPCs |
| App code | Must replay history | Worker handlers are plain code |
| Waits, RPC, locking | Composed from SDK primitives | Built into the Flow model |
| Engine | Workflow runtime | Dex interpreter on Temporal or Cadence |

## Charge → approval → ship in Dex

Same order flow from the previous page — charge, wait for seller approval (with reminders), then ship with rollback on failure.

<ExecutionApproachDiagram approach="dex" />

### Flow shape

```text
Start → ChargeStep → ApprovalStep → ShipStep → complete
                      ↑ timer / seller RPC
```

- **ChargeStep** calls the payment API with Step-level retry. On success, move to ApprovalStep.
- **ApprovalStep** waits for a seller **Channel** message or a **Timer**. If the timer fires first, send a reminder and keep waiting.
- **ShipStep** calls fulfillment. If retries exhaust, move to **RefundStep** (compensation).
- **RPC `waitUntilCharged`** lets the storefront API block until ChargeStep completes.
- **Attribute `orderStatus`** is indexed so support can search stuck orders.

### Code

<SdkTabs>
<SdkSnippet lang="python">

```python
from datetime import timedelta
from dex import Attribute, AttributeIndex, Channel, Context, Flow, IndexType, PersistenceSchema, RPCResult
from dex import Step, StepDecision, StepList, Timer, Wait, go_to, graceful_complete, rpc

class ChargeStep(Step[str]):
    def execute(self, context: Context, order_id: str) -> StepDecision:
        charge(order_id)
        OrderFlow.order_status.set(context, "charged")
        return go_to(ApprovalStep(OrderFlow.seller_ok, OrderFlow.reminder), order_id)

class ApprovalStep(Step[str]):
    def __init__(self, seller_ok: Channel[str], reminder: Channel[str]):
        self.seller_ok = seller_ok
        self.reminder = reminder

    def wait_for(self, context: Context, order_id: str) -> Wait:
        return Wait.any_of(
            self.seller_ok.for_one(),
            Timer.by_duration(timedelta(hours=24)),
        )

    def execute(self, context: Context, order_id: str) -> StepDecision:
        if context.has_timer_fired():
            self.reminder.publish(context, "approve-shipment")
            return go_to(self, order_id)
        return go_to(ShipStep(), order_id)

class ShipStep(Step[str]):
    def execute(self, context: Context, order_id: str) -> StepDecision:
        ship(order_id)
        OrderFlow.order_status.set(context, "shipped")
        return graceful_complete(order_id)

class RefundStep(Step[str]):
    def execute(self, context: Context, order_id: str) -> StepDecision:
        refund(order_id)
        return graceful_complete(f"refunded:{order_id}")

class OrderFlow(Flow[str]):
    order_status = Attribute(
        "order-status",
        str,
        index=AttributeIndex(type=IndexType.KEYWORD),
    )
    seller_ok = Channel("seller-ok", str)
    reminder = Channel("reminder", str)

    def get_steps(self) -> StepList[str]:
        return StepList.start_step(ChargeStep()).other_steps(
            ApprovalStep(self.seller_ok, self.reminder),
            ShipStep(),
            RefundStep(),
        )

    def get_persistence_schema(self) -> PersistenceSchema:
        return PersistenceSchema.attributes(self.order_status).channels(
            self.seller_ok, self.reminder
        )

    @rpc
    def approve_shipment(self, context: Context, _note: str) -> RPCResult:
        self.seller_ok.publish(context, "approved")
        return RPCResult(output="ok")

    @rpc
    def wait_until_charged(self, context: Context, _input: str) -> RPCResult:
        # Client API: block until ChargeStep completes, then return status.
        return RPCResult(output=self.order_status.get(context))
```

Step transitions are atomic. Timers and channel waits survive Worker restarts. Retries and compensation are declared on the Step, not scattered across queues and cron jobs. Dex Web shows each Step's inputs, outputs, and errors.

## Primitives map to the hard parts

| Problem from the storage-only approach | Dex primitive |
| --- | --- |
| Durable state between Steps | [Attribute](/primitives/attribute) |
| Atomic move to the next Step | [Step](/primitives/step) movement |
| Retry / timeout per Step | Step options |
| Wait for approval or timer | [Channel](/primitives/channel) + [Timer](/primitives/timer) |
| External read/write while running | [RPC](/primitives/rpc) |
| Refund after ship failure | Failure movement to a compensation Step |
| Frontend waits for charge | Client / RPC wait APIs |
| Search stuck orders | Indexed Attributes + Client search |

See [Durable Primitives](/primitives) for each building block — why it exists, how to use it, and what teams usually build by hand.
