# Compared to Existing Durable Execution

Dex shares the goal of other durable execution tools: a process that survives crashes, restarts, and long waits. It reaches that goal without replaying your code.

## Replay-based workflow engines

Traditional Durable Execution engines rebuild a workflow function's state by **replaying** its event history. Side effects must go in **activities**. Workflow code must be **deterministic**.

Dex has no replayed workflow function. You declare Steps and the movements between them. Worker handlers are ordinary code. **Attribute** data lives in a **blob store**, not in an event history.
