# Build with AI using Dex Skills

Dex Skills is the official coding-agent guidance for Dex. It is distributed as
a Plugin or as a standalone bundle of three Skills. It helps Codex, Claude
Code, and Cursor design and build Dex applications, work directly with the
public Dex SDK, and contribute official
[Connectors](/primitives/connector).

The plugin contains developer guidance, not runtime code. Dex Server, Workers,
and applications do not load it.

:::tip Start with Dex App Builder

For a product, application, or business-process request, start with
**dex-app-builder**. It owns the end-to-end workflow and loads the specialist
skills when SDK or Connector work is required.

:::

## Requires a coding workspace

Dex Skills is a developer plugin, not a hosted application builder. To create
or modify an application, run it in Codex or another coding-agent host with a
writable repository or project workspace, file-editing tools, and command
execution. An existing repository or a new empty repository both work.

In an ordinary chat without repository and command access, the skills can still
help with business discovery, architecture, and an implementation handoff. They
cannot create project files, run tests, build artifacts, or deploy the
application. Move the confirmed plan into a repository-backed coding workspace
before implementation.

## Choose a skill

| Skill | Role | Use it for |
| --- | --- | --- |
| [**Dex App Builder**](./dex-developer-skill/dex-app-builder.mdx) | **Primary skill** | Discover, prototype, implement, and locally verify an end-to-end process product with a Go backend. |
| [**Dex SDK**](./dex-developer-skill/dex-sdk.mdx) | Specialist sub-skill | Implement, debug, test, and operate Dex applications in Python, Go, Java, TypeScript, or Rust. |
| [**Dex Connector Contributor**](./dex-developer-skill/dex-connector-contributor.mdx) | Specialist sub-skill | Create, verify, and upstream official Connector operations, Triggers, and configuration UI units. |

Use **dex-sdk** directly only for a standalone SDK task. Use
**dex-connector-contributor** directly only for standalone work in the official
Dex Connectors Library.

## How the skills work together

Dex App Builder is the primary coordinator. It loads Dex SDK when backend
design and implementation begin, uses released Connectors directly, and routes
a confirmed official Connector gap to Dex Connector Contributor. Connector
Contributor also loads Dex SDK when it needs shared Flow and Step semantics.

Install all three Skills together so the agent can route between them. The
source and releases are maintained in
[superdurable/dex-skills](https://github.com/superdurable/dex-skills).

## Choose one installation path

Use one of these paths, not both:

1. **Plugin (recommended)** installs all three Skills and uses the host's
   marketplace lifecycle.
2. **Standalone Skills** installs all three Skills directly with the Agent
   Skills CLI.

Installing both can leave duplicate copies with ambiguous versions. Plugin and
standalone installations can also use different invocation syntax on the same
host.

## Install for Codex

### Codex in the ChatGPT desktop app

No terminal command or separately installed Codex CLI is required.

1. Open the plugin browser, select the add menu, and choose
   **Add a marketplace**.
2. Complete the form with these values:

   | Field | Value |
   | --- | --- |
   | **Source** | **https://github.com/superdurable/dex-skills** |
   | **Git ref** | **main** |
   | **Sparse paths** | Leave empty. The marketplace and plugin are at the repository root. |

3. Select **Add marketplace**.
4. Open the **Super Durable** marketplace, select **Dex**, and install it.
5. Open an existing repository or create an empty one, then start a new task.

To use the Plugin, type **@**, select **Dex** from the picker, and enter the
request. For example:

~~~text
Design and build this process application.
~~~

The picker selection creates the Plugin binding. Typing plain **@Dex** text
without choosing the picker item does not. All three Skills can route from a
matching natural-language request after the Plugin is selected:

~~~text
Diagnose this Flow retry behavior.
Add <XYZ> to Dex official connector library
~~~

### Optional: Codex CLI

The shell command below is valid only when the separate Codex CLI is installed
and available on your **PATH**. Check first:

~~~bash
codex --version
codex plugin marketplace add superdurable/dex-skills
codex plugin add superdurable-dex@superdurable
~~~

Start a new interactive Codex session, type **@**, and select **Dex** from the
picker. A raw **@Dex** string passed in the initial **codex** prompt or to
**codex exec** is not a structured Plugin binding. Codex can route a matching
natural-language request implicitly, but deterministic non-interactive
invocation should use the standalone Codex Skill below.

If the shell reports **command not found: codex**, use the desktop steps above
or install Codex CLI separately. The desktop app does not require this CLI
route.

## Install for Claude

### Claude on the web or in the desktop app

1. Open **Customize** and select the **Plugins** tab.
2. Select **Add**, then **Add marketplace**.
3. Choose **Add from a repository** and enter
   **https://github.com/superdurable/dex-skills**.
4. Open the **Super Durable** marketplace and install **Dex**.

Claude saves this installation to your account. It can sync into Claude Code
2.1.273 or later when signed in with the same account. Older Claude Code
versions can use the manual Plugin commands below.

Use natural language or the **/** picker. Dex does not distribute standalone
ZIP Skills for Claude web or desktop.

### Claude Code CLI

From a shell where the **claude** command is installed, run:

~~~bash
claude plugin marketplace add superdurable/dex-skills
claude plugin install superdurable-dex@superdurable
~~~

Alternatively, inside an interactive Claude Code session, run the slash-command
versions:

~~~text
/plugin marketplace add superdurable/dex-skills
/plugin install superdurable-dex@superdurable
~~~

Do not enter the slash-command versions directly in a shell. Start a new Claude
Code session after installation. The three skill invocations, in recommended
order, are:

~~~text
/superdurable-dex:dex-app-builder
/superdurable-dex:dex-sdk
/superdurable-dex:dex-connector-contributor
~~~

For example:

~~~text
/superdurable-dex:dex-connector-contributor Add <XYZ> to Dex official connector library
~~~

## Install for Cursor

### Cursor desktop app

1. Open a project, then open **Customize** in the sidebar.
2. Select **Plugins → Add → From GitHub Repository** and enter
   **github.com/superdurable/dex-skills**.
3. Open **Dex**, select **Install**, and choose a user or project scope.

The repository contains the required Cursor marketplace manifest. The three
skills appear as:

~~~text
/dex-app-builder
/dex-sdk
/dex-connector-contributor
~~~

### Cursor CLI

Cursor does not provide a non-interactive shell command for installing this
GitHub marketplace. A user-scope desktop installation is available to Cursor
CLI. Alternatively, start **cursor-agent**, enter **/plugin**, open the
Marketplace tab, and install **Dex**. Do not guess a **cursor plugin install**
command.

## Install standalone Skills

Use this path instead of the Plugin. Install all three Skills together for the
selected coding agent:

~~~bash
npx skills add superdurable/dex-skills --skill '*' --agent codex --global
npx skills add superdurable/dex-skills --skill '*' --agent claude-code --global
npx skills add superdurable/dex-skills --skill '*' --agent cursor --global
~~~

Invoke the standalone Connector Contributor with the host's Skill syntax:

| Host | Invocation |
| --- | --- |
| Codex | **$dex-connector-contributor Add &lt;XYZ&gt; to Dex official connector library** |
| Claude Code | **/dex-connector-contributor Add &lt;XYZ&gt; to Dex official connector library** |
| Cursor | **/dex-connector-contributor Add &lt;XYZ&gt; to Dex official connector library** |

Cursor uses the same short slash command for Plugin and standalone installs;
only the installation source differs. Standalone Skills are for coding-agent
hosts. Claude web and desktop use the Plugin path.

## Keep the installation current

Agents use an installed or cached copy. They do not fetch the latest GitHub
content for every prompt, and an active task keeps the version loaded when that
task started. The Dex version check only reports that a release exists. It
never installs or upgrades the Plugin or standalone Skills.

### Standalone Skills

Update all three Skills together:

~~~bash
npx skills update dex-app-builder dex-sdk dex-connector-contributor --global
~~~

If the installed **skills** CLI does not support **update**, rerun the exact
host-specific installation command above.

### Codex in the ChatGPT desktop app

Open the plugin browser's marketplace management view, find **Super Durable**,
and select **Upgrade**. Wait for the upgrade to finish, restart the desktop app,
and start a new task. This route does not require Codex CLI.

### Codex CLI

From a shell where **codex --version** works, refresh the Super Durable
marketplace and start a new session:

~~~bash
codex plugin marketplace upgrade superdurable
codex
~~~

Open **/plugins** and confirm that **Dex** is enabled.

### Claude Code CLI

Update Dex directly from a shell:

~~~bash
claude plugin update superdurable-dex@superdurable
~~~

Or update the marketplace inside an interactive Claude Code session:

~~~text
/plugin marketplace update superdurable
~~~

Start a new session after a manual update. To receive future releases
automatically, open **/plugin**, select **Marketplaces → Super Durable**, and
select **Enable auto-update**.

Claude's public web and desktop documentation does not describe a separate
per-user upgrade command. For an organization-managed GitHub marketplace, an
owner selects **Organization settings → Plugins & skills → Marketplaces →
Update**, and account users receive the synced version.

### Cursor

For a GitHub-imported team marketplace, an administrator can click **Refresh**
or enable **Auto Refresh**, then users reload the Cursor window. Cursor does not
document a personal **cursor plugin update** shell command for a direct GitHub
import; manage the installation through **Customize** instead of guessing one.

The Dex Skills version is separate from the Dex SDK version. Each skill inspects
the application's installed dependencies and immutable released sources before
using an exact API.

## Trust and permissions

Install agent extensions only from sources you trust. Dex declares no MCP
server, credentials, or application runtime code. Its optional lifecycle hook
reads the installed version and public GitHub release metadata, then reports a
newer release without installing it. Creating a GitHub fork, publishing a
branch, opening a pull request, and mutating a running Flow remain permissioned
actions.

Continue with [Dex App Builder](./dex-developer-skill/dex-app-builder.mdx), the
primary workflow.
