# Build with AI

Dex Skills is the official coding-agent plugin for Dex. It helps Codex, Claude
Code, Cursor, and other Agent Skills clients build Dex applications and
contribute official [Connectors](/primitives/connector).

The plugin contains guidance files only. Dex Server, Workers, and applications
do not load it at runtime.

## Requires a coding workspace

Dex Skills is a developer plugin, not a hosted application builder. To create
or modify an application, run it in Codex or another coding-agent host with a
writable repository or project workspace, file-editing tools, and command
execution. An existing repository or a new empty repository both work.

In an ordinary chat without repository and command access, the skills can still
help with business discovery, architecture, and an implementation handoff. They
cannot create project files, run tests, build artifacts, or deploy the
application. Move the confirmed plan into a repository-backed coding workspace
before implementation.

## Start with Dex App Builder

For most Dex requests, start with **dex-app-builder**. It is the primary skill
for discovering, designing, implementing, and verifying a complete Dex
application. It keeps ownership of the product workflow and loads specialist
guidance when backend or Connector work begins.

Use **dex-sdk** directly only for a standalone SDK implementation, debugging,
testing, or operations task. Use **dex-connector-contributor** directly only
for standalone work in the official Dex Connectors Library.

| Skill | Use it for |
| --- | --- |
| **dex-app-builder** | Primary skill for discovering, prototyping, implementing, and locally verifying an end-to-end process product with a Go backend. |
| **dex-sdk** | Specialist sub-skill for implementing, debugging, testing, and operating Dex applications in Python, Go, Java, TypeScript, or Rust. |
| **dex-connector-contributor** | Specialist sub-skill for creating or modifying official Connector operations, Triggers, and configuration UI units in the Dex Connectors Library. |

### Dex App Builder

Use **dex-app-builder** as the default entry point for a complete process
product. It starts with business roles, permissions, triggers, actions, waits,
approvals, recovery, and audit requirements. It then chooses either Dex Web as
the management experience or a custom UI, implements a Go backend from the
supported template, and verifies the product with a real Dex Server.

When the product needs a missing or defective external-provider Connector, the
workflow routes that contribution to **dex-connector-contributor**. Application
dependencies remain blocked on an exact published Connector release.

### Dex SDK

Use **dex-sdk** for standalone application-level Dex work. It models Flows,
Steps, transitions, durable state, messages, RPCs, timers, retries, and recovery
before implementation. It checks the SDK version installed by the application
before choosing exact APIs and runnable examples. App Builder loads this
guidance when backend implementation begins.

### Dex Connector Contributor

Use **dex-connector-contributor** for work in the official
[Dex Connectors Library](https://github.com/superdurable/dex-connectors-library).
It starts from a provider's documented public API or official SDK, updates the
manifest and generated surface, implements provider behavior, adds a runnable
example, runs the complete test matrix, and opens an upstream pull request.

The workflow first discovers and verifies the user's GitHub fork. If no fork
exists, it asks permission and opens GitHub's fork page. The user clicks
**Create fork** before the agent clones that fork and begins development.

## How the skills work together

**dex-app-builder** is the primary coordinator. It loads the shared **dex-sdk**
semantics when backend work begins. It uses released Connectors directly and
routes a confirmed Connector gap to **dex-connector-contributor**. Connector
Contributor also loads **dex-sdk** where it needs shared Flow and Step semantics.

App Builder owns the product workflow and consumption of released Connectors.
The specialist sub-skills own standalone SDK work and Connector library
contributions. An explicit specialist invocation does not expand into the full
product workflow.

Install the complete plugin so the agent can route between all three skills.
The source and releases are maintained in
[superdurable/dex-skills](https://github.com/superdurable/dex-skills).

## Install for Codex

Add the Super Durable marketplace and install the Dex plugin:

~~~bash
codex plugin marketplace add superdurable/dex-skills
codex plugin add superdurable-dex@superdurable
~~~

Open an existing repository or create an empty one, then start a new task.
Begin product work with App Builder:

~~~text
$dex-app-builder Design and build this process application.
$dex-sdk Design a reliable Dex Flow for this application.
$dex-connector-contributor Add this capability to an official Connector.
~~~

Codex can select **dex-app-builder** from the task context. The SDK and
Connector Contributor skills are explicit-only specialist entries, while App
Builder can still load them as part of the product workflow.

## Install for Claude Code

Run these commands inside Claude Code:

~~~text
/plugin marketplace add superdurable/dex-skills
/plugin install superdurable-dex@superdurable
/reload-plugins
~~~

The three invocations are:

~~~text
/superdurable-dex:dex-app-builder
/superdurable-dex:dex-sdk
/superdurable-dex:dex-connector-contributor
~~~

Start with **dex-app-builder** unless the task is standalone SDK or official
Connector library work.

## Install for Cursor

Import [superdurable/dex-skills](https://github.com/superdurable/dex-skills)
from **Customize → From GitHub Repository**, then install
**superdurable-dex**. The three skills appear as:

~~~text
/dex-app-builder
/dex-sdk
/dex-connector-contributor
~~~

Start with **dex-app-builder** unless the task is standalone SDK or official
Connector library work.

Agent Skills clients can install the complete bundle directly:

~~~bash
npx skills add superdurable/dex-skills --all
~~~

## Keep the plugin current

Agents use an installed or cached copy. They do not fetch the latest GitHub
content for every prompt, and an active task keeps the version loaded when that
task started.

- In Codex, upgrade the marketplace, reinstall the Dex plugin, and start a new
  task.
- In Claude Code, update the marketplace and reload plugins.
- In Cursor, refresh or reinstall the plugin, then reload the window.
- For a direct Agent Skills installation, rerun the installation command.

The plugin version is separate from the Dex SDK version. Each skill inspects
the application's installed dependencies and immutable released sources before
using an exact API.

## Trust and permissions

Install agent extensions only from sources you trust. The Dex plugin declares
no MCP server, hooks, credentials, or application runtime code. Creating a
GitHub fork, publishing a branch, opening a pull request, and mutating a running
Flow remain permissioned actions. Connector fork creation pauses for the user
to click GitHub's creation button.
