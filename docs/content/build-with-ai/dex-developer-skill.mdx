# Build with AI

Dex Skills teaches a coding agent, such as Codex, Claude Code, or Cursor, to
design and build Dex applications, use the Dex SDK, and contribute official
[Connectors](/concepts/connector). The Skills are guidance for the agent and
hold no runtime code.

## Install and use Dex Skills

<DexSkillHostTabs skill="all" />

:::tip Start with Dex App Builder

For a product, application, or business-process request, start with
**dex-app-builder**. It runs the whole job from start to finish. It loads the
other skills when the job needs SDK or Connector work.

:::

## Run the command at the top of a page {#copy-a-prompt}

Six pages open with a box for your coding agent: the [Quick Start](/quick-start), [Add Dex to Existing Code](/intro/add-to-existing-code), [Test Your Flows](/components/testing), [Deploy Code Changes](/concepts/change-flow-code), the [Agent Quick Start](/agent-frameworks/quick-start), and [Add Dex to Your Agent](/agent-frameworks/add-to-your-agent). The box has one command for Claude Code and one for Codex. It installs Dex Skills, then starts the agent with a one-line prompt that points at the page's Markdown version.

## What App Builder does {#what-app-builder-does}

App Builder builds a complete Dex application with a Go backend, from the
business process to a tested, committed result. It works in four stages:

1. **Confirm the business process.** It talks with you first. It works out the
   roles and their permissions, the triggers, waits, retries, and recovery, and
   the external systems with the Connector capabilities they need. It settles
   every open question that matters before it writes code.
2. **Choose the application surface.** Dex Web is the default process UI. A
   custom React UI is built only when the product needs screens that Dex Web
   does not offer, first as a prototype on mock data that you approve.
3. **Design and implement the Flow.** Before it writes code, it states the
   Flow's identity, input and output, Steps, Attributes, Channels, RPCs,
   Timers, retries, and recovery. It loads the Dex SDK skill for the SDK rules.
4. **Verify and hand off.** It runs the template's full check, including
   behavior against a real Dex Server and the recovery paths. The handoff lists
   your decisions, what was built, the test results, and known limits, in a
   clean Git commit.

<a id="before-implementation"></a>

To create files and run tests, App Builder needs a coding workspace: a
writable repository, file-editing tools, and command execution. Without one,
it still works out the process and writes a plan. [Before implementation](./dex-developer-skill/dex-app-builder.mdx#before-implementation) lists what it checks first.

When an official Connector, operation, Trigger, or configuration UI unit that
the application needs is missing or broken, App Builder loads the Connector
Contributor skill. The application can test against a local copy of the
Connector while the contribution is in review. It is not ready for production
until the Connector is released with an exact version.

[Dex App Builder](./dex-developer-skill/dex-app-builder.mdx) has the full
workflow.

## Trust and permissions

Install agent extensions only from sources you trust. The source and releases of Dex Skills are in
[superdurable/dex-skills](https://github.com/superdurable/dex-skills). Dex Skills adds no MCP
server, asks for no credentials, and contains no application runtime code. Its
optional hook reads the installed version and the public GitHub release
metadata. If a newer release exists, the hook tells you, but it does not
install it. The agent still needs your permission to create a GitHub fork,
push a branch, open a pull request, or change a running Flow.
