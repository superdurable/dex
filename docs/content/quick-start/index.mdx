# Quick Start

Run your first Flow, stop its Worker in the middle of a wait, and watch Dex continue the Flow after a restart. It takes about 10 minutes.

<a id="before-you-start"></a>

## 1. Install Dex and get the code

You need macOS or Linux and three terminals: one for `dexcli dev`, one for the Worker, and one to start Flows.

In the first terminal, install `dexcli` and start Dex. [Run Locally](/components/run-locally) shows how to install it without Homebrew.

```bash
brew install superdurable/tap/dexcli
dexcli dev
```

In a second terminal, download the example. The command fetches only the example's folder, with no clone of the repository:

## 2. Read the Flow

<a id="what-you-will-build"></a>

The example is an order Flow with two Steps:

- **Charge** charges the order through a mock payment API.
- **Ship** waits 60 seconds on a Timer, then ships the order through a mock shipping API.

The mock API prints each call, so the Worker's output shows which Steps ran. You start a Flow, stop the Worker while Ship waits, and start the Worker again. Ship runs when the Timer fires, and Charge runs only once.

<CrashTimeline variant="quick-start" />

This step and the next one walk through the code in the folder you downloaded.

A Flow is a process that Dex runs to completion. Each Step is one unit of work in it. Dex saves the result of each Step, so a Step that finished does not run again.

**Charge** calls the payment API and moves to **Ship**. **Ship** waits on a Timer, 60 seconds by default, then calls the shipping API. Each call passes an idempotency key, which step 6 shows at work. The mock API comes in through the constructor.

```python
class Charge(Step[str]):
    def __init__(self, shop: ShopApi) -> None:
        self.shop = shop

    def execute(self, context: Context, input: str) -> StepDecision:
        self.shop.charge(input, idempotency_key=f"charge-{input}")
        return go_to(Ship, input)


class Ship(Step[str]):
    def __init__(self, shop: ShopApi) -> None:
        self.shop = shop

    def wait_for(self, context: Context, input: str) -> Wait:
        return Wait.until(
            Timer.by_duration(SHIP_DELAY, condition_id=SHIP_DELAY_TIMER)
        )

    def execute(self, context: Context, input: str) -> StepDecision:
        self.shop.ship(input, idempotency_key=f"ship-{input}")
        return graceful_complete(f"shipped {input}")


class OrderFlow(Flow[str]):
    def __init__(self, shop: ShopApi) -> None:
        self.charge = Charge(shop)
        self.ship = Ship(shop)

    def get_steps(self) -> StepList[str]:
        return StepList.start_step(self.charge).other_steps(self.ship)
```

A decision names the next Step by its class: `go_to(Ship, input)`.

The `condition_id` argument to `Timer.by_duration`, **ship-delay**, names the Timer, so a test or an operator can end the wait early with **skip-timer** instead of waiting it out.

`graceful_complete` ends the Flow successfully once no other Step is running, and returns the Flow's result.

</SdkSnippet>
<SdkSnippet lang="go">

```go
// OrderFlow charges an order, waits 60 seconds, and then ships it.
type OrderFlow struct {
	dex.FlowDefaults
	shop *ShopAPI
}

// NewOrderFlow returns an OrderFlow whose Steps call shop.
func NewOrderFlow(shop *ShopAPI) *OrderFlow {
	return &OrderFlow{shop: shop}
}

// GetSteps returns Charge as the start Step, then Ship.
func (flow *OrderFlow) GetSteps() []dex.StepDef {
	return []dex.StepDef{
		dex.DefineStartStep(Charge{shop: flow.shop}),
		dex.DefineStep(Ship{shop: flow.shop}),
	}
}

// GetPersistenceSchema returns an empty schema: OrderFlow keeps no Attributes.
func (*OrderFlow) GetPersistenceSchema() dex.PersistenceSchema {
	return dex.PersistenceSchema{}
}

// Charge charges the order and moves to Ship.
type Charge struct {
	dex.StepDefaultsNoWaitFor[string]
	shop *ShopAPI
}

// Execute charges the order.
func (step Charge) Execute(_ dex.Context, orderID string) (*dex.StepDecision, error) {
	if err := step.shop.Charge(orderID, "charge-"+orderID); err != nil {
		return nil, err
	}
	return dex.GoTo(Ship{}, orderID), nil
}

// Ship waits on a Timer, 60 seconds by default, then ships the order.
type Ship struct {
	dex.StepDefaults
	shop *ShopAPI
}

// WaitFor waits on the ship-delay Timer.
func (Ship) WaitFor(_ dex.Context, _ string) (*dex.Wait, error) {
	return dex.Until(dex.Timer(ShipDelay(), dex.WithConditionID(ShipDelayTimer))), nil
}

// Execute ships the order and completes the Flow.
func (step Ship) Execute(_ dex.Context, orderID string) (*dex.StepDecision, error) {
	if err := step.shop.Ship(orderID, "ship-"+orderID); err != nil {
		return nil, err
	}
	return dex.GracefulComplete("shipped " + orderID), nil
}
```

A decision names the next Step by its type: `dex.GoTo` takes an empty `Ship` struct value.

The Timer's `dex.WithConditionID` option, **ship-delay**, names it, so a test or an operator can end the wait early with **skip-timer** instead of waiting it out.

`dex.GracefulComplete` ends the Flow successfully once no other Step is running, and returns the Flow's result.

</SdkSnippet>

```java
public final class OrderFlow implements Flow<String> {
    public static final String SHIP_DELAY_TIMER = "ship-delay";

    private final Charge charge;
    private final Ship ship;

    public OrderFlow(final ShopApi shop) {
        this.charge = new Charge(shop);
        this.ship = new Ship(shop);
    }

    @Override
    public StepList<String> getSteps() {
        return StepList.startStep(charge).otherSteps(ship);
    }

    static final class Charge implements Step<String> {
        private final ShopApi shop;

        Charge(final ShopApi shop) {
            this.shop = shop;
        }

        @Override
        public Class<String> getInputType() {
            return String.class;
        }

        @Override
        public StepDecision execute(final Context context, final String orderId) {
            shop.charge(orderId, "charge-" + orderId);
            return StepDecision.goTo(Ship.class, orderId);
        }
    }

    static final class Ship implements Step<String> {
        private final ShopApi shop;

        Ship(final ShopApi shop) {
            this.shop = shop;
        }

        @Override
        public Class<String> getInputType() {
            return String.class;
        }

        @Override
        public Wait waitFor(final Context context, final String orderId) {
            return Wait.until(Timer.byDuration(QuickStartConfig.SHIP_DELAY, SHIP_DELAY_TIMER));
        }

        @Override
        public StepDecision execute(final Context context, final String orderId) {
            shop.ship(orderId, "ship-" + orderId);
            return StepDecision.gracefulComplete("shipped " + orderId);
        }
    }
}
```

`StepDecision.gracefulComplete` ends the Flow successfully once no other Step is running, and returns the Flow's result.

```rust
#[derive(Clone)]
pub struct Charge {
    shop: ShopApi,
}

impl Step for Charge {
    type Input = String;

    fn execute(&self, _context: &mut Context, order_id: String) -> HandlerResult<StepDecision> {
        self.shop
            .charge(&order_id, &format!("charge-{order_id}"))
            .map_err(HandlerError::from_error)?;
        let ship = Ship {
            shop: self.shop.clone(),
        };
        Ok(StepDecision::go_to(&ship, order_id))
    }
}

#[derive(Clone)]
pub struct Ship {
    shop: ShopApi,
}

impl Step for Ship {
    type Input = String;

    fn wait_for(&self, _context: &mut Context, _order_id: String) -> HandlerResult<Wait> {
        let delay = Timer::by_duration(ship_delay_from_environment()).with_id(SHIP_DELAY_TIMER);
        Ok(Wait::until(delay))
    }

    fn execute(&self, _context: &mut Context, order_id: String) -> HandlerResult<StepDecision> {
        self.shop
            .ship(&order_id, &format!("ship-{order_id}"))
            .map_err(HandlerError::from_error)?;
        Ok(StepDecision::graceful_complete(format!(
            "shipped {order_id}"
        )))
    }
}

#[derive(Clone)]
pub struct OrderFlow {
    pub charge: Charge,
    pub ship: Ship,
}

impl OrderFlow {
    pub fn new(shop: ShopApi) -> Self {
        Self {
            charge: Charge { shop: shop.clone() },
            ship: Ship { shop },
        }
    }
}

impl Flow for OrderFlow {
    type StartInput = String;

    fn steps(&self) -> StepList<'_, String> {
        StepList::start(&self.charge).and(&self.ship)
    }
}
```

A decision names the next Step with a `Ship` value.

The Timer's `with_id`, **ship-delay**, names it, so a test or an operator can end the wait early with **skip-timer** instead of waiting it out.

`StepDecision::graceful_complete` ends the Flow successfully once no other Step is running, and returns the Flow's result.

The Timer is durable. Dex keeps the wait on the server, so the wait does not depend on a running Worker.

## 3. Add a Worker and a Client

The Worker runs the Steps. It connects out to Dex for work, so it needs no open port. The Client starts Flows.

Both programs build the same Flow and register it in a `Registry`, the list of Flows a Worker runs and a Client can start. So a web service that starts Flows needs the Flow's code too: it registers the Flow definition, but never runs its Steps. [Start Flows from an API service](/concepts/client#start-from-an-api-service) shows the pattern.

:::note Details

Both Steps are SYNC, the default: Dex stores each result before the Flow moves on. [SYNC and ASYNC Steps](/concepts/step/advanced-guarantees#sync-and-async) explains the other choice.

The Client uses the registered Flow to name its type and encode the input, so its copy of the mock API is never called. In your own API service, pass stand-ins the same way; see [Start Flows from an API service](/concepts/client#start-from-an-api-service). The SDK Clients have no call that starts a Flow by its type name alone; **dexcli flow start -flow-type** does that from a terminal. Each program also opens a local [blob cache](/components/application#blob-cache), which keeps copies of large values.

:::

```go
func run() (err error) {
	shop, err := quickstart.NewShopAPIFromEnvironment()
	if err != nil {
		return err
	}
	registry, err := dex.NewRegistry([]dex.Flow{quickstart.NewOrderFlow(shop)})
	if err != nil {
		return err
	}
	cache, err := quickstart.OpenCache(".dex-blob-cache/worker")
	if err != nil {
		return err
	}
	defer func() { err = errors.Join(err, cache.Close()) }()
	worker, err := dex.NewWorker(registry, cache, dex.WorkerOptions{
		FlowServiceAddress: quickstart.ServerAddress(),
	})
	if err != nil {
		return err
	}
	workerResult := make(chan error, 1)
	go func() { workerResult <- worker.Start() }()

	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()
	startupCtx, cancel := context.WithTimeout(ctx, 30*time.Second)
	defer cancel()
	if err := worker.WaitPullRegistered(startupCtx); err != nil {
		return errors.Join(err, worker.Stop(context.Background()), <-workerResult)
	}
	fmt.Printf("Worker is ready (process %d). Press Ctrl+C to stop it.\n", os.Getpid())

	select {
	case err := <-workerResult:
		return err
	case <-ctx.Done():
		fmt.Println("Stopping the Worker.")
		return errors.Join(worker.Stop(context.Background()), <-workerResult)
	}
}
```

```java
    final Registry registry = new Registry(List.of(orderFlow));
```

The Worker, in `src/bin/worker.rs`:

```rust
fn main() -> Result<(), Box<dyn Error>> {
    let config = QuickStartConfig::from_environment();
    let registry = Registry::new().register(OrderFlow::new(config.new_shop_api()))?;
    let cache = open_blob_cache(".dex-blob-cache/worker")?;
    let options = WorkerOptions::new().server_address(config.server_address);
    let worker = Arc::new(Worker::try_new(registry, cache, options)?);
    let running_worker = Arc::clone(&worker);
    let worker_thread = thread::spawn(move || running_worker.start());

    let runtime = tokio::runtime::Builder::new_current_thread()
        .enable_all()
        .build()?;
    let outcome = runtime.block_on(async {
        tokio::time::timeout(Duration::from_secs(30), worker.wait_pull_registered()).await??;
        println!(
            "Worker is ready (process {}). Press Ctrl+C to stop it.",
            std::process::id()
        );
        tokio::signal::ctrl_c().await?;
        println!("Stopping the Worker.");
        Ok::<(), Box<dyn Error>>(())
    });

    worker.stop();
    let stopped = worker_thread
        .join()
        .map_err(|_| "the Worker thread panicked")?;
    outcome?;
    Ok(stopped?)
}
```

## 5. Stop the Worker

Within 60 seconds, press Ctrl+C in the Worker's terminal. Then start the Worker again with the same command. If you miss the window, restart the Worker with a longer wait, such as `QUICK_START_SHIP_DELAY_SECONDS=120` in front of its command, and start a new Flow.

When the Timer fires, the new Worker prints the shipment:

```text
Worker is ready (process 41388). Press Ctrl+C to stop it.
Shipped order-1a2b3c4d with key ship-order-1a2b3c4d
```

Only Ship ran: Dex had saved the result of Charge, so **Charged** appears once.

### If nothing happens

- **"Worker is ready" is missing.** Check that **dexcli dev** is still running and printed "Dex development environment is ready".
- **Dex runs on another address.** Set `DEX_FLOW_SERVICE_ADDRESS`, such as **127.0.0.1:8801**, in both the Worker's and the start command's terminal.
- **The start command fails.** Run it from the example folder, after the install command in step 1.
- **Ship ran before you stopped the Worker.** You missed the 60-second window. Restart the Worker with `QUICK_START_SHIP_DELAY_SECONDS=120` and start a new Flow.
- **The Worker keeps running after Ctrl+C.** It finishes the running Step first. To stop it at once, use **kill -9** with its process number.

## 6. Stop the Worker inside a Step

Step 5 stopped the Worker between two Steps. This step stops it inside Charge, after the payment call and before Dex records the Step. Dex then runs Charge again, and the idempotency key keeps the payment from happening twice. [Idempotency keys](/concepts/step#idempotency-keys) explains how to build the key.

The mock API remembers each key in `.shop-api-keys`, as a payment provider would. Stop the Worker with Ctrl+C. Start it again with a 20-second pause after each new charge:

<SdkTabs>
<SdkSnippet lang="python">

```bash

```

</SdkSnippet>

</SdkSnippet>


</SdkSnippet>

```bash

```

</SdkSnippet>
<SdkSnippet lang="rust">

```bash

```

</SdkSnippet>
</SdkTabs>

Start another Flow with the start command from step 4. When the Worker prints **Charged**, stop it at once from the third terminal. Replace **PID** with the process number this Worker printed when it started. Ctrl+C would let Charge finish first.

```bash
kill -9 PID
```

Start the Worker again with the command from step 4. Dex never recorded the first Charge, so it runs Charge again. The mock API sees the same key and does not charge twice:

```text
Worker is ready (process 41502). Press Ctrl+C to stop it.
Charge for order-5e6f7a8b already done (key charge-order-5e6f7a8b); not charged again
```

When the Ship Timer fires, 60 seconds after Charge finishes by default, the Worker ships the order.
