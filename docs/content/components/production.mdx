# Run Dex in Production

Check each item before launch. In Dex Cloud, Super Durable runs the server; the Worker, code-change, and database items still apply. Each item links to the page with the details.

## Before you launch {#before-you-launch}

The [minimal configuration](#minimal-configuration) below covers authentication, one node, its bucket, retention, and metrics.

| Item | What to do | Details |
| --- | --- | --- |
| Authentication and TLS | Public API authentication is off by default, so any client that reaches the server can call it. Configure an authenticator before you expose the port. The API port serves plaintext gRPC: put TLS in front of it, or keep it on a private network. | [Authentication](/reference/server/authentication), [TLS](/reference/server/authentication#tls) |
| Topology | One active node serves the cluster. Add a hot standby if you need fast failover. | [Self-Host Dex](/components/self-host), [Lease, hot standby, and step down](/reference/server/high-availability) |
| Storage and backup | One object storage bucket and prefix holds all server state for the cluster. db9 can replace it; stock PostgreSQL is not supported. The bucket prefix is the only source of truth: version or replicate it, and practice a restore. | [Object storage and backup](/reference/server/object-storage), [Backup and restore](/reference/server/object-storage#backup-and-restore) |
| Retention | Closed runs, with their Step history, are deleted after 7 days by default. A deleted run frees its Flow ID. Set `retention.closedFlowDuration` to cover your longest client retry window, and copy data you must keep longer to [your own database](/components/your-database). | [Retention reference](/reference/server/configuration#retention) |
| Monitoring | Serve metrics on their own listener. Alert on a node that is not serving and on failed lease renewals. | [Metrics and alerts](/reference/server/metrics) |
| Workers | Workers connect out. Size their task slots, and stop them gracefully in a deploy. | [Workers and the task queue](/reference/server/workers) |
| Step retries | Step retries stop after 4 hours by default, and then the Flow fails. Set a retry policy or a failure route. | [StepOptions](/concepts/step#stepoptions) |
| Upgrades | Upgrades roll forward. Read each release's notes first; some need every process stopped. | [Upgrades and compatibility](/reference/server/upgrades), [Agent release notes](/reference/agents/upgrades#release-notes) |
| Code changes | Keep old Step types and RPCs until their Flows close. | [Deploy Code Changes](/concepts/change-flow-code) |
| Your database | Writes from Steps must be safe to repeat. | [Dex and Your Database](/components/your-database) |
| Search backend | Built-in search needs no database. Heavy search can use PostgreSQL or ParadeDB. | [Search backends](/reference/server/search) |
| Kubernetes | Run the server as a StatefulSet with graceful shutdown. | [Kubernetes deployment](/reference/server/kubernetes) |
| Capacity and cost | CPU is the limit. Start small; see [Sizing](#sizing). | [Performance](/intro/performance), [Grow past one node](/intro/limits#grow-past-one-node) |

### Sizing {#sizing}

As a starting point derived from the benchmark, a 2-vCPU node peaked near
1,800 SYNC Steps per second and a 16-vCPU node near 8,400. Start small and
watch CPU. Past one node, run separate clusters.

## Minimal configuration {#minimal-configuration}

This configuration runs one Dex Server node on Amazon S3, with authentication on:

~~~yaml
cluster:
  nodeId: dex-zd
objectStore:
  region: us-east-1
  bucket: BUCKET
  prefix: PREFIX
localStorage:
  directory: /var/lib/dex-server-zd/store
lease:
  duration: 60s
retention:
  closedFlowDuration: 7days
metrics:
  listen: 0.0.0.0:9090
auth:
  authenticators:
    - kind: staticTokens
      file: /etc/dex-server-zd/tokens.yaml
~~~

Replace `BUCKET` and `PREFIX` with your bucket and key prefix. The token file lists SHA-256 hashes of the bearer tokens that Workers and Clients send; [Authentication](/reference/server/authentication) shows its format and the JWT option. `cluster.nodeId`, `objectStore.bucket`, and `localStorage.directory` are required, and the node ID and partition count cannot change after the first start. The 60-second lease suits a single node; with hot standbys, keep the 10-second default. [Install and configure server-zd](/reference/server/configuration#minimal-production-configuration) explains every key.

Give each Worker and Client its token through the SDK's `credential` option;
a file credential rereads the token file, so you can rotate tokens without a
restart. [Send credentials from Workers and Clients](/reference/server/authentication#sdk-credentials)
lists the option in each SDK. The API port serves plaintext gRPC: put TLS in
front of it, or keep it on a private network. [TLS](/reference/server/authentication#tls)
lists the matching SDK option.
