# Run Dex in Production

**dexcli dev** runs everything on one machine for development. In production
you run Dex Server yourself, next to your own Workers. This page lists what to
decide and set up before launch. Each item links to the page with the details.

## Smallest real deployment {#smallest-deployment}

- One Dex Server node, with a hot standby if you need fast failover.
- One object storage bucket and prefix for the cluster.
- Authentication turned on before the API is reachable.
- TLS in front of the API port, or a private network. See [TLS](/reference/server/authentication#tls).
- Retention set to at least your longest client retry window.
- Metrics served and alerts on the node and its lease.

The [minimal configuration](#minimal-configuration) below sets up this deployment.

## Before you launch

### Sizing {#sizing}

As a starting point derived from the benchmark, a 2-vCPU node peaked near
1,800 SYNC Steps per second and a 16-vCPU node near 8,400. Start small and
watch CPU. Past one node, run separate clusters.

### Retention {#retention}

Set `retention.closedFlowDuration` to at least your longest client retry
window: once a run is deleted, its Flow ID can start a new Flow. Copy data you
must keep longer to your own tables with
[Attribute Store sync](/components/your-database).

## Minimal configuration {#minimal-configuration}

This configuration runs one Dex Server node on Amazon S3, with authentication on:

~~~yaml
cluster:
  nodeId: dex-zd
objectStore:
  region: us-east-1
  bucket: BUCKET
  prefix: PREFIX
localStorage:
  directory: /var/lib/dex-server-zd/store
lease:
  duration: 60s
retention:
  closedFlowDuration: 7days
metrics:
  listen: 0.0.0.0:9090
auth:
  authenticators:
    - kind: staticTokens
      file: /etc/dex-server-zd/tokens.yaml
~~~

Replace `BUCKET` and `PREFIX` with your bucket and key prefix. The token file lists SHA-256 hashes of the bearer tokens that Workers and Clients send; [Authentication](/reference/server/authentication) shows its format and the JWT option. `cluster.nodeId`, `objectStore.bucket`, and `localStorage.directory` are required, and the node ID and partition count cannot change after the first start. The 60-second lease suits a single node; with hot standbys, keep the 10-second default. [Install and configure server-zd](/reference/server/configuration#minimal-production-configuration) explains every key.

Give each Worker and Client its token through the SDK's `credential` option;
a file credential rereads the token file, so you can rotate tokens without a
restart. [Send credentials from Workers and Clients](/reference/server/authentication#sdk-credentials)
lists the option in each SDK. The API port serves plaintext gRPC: put TLS in
front of it, or keep it on a private network. [TLS](/reference/server/authentication#tls)
lists the matching SDK option.
