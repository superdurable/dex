# Managed Dex App

A **Managed Dex App** is a Dex application that Dex Cloud builds and runs from your GitHub repository. Super Durable runs the application and its Workers in Preview and Live. You maintain the code.

## When to use it {#when-to-use}

Dex Cloud offers two products:

| | Managed Dex Server | Managed Dex App |
| --- | --- | --- |
| Super Durable runs | Dex Server | Dex Server, your Workers, and your web server |
| You run | Your Workers, wherever you deploy them | Nothing. You push code to GitHub. |
| You provide | Worker code and its deployment | A GitHub repository in the Dex app structure |
| Start here | [Run on Dex Cloud](/components/dex-cloud) | This page |

Choose a Managed Dex App when you want Dex Cloud to run your application and Workers. Check the [supported stacks](/components/dex-app-manifest#template-manifest) before importing. Choose a managed Dex Server when you deploy your own Workers.

## Start from the example {#example}

The minimal example is [`superdurable-apps/cloud-dex-app-example`](https://github.com/superdurable-apps/cloud-dex-app-example). It is a small TypeScript process that meets every repository rule. Copy it, or compare your repository with it file by file.

## Follow the repository rules {#repository-rules}

Prepare your repository using the [repository layout and import rules](/components/dex-app-manifest#repository-layout).

## Import a repository {#import}

Import is in early access and is rolling out to accounts over time. Availability for your account can change without notice.

Dex Cloud reads your repository through the **SuperDurable Dex Cloud** GitHub App. The app asks for these permissions:

- **Contents**: read and write. When you ask the coding agent for a change, it pushes to `main`.
- **Metadata**: read.
- **Members**: read.

To import a repository:

1. A workspace admin connects your GitHub organization: they install the [SuperDurable Dex Cloud](https://github.com/apps/superdurable-dex-cloud) GitHub App on it and give the app access to the repository.
2. A member of the workspace chooses **Import project** on the Dex Cloud start page.
3. Pick the repository from the list, or enter it as `owner/name`.
4. Review the check. Dex Cloud reads `main` and shows `kind`, `stack`, and every rule the repository breaks.
5. When the check passes, create the project.

Importing leaves your repository unchanged. Deleting the project removes its Preview, Live and data, and leaves the repository untouched.

## Build, Preview, and Live {#build-preview-live}

Dex Cloud builds the application from the build profile. Your repository needs no Dockerfile.

- **Preview** runs `main` on its own Dex Server, with no change to your code. When new commits reach `main`, Preview offers to follow them.
- **Live**: choose **Publish**, pick a version (a commit of `main`) and choose **Publish to Live**; Dex Cloud builds it and deploys it.

Both run your web server and your Worker as two modes of one build; Live builds an image. Dex Cloud publishes your Flow definitions from the Flow sources that `dex-app.yaml` declares. The **Runs** tab opens Dex Web on the running Preview and on the current Live deployment.

You and your team keep pushing to `main` as before. When you ask the coding agent for a change, it commits to `main`, and Dex Cloud checks those commits against the same rules.

## Fix a refused import {#fix-refused-import}

The import check lists each problem as a finding. Each finding names where it is, what is wrong and how to fix it, with a link to its rule.

Each finding code has its own section on [the reference page](/components/dex-app-manifest#import-report), such as [`flow_source_missing`](/components/dex-app-manifest#flow_source_missing). Fix the repository, push to `main`, and check again.

If the check says the repository cannot be read, give the SuperDurable Dex Cloud GitHub App access to it on GitHub.
