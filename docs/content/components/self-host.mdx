# Self-Host Dex

You run **dex-server-zd** next to your Workers. It keeps every Flow in object storage, such as Amazon S3, and a standby can take over when the active node stops. You configure authentication, TLS, retention, and monitoring yourself.

The [Sustainable Use License](/intro/limits#license) lets you run Dex for your own business.

## What it needs {#dependencies}

| Dependency | Required | What it gives you |
| --- | --- | --- |
| Object storage, such as Amazon S3 or an S3-compatible store | Yes, or db9 in its place | The record of every Flow |
| A PostgreSQL or ParadeDB search backend | No | Large or frequent searches served from SQL. See [Search backends](/reference/server/search). |
| A PostgreSQL Attribute Store | No | Copies of selected Attributes in your own tables. See [Dex and Your Database](/components/your-database). |
| A metrics listener | No | Prometheus metrics. See [Metrics](/reference/server/metrics). |

In place of object storage, Dex Server can store its state in db9, a PostgreSQL-compatible database. Stock PostgreSQL is not supported. See [db9 provider](/reference/server/object-storage#db9).

## Run it {#run-it}

In production, run **dex-server-zd serve** with one YAML configuration file. The release publishes [binaries and a container image](/reference/server/configuration#install-and-start). On Kubernetes, run it as a [StatefulSet](/reference/server/kubernetes).

```bash
dex-server-zd serve --config /etc/dex-server-zd/config.yaml
```

To run one production node on local disk without external object storage, run **dex-server-zd local**. It keeps an embedded object store in its data directory and has no standby.

[Run Dex in Production](/components/production#minimal-configuration) has a minimal configuration with authentication on.

## Availability {#failover}

<a id="how-it-works"></a>

One active node serves a cluster. A standby takes over after the active node's lease expires, plus 1 second; the lease is 10 seconds by default. [Dex Server](/components/server#how-it-works) explains how it stores Flows, and [Failover and Deploys](/concepts/failover-and-deploys#a-dex-server-node-fails-over) lists what runs again.
