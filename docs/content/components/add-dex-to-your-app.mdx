# Add Dex to Your App

Run a Worker and a Client inside your service, and drive Flows from your HTTP handlers. The [Order Processing](/use-cases/order-processing) example shows every rule on this page in full code.

## Pass services to the Flow

Pass each service that a Flow calls, such as a payment API, to the Flow constructor. Do not set it later with a setter. Do not read it from a global variable.

## Register the Flow and start a Worker

Create a Registry, a Worker, and a Client that connect to the Dex Server address. Construct the Flow with its services, then register it.

The Worker connects out to the server to receive tasks. So it needs no open inbound port. [Workers and the task queue](/reference/server/workers) covers capacity, readiness, and production setup.

## Start a Flow from a handler

A **start** handler starts the Flow. Then it waits for the first Step with the Client **wait-for-Step-completion** API. It does not poll a status of its own.

## Send commands and read state through RPCs

A handler that changes a Flow calls an RPC, such as **approve**. The RPC publishes the message to a Channel. A handler that reads a Flow calls a read RPC, such as **describe**.

The handlers get the Client and the Flow from their constructor or factory arguments.
