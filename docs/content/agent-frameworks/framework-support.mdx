# Framework Support

Dex runs agents built with eight frameworks, plus its own built-in agent loop. Every one of them gets a durable session, tool policies, approvals, Connectors as tools, queued messages with **Steer** and `cancel_turn`, and live events on the AgentEvents Stream.

## Frameworks and features {#features-by-harness}

<a id="how-each-framework-runs-a-turn"></a>

| Framework | Languages | Each tool call in its own Step | Dex compaction | Questions and plans |
| --- | --- | --- | --- | --- |
| Claude Agent SDK | Python, TypeScript | Writes and Connector calls. Reads run inside the model call's Step. | No. Claude Code compacts its own transcript. | No |
| Google ADK | Python | Yes | Yes | No |
| LangChain and LangGraph | Python | Yes | Yes | No |
| Mastra | TypeScript | Yes, except tools that Mastra runs itself | Yes | No |
| OpenAI Agents SDK | Python, TypeScript | Function tools. Hosted tools run at the provider. | Yes | No |
| Pi | TypeScript | Yes | Yes | Yes |
| Pydantic AI | Python | Yes. Provider-run tools run at the provider. | Yes | No |
| Vercel AI SDK | TypeScript | Yes. Provider-executed tools run at the provider. | Yes | No |
| Built-in agent loop | Python, TypeScript | Yes | Yes | Yes |

A tool call in its own Step runs once for a write, and Dex can retry it for a read. A tool that runs inside the model call's Step, or at the provider, runs again when that Step retries.

## Limits {#limits}

These limits change how you write an agent. Each framework's tab on [How Each Framework Runs on Dex](/agent-frameworks/framework-details#limits) gives the full list and what to do instead.

| Framework | Main limits |
| --- | --- |
| Claude Agent SDK | The write calls of one model reply run one at a time. Tools inside the Claude Code CLI, such as **Bash** and **Edit**, can run again. |
| Google ADK | The App root must be a `BaseAgent`. A tool's state and artifact changes are discarded. |
| LangChain and LangGraph | Only the message list carries over between turns. Tools cannot use `ToolRuntime`, `InjectedState`, or `InjectedStore`. |
| Mastra | Mastra Memory is replaced by the session. A tool that calls `suspend()` fails. |
| OpenAI Agents SDK | MCP servers go through `tool_sources`, not `mcp_servers`. Server-managed conversation state and SDK sessions are not used. |
| Pi | Tools must be safe to run in parallel. Pi's `beforeToolCall` and `afterToolCall` hooks do not run. |
| Pydantic AI | Output functions run inside the model call's Step. `UsageLimits` apply per Step. |
| Vercel AI SDK | Every tool needs its own **execute**. Approval comes from Dex, not AI SDK `toolApproval`. |
| Built-in agent loop | See [Built-in Agent Loop limits](/agent-frameworks/built-in-agent-loop#limits). |

[Limits for long sessions](/reference/agents/session-limits) has the server limits that apply to every framework.
