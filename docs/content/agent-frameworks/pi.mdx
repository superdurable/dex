# Pi

Pi is a TypeScript toolkit for agents. Its **pi-ai** package calls models from many providers, such as OpenAI, Anthropic, Google, and Bedrock. Its agent core defines tools. The Dex package runs a Pi agent as a durable session. It is available for TypeScript.

## When to use it

Use it when your agent already uses pi-ai models and Pi tools. Keep the models and the tools, and let Dex own the session and the loop.

Use it also when you move an agent from **pi-durable** to Dex. [Migrate from pi-durable](/agent-frameworks/migrate-from-pi-durable) walks through the move.

## How a session runs

Dex runs the agent loop, not Pi. The session is the [built-in agent loop](/agent-frameworks/built-in-agent-loop) of Dex Agents. Dex decides when to call the model, when to run tools, when to wait for an approval, and when the turn ends.

Pi supplies two things:

- **The model call.** Each **RunModel** attempt sends one pi-ai request. pi-ai's own retries are off, so a retry is a new **RunModel** attempt that the Flow history shows. Bedrock is the exception: the AWS SDK retries inside one attempt, 3 times by default, as the AWS configuration sets. So the attempts in the Flow history do not count Bedrock requests. See [Not supported](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#not-supported) in the package README.
- **The tools.** Each tool is a Pi **AgentTool**. Each tool call runs in its own Step, in parallel: **CallTool** for a read or an idempotent write, **CallSingleAttemptTool** for any other write. A call that needs approval waits in **AwaitToolApproval** first.

Pi's **Agent**, **agentLoop**, and the **pi-durable** harness are not used. This makes the package different from the other adapters, which run their framework's own loop inside the session.

A turn that looks up an order runs **RunModel**, **CallTool**, **ResumeTurn**, and **RunModel**.

Each model response is stored as a pi-ai message with the fields that later model calls need: the content with its thinking signatures, the provider and model that produced it, and its token usage. Local telemetry, such as timestamps and cost, is not stored. Every later call replays these fields. pi-ai converts them for another provider, so a session can change its model between turns. [Stored messages](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#stored-messages) in the package README lists the fields.

### Agent and tools

The tools are Pi **AgentTool** objects. **piAgentFunctionTool** turns each one into a tool of the built-in loop. **createPiAiModelClient** turns a pi-ai model into the session's model client.

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/pi/pi-order-support-flow.ts',
  }}>
<SdkSnippet lang="typescript">

```typescript
export function createPiOrderSupportFlow(
  orderDesk: OrderDesk,
  model: Model<Api>,
  slack: Connection | undefined,
): OrderSupportSessionFlow {
  const lookUpOrder: AgentTool<typeof lookUpOrderArguments> = {
    name: "look_up_order",
    label: "Look up order",
    description: "Look up one order by its order ID and return its items and status.",
    parameters: lookUpOrderArguments,
    execute: async (_toolCallId, { order_id }) => textResult(orderDesk.describeOrder(order_id)),
  };
  const cancelOrder: AgentTool<typeof cancelOrderArguments> = {
    name: "cancel_order",
    label: "Cancel order",
    description: "Cancel one order that has not shipped yet.",
    parameters: cancelOrderArguments,
    // Not safe to repeat, so Dex asks for approval first and runs it at most once.
    replay: "never",
    execute: async (_toolCallId, { order_id, reason }) => textResult(orderDesk.cancelOrder(order_id, reason)),
  };
  return createBuiltinAgentSessionFlow(
    {
      name: "order-support",
      instructions: orderSupportInstructions,
      model: createPiAiModelClient(model),
      tools: [piAgentFunctionTool(lookUpOrder, { effect: "read" }), piAgentFunctionTool(cancelOrder)],
      toolSources: createSlackConnectorToolSources(slack),
    },
    piOrderSupportFlowType,
  );
}
```

</SdkSnippet>
</SdkTabs>

### Effect classes

Every Dex tool declares its [effect class](/agent-frameworks#effect-classes). A Pi tool's **replay** field gives it, unless you pass **effect**:

| The tool declares | **effect** passed | Effect class |
| --- | --- | --- |
| anything | yes | the passed effect |
| **replay: "safe"** | no | **idempotent_write**: rerun when a run is interrupted |
| **replay: "never"** | no | **non_idempotent_write**: approved first, runs at most once |
| no **replay** | no | an error when the session Flow is built |

In the example, **look_up_order** passes **effect: "read"**, so it runs without approval. **cancel_order** declares **replay: "never"**, so it waits for approval and runs at most once.

The effect class decides what happens when a run is interrupted, such as by a Worker crash. Dex reruns an interrupted **read** or **idempotent_write** call in its **CallTool** Step. It never reruns a **non_idempotent_write** call.

An error that the tool reports is not retried. A result with **isError**, or a thrown **ToolExecutionError**, records the call as **failed**. The model sees the message, and the session continues.

A tool's **prepareArguments**, when it has one, repairs the raw arguments before the schema check, as in Pi.

A plain thrown error is classified by the effect the call runs with, after tool policies apply. From a **read** or **idempotent_write** call, it records **failed**, as above. From any other call, such as a **non_idempotent_write** or **unclassified** one, it may come after the write, so the call records **outcome_unknown** and never runs again. To report a definite failure from a write, return **isError** or throw **ToolExecutionError**.

### The model

The Worker picks a model from pi-ai's built-in catalog. pi-ai reads the provider's key from the Worker's environment, so the key never enters Flow state.

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/pi/pi-order-support-flow.ts',
  }}>
<SdkSnippet lang="typescript">

```typescript
export function loadPiOrderSupportModel(): Model<Api> {
  const name = environmentOr("DEX_PI_MODEL", "openai/gpt-5-mini");
  const separator = name.indexOf("/");
  const provider = name.slice(0, separator) as BuiltinProvider;
  const modelId = name.slice(separator + 1);
  const model = separator > 0 ? getBuiltinModels(provider).find((candidate) => candidate.id === modelId) : undefined;
  if (model === undefined) {
    throw new Error(`DEX_PI_MODEL ${name} is not a <provider>/<model ID> of pi-ai's built-in catalog`);
  }
  return model;
}
```

</SdkSnippet>
</SdkTabs>

**createPiAiModelClient** also takes an **apiKey**, and a **prepareRequest** hook that changes the context of one request. The [package README](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#the-model-client) describes them.

| Variable | Default | Meaning |
| --- | --- | --- |
| **DEX_PI_MODEL** | **openai/gpt-5-mini** | A model of pi-ai's built-in catalog, as provider and model ID. |
| **OPENAI_API_KEY** | none; required for the default | The provider key. Another provider reads its own variable, such as **ANTHROPIC_API_KEY**. |
| **DEX_AGENT_SESSION_KEY** | a random key | The key that signs session tokens. |

### Call the session

Start a session, ask the agent to cancel order 1002, and approve the call:

<SdkTabs
  examples={{
    typescript: 'examples/typescript/src/products/agent-harnesses/README.md',
  }}>
<SdkSnippet lang="typescript">

```bash
base=http://127.0.0.1:8080/products/agent-harnesses/pi
session=$(curl -s -X POST "$base/sessions" -H 'Content-Type: application/json' \
  -d '{"message": "Please cancel order 1002"}')
id=$(echo "$session" | jq -r .session_id)
token=$(echo "$session" | jq -r .session_token)
until interrupt=$(curl -s "$base/sessions/$id/snapshot" -H "X-Agent-Session-Token: $token" \
  | jq -re '.pending_interrupts[0].interrupt_id'); do sleep 1; done
curl -s -X POST "$base/sessions/$id/interrupts/$interrupt/approve" -H "X-Agent-Session-Token: $token"
```

</SdkSnippet>
</SdkTabs>

The loop reads the snapshot until the agent asks to run **cancel_order**. That call waits for approval, then runs once. Read the snapshot again to see the agent's answer.

## Run it with the CLI {#run-it-with-the-cli}

The **dex-agents-pi** command runs a Pi coding agent as a durable session and chats with it in your terminal. It is in the npm package **@superdurable/dex-agents-pi-cli**. Dex runs the loop, as in the example. The command starts or reuses **dexcli dev**.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
npx -p @superdurable/dex-agents-pi-cli dex-agents-pi
```

The first run asks a few questions and writes **~/.dex/agents/pi.yaml**. Then type a message. Approve or reject a tool call with **y** or **n**. The session stays in Dex, and the command prints how to resume it.

The model is a provider and model ID from pi-ai's catalog, such as **anthropic/claude-opus-5-5**. The command reads only the provider's API key from the environment, such as **ANTHROPIC_API_KEY** or **OPENAI_API_KEY**. It never reads Pi's stored logins.

The **pi** section of the file holds the Pi options:

```text
model: anthropic/claude-opus-5-5
workspace: ~/dex-agent-workspace
local_tools:
  files: true
  shell: {enabled: true, allow: ["git status", "ls"]}
pi:
  load_project_context: true
  bash_timeout_seconds: 120
```

The agent uses Pi's own coding tools, each as its own tool Step:

| Tools | Effect | Approval |
| --- | --- | --- |
| **read**, **grep**, **find**, **ls** | read | No |
| **write**, **edit** | runs once | Every call |
| **bash** | runs once | Unless **local_tools.shell.allow** has the whole command |

File tools stay inside the workspace. Like Pi, each model call adds the project's **AGENTS.md** files to the instructions: the one in Pi's global directory, then the ones in the workspace and the directories above it. Set **pi.load_project_context: false** to add none.

The [command's README](https://github.com/superdurable/dex/tree/main/agents/cli/typescript/pi) describes every option, the file rules, and the AGENTS.md rules.

## What replaces Pi's features {#pi-feature-mapping}

| Pi feature | On Dex |
| --- | --- |
| **steer()** and **followUp()** | The **sendUserMessage** RPC and the session's steering |
| **beforeToolCall**, to approve or block a call | Tool policies and the **AwaitToolApproval** Step. An approval may wait as long as needed. |
| **afterToolCall**, to change a result | Change the result inside your tool. |
| **transformContext**, to trim or compact | The session's context compaction. **prepareRequest** changes one request. |
| **prepareRequest** | The **prepareRequest** option of **createPiAiModelClient** |
| **finishTurn** returns **end**: end the turn after the tools | The **decideTurnContinuation** hook of the agent definition returns **"end"**. |
| **finishTurn** returns **continue**: run again after an answer | **decideTurnContinuation** returns **\{ action: "continue", message \}**. The message is required. The model gets it as user text in the same turn. At most 8 such continuations may follow answers in a row. |
| **subscribe()** events | The **AgentEvents** Stream and the UI stream |
| **abort()** | The session's **cancel_turn** |
| **pi-durable** | Dex itself. See [Migrate from pi-durable](/agent-frameworks/migrate-from-pi-durable). |

[Ending or continuing a turn](https://github.com/superdurable/dex/tree/main/agents/typescript/core#ending-or-continuing-a-turn) in the core README describes **decideTurnContinuation**.

## Limits

- Dex runs the tool calls of one model response in parallel. A tool with **executionMode: "sequential"** is rejected.
- **AgentToolResult.terminate** is ignored. End a turn after tools with **decideTurnContinuation**.
- pi-ai's tool choice is **auto** or **none**, so a request that forces a tool fails.
- An image in a tool result reaches the model as a text note.
- A tool's **details** are not stored. The model sees the text parts of the result.
- Pi's **Agent**, **agentLoop**, and session files are not used.

The [package README](https://github.com/superdurable/dex/tree/main/agents/typescript/pi#not-supported) lists every limit. See [Limits for long sessions](/reference/agents/session-limits) for the server limits.

## Move from pi-durable

Dex replaces **pi-durable**, not Pi. Your pi-ai models and Pi tools stay. The harness entry code changes: **Harness.open**, the root conversation, **submit**, and **wait** become a session Flow, a Worker, and Client calls. [Migrate from pi-durable](/agent-frameworks/migrate-from-pi-durable) walks through the move.

A compatibility layer for the **pi-durable** API is tracked in [issue #1571](https://github.com/superdurable/dex/issues/1571).
