# Agent Quick Start

Run an agent built with your framework as a durable Dex session, then stop it in the middle of a conversation and watch it carry on. It takes about 10 minutes.

Building a new agent without a framework? Start with the [Built-in Agent Loop](/agent-frameworks/built-in-agent-loop).

## What you will build {#what-you-will-build}

A small order support agent. It has two tools on an in-memory order desk:

- `look_up_order` reads an order. It is a read, so Dex may retry it.
- `cancel_order` cancels an order that has not shipped. It is a write, so it runs at most once, and only after a person approves it.

You wrap a plain agent with Dex and ask it to cancel an order. Then you stop the program while the cancellation waits for approval, and again in the middle of a tool call, and check what Dex ran.

## Before you start {#before-you-start}

- `dexcli`: run **brew install superdurable/tap/dexcli**. [Run Locally](/components/run-locally) has the other ways to install it.
- Git, to get the example, and `jq` for one check in step 5.
- **Python 3.11 or later with uv**, or **Node.js 22 or later with npm**, depending on your framework.
- For Python, nothing else: Google ADK, LangChain, OpenAI Agents SDK, and Pydantic AI run on a local demo model that needs no API key. The Claude Agent SDK and every TypeScript framework call a real model, so they need your provider key, such as `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`, in the environment.

## 1. Get the example {#get-the-example}

Clone the Dex repository and start Dex in a first terminal:

```bash
git clone https://github.com/superdurable/dex.git
cd dex
dexcli dev
```

Keep **dexcli dev** running. Open a second terminal in the **dex** folder for the next steps.

## 2. Make your agent durable {#make-it-durable}

Each framework's example file has two functions. The first is the agent as the framework alone writes it, with the two tools. The second wraps the same agent in a Dex agent session and gives each tool a policy. For these two function tools, that is the only change. Tools the framework runs itself, such as MCP servers and hosted tools, need the changes in your framework's [Limits](/agent-frameworks/sessions#limits).

`look_up_order` is a read, and `cancel_order` is a non-idempotent write. [Tool Calls](/agent-frameworks/tool-calls) says how each kind runs and why the write waits for approval.

Some adapters need one more thing. LangChain takes a factory and adds `DurableToolCallMiddleware`, which runs each tool call as its own Step. The Claude Agent SDK takes the tools in a list next to the options, so Dex can run each one itself.

The session also needs a Worker and a Client, as any Dex application does. The example creates both in one process. The Worker runs the session's Steps, and the Client starts the session and talks to it. Both also open a [blob cache](/components/application#blob-cache): a local, size-limited directory for large values, which you can delete at any time:

```python
    def __init__(
        self, session_flow: AgentSessionFlow, server_address: str, blob_cache_dir: Path
    ) -> None:
        # Agent session Steps are async, so the Registry allows async handlers.
        self.registry = Registry((session_flow,), allow_async_handlers=True)
        blob_cache_dir.mkdir(parents=True, exist_ok=True)
        self.blob_cache = open_blob_cache(BlobCacheConfig(str(blob_cache_dir), 1 << 30))
        self.worker = AsyncWorker(
            self.registry,
            self.blob_cache,
            WorkerOptions(
                server_address=server_address,
                pull=PullWorkerOptions(max_concurrent_tasks=MAX_CONCURRENT_TASKS),
                # Dex Web draws the session and offers Approve from this graph.
                flow_definitions=[
                    session_flow_definition_document(
                        session_flow.get_flow_type(), ACTION_PERMISSION
                    )
                ],
            ),
        )
        self.client = AsyncClient(
            self.registry, self.blob_cache, ClientOptions(server_address=server_address)
        )
        self.sessions = AgentSessionClient(self.client, session_flow)
        self._worker_task: asyncio.Task[None] | None = None
```

<SdkSnippet lang="typescript">

```ts
  public static async start(flow: AgentSessionFlow, serverAddress: string, blobCacheDir: string): Promise<QuickStartApp> {
    const registry = new Registry([flow]);
    const blobCache = openBlobCache({ directory: blobCacheDir, maxBytes: 1 << 30 });
    const worker = new Worker(registry, blobCache, {
      serverAddress,
      pull: { maxConcurrentTasks: 16 },
      // Dex Web draws the session and offers Approve from this graph.
      flowDefinitions: [sessionFlowDefinitionDocument({ flowType: flow.getFlowType(), actionPermission })],
    });
    const client = new Client(registry, blobCache, { serverAddress });
    const app = new QuickStartApp(flow, client, worker, blobCache);
    try {
      await worker.start();
      await worker.waitPullRegistered({ timeoutMs: pullRegistrationTimeoutMs });
    } catch (failure) {
      await app.close();
      throw failure;
    }
    return app;
  }
```

## 5. Stop it while a tool runs {#stop-while-a-tool-runs}

Step 4 stopped the program while nothing ran. A crash in the middle of a tool call is the harder case. The example can slow each tool call down, so you have time to stop it.

1. Ask about an order again, with a 20-second delay on each tool call. Set `DEX_ORDER_DESK_TOOL_DELAY_SECONDS=20` in front of the step 3 command.
2. Within 20 seconds, kill the program as a crash would. Ctrl+C is not a crash: it lets a running call finish first.

3. Run the program again with `--session-id` and no message. The agent answers with the order.
4. Check how the tool call ran:

```bash

  | select(.payload.context.stepType == "CallTool")
  | .payload.context | {finalAttempt, failure: .lastFailureInfo.details.detail}'
```

`finalAttempt` is **2**. The first attempt failed because the Worker disconnected. `look_up_order` is a read, so Dex ran it again on the new Worker. The model call before it did not run again.

Now try a write. Ask to cancel order 1002 with the delay set, approve it, and kill the program within 20 seconds. Then run it again with `--session-id`.

`cancel_order` is a non-idempotent write, so Dex does not run it a second time. The call records `outcome_unknown`, and the agent tells the user so. With the demo model, the reply reads: "The tool call's outcome is unknown: it stopped without returning a result, so it may or may not have taken effect. It will not be retried automatically." Your application then checks the order system before anyone tries again. [Reconcile outcome_unknown](/agent-frameworks/tool-calls#reconcile-outcome-unknown) shows how.

You have run your first durable agent. Its Worker went away in the middle of a conversation, and the session lost nothing. The read that was cut off ran again, and the write that was cut off was reported as `outcome_unknown` instead of running twice.

### Wire the session into your app {#wire-it-into-your-app}

The change to your agent is small: the wrap in step 2. The rest is hosting code that every Dex app has, a Worker that runs Steps and a Client that calls them. This function is the smallest host. It runs one Worker and one Client in your process, starts a session, sends one message, and returns the session after the turn:

```python
"""The smallest host for a durable agent: one Worker, one Client, one turn."""

from __future__ import annotations

import asyncio

from dex import (
    AsyncClient,
    AsyncWorker,
    BlobCacheConfig,
    ClientOptions,
    Registry,
    WorkerOptions,
    open_blob_cache,
)
from dex_agents import AgentSessionClient, AgentSessionFlow, AgentSessionStatus, AgentSnapshot


async def ask_agent(
    session_flow: AgentSessionFlow,
    session_id: str,
    message: str,
    server_address: str = "127.0.0.1:8801",
    blob_cache_dir: str = ".dex-blob-cache",
) -> AgentSnapshot:
    """Starts a session, sends one message, and returns the session after the turn."""
    registry = Registry((session_flow,), allow_async_handlers=True)
    cache = open_blob_cache(BlobCacheConfig(blob_cache_dir, 1 << 30))
    worker = AsyncWorker(registry, cache, WorkerOptions(server_address=server_address))
    client = AsyncClient(registry, cache, ClientOptions(server_address=server_address))
    worker_task = asyncio.create_task(worker.start())
    try:
        await worker.wait_pull_registered(timeout=30)
        sessions = AgentSessionClient(client, session_flow)
        await sessions.start_session(session_id)
        await sessions.send_user_message(session_id, message)
        while True:
            snapshot = await sessions.get_agent_snapshot(session_id)
            state = snapshot.state
            if state and state.turn_count >= 1:
                if state.status == AgentSessionStatus.WAITING_FOR_USER_MESSAGE:
                    return snapshot
            if state and state.status == AgentSessionStatus.FAILED:
                raise RuntimeError(f"the session failed: {state.last_turn_error}")
            await asyncio.sleep(0.5)
    finally:
        await client.close()
        await worker.close()
        await worker_task
        cache.close()
```

```ts
// The smallest host for a durable agent: one Worker, one Client, one turn.

import { Client, Registry, Worker, openBlobCache } from "@superdurable/dex";
import {
  readAgentSnapshot,
  sendAgentUserMessage,
  startAgentSession,
  type AgentSessionFlow,
  type AgentSnapshot,
} from "@superdurable/dex-agents";

/** Starts a session, sends one message, and returns the session after the turn. */
export async function askAgent(
  flow: AgentSessionFlow,
  sessionId: string,
  message: string,
  serverAddress = "127.0.0.1:8801",
  blobCacheDir = ".dex-blob-cache",
): Promise<AgentSnapshot> {
  const registry = new Registry([flow]);
  const blobCache = openBlobCache({ directory: blobCacheDir, maxBytes: 1 << 30 });
  const worker = new Worker(registry, blobCache, { serverAddress });
  const client = new Client(registry, blobCache, { serverAddress });
  try {
    await worker.start();
    await worker.waitPullRegistered({ timeoutMs: 30_000 });
    await startAgentSession(client, flow, sessionId, {});
    await sendAgentUserMessage(client, flow, sessionId, { text: message });
    for (;;) {
      const snapshot = await readAgentSnapshot(client, flow, sessionId);
      const state = snapshot.state;
      if (state?.status === "failed") {
        throw new Error(`the session failed: ${state.lastTurnError ?? "unknown error"}`);
      }
      if (state !== null && state.turnCount >= 1 && state.status === "waiting_for_user_message") {
        return snapshot;
      }
      await new Promise((resolve) => setTimeout(resolve, 500));
    }
  } finally {
    await client.close();
    await worker.close();
    blobCache.close();
  }
}
```

It takes the session Flow that your module's `build_durable_agent` or `buildDurableAgent` returns. A turn that needs an approval waits until your app resolves it; [Approve from your application](/agent-frameworks/approvals#approve-from-your-application) shows how.

A web app splits the same pieces across routes:

1. A **Registry** with your session Flow, a **Worker** that runs its Steps, and a **Client** that calls it, as in the function above. The Worker connects out to Dex, so it needs no open port. Both open a blob cache, a local cache for large values; [Registry and blob cache](/components/application#blob-cache) explains it.
2. A route that starts a session. The session ID is the Flow ID.
3. A route that sends a user message, and one that reads the session snapshot with the agent's reply. To stream the reply as it is written, read the AgentEvents Stream, as [the next section](#web-handler) shows.
4. A route that approves or rejects a waiting tool call. [Approve from your application](/agent-frameworks/approvals#approve-from-your-application) covers it.

The [Order Support Agent](/use-cases/order-support-agent) example has these routes over HTTP, for every framework.

#### What replaces Runner.run in a web handler {#web-handler}

Without Dex, a handler calls the framework, such as `Runner.run`, and waits for the reply. With Dex, the handler queues the message on the session and returns. The reply arrives on the session's [AgentEvents Stream](/reference/agents/event-stream#read-the-stream), which your UI reads as server-sent events. The polling in `ask_agent` above suits scripts and tests. A chat UI reads the stream instead. The [AI Agent](/use-cases/ai-agent) example's routes show both halves:
