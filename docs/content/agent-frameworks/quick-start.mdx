# Agent Quick Start

Run your framework's agent as a durable Dex session, then stop it in the middle of a conversation and watch it carry on. It takes about 10 minutes.

The program starts a session, prints its ID, and prints the agent's reply:

```text
Session openai-agents-quick-start-6792dcbb
Agent: Local demo response: Order 1001: 2 notebooks, shipped.
```

The agent is a small order support agent with two tools. `look_up_order` reads an order, so Dex may retry it. `cancel_order` cancels an order that has not shipped; it is a write, so it runs at most once, and only after a person approves it.

## 2. Approve a write {#approve-a-write}

Run the same command with the message **Cancel order 1002**. The program stops and asks:

```text
cancel_order wants to run with {"order_id":"1002","reason":"requested by the customer"}. Approve? [y/N]
```

The session waits in `AwaitToolApproval`. Type **y**, and the agent cancels the order and replies. [Approvals](/agent-frameworks/approvals) shows how your app reads and answers the waiting call, and how a person approves it in Dex Web.

## 3. Stop the program while the agent waits {#stop-the-worker}

Ask to cancel order 1002 again; each run without `--session-id` starts a new session. When the program asks you to approve, press Ctrl+C. The program, its Worker, and its Client stop, and the session keeps waiting in Dex.

Run the step 1 command again from the same folder, with `--session-id SESSION_ID` in place of the message. A new Worker starts, and the program asks about the same `cancel_order` call. Type **y**. The order is cancelled once, and the model calls before the restart stay done.

## 4. Stop it while a tool runs {#stop-while-a-tool-runs}

A crash in the middle of a tool call is the harder case. The example can slow each tool call down, so you have time to stop it.

1. Put `DEX_ORDER_DESK_TOOL_DELAY_SECONDS=20` in front of the step 1 command and ask about order 1001.
2. Within 20 seconds, kill the program as a crash would. A crash is a kill signal; Ctrl+C lets a running call finish first.

3. Run the program again with `--session-id` and no message. The agent answers with the order.
4. Check how the tool call ran:

```bash
dexcli flow history --all SESSION_ID | jq '.events[]
  | select(.payload.context.stepType == "CallTool")
  | .payload.context | {finalAttempt, failure: .lastFailureInfo.details.detail}'
```

`finalAttempt` is **2**. The first attempt failed when the Worker disconnected, and because `look_up_order` is a read, Dex ran it again on the new Worker. The model call before it ran once.

Now do the same with a write: ask to cancel order 1002 with the delay set, approve it, kill the program within 20 seconds, and run it again with `--session-id`. Dex records `cancel_order` as `outcome_unknown` and runs it no second time, because it is a non-idempotent write. The agent tells the user that the outcome is unknown, and your application checks the order system before anyone tries again. [Reconcile outcome_unknown](/agent-frameworks/tool-calls#reconcile-outcome-unknown) shows how.

## What made it durable {#make-it-durable}

Each framework's example wraps the same agent in a Dex agent session and gives each tool a policy. For these two function tools, that is the only change:

```python
def build_durable_agent(order_desk: OrderDesk, model: str) -> AgentSessionFlow:
    """Returns the same agent as a durable Dex agent session."""

    # Dex passes the tools to the CLI itself and decides when each one runs.
    def build_options(context: ClaudeAgentOptionsContext) -> ClaudeAgentOptions:
        return ClaudeAgentOptions(
            model=model,
            env=build_claude_cli_environment(os.environ),
            system_prompt=ORDER_SUPPORT_INSTRUCTIONS,
            tools=[],
            setting_sources=[],
        )

    return claude_agent_session_flow(
        build_options,
        build_order_tools(order_desk),
        flow_type="ClaudeAgentSDKQuickStart",
        tool_policies={
            "look_up_order": ToolPolicy(ToolEffect.READ),
            "cancel_order": ToolPolicy(ToolEffect.NON_IDEMPOTENT_WRITE),
        },
    )
```

</SdkSnippet>
<SdkSnippet lang="typescript">

```ts
/** Returns the same agent as a durable Dex agent session. Dex passes the tools to the CLI itself. */
export function buildDurableAgent(
  orderDesk: OrderDesk,
  model: string,
  cliEnvironment: Readonly<Record<string, string>>,
): AgentSessionFlow {
  return createClaudeAgentSessionFlow(
    {
      options: { model, systemPrompt: orderSupportInstructions, tools: [], settingSources: [], env: { ...cliEnvironment } },
      customTools: buildOrderTools(orderDesk),
      toolPolicies: {
        look_up_order: { effect: "read" },
        cancel_order: { effect: "non_idempotent_write" },
      },
    },
    "ClaudeAgentSdkQuickStart",
  );
}
```

LangChain also adds `DurableToolCallMiddleware`, which runs each tool call as its own Step. The Claude Agent SDK takes the tools in a list next to the options, so Dex runs each one itself. Tools the framework runs itself, such as MCP servers and hosted tools, need the changes in your framework's [Limits](/agent-frameworks/sessions#limits). The session runs in a Worker and is driven by a Client; [Add Dex to Your Agent](/agent-frameworks/add-to-your-agent#wire-it-into-your-app) shows that host code.

## Start from one file {#start-in-an-empty-folder}

The one-file starter is the OpenAI Agents SDK agent with its Worker and Client in one Python file. It uses published packages only and calls a real model, so set `OPENAI_API_KEY`. With `dexcli dev` running:

```bash
mkdir order-agent && cd order-agent
python3 -m venv .venv && source .venv/bin/activate
pip install dex-agents-openai-agents==0.5.0 dex-python-sdk==1.45.0
curl -fsSLO https://raw.githubusercontent.com/superdurable/dex/main/examples/python/agent-starter/agent.py
python agent.py "Cancel order 1002, it was a mistake"
```

The program asks **Approve cancel_order? [y/N]** before the write runs. [agent.py](https://github.com/superdurable/dex/blob/main/examples/python/agent-starter/agent.py) is the whole program.
