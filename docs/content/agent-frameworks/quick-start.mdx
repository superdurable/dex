# Agent Quick Start

Run an agent built with your framework as a durable Dex session, then stop it in the middle of a conversation and watch it carry on. It takes about 10 minutes.

Building a new agent without a framework? Start with the [Built-in Agent Loop](/agent-frameworks/built-in-agent-loop).

## What you will build {#what-you-will-build}

A small order support agent. It has two tools on an in-memory order desk:

- **look_up_order** reads an order. It is a read, so Dex may retry it.
- **cancel_order** cancels an order that has not shipped. It is a write, so it runs at most once, and only after a person approves it.

You see what Dex adds to a plain agent, then run it from the command line and ask it to cancel an order. While the cancellation waits for your approval, you stop the program and start it again. Then you approve the call and check what ran. Last, you kill the program in the middle of a tool call and see what Dex runs again.

## Before you start {#before-you-start}

- **dexcli**, installed as [Run Locally](/components/run-locally) shows.
- Git, to get the example, and **jq** for one check in step 5.
- **Python 3.11 or later with uv**, or **Node.js 22 or later with npm**, depending on your framework.
- For Python, nothing else: Google ADK, LangChain, OpenAI Agents SDK, and Pydantic AI run on a local demo model that needs no API key. The Claude Agent SDK and every TypeScript framework call a real model, so they need your provider key, such as **ANTHROPIC_API_KEY** or **OPENAI_API_KEY**, in the environment.

## 1. Get the example {#get-the-example}

Clone the Dex repository and start Dex in a first terminal:

```bash
git clone https://github.com/superdurable/dex.git
cd dex
dexcli dev
```

Keep **dexcli dev** running. Open a second terminal in the **dex** folder for the next steps.

## 2. Make your agent durable {#make-it-durable}

Each framework's example file has two functions. The first is the agent as the framework alone writes it, with the two tools. The second wraps the same agent in a Dex agent session and gives each tool a policy. That is the only change to the agent.

**look_up_order** is a read. **cancel_order** is a non-idempotent write, so it runs at most once, and by default it waits for approval. [Require approval](/agent-frameworks/tool-calls#require-approval) explains the default.

Some adapters need one more thing. LangChain takes a factory and adds **DurableToolCallMiddleware**, which runs each tool call as its own Step. The Claude Agent SDK takes the tools in a list next to the options, so Dex can run each one itself.

The session also needs a Worker and a Client, as any Dex application does. The example creates both in one process. The Worker runs the session's Steps, and the Client starts the session and talks to it:

```ts
  public static async start(flow: AgentSessionFlow, serverAddress: string, blobCacheDir: string): Promise<QuickStartApp> {
    const registry = new Registry([flow]);
    const blobCache = openBlobCache({ directory: blobCacheDir, maxBytes: 1 << 30 });
    const worker = new Worker(registry, blobCache, { serverAddress, pull: { maxConcurrentTasks: 16 } });
    const client = new Client(registry, blobCache, { serverAddress });
    const app = new QuickStartApp(flow, client, worker, blobCache);
    try {
      await worker.start();
      await worker.waitPullRegistered({ timeoutMs: pullRegistrationTimeoutMs });
    } catch (failure) {
      await app.close();
      throw failure;
    }
    return app;
  }
```

The program starts a session and prints its ID. It sends the message and prints the agent's reply:

```text
Session openai-agents-quick-start-6792dcbb
Agent: Local demo response: Order 1001: 2 notebooks, shipped.
```

**look_up_order** is a read, so it ran without asking you. Now ask the agent to cancel an order. Use the same command with the message **Cancel order 1002**. This time the program stops and asks:

```text
cancel_order wants to run with {"order_id":"1002","reason":"requested by the customer"}. Approve? [y/N]
```

## 4. Stop the program while the agent waits {#stop-the-worker}

Ask to cancel an order again, in a new session. When the program asks you to approve, press Ctrl+C instead. The program, its Worker, and its Client are gone, and the program prints how to resume. The session keeps waiting in Dex, and the wait holds no Worker.

Run the program again with the session ID it printed, and no message:

```bash
uv run --frozen python -m agent_harness_examples.quick_start openai-agents --session-id SESSION_ID
```

Use your framework's name, and **npm run agent-quick-start --** for TypeScript. A new Worker starts, and the program asks about the same **cancel_order** call. Type **y**. The order is cancelled once. The model calls and the look-up before the restart did not run again.

A person can also approve the call in Dex Web instead of in your program. [Approvals](/agent-frameworks/approvals) shows how.

## 5. Stop it while a tool runs {#stop-while-a-tool-runs}

Step 4 stopped the program while nothing ran. A crash in the middle of a tool call is the harder case. The example can slow each tool call down, so you have time to stop it.

1. Ask about an order again, with a 20-second delay on each tool call. Set **DEX_ORDER_DESK_TOOL_DELAY_SECONDS=20** in front of the step 3 command.
2. Within 20 seconds, kill the program as a crash would. Ctrl+C is not a crash: it lets a running call finish first.

3. Run the program again with **--session-id** and no message. The agent answers with the order.
4. Check how the tool call ran:

```bash
  | select(.payload.context.stepType == "CallTool")
```

**finalAttempt** is **2**. The first attempt failed because the Worker disconnected. **look_up_order** is a read, so Dex ran it again on the new Worker. The model call before it did not run again.

Now try a write. Ask to cancel order 1002 with the delay set, approve it, and kill the program within 20 seconds. Then run it again with **--session-id**.

**cancel_order** is a non-idempotent write, so Dex does not run it a second time. The call records **outcome_unknown**, and the agent tells the user so. With the demo model, the reply reads: "The tool call's outcome is unknown: it stopped without returning a result, so it may or may not have taken effect. It will not be retried automatically." Your application then checks the order system before anyone tries again. [Reconcile outcome_unknown](/agent-frameworks/tool-calls#reconcile-outcome-unknown) shows how.

You have run your first durable agent. Its Worker went away in the middle of a conversation, and the session lost nothing and repeated nothing.

### Wire the session into your app {#wire-it-into-your-app}

The quick start program shows the pieces your app needs, in one process. A web app splits them across routes:

1. A **Registry** with your session Flow, a **Worker** that runs its Steps, and a **Client** that calls it, as in step 2. The Worker connects out to Dex, so it needs no open port. Both open a blob cache, a local cache for large values; [Registry and blob cache](/components/application#blob-cache) explains it.
2. A route that starts a session. The session ID is the Flow ID.
3. A route that sends a user message, and one that reads the session snapshot with the agent's reply. To stream the reply as it is written, read the [AgentEvents Stream](/reference/agents/event-stream#read-the-stream).
4. A route that approves or rejects a waiting tool call. [Approve from your application](/agent-frameworks/approvals#approve-from-your-application) covers it.

The [Order Support Agent](/use-cases/order-support-agent) example has these routes over HTTP, for every framework.
