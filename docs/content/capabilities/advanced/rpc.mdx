# RPC for external read + write

## Why you need it

External callers need to read durable state, mutate it, and optionally move the Flow — atomically from the caller’s point of view.

## Code examples

Choose an SDK (preference is sticky in this browser; default Python).

    unblock.publish(context, message)
    return RPCResult(output="ok")

Declare `@rpc` / RPC methods on the Flow; invoke via client `InvokeRPC`.

## How Dex implements it

On Temporal, the server runs InvokeRPC as one synchronous Workflow Update,
applies Attribute locks when requested, and commits Attribute/channel/Step
effects with the result. Once terminal finalization begins, the Update validator
rejects new RPCs. Large input and output values are stored in the configured
Blob Store and hydrated when displayed or returned through an SDK.

Cadence has no synchronous Update. It retains the query, Worker call, and
optional signal implementation for non-locking RPCs.

## Traditional workarounds

Without Dex: separate read APIs, write APIs, and “signal” endpoints with careful locking — often inconsistent under concurrency.
