# Metrics

When the Prometheus reporter is enabled, Dex Server exports the metric catalog
on this page. These are the final metric names. A series is absent until the
corresponding operation occurs, and optional components export their metrics
only when enabled.

A duration timer records elapsed time. Its unit is seconds in Prometheus; the
reporter exposes it as a histogram or summary according to its configuration.
All other types below are Prometheus counters or gauges.

## Labels and cardinality

Server-generated series carry these common labels where the runtime supplies
them:

| Label | Values and constraint |
| --- | --- |
| **namespace** | The configured execution namespace. Keep the number of namespaces small. |
| **client_name** | The fixed runtime client identifier. It has one bounded value per deployed runtime. |
| **worker_type** | The bounded worker category, or **none** when no worker applies. |
| **workflow_type** | A registered workflow implementation name, or **none**. Do not use an execution ID as a type name. |
| **activity_type** | A registered activity implementation name, or **none**. |
| **task_queue** | A configured task-queue name, or **none**. Use a bounded set of queue names. |

Dex adds one of the following semantic label sets to Flow and Step metrics:

| Metric subject | Additional labels |
| --- | --- |
| Application Flow | **flow_type** |
| Synchronous or asynchronous Step | **flow_type**, **step_type** |
| Synchronous or asynchronous SubFlow start | **flow_type**, **sub_flow_type** |
| Synchronous or asynchronous Worker RPC | **flow_type**, **rpc_name** |
| Synchronous or asynchronous system Step | **flow_type** |

For a Dex semantic label, **none** means that the metric family has that label
but no value applies to this observation. For example, a system Step outside an
application Flow has **flow_type="none"**. It is not an unknown Flow type.

The catalog also uses these bounded labels:

| Label | Values and constraint |
| --- | --- |
| **poller_type** | One of **workflow_task**, **workflow_sticky_task**, **activity_task**, or **nexus_task**. |
| **operation** | A stable server RPC operation name. Never place request IDs or user input here. |
| **status_code** | A finite gRPC status code such as **UNAVAILABLE** or **INTERNAL**. It appears on failed request metrics. |
| **failure_reason** and **cause** | Bounded runtime reason values. Do not copy an error message into either label. |
| **nexus_service** and **nexus_operation** | Configured Nexus names. Keep both sets bounded. |
| **prefix** | The configured Blob Store namespace or domain. |
| **step_method** | **wait_for** or **execute**. |
| **reason** | A bounded Step-stream write failure reason. |

Do not add Flow IDs, Run IDs, Step execution IDs, customer IDs, request IDs,
payload values, or error text as metric labels. They create unbounded
Prometheus cardinality.

## Flow results

Application Flow metrics have the common labels plus **flow_type**. System Flow
metrics have the common labels and no **flow_type** label.

| Final metric names | Type | Meaning |
| --- | --- | --- |
| **dex_flow_completed**<br/>**dex_sys_flow_completed** | Counter | Flows that completed successfully. |
| **dex_flow_canceled**<br/>**dex_sys_flow_canceled** | Counter | Flows that closed as canceled. |
| **dex_flow_failed**<br/>**dex_sys_flow_failed** | Counter | Flows that closed as failed. |

| **dex_flow_endtoend_latency**<br/>**dex_sys_flow_endtoend_latency** | Duration timer, seconds | Time from Flow-run start to close. |

## Queries and alert directions

Use counters for portable dashboards and alerts. The following examples do not
depend on a histogram or summary configuration.

Failed application Flows by Flow type:

~~~promql
sum(rate(dex_flow_failed[5m])) by (flow_type)
~~~

Failed synchronous Steps by Flow and Step type:

~~~promql
sum(rate(dex_sync_step_execution_failed[5m])) by (flow_type, step_type)
~~~

Failed Worker RPC calls:

~~~promql
sum(rate(dex_sync_invoke_rpc_execution_failed[5m])) by (flow_type, rpc_name)
~~~

Step-stream write failures:

~~~promql
sum(rate(dex_step_stream_write_failure[5m])) by (flow_type, step_type, reason)
~~~

Blob Store read and write errors:

~~~promql
sum(rate(read_object_error[5m])) by (prefix)
+ sum(rate(write_object_error[5m])) by (prefix)
~~~

Alert on a sustained increase in **dex_flow_failed**, Step failure counters,
request failures, Blob Store errors, or Step-stream write failures. Pair an
alert with a bounded **flow_type**, **step_type**, **rpc_name**, **operation**,
or **prefix** breakdown so the responder can identify the affected service
without querying high-cardinality labels.
