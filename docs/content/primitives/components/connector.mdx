# Connector

A **Connector** is a Dex component that integrates a Flow with an
external provider, such as an email, payment, or news service. It packages typed operations, event ingress,
authorization, and optional configuration UI. Provider credentials stay out of
durable Flow state.

Official Connectors are released separately from Dex. Browse the
[Connector directory](https://connectors.superdurable.io/) before you write
provider integration code yourself.

## Capabilities

A Connector can expose five capabilities:

- **Auth** authorizes a logical connection and keeps credentials outside the
  Flow.
- **Trigger** converts a provider event into a typed event that can start a Flow
  or invoke a typed RPC.
- **Query** reads provider state from a Connector Step.
- **Mutation** changes provider state with explicit idempotency and uncertainty
  handling.
- **UI** supplies reusable configuration units that Dex Web composes for a Step
  or Trigger binding.

A provider module exposes only the capabilities it needs. Applications use the
generated types for that exact module release.

## Operations are Connector Steps

An operation-specific factory creates a Connector Step. The application maps
the current Step input to the provider input. It connects each required result
branch to another Step. The provider call runs in **Execute**, so it gets Dex
retries, timeouts, durability, and recovery like any other
[Step](/primitives/step).

A Connector result contains the operation output, a receipt, the selected
branch, and a safe failure classification when one exists. It does not forward
the previous Step input. Keep business context in an
[Attribute](/primitives/attribute), or pass it through an application Step
before the Connector.

Queries read provider state. Mutations change it with a stable idempotency key
derived from the Step execution. When a mutation's outcome is unknown, the
Connector selects an uncertainty branch. The Flow can then query and reconcile
instead of sending the mutation again blindly.

Only the happy-path branch must be connected. An optional branch can stay
unwired. If the Connector selects an unwired branch, the Flow fails, and the
provider outcome stays visible for recovery.

## Triggers start or update Flows

A Connector Trigger is a long-running event source outside the Flow. It keeps
the provider event ID and occurrence time. It delivers each event at least once
to a target that the application owns.

The application supplies the final filter, resolves the Flow ID, and maps the
provider event to a typed input. It chooses whether the event starts a Flow or
invokes a typed [RPC](/primitives/rpc) on an existing Flow. A Flow start reuses
the provider event ID as its request identity, so a repeated event does not
start a second Flow. An RPC target handles duplicates in its own bounded
state.

Local Trigger runners persist a matched event before they acknowledge it to
the provider. They replay pending deliveries after a restart.

## Connections and configuration

Flow definitions refer to a logical connection name, not to credentials. In
local development, Dex Web lists those names under **Connectors**. It verifies
the exact official module release before it writes connection, operation, or
Trigger-binding configuration.

A Connector UI runs in an opaque-origin sandboxed iframe. Dex Web runs the provider commands
that the Connector release declares. Stored credentials never enter the iframe,
Flow input, Attributes, results, receipts, Streams, logs, or generated
artifacts.

## Languages

Connectors support Go, Python, and TypeScript. Java and Rust do not support
Connectors yet. Each language package implements only the operations and
Triggers that the Connector lists for that language. Use the language filter in
the [Connector directory](https://connectors.superdurable.io/) to see what each
Connector offers.

Go packages are the Go module of each Connector. Python packages are on PyPI as
**dex-connector-&lt;slug&gt;**. TypeScript packages are on npm as
**@superdurable/connector-&lt;slug&gt;**. Every Python and TypeScript package
replays the Go-verified provider scenarios. Runnable examples are under
**connectors/&lt;directory&gt;/&lt;language&gt;/examples/** in the
[Dex Connectors Library](https://github.com/superdurable/dex-connectors-library).
If you need another language,
[open a Dex Connectors Library issue](https://github.com/superdurable/dex-connectors-library/issues/new).

## Use or contribute a Connector

The [Dex Connectors Library](https://github.com/superdurable/dex-connectors-library)
contains manifests, generated APIs, provider implementations, UI units, and
runnable examples.

Use the [Dex SDK skill](../../build-with-ai/dex-developer-skill/dex-sdk.mdx) when an
application consumes a released Connector. Use the
[Dex Connector Contributor skill](../../build-with-ai/dex-developer-skill/dex-connector-contributor.mdx)
to add or modify an official Connector, operation, Trigger, or UI unit.

## How it fits with the other components

Official Connectors are released separately from Dex. Your
[application](/primitives/components/application) imports a Connector package.
It runs the Connector's operations as Connector Steps. A Trigger turns a
provider event into a Flow start or an RPC call. Credentials stay outside
durable Flow state.

## Find a Connector

Browse the [Connector catalog](https://connectors.superdurable.io/). It lists the
released Connectors, their operations, and their language support. The catalog
is the reference for each Connector. The
[Dex Connectors Library](https://github.com/superdurable/dex-connectors-library)
holds their source and runnable examples.

## Set up Connectors locally

For local development, [Dex Web](/primitives/components/web) configures
Connector accounts and Trigger bindings for a Go application. It does this only
in **dexcli dev**.

1. Start **dexcli dev** with your Flow Definition Graph directory.
2. Open the **Connectors** page in Dex Web and configure each account.
3. Start your application with the connection file that Dex Web shows.

The connection file holds plaintext secrets for local use only. Do not commit
it or use it in production.

[Local Connector setup](/reference/web/local-connector-setup) describes each step
and its settings.
