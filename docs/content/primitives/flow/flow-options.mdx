# Flow options

Dex allows you to customize the behavior of a Flow execution.

- **StartFlowOptions** apply when a client starts a Flow (or SubFlow). They are immutable after start.
  - They control timeout, ID reuse, cron schedule, initial Attributes, request idempotency, and optional config overrides for that execution.
- **FlowConfig** provide runtime behavior. They are mutable after start.
  - Step durability defaults, Worker routing, active-Step search indexing, continue-as-new thresholds, and Attribute Store projection targets.

## StartFlowOptions {#start-flow-options}

| Field | Purpose                                                                |
|-------|------------------------------------------------------------------------|
| **Timeout** | Flow timeout. Omit it or set zero to disable it.                       |
| **TimeoutPolicy** | What happens when the flow timeout fires.                              |
| **IDReusePolicy** | How to reuse existing Flow ID to start                                 |
| **RequestID** | Idempotency key for retrying one start request.                        |
| **AlreadyStartedOptions** | How to handle an already-started Flow.                                 |
| **CronSchedule** | Cron expression for recurring starts.                                  |
| **RetryPolicy** | Retry policy for one Flow execution after failure.                     |
| **StartDelay** | Delay before the start Step to run.                   |
| **Attributes** | Initial Attribute values.                            |
| **FlowConfig** | Per-execution Flow configuration |

### Timeout and TimeoutPolicy {#timeout-and-timeout-policy}

**Timeout** is one durable timer for the whole Flow. Set **TimeoutPolicy** only when **Timeout** is positive.

- **FAIL** — fail the Flow with a timeout error. **RetryPolicy** can retry it.
- **CANCEL** — cancel the Flow. It does not retry.
- **HANDLER** — run the Flow timeout handler once.

With a positive **Timeout**, a Dex SDK uses **FAIL** by default. If the Flow has a timeout handler, it uses **HANDLER** instead. **HANDLER** is invalid when the Flow has no handler. A retry starts with a new timeout budget.

Set **TimeoutPolicy** to **HANDLER** to run this code when the timeout fires. This handler records why the Flow ended, then fails it with an application reason.

### Flow ID, RequestID, and AlreadyStartedOptions {#flow-id-request-id-and-already-started}

**IDReusePolicy** says what to do when this Flow ID already exists. **RequestID** says whether this call retries the same start request.

| ID reuse policy | Result |
|-----------------|--------|
| **IDReuseDefault** | Use the Dex Server policy. StartFlow allows reuse when no run is active. |
| **IDReuseAllowIfPreviousFailed** | Reuse the ID only after a failed run. |
| **IDReuseAllowIfNotRunning** | Reuse the ID after any closed run, never while one is active. |
| **IDReuseDisallow** | Never reuse the ID. |
| **IDReuseTerminateIfRunning** | Stop the active run, then start the replacement. |

Use a stable **RequestID** if the caller may retry after losing the StartFlow response. Retry with the same Flow ID, start input, options, and RequestID. With **AlreadyStartedOptions.IgnoreError**, Dex returns the existing Run ID only when that Flow started with the same RequestID. A different RequestID is still an already-started error. This option does not attach to an unrelated Flow.

### RetryPolicy and CronSchedule {#retry-policy-and-cron-schedule}

**RetryPolicy** retries one Flow execution after it fails. **MaximumAttempts** includes the first execution. **InitialInterval**, **BackoffCoefficient**, and **MaximumInterval** set the exponential backoff. A **FAIL** timeout can use this retry policy. A **CANCEL** timeout cannot.

**CronSchedule** asks the configured backend to start new executions on a schedule. It is not Flow retry. Retry recovers one failed execution. Cron creates later executions. The backend decides what happens to overlapping or missed runs. See the [cron schedule pattern](/design-patterns/cron) before using it in production.

### StartDelay {#start-delay}

**StartDelay** accepts the Flow start now, then waits before the start Step can run. Use it for a one-off delay, for example, wait five minutes before processing a new order. It does not repeat. Use **CronSchedule** for recurring work.

### Attributes {#attributes}

**Attributes** write durable state before the start Step runs. Each value must match an Attribute or Attribute map in the Flow persistence schema. An Attribute map also needs its instance key. Dex rejects undeclared names, duplicate physical keys, and definitions that do not match the registered map, index, or synchronization settings.

Use the SDK's **InitialAttribute** and Attribute-map helper. The start Step reads these values like any other Attribute.

## FlowConfig {#flow-config}

Use **ConfigOverride** in **StartFlowOptions** to change the initial configuration for one Flow. It changes only the fields you provide. It does not replace the whole **FlowConfig**.

At start, Dex applies the supplied fields over the Dex Server defaults. Omitted fields keep their default values.

| Field | Behavior |
|-------|----------|
| **ActiveStepSearchMode** | Index every active Step, only Steps that ran **WaitFor**, or no active Steps. The default indexes Steps with **WaitFor**. |
| **ContinueAsNewThreshold** | Continue as new after this many tracked events. Zero turns it off. |
| **ContinueAsNewPageSizeBytes** | Limit each page of state carried into continue-as-new. Zero uses 1 MiB. |
| **StepDurability** | Default durability for Step writes. A Step override wins. Recovery uses synchronous durability unless you override it. |
| **WorkerTarget** | WorkerService endpoint for later Step and RPC calls. Use it to move later work to a new Worker. |
| **AttributeStoreName** | Dex Server Attribute Store for Attributes that opt in to asynchronous projection. An empty value turns off later projections. |

### Update FlowConfig with a Client {#update-flow-config-with-a-client}

Call **UpdateFlowConfig** while the Flow is active. Send only the fields you want to change. The change applies to later Flow decisions. Dex does not recall work it already dispatched.
