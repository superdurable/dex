# Flow Basics

A **Flow** is the top-level component that you register with Dex.

It defines the [Steps](/primitives/step) that run in the background, the [Attributes](/primitives/attribute) and [Channels](/primitives/channel) that persist state, and the [RPCs](/primitives/rpc) that provide durable communication.

## Implement a Flow {#implement-a-flow}

You define a Flow by implementing the **Flow** interface.

Most SDKs derive **FlowType** from the struct/class type name unless you override it.

A Flow implementation mainly contains:

1. **Steps** — the start Step and other Steps the Flow runs.
2. **Persistence schema** — the Attribute and Channel the Flow reads or writes.
3. **RPC handlers** — methods that the Flow may invoke.

	return dex.PersistenceSchema{
		Attributes: []dex.AttributeDef{Status},
		Channels:   []dex.ChannelDef{Notify},
	}

func (*ExampleFlow) Describe(ctx dex.Context, _ dex.None) (*dex.RPCResult[string], error) {
	value, err := Status.Get(ctx)
	if err != nil {
		return nil, err
	}
	return &dex.RPCResult[string]{Output: value}, nil
}

impl Flow for ExampleFlow {
    type StartInput = i32;

    fn steps(&self) -> StepList<'_, Self::StartInput> {
        StepList::start(&self.example).and(&self.finish)
    }

    fn persistence(&self) -> PersistenceSchema {
        PersistenceSchema::new()
            .attribute(&status())
            .channel(&notify())
    }

    fn rpcs(&self) -> RpcList<Self> {
        RpcList::new().function(DESCRIBE, Self::describe)
    }

## Identifiers {#identifiers}

Dex uses these identifiers throughout its APIs and documentation.

First, when mentioning **Flow**,  depending on the context, it usually means a Flow definition identified by its **FlowType**, or a Flow run instance identified by its **Flow ID**.

| Identifier | Who sets it | Meaning |
|----------|-------------|---------|
| **FlowType** | Application (via Flow implementation) | Stable type name Dex uses to route Worker calls and search results. |
| **Flow ID** | Application client on start           | Business identity for one logical Flow. Reuse policy controls whether a new run may replace or attach to an existing ID. |
| **Run ID** | Dex Server | Identity of one run attempt. Time travel and continue-as-new start a fresh Run ID while optionally keeping the same Flow ID. |
| **StepType** | Application (via Step implementation) | Stable name for a Step definition inside the Flow. |
| **StepExecutionID** | Dex Server | One execution instance of a Step type, formatted as **StepType-Number**. |


## Steps {#steps}

**GetSteps** / **get_steps** / **steps** registers one start Step and every other Step type the Flow may reach through [StepDecision](/primitives/step/basic#stepdecision-movements) movements. The start Step input type is also the Flow start input.

An empty Step list, or a list with no start Step, is valid when the Flow is driven entirely by RPCs that later move into Steps.

See [Step basics](/primitives/step/basic) for **WaitFor**, **Execute**, and default Step options.

## Persistence schema {#persistence-schema}

The persistence schema lists every [Attribute](/primitives/attribute) and [Channel](/primitives/channel) used from Steps or RPCs. Dex rejects reads and writes to names that are not declared.

## RPC handlers {#rpc-handlers}

Dex registers RPC methods under their method names (or explicit RPC names in Rust). Clients call them with [InvokeRPC](/primitives/rpc); Dex then dispatches the call to the Worker.
