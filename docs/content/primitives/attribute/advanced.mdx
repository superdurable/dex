# Attribute advanced

This page covers the parts of Attribute that change how a Flow is operated: search indexes, projecting state to an application database, and serializing concurrent changes.

## Indexed Attributes {#indexed-attributes}

An Attribute is not searchable unless you give its definition an **AttributeIndex**. Dex registers the index with the configured backend when the Worker starts, then updates it whenever that Attribute changes. You can use the field in **SearchFlows** queries.

Choose the index type from the value you plan to write:

| Index type | Value |
| --- | --- |
| **KEYWORD** | One exact string. |
| **FULL_TEXT** | Text for tokenized search. |
| **KEYWORD_ARRAY** | A list of exact strings. |
| **INT**, **DOUBLE**, **BOOL** | The corresponding scalar value. |
| **DATETIME** | A date and time value. |

The index type is part of the Attribute contract. Do not write a different shape later. A singleton Attribute uses its Attribute name as the index field unless you set an explicit index key. An indexed **AttributeMap** must use an explicit index key because all of its dynamic instances share one search field.

An index is for finding Flows. It is not a second source of truth and is not a substitute for **GetAttributes** when you need the current durable value.

## Attribute Store projection {#attribute-store-projection}

Some applications need the same Flow state in their existing MySQL or PostgreSQL read model. Dex can asynchronously project selected Attribute writes to a Server-configured **Attribute Store**.

There are three parts:

1. The Server configures a named Attribute Store and the destination table.
2. The Flow selects that name through **FlowConfig**. Set it in **StartFlowOptions** for a new Flow or with **UpdateFlowConfig** for an active Flow.
3. Each Attribute or AttributeMap definition explicitly opts in to **SyncToAttributeStore** or its SDK equivalent.

When all three are present, initial Attribute values and writes from Steps, RPCs, and Clients are projected. The Flow Attribute remains authoritative. The SQL row is a latest-state projection: the write is asynchronous, a projection failure does not roll back the Flow write, and Dex does not backfill missed writes. Deleting a synced Attribute projects SQL **NULL** when that column allows it.

Changing the Attribute Store target changes future writes. Mutations already queued keep the target that was selected when Dex accepted them.

This is a good fit for a read model, reporting table, or an entity that is orchestrated by one long-running Flow. It is not the right choice when the external update must be in the same business transaction as another database write.

See [Entity Store](/design-patterns/entity-store) for a complete pattern, and [Custom Attribute Store operations](/production/attribute-store) for table requirements, types, retries, and shutdown behavior.

## Locking {#locking}

One Attribute write is durable with its Step or RPC result. That alone does not make a read-modify-write sequence safe. Two concurrent handlers can both read the same old value and then write different results.

Declare an Attribute lock on the Step method or RPC that performs that sequence. Dex acquires the requested locks together before invoking the handler, then releases them when that handler invocation finishes. A singleton Attribute has one lock; an AttributeMap lock is scoped to one map instance.

**WaitFor** and **Execute** have separate lock options. A lock held by **WaitFor** is released before the Flow starts waiting, and is not held until **Execute** later runs. Add the lock to the method that actually reads and changes the value.

Keep the locked set small. Locking an unrelated Attribute reduces concurrency. Missing a conflicting Attribute leaves a race. Client **GetAttributes** followed by **SetAttributes** is not a locked read-modify-write operation; put that operation in an RPC when it must be serialized.

RPC Attribute locking uses Temporal synchronous Updates and is unavailable with Cadence. Step Attribute locks work through normal Step execution.
