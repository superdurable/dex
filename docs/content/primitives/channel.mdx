# Channel

A **Channel** is a durable first-in, first-out (FIFO) queue inside one Flow
execution. Steps and RPCs publish typed messages to it. A Step consumes messages
by waiting on the Channel in **WaitFor**.

A Channel is scoped to one Flow execution. Messages never cross between Flow
executions.

<ChannelScopeDiagram />

## When to use a Channel

Use a Channel for events that a Step waits for, such as an approval, a user
reply, or a new work item. Use an [Attribute](/primitives/attribute) for state
that you overwrite and read many times. Use a [Stream](/primitives/stream) for
live progress that a user can afford to lose.

## Guarantees

- Dex stores every message durably with the Flow.
- Messages stay in arrival order.
- One wait consumes a message, once. Dex does not copy it to other waiting
  Steps.
- A message can arrive before a Step starts waiting. Dex keeps it until a later
  wait consumes it.
- A publication commits together with the Step or RPC result that made it.

## Define, publish, and wait {#persistence-schema}

A Channel has a stable name and a message type. Define it and add it to the
Flow persistence schema.

In this example, the start Step waits for one message on the
**ApprovalMessages** Channel, or for a Timer. The
**publishApprovalMessage** RPC publishes the approval.

var ApprovalMessages = dex.DefineChannel[string]("ApprovalMessages")

func (channelWait) WaitFor(_ dex.Context, input int) (*dex.Wait, error) {
	return dex.AnyOf(
		ApprovalMessages.ForOne(),
		dex.Timer(time.Duration(input)*time.Second),
	), nil
}

func (channelWait) Execute(ctx dex.Context, _ int) (*dex.StepDecision, error) {
	if ctx.HasTimerFired() {
		return dex.GracefulComplete("approval timed out"), nil
	}
	approvalMessageValues, err := ApprovalMessages.GetConditionResults(ctx)
	if err != nil {
		return nil, err
	}
	return dex.GracefulComplete(approvalMessageValues[0]), nil
}

func (*ChannelFlow) PublishApprovalMessage(ctx dex.Context, _ dex.None) (*dex.RPCResult[dex.None], error) {
	if err := ApprovalMessages.Publish(ctx, "approved"); err != nil {
		return nil, err
	}
	return &dex.RPCResult[dex.None]{}, nil
}

impl ChannelFlow {

        Ok(Wait::any_of([

        }

    }

## Wait and consume {#wait-and-consume}

A Channel condition in **WaitFor** waits until enough messages are queued. Dex
then removes the selected messages in FIFO order and passes them to **Execute**
as Channel results.

| Condition | When it proceeds | What it consumes |
| --- | --- | --- |
| **ForOne** | At least one message is queued. | Exactly one message. |
| **ForN** | At least the requested number is queued. | Exactly that number of messages. |
| **AtLeast** | At least the requested number is queued. | Every message currently available. |
| **AtMost** | Immediately, including when the queue is empty. | Up to the requested number of currently queued messages. |
| **AtLeastAtMost** | At least the lower bound is queued. | From the lower bound up to the upper bound of currently queued messages. |

## Publish messages {#publish-messages}

Inside a Step or RPC, publish with the handler **Context**. Code outside a
Worker calls a Flow RPC that publishes. This keeps validation, authorization,
and related state changes inside the Flow.

## Manage pending messages {#manage-pending-messages}

Each message gets an ID when Dex accepts it. A Step or RPC can load the pending
messages, read them in FIFO order, and delete one by ID. Reading does not
consume a message. Other Steps and RPCs can change the queue while a handler
runs, so a loaded list can be stale.

Deleting a message that is gone is a no-op, except in a transactional RPC. A
transactional RPC fails instead and commits nothing. See
[Pending messages](/reference/server/runtime-data#manage-pending-messages).

## ChannelMap {#channelmap}

Use a **ChannelMap** when one Flow needs many independent queues, such as one
per order, customer, or job. A ChannelMap has one name and one message type.
Each instance key has its own FIFO queue.
