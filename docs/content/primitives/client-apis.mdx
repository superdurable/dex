# Client

**Client** is how application code outside a Worker talks to Dex Server.

The Client starts a Flow, sends it external input, waits for it, reads its state, and controls it. It does not call a Step directly. Dex Server records the operation and sends Step or RPC work to the Worker when needed.

## Start a Flow

**StartFlow** takes a registered Flow, a business **Flow ID**, its start input, and **StartFlowOptions**. It returns the **Run ID** after Dex Server accepts the request. It does not wait for the Flow to complete.

The **Flow ID** identifies the logical work, for example **order-123**. Dex Server generates a new **Run ID** for each execution. Retry, time travel, and continue-as-new can create another Run ID while keeping the same Flow ID.

See [Flow options](/primitives/flow/flow-options) for timeout, request idempotency, ID reuse, retry, and initial configuration.

## Send input to an active Flow

There are three ways to send external input:

- **InvokeRPC** calls a registered [RPC](/primitives/rpc) handler on the Worker and returns its output. Use it when the caller needs a response or the Flow needs to read and change state in one handler.
- **PublishToChannel** appends one or more durable messages to a [Channel](/primitives/channel). A waiting Step can consume them later.
- **SetAttribute** writes a registered [Attribute](/primitives/attribute). Use **GetAttribute** to read one. SDKs also provide AttributeMap variants and batch Attribute helpers where appropriate.

An RPC, Channel publish, and Attribute write all require an active Flow. Reading an Attribute also works after the Flow closes.

## Wait for work or state

- **WaitForFlow** waits for terminal Flow status. It returns the status, failure details when present, and Step completion outputs when requested. A long-poll timeout means the Flow is still open; call it again to keep waiting.
- **WaitForStepCompletion** waits for one **StepExecutionID** while the Flow continues. It observes completion but does not return the Step output. A Step execution ID is **StepType-Number**; see [Step basics](/primitives/step/basic).
- **WaitForAttributeEqual** waits until one Attribute, or one AttributeMap instance, equals a string, boolean, integer, or double. It is for an active Flow only.

This lets an HTTP handler return after the work a caller cares about, without polling a separate status database.

## Inspect Flows

- **DescribeFlow** returns the current or latest run's Flow ID, Run ID, Flow type, status, and start time.
- **SearchFlows** returns one page of Flows matching a visibility query. Each entry includes IDs, type, status, timestamps, and indexed Attributes. Pass the returned page token unchanged to get the next page.
- **GetAttribute** reads registered durable state from an existing Flow. It does not require the Flow to be active.

Search is for finding Flow instances. **DescribeFlow** is for one known Flow ID.

## Control a Flow

- **StopFlow** ends an active Flow. Cancel asks it to stop cooperatively, terminate stops it immediately, and fail records an application failure reason.
- **SkipTimer** makes one pending [Timer](/primitives/timer) ready now. Select the Step execution and either the Timer condition ID or its zero-based position in the condition.
- **UpdateFlowConfig** changes selected runtime settings on an active Flow. Send only the fields to change; Dex merges them with the current configuration. See [FlowConfig](/primitives/flow/flow-options#flow-config).
- **TriggerContinueAsNew** asks an active Flow to continue in a new Run ID while keeping its Flow ID.
- **TimeTravel** starts a new Run ID from a selected point in an existing Flow's history. Use it after a code fix when retrying the failed Step is not enough. See [application operations](/production/application-operations).

## Which run receives a call?

The public Client API takes a **Flow ID**, not a Run ID.

| Operation | Flow state |
|---|---|
| **InvokeRPC**, **PublishToChannel**, **SetAttribute**, **WaitForStepCompletion**, **WaitForAttributeEqual**, **StopFlow**, **SkipTimer**, **UpdateFlowConfig**, **TriggerContinueAsNew** | Active Flow required. |
| **GetAttribute**, **DescribeFlow**, **WaitForFlow**, **TimeTravel** | An existing Flow is enough. Dex uses its current or latest run. |
| **SearchFlows** | No Flow ID. It searches Flow runs. |

That is why a Client call normally carries a Flow ID in application code, while the Run ID is useful for a start response, search result, or operator investigation.
