# Client Basics

Client calls are made by your application, not by a Step. The examples below use a **Flow ID** named **order-123**.

## Start a Flow

**StartFlow** creates a Flow execution and returns as soon as Dex Server accepts it. It takes a registered Flow, a business **Flow ID**, the start Step input, and **StartFlowOptions**.

The Flow ID is the identity your application chooses. Dex Server creates the Run ID. See [Flow options](/primitives/flow/flow-options) for timeout, request idempotency, ID reuse, retry, initial Attributes, and configuration overrides.

## Stop a Flow

**StopFlow** closes an active Flow. The default asks it to cancel cooperatively. You can instead terminate it immediately, or fail it with a reason.

<SdkTabs examples={{python: 'examples/python/dex_examples/products/job-post/controller.py', go: 'examples/go/products/job-post/controller.go', java: 'examples/java/src/main/java/io/superdurable/dex/products/jobpost/JobPostingController.java', typescript: 'examples/typescript/src/products/job-post/controller.ts', rust: 'examples/rust/src/products/job_post/controller.rs'}}>
<SdkSnippet lang="python">

```python
await client.stop_flow("order-123", StopFlowOptions(reason="customer cancelled"))
```

</SdkSnippet>
<SdkSnippet lang="go">

```go
err := client.StopFlow(ctx, "order-123", sdk.StopOptions{Reason: "customer cancelled"})
```

</SdkSnippet>
<SdkSnippet lang="java">

```java
client.stopFlow("order-123", new StopFlowOptions(StopType.CANCEL, "customer cancelled"));
```

</SdkSnippet>
<SdkSnippet lang="typescript">

```typescript

```

</SdkSnippet>
<SdkSnippet lang="rust">

```rust
client.stop_flow("order-123", StopFlowOptions::cancel().reason("customer cancelled"))?;
```

</SdkSnippet>
</SdkTabs>

## Invoke an RPC

**InvokeRPC** calls a registered [RPC](/primitives/rpc) handler on an active Flow and returns its result.

<SdkTabs examples={{python: 'examples/python/dex_examples/primitives/rpc/controller.py', go: 'examples/go/primitives/rpc/controller.go', java: 'examples/java/src/main/java/io/superdurable/dex/primitives/rpc/RpcController.java', typescript: 'examples/typescript/src/primitives/rpc/controller.ts', rust: 'examples/rust/src/primitives/rpc/controller.rs'}}>
<SdkSnippet lang="python">

```python
result = await client.invoke_rpc(flow.trigger, "order-123", "approved")
```

</SdkSnippet>
<SdkSnippet lang="go">

```go
var result string
err := client.InvokeRPC(ctx, "order-123", flow.Trigger, "approved", &result)
```

</SdkSnippet>
<SdkSnippet lang="java">

```java
final RpcFlow stub = client.newRpcStub(RpcFlow.class, "order-123");

```

</SdkSnippet>
<SdkSnippet lang="typescript">

```typescript
const result = await client.invokeRPC(rpcFlow.trigger, "order-123", "approved");
```

</SdkSnippet>
<SdkSnippet lang="rust">

```rust
let result = client.invoke_rpc("order-123", TRIGGER_RPC, "approved".to_owned())?;
```

</SdkSnippet>
</SdkTabs>

## Read and write Flow state

Use Flow RPCs as the application boundary for Attribute, AttributeMap, Channel, and ChannelMap state. Define a typed RPC for each command or query, select only the state it needs, then call it with **InvokeRPC**. This keeps authorization, validation, locks, transactions, and state changes inside the Flow.

The Client still provides **WaitForAttributeMatch** as a blocking observation API. Use it when an application must wait for a known scalar Attribute condition rather than read an arbitrary state snapshot.
