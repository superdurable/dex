# server-zd reference

server-zd is a Dex Server whose only runtime dependency is object storage, such
as Amazon S3 or an S3-compatible store. It keeps Flow state in a local store. It
writes every change to object storage before it acknowledges the change. The
local disk is only a cache: a node rebuilds it from the latest snapshot and the
command log in object storage.

server-zd serves the **FlowService**, **WorkerTaskService**, and **AdminService**
APIs. It supports only [pull Workers](/reference/server/0.1.28/workers). It does not
serve [Dex Web](/reference/web/dex-web); run Dex Web as a separate process. For
local development, run **dexcli dev**, which starts both server-zd and Dex Web.
To run one production node on local disk without external object storage, see
[Single node on local disk](/reference/server/0.1.28/configuration#single-node-local).

This reference covers server-zd 0.1. See [Server](/components/server) for how
server-zd fits with the other components.

## Unsupported features

server-zd rejects these options with **INVALID_ARGUMENT**:

- A Flow start delay: **flow_start_delay_seconds** greater than zero. Tracked
  in [issue 995](https://github.com/superdurable/dex/issues/995).
- A Flow-level retry policy: **retry_policy** in the Flow start options. Tracked
  in [issue 996](https://github.com/superdurable/dex/issues/996). Step-level
  retry is supported.

The only Attribute Store is PostgreSQL. Redis is tracked in
[issue 616](https://github.com/superdurable/dex/issues/616).
