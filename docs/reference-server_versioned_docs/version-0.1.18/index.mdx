# server-zd reference

server-zd is a Dex Server whose only runtime dependency is object storage, such
as Amazon S3 or an S3-compatible store. It keeps Flow state in a local store and
commits every write to object storage before it acknowledges the write. The
local disk is only a cache. A node rebuilds it from the latest snapshot and the
command log in object storage.

server-zd serves the **FlowService**, **WorkerTaskService**, and **AdminService** API. It supports
only [pull Workers](/reference/server/workers). Run [Dex Web](/reference/web/dex-web)
as a separate process; server-zd does not serve it. For local development, run
**dexcli dev**, which starts server-zd and Dex Web. This reference covers server-zd
0.1. See [Server](/primitives/components/server) for how server-zd fits with the
other components.

## Unsupported features

server-zd rejects these options with **INVALID_ARGUMENT**:

- A Flow start delay, which is **flow_start_delay_seconds** greater than zero.
  Tracked in [issue 995](https://github.com/superdurable/dex/issues/995).
- A Flow-level retry policy, which is **retry_policy** in the Flow start
  options. Tracked in [issue 996](https://github.com/superdurable/dex/issues/996).
  Step-level retry is supported.

The only Attribute Store is PostgreSQL. Redis is tracked in
[issue 616](https://github.com/superdurable/dex/issues/616).
