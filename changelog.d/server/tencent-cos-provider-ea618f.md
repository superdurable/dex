- **objectStore.provider: tencentCOS** lets **serve** keep its object storage in a Tencent COS bucket through the COS S3-compatible endpoint, such as **https://cos.ap-guangzhou.myqcloud.com**. The server creates objects with AppendObject, so the bucket must be single-AZ, must not use INTELLIGENT_TIERING, and must never have had versioning enabled; startup checks this. Objects that the server replaces, such as the cluster manifest and node leases, are stored as versions that the server manages. COS listings can repeat an earlier listing for a few seconds, so the server finds the newest version with HEAD requests, and **objectStore.versionDiscovery** must be **head**. **objectStore.hardDeleteStore.provider** accepts **tencentCOS** and defaults to it when the primary store uses it. With **tencentCOS**, **localStorage.writeBufferBytes** can be at most 1 GiB, and **commit.maxInFlight** can be at most 32. The server treats an empty object, which COS shows during an append and can keep after an interrupted one, as absent and creates its object over it. A listing request whose truncated pages hold no key after its position for 5 seconds fails as retryable. Snapshot retention deletes a snapshot file only when it knows every snapshot that can use it without a listing, so files of a former owner's snapshots can stay until **snapshot.retainedCount** later snapshots are older than **snapshot.logDeletionDelay**. A run purge deletes the run's referenced hard-delete objects by key and then needs two empty listings 5 seconds apart. Data cannot move between **tencentCOS** and other providers. [Reference](/reference/server/object-storage#tencent-cos).
