- **objectStore.provider: tencentCOS** lets **serve** keep its object storage in a Tencent COS bucket through the COS S3-compatible endpoint, such as **https://cos.ap-guangzhou.myqcloud.com**. The server creates objects with AppendObject, so the bucket must be single-AZ, must not use INTELLIGENT_TIERING, and must never have had versioning enabled; startup checks this. Objects that the server replaces, such as the cluster manifest and node leases, are stored as versions that the server manages. COS listings can repeat an earlier listing for a few seconds, so the server finds the newest version with HEAD requests, and **objectStore.versionDiscovery** must be **head**. **objectStore.hardDeleteStore.provider** accepts **tencentCOS** and defaults to it when the primary store uses it. With **tencentCOS**, **localStorage.writeBufferBytes** can be at most 1 GiB, and **commit.maxInFlight** can be at most 32. Data cannot move between **tencentCOS** and other providers. [Reference](/reference/server/object-storage#tencent-cos).
