section: Added
---
- **PullWorkerOptions::task_queue** makes a **Worker** pull one named task queue, and **StartFlowOptions::task_queue** and **SubFlowOptions::task_queue** run a Flow or SubFlow on one. Workers on different task queues never take each other's work, even for the same Flow type. A SubFlow inherits its parent's task queue unless it names another one, and **dex.default** selects the default task queue. A named task queue requires Server protocol version 5; with an older Server, the Worker refuses to open task streams and the Client refuses to send the start, and a stream that Dex confirms for another task queue is a permanent rejection with an SDK-synthesized **FAILED_PRECONDITION** status. **Worker::task_queue** returns the Worker's task queue. For a Worker on a named task queue, the message of the **SdkError** that reports a registration rejection names the task queue; the typed **PullRegistrationError** keeps its existing fields. The default task queue still works with protocol version 4. [Reference](/reference/rust/workers#task-queue).
