- App Builder SKILL.md is facts first: fifteen fact groups state how each Dex mechanism behaves in each case and its defaults, from commits, locks, and RPCs to Timers, Flow timeout, starts, runs, SubFlows, Joins, Streams, Workers, and limits.
- New inline fact tables: the ID reuse policy by the latest run's state, the Request ID with and without ignore-already-started, and the SubFlow reuse policy. A retry with the same Request ID skips the reuse policy and returns the run only with ignore-already-started.
- The default limits table adds what happens when each limit is exceeded, plus the request IDs kept per run, concurrent waits per Flow, and child results per parent. The heartbeat timeout, retry total duration, and RPC timeout defaults are stated inline.
- Corrected facts: WaitFor may write Attributes and publish or delete messages; a Timer can fire late after an outage; a retry can run past the retry total duration, by about one method timeout or longer when it queues; AnyOf selection order applies only within one check.
- Several interchangeable one-message waiters may share a Channel, such as a worker pool; Dex offers messages in the order the waits started, and a wait for more messages than are queued can starve.
- One Must rule remains: make each external effect safe to repeat. The facts behind the former Musts are stated plainly: Workers can be replaced at any time, commits are atomic but not isolated, and open runs continue on new code by Step type, RPC name, and stored data.
- Rules that follow from one or two facts are removed. Former Prefer items, provider writes and polling outside WaitFor, and generic index slots become suggestions. Start first is replaced by the fact that StartFlow decides repeats atomically per Flow ID.
- Each pattern names the facts it derives from and states its conditions: manual recovery claims a failure under a lock only when needed, a critical section returns the token on exits that keep the Flow running, and a child Flow timeout applies when its limit is fixed at start.
- The reply window supports a hard cutoff by comparing the clock with the stored deadline under the lock. Back pressure loops normally while the parent is full instead of spending the retry budget.
- The product workflow and product constraints move from SKILL.md to references/product-route.md, which the product route reads before Stage 0. One backend language and the default store become conditional choices.
- core/patterns.md becomes an index; each pattern family lives in its own file under core/patterns/, so an agent opens only the family it needs.
- New facts: RPC request ID replay by RPC kind, Flow close waiting for admitted RPCs and Attribute Store writes, ForceCompleteIfChannelsEmpty, Join reporting and partial joins, durability, retention and start deduplication, search lag, and index capacity.
- Removed general advice that is not Dex-specific: browser permission checks, repository conduct, file-reading tips, and test harness recipes. General model and tool guidance moves from the AI agent pattern to the agents Developer reference.
- Corrected facts: a hard-delete value becomes readable only when its method commits and belongs to one run; StopFlow can also complete gracefully or force-complete; a lock conflict is never retried for the caller; a timeout handler's GoTo leaves no Flow timeout.
- New facts: history never limits a run, Channel Condition kinds, a new run inherits no state, time travel, heartbeat checkpoints, Server restarts interrupting attempts, the already-started error without a Run ID, and RPC and timeout handler loads.
- Corrected facts: a canceled attempt can finish its call after compensation starts; all RPC names share one request ID window; canceling a Step releases its locks; time travel is a Client operation; an RPC Context has no first-attempt time; an Attribute write wakes no Step.
- New pattern rows for changing Flow code with open runs and for interrupting one turn. Pattern rows state the facts that connect at hand-offs, such as a reply that commits after a Timer won but before the deciding Execute takes its lock.
- New Time travel and IDs across repeats facts: what is restored and reapplied, Wait Timers keep their fire times, hard-delete values and request IDs stay current, and a Step execution ID created after the point can name other work, so keys come from business data.
- New pending close facts: which requests fail with FLOW_CLOSING, which RPCs commit without their Step starts, and that a requested graceful completion is not a pending close and never checks Channels.
- Corrected facts: WaitFor's failure policy can proceed to Execute; skipping the Flow timeout fires it; only unknown Step types and undelivered tasks return without a retry; locks are released when the result commits; Dex never retries an RPC.
- Rust: pass a cancellation check into a call that can poll it, so a canceled branch ends its open request.
