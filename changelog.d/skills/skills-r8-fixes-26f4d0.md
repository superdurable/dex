- A deadline measured from an event is a Timer started when the event is handled: after each activity the next WaitFor starts a full window, and a polling deadline uses a watchdog Step scheduled with the polling Step. The provider call stays in the unlocked polling Step; a short result Step and the watchdog share a lock, write the terminal state only while it is open, and whoever commits first ends the other. The remaining time is never re-derived from a stored timestamp and the clock.
- Once the decision's snapshot or a closed window fixes the candidates, no clock or Timer grace window waits for later events. Under a reply window, the reply RPC publishes the reply and changes only the window flag; the waiting Step's Execute decides the outcome and records it or moves to the branch that records it.
- A client timeout on a blocking call that cannot observe cancellation is now a recommendation. The method or heartbeat timeout still ends the attempt, and Dex schedules later attempts by the retry policy.
- A child Flow reopened by its own business number keeps that number as its Flow ID. A resend keeps its Request ID; a deliberate reopen is a new start request with a new Request ID, and every reuse policy rejects an active run. The parent accepts only reads, reports, and stops it can tie to the run ID it claimed. A rejected admission is its own state, never ended or failed.
- The lock rule states the decision-commit deadline first: the stop RPC and the deciding Step share the lock, the deciding Step commits only when no stop is committed, and the next, unlocked Step calls the external system. The no-lock grace variant is a separate, shorter rule.
