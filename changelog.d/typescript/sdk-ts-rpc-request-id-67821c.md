- **RPCInvokeOptions.requestId** sets the request ID of one **Client.invokeRPCWithOptions** call. Pass the same ID on every attempt, such as the ID of an event that is delivered at least once, and Dex Server applies the RPC's Flow changes at most once. A transactional or locking RPC answers a repeat from the recorded reply without running its handler again, and rejects a different request under the same ID with **DexServiceError** INVALID_ARGUMENT. Any other RPC runs its handler again; when that attempt changes Flow state or records an event, Dex Server discards those changes and returns the recorded reply, and when it changes no Flow state and records no event, the caller gets the attempt's new output. Use a transactional RPC when callers need the exact recorded reply. Without the option, each call still sends a new random request ID. [Reference](/reference/server/runtime-data#rpc-request-ids).
